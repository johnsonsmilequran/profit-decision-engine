## 4. 边界与降级

- 新品以数据批次业务截止日为基准，按上架未满两个自然月判断，避免使用导入时间导致同一批数据结论漂移。
- 销售、利润、品退和库存字段缺失按字段级降级；只有商品链接等必要身份字段缺失才拒绝整行。
- 新品暂不生成补货建议；库存或最近十四天销量不足时不生成补货建议。
- 表格没有评价、退款原因和广告明细时，产品不输出无证据的归因或明细优化动作。
- 钉钉认证成功但身份属性不足、跨企业作用域、双角色或审批证据不完整时只保留待处理/冲突事实，不创建业务会话或猜测角色。
- setup、保存型恢复码和部署恢复材料均为环境/代次约束的一次性秘密；提交结果未知时查询幂等结果，不重复创建 Admin 或重复消费材料。
- 外部通知通道失败不得伪装已送达；只有 `delivered` 或有认可证据的 `compensated_closed` 才形成通知闭环。

## 5. 决策依赖与未决项

- 当前没有阻塞规格定稿的产品 P0/P1 未决项；生产启用仍受真实身份双属性、岗位联系人、证据目录、环境隔离和恢复演练等明确门禁约束，这些是 required 前置，不是 OPEN_QUESTION。
- Asia/Shanghai 作为当前业务日期实现假设；如后续事业部跨时区，应在不改变业务口径的前提下参数化。
- 双角色身份认证与映射能力已形成 committed 责任承诺：当前 Client 凭据的 Access Token 与 OAuth 授权跳转已验证；生产前仍需真实链路取得稳定身份、企业作用域和至少两个可靠组织属性。已有唯一角色进入原工作台，无唯一角色进入 F09 待处理，认证失败或会话失效才默认拒绝。
- 钉钉企业内部机器人单聊已完成真实手动协同和 Worker 每日催办验证：官方 `readStatus` 两次均为 `SUCCESS`、收件人数 1，同日催办无重复；未读仍不等于业务确认，失败时仍保留通知失败和人工补发。
- 当前验收数据唯一使用仓库根目录 `商品链接.xlsx` 的实际 10 个 SPU、单期和缺失字段状态；SPU 515 仅保留为历史价值案例，不是当前导入前置。跨周续接和动作变化行为仍 required，使用真实 PostgreSQL 持久化集成测试验证。
- Go 后端与 React 前端已在后续设计阶段由用户确认；该实现选择不改变本需求契约的行为语义或 Source revision。
