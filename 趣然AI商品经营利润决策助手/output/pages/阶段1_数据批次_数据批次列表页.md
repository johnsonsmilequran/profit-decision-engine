## 2. 页面概述

### 2.1 一句话定位

数据批次列表页是每周一 XLSX 经营数据进入系统后的历史总账：运营和运营主管可在这里区分当前批次与历史批次，查看处理状态及校验摘要，并进入冻结的批次详情追溯当时使用的数据期间和规则版本。

### 2.2 存在理由

1. 没有统一批次历史，运营无法确认某份周报是否已进入系统，也难以解释某周行动清单来自哪份数据。
2. 如果新批次覆盖旧批次，历史建议、审核动作和执行结果将失去可追溯依据。
3. 如果处理状态和校验摘要不可见，运营只能反复询问数据支持部门，无法判断应等待、修正数据还是继续查看已完成结果。
4. 如果不同角色看到相同入口，运营主管可能误触导入，采购计划也可能接触超出职责范围的利润、推广和售后批次信息。

### 2.3 页面目标（可衡量）

| 目标维度 | 具体指标 |
| :--- | :--- |
| 批次识别 | 页面中的每个批次 100% 展示唯一批次标识、事业部、数据期间和业务截止日 |
| 状态透明 | 已加载批次 100% 展示当前处理状态；处理失败时给出可继续处理的明确入口 |
| 校验可见 | 已完成校验的批次 100% 展示有效、拒绝、降级数量摘要，零值与尚未产出可区分 |
| 历史保留 | 导入新批次后，已有历史批次及其详情入口保留率为 100%，不得被覆盖 |
| 幂等展示 | 同一文件指纹的重复提交只展示原批次，不产生第二条批次记录 |
| 版本追溯 | 已进入规则处理的批次 100% 可进入批次详情，查看其冻结期间、业务截止日、校验结果和规则版本 |

### 2.4 不做什么（范围边界）

- **不在列表页直接上传 XLSX**——本页仅提供导入入口，文件选择、事业部和期间确认由 `PAGE-F01-02` 承担。
- **不展示逐行错误、源表原值和完整错误分组**——本页只展示校验摘要，详细问题在批次详情页查看。
- **不展示加投、广告止损、补货、禁补或清仓结论**——这些属于行动清单，不属于批次历史索引。
- **不允许删除、覆盖或以当前规则重新计算历史批次**——历史批次必须保留当时版本，确保审计可追溯。
- **不提供 CSV 导入、外部系统自动同步、批量导出或错误文件下载**——这些能力未被本页 Source IDs 覆盖。
- **不向采购计划开放本页**——采购计划只看补货/禁补结论及必要库存、销量依据，不应接触完整批次经营数据。

## 3. 用户与场景

### 3.1 目标用户

| 维度 | 运营 | 运营主管 |
| :--- | :--- | :--- |
| 页面权限 | 查看全部批次、进入详情、发起新批次导入 | 查看全部批次、进入详情，不可发起导入 |
| 使用频率 | 每周一导入新表时使用，并在处理期间复查状态 | 审核经营清单或复盘历史决策时使用 |
| 技术熟练度 | 中等，熟悉经营表格与日常系统操作 | 中等，关注经营结果与追溯依据 |
| 使用设备 | 办公电脑 | 办公电脑 |
| 使用姿势 | 近距离坐姿，先确认批次再进入详情或行动流程 | 近距离坐姿，以查阅和追溯为主 |

采购计划不是本页目标用户，不显示本页导航，也不能通过直接访问进入页面。

### 3.2 核心使用场景

**场景 A：每周一发起新数据批次（主场景）**

- 时机：数据支持部门提供本周经营 XLSX 后。
- 前置：运营已登录并拥有导入权限；当前仍可查看最近一个已完成批次及其行动清单。
- 动作：运营进入本页确认历史批次 → 点击“导入新批次” → 进入 `PAGE-F01-02` 完成导入 → 返回或重新进入本页查看新批次的处理状态与校验摘要。
- 情绪：希望快速确认文件确实已被接收，并知道当前应等待还是处理校验问题。

**场景 B：主管追溯某周经营结论（复盘场景）**

- 时机：运营主管审核经营动作、复盘损失或核对某周建议来源时。
- 前置：目标批次仍保留在历史记录中；主管拥有查看权限。
- 动作：主管按数据期间定位批次 → 核对业务截止日、处理状态和有效/拒绝/降级数量 → 进入批次详情查看冻结的校验信息与规则版本。
- 情绪：希望看到稳定、未被新数据改写的证据，能够解释当时结论。

**场景 C：重复提交后确认没有重复批次（兜底场景）**

- 时机：运营因重复点击、网络重试或多人同时提交同一份文件而担心产生重复结果。
- 前置：相同文件指纹的首次提交已经成功创建批次。
- 动作：运营回到列表 → 看到原批次及原处理状态，没有新增第二条同指纹批次 → 进入原批次继续处理。
- 情绪：不困惑、不担心重复清单或重复经营动作。

### 3.3 用户核心诉求（优先级排序）

1. **准**：清楚知道某条记录对应哪一批、哪个事业部和哪个自然月数据。
2. **稳**：新数据和重复提交都不能覆盖、复制或篡改历史批次。
3. **快**：一眼识别当前批次的处理阶段、校验结果和下一步入口。
4. **可追溯**：任何历史批次都能回到冻结详情核对规则版本和关键时间。
5. **权限清楚**：运营能导入，运营主管只读，采购计划无法进入。

## 4. 信息架构

### 4.1 区域划分

1. 页面上下文区
2. 当前批次区
3. 历史批次区
4. 加载与异常反馈区
5. 分页区

### 4.2 区域内容

**1. 页面上下文区**

- 页面名称与用途说明。
- 当前事业部、当前批次上下文和登录角色。
- 仅运营可见的“导入新批次”入口。

**2. 当前批次区**

- 最近一个已成功生成行动清单的批次摘要。
- 批次标识、数据期间、业务截止日、处理状态、校验摘要和规则版本。
- 进入冻结批次详情的入口。
- 如果最新提交仍在处理或处理失败，继续保留最近一个已完成批次为当前经营上下文，并单独提示最新提交状态。

**3. 历史批次区**

- 当前批次以外的所有历史批次。
- 每条记录展示批次身份、期间、处理状态、校验摘要、创建信息和追溯入口。
- 批次按业务截止日从新到旧排列；同一业务截止日内保持确定顺序，翻页后不重复、不遗漏。

**4. 加载与异常反馈区**

- 首次无批次、加载中、加载失败、处理失败、会话过期和无权限反馈。
- 反馈只说明用户下一步，不暴露源文件内容、存储位置或内部错误细节。

**5. 分页区**

- 默认每页 50 条，可切换 20、50、100 条。
- 显示总记录数、当前页和总页数。
- 当前页与每页数量在用户返回本页时保持，避免追溯后丢失位置。

## 5. 界面内容

### 5.1 元素清单

**页面标题**

- 内容：“数据批次”。
- 辅助文案：“查看每周经营数据的处理状态、校验摘要与历史版本。”
- 数据来源：固定页面文案。
- 显示条件：已通过本页权限校验。

**上下文信息**

- 内容：当前事业部、当前批次标识、当前用户角色。
- 数据来源：登录身份与当前成功批次。
- 显示条件：始终显示；无当前成功批次时显示“暂无当前批次”。

**导入新批次入口**

- 文案：“导入新批次”。
- 数据来源：当前用户权限。
- 显示条件：仅运营角色显示；运营主管不显示；采购计划和未知角色无权进入本页。
- 操作结果：进入 `PAGE-F01-02` 的新批次导入状态，不在本页弹出上传表单。

**当前批次摘要**

- 内容：当前批次标识、事业部、数据期间、业务截止日、处理状态、有效/拒绝/降级数量、规则版本、创建时间和提交人。
- 数据来源：最近一个已成功生成行动清单的批次及其冻结快照。
- 显示条件：存在已完成批次时显示；否则显示首次使用空状态。

**最新提交提示**

- 内容：最新提交批次的批次标识、处理状态和下一步说明。
- 数据来源：按创建时间识别的最新提交批次。
- 显示条件：最新提交仍在接收、校验、规则处理或失败，且它不是当前成功批次时显示。
- 约束：不得用尚未完成或失败的最新提交替换当前成功批次。

**历史批次记录**

- 批次标识：用于唯一识别和进入详情。
- 事业部：阶段1固定为玩具事业部，但仍需展示以便历史核对。
- 数据期间：展示自然月起止日期；首批为 2026-06-01 至 2026-06-30，并标明“上一个完整自然月”。
- 业务截止日：展示批次数据覆盖到的业务日期。
- 文件显示名：只展示用户可识别的文件名，不展示文件存储位置。
- 处理状态：收到、校验中、规则处理中、清单已生成或失败。
- 校验摘要：有效数量、拒绝数量、降级数量；校验未完成时显示“待产出”，不得显示为 0。
- 规则版本：规则处理完成后展示冻结版本；尚未进入规则处理时显示“待生成”。
- 创建信息：创建时间、提交人。
- 详情入口：文案“查看批次详情”，进入该批次的 `PAGE-F01-02`。
- 数据来源：对应批次记录及冻结快照。
- 显示条件：该用户具有本页查看权限。

**分页控件**

- 内容：总记录数、当前页、总页数、上一页、下一页和每页数量。
- 数据来源：历史批次总量与当前列表位置。
- 显示条件：存在批次记录时显示；不足一页时仍明确总记录数。

### 5.2 辅助信息

- 周期说明：“数据支持部门每周一提供经营表格；每次有效新批次生成一份独立行动清单。”
- 历史说明：“新批次不会覆盖历史批次及其审核、执行和结果记录。”
- 状态说明：处理状态反映批次主链路；AI 说明是否成功不改变批次是否可生成行动清单的判断。
- 追溯说明：规则版本、数据期间和校验详情以批次详情中的冻结信息为准。

## 6. 交互流程

### 6.1 页面加载与初始化

1. 用户进入本页后先校验登录状态和角色权限。
2. 运营或运营主管通过后，加载当前成功批次、最新提交状态和历史批次首屏；采购计划或未知角色不得加载批次数据。
3. 存在已完成批次时，将最近一个“清单已生成”批次标记为当前批次；最新批次尚在处理或失败时不替换它。
4. 历史列表默认每页 50 条，先显示当前批次，再显示其余历史记录。
5. 首次尚无任何批次时显示空状态；运营可从空状态进入导入页，运营主管只能看到“等待运营导入首批数据”的说明。

### 6.2 核心操作流程

**流程一：查看批次历史并进入追溯详情**

```text
运营或运营主管进入数据批次列表页
        │
        ├─ 无可访问权限 → 拒绝访问，不展示任何批次信息
        │
        └─ 有查看权限 → 展示当前批次、最新提交提示和历史批次
                          │
                          ├─ 点击某批次“查看批次详情”
                          │        ↓
                          │   进入 PAGE-F01-02，查看冻结期间、校验详情与规则版本
                          │
                          └─ 加载失败 → 保留明确错误反馈，用户可重试
```

**流程二：运营发起每周一新批次导入**

```text
运营点击“导入新批次”
        ↓
进入 PAGE-F01-02 的导入状态
        ↓
提交 XLSX 后创建或返回已有批次
        │
        ├─ 新文件指纹 → 新批次独立进入处理，历史批次不变
        │
        └─ 相同文件指纹 → 返回首次成功创建的原批次，不新增列表记录
        ↓
回到本页时显示该批次当前处理状态与已产出的校验摘要
```

### 6.3 辅助操作

- 点击“重试加载”仅重新获取列表，不创建新批次，也不改变批次处理状态。
- 切换每页数量后回到第一页，避免当前页超出新的总页数。
- 从批次详情返回时，恢复离开前的页码和每页数量。
- 对仍在处理的批次，用户可重新加载查看最新状态；同一次加载动作不可触发重新处理。
- 运营主管直接访问导入状态时返回本列表页并说明“仅运营可导入新批次”，不得显示上传控件。

## 7. 状态与边界

### 7.1 页面状态全景

| 状态 | 触发条件 | 页面表现 |
| :--- | :--- | :--- |
| 权限校验中 | 刚进入页面，身份与角色尚未确认 | 暂不展示批次内容和导入入口 |
| 加载中 | 角色可访问，批次列表尚未返回 | 展示正在加载说明，不显示虚构批次数据 |
| 首次空状态 | 用户有查看权限，但尚无任何批次 | 说明尚未导入；运营可进入导入页，主管只读等待 |
| 正常有数据 | 当前与历史批次加载成功 | 展示当前批次、最新提交提示、历史列表和分页 |
| 批次处理中 | 某批次处于收到、校验中或规则处理中 | 展示对应处理状态；未产生的校验数量或规则版本显示“待产出/待生成” |
| 清单已生成 | 有效批次完成规则处理并生成行动清单 | 可显示为当前成功批次，并保留规则版本及详情入口 |
| 批次失败 | 接收、校验或规则处理失败 | 该批次保留在历史中并显示失败；不替换当前成功批次 |
| 列表加载失败 | 网络或系统异常导致列表不可用 | 展示“数据批次加载失败，请重试”，提供重试加载入口 |
| 会话过期 | 使用中登录状态失效 | 停止展示批次数据，引导重新登录；重新登录后按权限返回 |
| 无权限 | 采购计划、未知角色或权限被撤销 | 拒绝访问，不展示批次身份、数量、文件名或详情入口 |
| 非支持设备 | 可用宽度低于 1024px | 提示“请使用电脑访问”，不进入批次操作流程 |

### 7.2 边界与容错

| 边界场景 | 处理策略 |
| :--- | :--- |
| 网络中断或请求超时 | 显示加载失败和重试入口；重试只刷新列表，不创建、覆盖或重新处理批次 |
| 会话在查看期间过期 | 立即停止继续获取或展示批次详情，引导重新登录；恢复后重新校验角色 |
| 连续多次加载失败 | 每次均提供一致、可行动的反馈，不伪造空列表；不得把“加载失败”表达为“暂无批次” |
| 异常页码或每页数量 | 回到可用页码并采用允许的 20、50、100 之一，不影响批次数据本身 |
| 相同文件重复点击、网络重试或并发提交 | 列表只保留首次成功创建的原批次，后续请求返回原批次及原清单状态 |
| 不同文件并发提交 | 每个不同指纹形成独立批次；各批次状态分别展示，互不覆盖 |
| 最新批次处理中，已有上周成功批次 | 继续以上周成功批次作为当前经营上下文，同时单独展示最新提交的处理状态 |
| 最新批次处理失败 | 保留失败记录供追溯，不替换当前成功批次，不删除此前行动清单 |
| 校验数量为 0 | 明确显示 0；只有尚未产出时才显示“待产出”，两者不得混淆 |
| 某周一没有新文件 | 继续展示现有当前与历史批次，不虚构本周批次，也不改变历史状态 |
| 批次超过一页 | 使用稳定分页；翻页和返回后不重复、不遗漏，并保持用户离开前的位置 |
| 直接访问不存在的批次详情 | 返回本页并提示“未找到该批次或无权查看”，不透露批次是否属于其他角色可见范围 |
| 主管尝试进入导入状态 | 不显示文件选择和提交能力，返回列表并说明仅运营可导入 |
| 采购计划直接访问本页 | 拒绝访问且不返回任何批次经营数据 |

## 8. 业务规则与校验

### 8.1 字段定义

| 字段 | 说明 |
| :--- | :--- |
| `batch_id` | 批次唯一标识；同一文件指纹的重复提交沿用首次成功创建的标识 |
| `business_unit` | 批次所属事业部；阶段1为玩具事业部 |
| `period_start` / `period_end` | 本批次经营数据的自然月起止日期 |
| `business_date` | 数据覆盖到的业务截止日，用于判断批次时点 |
| `source_file_name` | 供用户识别来源的文件显示名，不包含文件存储位置 |
| `batch_status` | 收到、校验中、规则处理中、清单已生成或失败 |
| `valid_count` | 通过批次与经营字段校验、可进入规则计算的 SPU 数量 |
| `rejected_count` | 因批次或身份问题被拒绝进入规则计算的记录数量 |
| `degraded_count` | 因经营字段缺失等原因被降级处理或仅产生提醒的记录数量 |
| `rule_version` | 本批次规则处理使用并冻结的规则版本；处理前可为空 |
| `list_status` | 本批次行动清单是否已生成，用于识别当前成功批次 |
| `created_at` / `created_by` | 批次首次成功创建的时间与提交人 |
| `current_batch` | 是否为最近一个已成功生成行动清单的经营上下文 |

### 8.2 校验规则

| 校验项 | 时机 | 规则 | 失败反馈 |
| :--- | :--- | :--- | :--- |
| 角色权限 | 页面进入及每次操作时 | 运营可查看和导入；运营主管可查看不可导入；采购计划和未知角色不可访问 | “你没有查看数据批次的权限”或“仅运营可导入新批次” |
| 批次身份 | 列表展示和进入详情时 | 每条记录必须具备唯一批次标识，详情入口只能携带当前行对应批次 | “未找到该批次或无权查看” |
| 数据期间 | 展示批次时 | 起止日期必须组成已记录的自然月期间；首批展示 2026-06-01 至 2026-06-30，并标明上一个完整自然月 | 数据异常时该批次显示失败或不可用，不用猜测日期补齐 |
| 业务截止日 | 展示批次时 | 必须显示批次冻结的业务截止日，不得用当前日期替换 | 缺失时显示批次数据异常，并引导进入详情核对 |
| 校验摘要 | 校验完成后 | 有效、拒绝、降级数量均应有明确非负值；尚未完成时统一显示“待产出” | 数量不可用时不显示为 0，提示进入详情核对 |
| 规则版本 | 规则处理完成后 | 显示本批次冻结版本；新版本不得回写历史批次 | 未进入规则处理时显示“待生成” |
| 处理状态 | 每次列表加载时 | 状态必须来自该批次实际主链路；AI 说明状态不得将失败主链路标记为成功，也不得阻止规则成功批次就绪 | 无法识别时显示异常，不推断为清单已生成 |
| 分页位置 | 翻页或切换每页数量时 | 每页数量只能为 20、50、100；页码必须在当前总页数内 | 自动回到有效页并提示列表已更新 |

### 8.3 特殊业务规则

- **当前批次定义**：最近一个已成功生成行动清单的批次才可作为当前经营上下文；“最新提交”不等于“当前批次”。
- **一批一清单**：每个有效新批次只生成一份行动清单，列表需保留批次与该清单的稳定对应关系。
- **幂等导入**：相同文件指纹的重复点击、重试和并发提交返回首次成功创建的原批次及原清单状态，不新增列表行、建议或事件。
- **历史不可覆盖**：不同指纹创建独立批次；后续批次不得改写历史批次、历史清单、审核、执行或结果记录。
- **冻结追溯**：历史详情必须以该批次的数据期间、业务截止日、规则版本、关键值和当时状态为准，不套用当前规则重算。
- **状态独立**：批次主处理是否就绪由接收、校验和规则处理决定；AI 解释异常只能影响解释显示，不得改变主规则输出是否生成。
- **数据粒度**：阶段1按商品链接作为 SPU 处理；本页统计和批次身份不得切回 SKU 口径。
- **事业部范围**：阶段1只处理玩具事业部；本页不提供跨事业部混合查看或切换。
- **历史保留**：本页不提供删除、归档、覆盖或重算历史批次的操作。

## 9. 页面流转

### 9.1 流转图

```text
运营工作台 / 系统导航
          │
          ▼
数据批次列表页（本页）
    │                 │
    │ 运营：导入新批次 │ 运营或主管：查看批次详情
    ▼                 ▼
PAGE-F01-02       PAGE-F01-02
导入状态             冻结详情状态
    │                 │
    │ 创建新批次或     │ 查看期间、校验摘要、
    │ 返回原批次       │ 规则版本和处理结果
    └────────┬────────┘
             ▼
       返回本页对应位置
```

### 9.2 与其他模块的关系

- **高保真联调**：工作台、行动中心、历史与追溯以及导入/批次详情入口均使用真实 HTML 目标，不得被通用原型提示阻断。
- **运营工作台**：提供进入数据批次列表的入口；工作台当前批次上下文必须与本页最近一个成功批次一致。
- **数据导入与批次详情页 `PAGE-F01-02`**：承担 XLSX 导入、处理阶段、详细校验结果和冻结版本查看；本页只显示摘要与入口。
- **行动清单**：有效批次完成后产生独立行动清单；本页保存批次身份和清单状态，但不展示具体建议。
- **历史与追溯**：历史批次是建议快照、审核、执行和结果追溯的上游证据，任何新批次不得覆盖该证据链。
- **权限模块**：运营拥有导入能力，运营主管只读，采购计划与本模块隔离。

### 9.3 扩展预案

| 扩展方向 | 触发条件 | 改造点 |
| :--- | :--- | :--- |
| 多事业部批次 | PRD 新增多事业部范围并明确角色授权 | 增加已授权事业部上下文与批次隔离规则；不改变既有批次身份 |
| 自动数据同步 | PRD 明确数据源、同步周期和失败责任 | 增加自动来源标识与同步状态；继续保留一批一版本和历史不可覆盖 |
| 批次导出 | PRD 明确导出字段、权限和审计要求 | 增加受控导出入口；不得借此开放源文件或越权经营信息 |
| 历史归档 | PRD 明确保留期与恢复规则 | 增加可恢复的历史分层；当前阶段不预埋删除入口 |

## 11. 验收标准

### 11.1 功能验收

| 编号 | 验收点 | 通过标准 |
| :--- | :--- | :--- |
| F-01 | 批次历史完整 | 导入一个不同指纹的新批次后，新批次增加一条记录，原有批次及其详情入口全部保留且内容不变 |
| F-02 | 幂等批次展示 | 对同一 XLSX 进行重复点击、网络重试或并发提交后，列表仍只有首次成功创建的一条批次记录，并展示原处理与清单状态 |
| F-03 | 当前批次识别 | 最新提交处于处理中或失败时，页面仍将最近一个“清单已生成”批次标为当前批次，并另行展示最新提交状态 |
| F-04 | 校验摘要 | 校验完成的每条批次均展示有效、拒绝、降级数量；零值显示 0，未完成显示“待产出” |

| F-06 | 状态展示 | 收到、校验中、规则处理中、清单已生成和失败五类主状态均能被准确区分，AI 解释状态不改变主状态 |
| F-07 | 版本追溯 | 对已完成规则处理的任一历史批次点击详情，可查看该批次冻结的数据期间、业务截止日、校验结果和规则版本 |
| F-08 | 导入入口 | 运营能从本页进入 `PAGE-F01-02` 的导入状态；运营主管不显示导入入口且不能进入导入状态 |
| F-09 | 分页完整 | 历史记录超过 50 条时默认分页为 50，可切换 20、50、100；逐页浏览无重复、无遗漏 |
| F-10 | 首次空状态 | 没有任何批次时，运营看到可执行的导入入口；运营主管看到等待运营导入的只读说明 |

| 编号 | 验收点 | 通过标准 |

### 11.3 安全验收（产品层）

| 编号 | 验收点 | 通过标准 |
| :--- | :--- | :--- |
