| 冲突主题 | 处理结论 | 关联需求 |
| :--- | :--- | :--- |

| 止损/清仓与继续补货冲突 | 止损或清仓与禁补在同一规则决策中原子生成，责任运营通过 OA 协调相关人员并核验回填禁补结果。 | REQ-F03-03、REQ-F06-02 |
| AI 与固定规则权威冲突 | 固定规则是唯一的原始建议判定源；AI 仅解释且不能发起人工改判，失败不阻塞清单、审核或执行。 | REQ-F03-02、REQ-F04-01、REQ-F04-02、REQ-F06-04 |
| 重复导入与重复清单 | 相同指纹及期间直接返回原批次和原清单，不产生新的业务对象。 | REQ-F01-02、REQ-F05-01 |
| 新批次与重复执行任务 | 每周新决策快照独立保留；同一 SPU 同动作只续接稳定任务并保留状态，不重复建任；动作变化则追加待主管确认版本。 | REQ-F05-01、REQ-F05-04、REQ-F06-01、REQ-F08-01、REQ-F08-02 |
| 单一当前状态与审计历史 | 当前状态使用版本控制；所有变更以追加事件保留，过期更新不得覆盖。 | REQ-F06-02、REQ-F06-03、REQ-F08-02 |
| 外部协同与最小可见 | 采购、仓库等相关人员不登录产品；OA 消息只含 SPU、协同动作、责任运营和反馈要求，最终状态由运营核验录入。 | REQ-F06-02、REQ-F07-02 |
| 统一身份与业务角色权限 | 钉钉只映射运营、运营主管；事业部负责人审批，运维/系统管理员配置；无认证或无双角色映射时默认拒绝。 | REQ-F07-01、REQ-F07-03 |

| 跨周规则变化与现有审核边界 | 同动作续接不重复审核；如清仓变为观察，先显示新规则动作并建立待主管确认版本，通过后才切换当前生效动作，驳回不覆盖原任务。 | REQ-F05-04、REQ-F06-01、REQ-F06-04、REQ-F08-02 |
| SPU 稳定任务与前序建议快照 | 经营待办以事业部与 SPU/商品链接精确锚定；当前周记录显示当前任务生命周期，最近前序待办则从其原批次不可变决策快照展示当时的主动作、关键依据、库存语境、经营状态和时间，避免用当前周数据回填历史或把更新时间冒充执行时间。 | REQ-F05-04、REQ-F05-05、REQ-F08-01、REQ-F08-02 |
| 经营状态与聚合状态 | 经营状态筛选只匹配经营动作轨；建议审核、库存协同和总览聚合状态继续分别存在，不能代替经营状态。 | REQ-F05-02、REQ-F05-05、REQ-F06-01、REQ-F06-02 |
| 清仓完成与跨周续接 | 清仓同动作跨周沿用稳定任务；运营提交实际完成时间、主管确认后闭环，未确认前按自然日幂等 OA 催办责任运营。 | REQ-F05-04、REQ-F06-05、REQ-F08-02 |

## 4. 边界与降级

- 新品以数据批次业务截止日为基准，按上架未满两个自然月判断，避免使用导入时间导致同一批数据结论漂移。
- 销售、利润、品退和库存字段缺失按字段级降级；只有商品链接等必要身份字段缺失才拒绝整行。
- 新品暂不生成补货建议；库存或最近十四天销量不足时不生成补货建议。
- 表格没有评价、退款原因和广告明细时，产品不输出无证据的归因或明细优化动作。

## 5. 决策依赖与未决项

- 当前没有阻塞 MVP 设计和开发的产品 P0/P1 未决项。
- Asia/Shanghai 作为当前业务日期实现假设；如后续事业部跨时区，应在不改变业务口径的前提下参数化。
- 双角色身份认证与映射能力已形成 committed 责任承诺：当前 Client 凭据的 Access Token 与 OAuth 授权跳转已验证；最终回调仍需真实测试账号的稳定 `unionId` 命中唯一已审批角色映射，失败时默认拒绝。
- 钉钉企业内部机器人单聊已完成真实手动协同和 Worker 每日催办验证：官方 `readStatus` 两次均为 `SUCCESS`、收件人数 1，同日催办无重复；未读仍不等于业务确认，失败时仍保留通知失败和人工补发。
- 当前验收数据唯一使用仓库根目录 `商品链接.xlsx` 的实际 10 个 SPU、单期和缺失字段状态；SPU 515 仅保留为历史价值案例，不是当前导入前置。跨周续接和动作变化行为仍 required，使用真实 PostgreSQL 持久化集成测试验证。
- Go 后端与 React 前端已在后续设计阶段由用户确认；该实现选择不改变本需求契约的行为语义或 Source revision。
