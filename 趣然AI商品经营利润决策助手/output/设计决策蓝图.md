# 设计决策蓝图（推荐方案待总确认）

> 项目：趣然 AI 商品经营与利润决策助手  
> 上游契约：`PRD详细版.md` + `requirements.md` revision 2 + `requirements-analysis.md`  
> 工作模式：Feature / standard  
> 当前闸门：阶段 I 已收敛；用户总确认后进入阶段 II 静默批量交付

## 0. 设计目标与范围

- 核心问题：把每周 SPU 经营数据变成一份确定、可审核、可分角色执行、可追溯的行动清单，防止运营止损与采购继续补货互相抵消。
- MVP 范围：完整覆盖 F01—F08；决策粒度只到 SPU/商品链接；AI 只解释，不改写固定规则结论。
- 明确不做：移动端业务操作、账号密码体系、业务侧角色管理、广告/采购/库存系统自动写入、SKU 决策、错误文件下载、全局导出、批量审核或执行。

## 1. 盘子

### 1.1 端形态与响应式

- PC Web 后台优先，以 1440px 主画布设计，最低支持 1280px。
- 低于 1280px 时保留登录与业务阅读提示，不保证密集表格与审核操作；MVP 不建设移动端业务流。
- 主内容区适应窗口宽度，密集表格使用固定关键列 + 水平滚动，不通过压缩字号牺牲可读性。

### 1.2 角色化工作台

- 运营：本周风险、待执行经营动作、本人最近结果、新建数据批次入口。
- 运营主管：待审核数、高优先级建议、经营/采购跨角色阻塞、最近审核。
- 采购计划：待补货、待禁补、已执行待回填结果；仅显示库存、销量与补货决策的最小必要依据。
- 三种视图共用同一批次、建议、动作与事件真值源，不创建角色私有副本。

## 2. 信息架构与站点地图

### 2.1 全站框架

- 固定左侧导航：工作台、行动清单、数据批次、追溯记录。
- 顶部上下文栏：当前业务角色、当前批次、钉钉身份；角色不由用户自由切换。
- 详情层：建议详情为独立页，配面包屑和固定操作区；指标、规则、AI 解释、审核、执行与追溯不拆为一级导航。

### 2.2 MVP 页面与调用关系

```text
钉钉登录 PAGE-AUTH-001
  ├─ 认证/映射成功 → 角色化工作台 PAGE-WORK-001
  └─ 无映射/越权 → 无权限 PAGE-AUTH-002

工作台 PAGE-WORK-001
  ├─ 待办/风险 → 行动清单 PAGE-ACTION-001
  ├─ 具体建议 → 建议详情 PAGE-ACTION-002
  └─ 导入入口（仅运营）→ 新建导入 PAGE-BATCH-002

数据批次 PAGE-BATCH-001
  ├─ 新建 → 新建导入 PAGE-BATCH-002
  └─ 批次行 → 批次详情 PAGE-BATCH-003

新建导入 PAGE-BATCH-002
  └─ 提交后自动校验、运行规则 → 批次详情 PAGE-BATCH-003

批次详情 PAGE-BATCH-003
  ├─ 行动清单 Tab/指标表行 → 建议详情 PAGE-ACTION-002
  └─ 批次追溯 → 追溯记录 PAGE-TRACE-001

行动清单 PAGE-ACTION-001
  └─ 建议行 → 建议详情 PAGE-ACTION-002

追溯记录 PAGE-TRACE-001
  └─ 建议/事件 → 建议详情 PAGE-ACTION-002
```

## 3. 角色、认证与权限

- 上游已确认认证：产品独立登录页只提供钉钉登录；不提供注册、账号密码、找回密码或共享账号。
- 登录恢复：认证失败、登录态失效或无有效角色映射时，提供重新登录与联系 IT 指引；不降级开放业务数据。
- 角色责任：IT 维护运营、运营主管、采购计划映射；产品仅消费服务端认证与映射结果，不建业务侧角色管理页。
- 同页差异：永远不属于当前角色的能力直接隐藏；属于该角色但受当前状态限制的控件保留并置灰，显示原因。
- 越权直链：返回通用无权限页，错误文案不泄露 SPU、利润、推广、售后或对象存在性。
- 服务端默认拒绝：前端隐藏不构成权限边界；采购读模型仅返回补货/禁补结论与库存、销量等必要依据。

## 4. 页面地图与 MVP 施工图深度

### 4.1 PAGE-AUTH-001 钉钉登录

- 骨架：产品标识、一句价值说明、唯一主操作“使用钉钉登录”、内部系统声明。
- 状态：初始、跳转/回调加载、认证失败、登录态失效、无角色映射；不存在已登录用户的“无权限”业务数据状态。

### 4.2 PAGE-AUTH-002 无权限

- 骨架：通用拒绝说明、返回工作台、重新登录、联系 IT。
- 状态：无角色映射、已登录但无页面权限、会话失效；始终不显示受限对象摘要。

### 4.3 PAGE-WORK-001 角色化工作台

- 骨架：当前批次摘要、角色 KPI/待办卡、高优先级项、最近动态、角色化快捷入口。
- 状态：首次无批次、无本人待办、加载、部分卡片失败、整页失败、无权限。无批次时仅运营看到新建导入主操作。

### 4.4 PAGE-BATCH-001 数据批次列表（F01）

- 骨架：批次编号、事业部、数据期间、业务截止日、文件名、处理状态、有效/拒绝/降级数、清单状态、导入人与时间。
- 行为：运营可新建导入；重复指纹返回原批次而非新增。
- 状态：无批次、筛选无结果、加载、失败、无权限。

### 4.5 PAGE-BATCH-002 新建导入（F01）

- 骨架：事业部、数据期间、批次业务截止日、XLSX 文件、口径提醒、提交。
- 行为：提交后自动校验、运行固定规则并进入批次详情；不增加第二个“生成清单”按钮。
- 状态：初始、文件解析中、上传/处理中、字段/期间错误、不可读文件、指纹命中旧批次、网络失败、无权限。

### 4.6 PAGE-BATCH-003 批次详情（F01—F03、F05、F08）

- 顶部：批次身份、期间/截止日、规则版本、处理状态、有效/拒绝/降级/警告汇总卡。
- Tab A「校验结果」：拒绝行、字段级降级、普通警告分区表格，每项显示源行号、字段、原值、原因、是否继续计算；MVP 不下载错误文件。
- Tab B「指标与数据质量」：SPU 身份、月净销售额/期间、经营准利润率/来源、近 7 日品退率/验证标记、库存可售天数/状态、质量标记。
- Tab C「规则结果」：商品分类、经营主动作、补货/禁补动作、触发阈值、依赖降级、规则版本；全部只读。
- Tab D「行动清单」：该批次发布的建议与审核/动作汇总状态，点击进入建议详情。
- 状态：处理中、处理失败、无有效行、某 Tab 无结果、加载、部分失败、无权限。采购不进入完整指标与规则数据视图。

### 4.7 PAGE-ACTION-001 行动清单（F05—F07）

- 骨架：默认展示最新成功批次，可切换历史批次；顶部汇总、搜索、筛选、筛选标签、稳定分页、角色化结果表。
- 筛选：动作类型、店铺、责任运营、审核状态、经营执行状态、采购执行状态；采购只看与本角色相关的筛选。
- 排序：服务端按业务行动优先级排序，相同优先级使用稳定建议 ID 打破平局；MVP 不开放用户改写规则排序。
- 状态：最新批次不存在、清单空、筛选无结果、加载、失败、批次切换失败、无权限。MVP 不做无限滚动、批量操作或导出。

### 4.8 PAGE-ACTION-002 建议详情（F02—F08）

- 首屏层级：SPU 身份 + 固定规则结论 + 问题 + 关键依据 + 推荐动作；右侧/页底固定操作区随角色和状态变化。
- 指标依据：显示统计期间、原值、校验状态、数据质量标记与来源批次。
- 规则路径：商品分类、命中阈值、主动作唯一化、补货冲突约束、规则版本和输入快照，全部只读。
- AI 解释：结构化四要素兜底始终先可用；AI 状态显示等待、成功、失败或越界被过滤；AI 增强文案为次级可折叠内容，不覆盖、弱化或改写固定规则。不提供用户手动重生成或版本选择。
- 审核：仅运营主管对整条建议一次通过或驳回；通过备注可选，驳回原因必填；确认弹窗明示这会同时决定经营与补货/禁补动作是否激活。
- 执行：通过后分为经营动作和采购动作两条轨道；运营与采购计划只能更新自己负责的动作、结果与后续数据。
- 并发冲突：version 冲突时拒绝覆盖，页顶强提示最新操作人/时间并要求刷新；不提供“仍然保存”。
- 时间线：建议级审核、经营动作、采购动作三类事件分轨显示，保留操作人、时间、前后状态、备注/结果和快照引用。
- 状态：AI 待生成/生成中/已生成/生成失败/越界被过滤；建议待审核/已通过/已驳回；动作待审核激活/随建议驳关闭/待执行/已执行/已记录结果；建议总览可只读汇总为执行中。同时覆盖并发冲突、加载、部分失败、对象不存在/无权限通用化。

### 4.9 PAGE-TRACE-001 追溯记录（F08）

- 骨架：批次、SPU、动作类型、状态、操作人、时间筛选；追溯表显示事件类型、对象、前后状态、操作人、时间、批次与规则版本引用。
- 行为：行点击进入建议详情的对应时间线；批次详情可带预置批次筛选跳入。
- 权限：采购只看其被授权建议的采购动作与必要快照；不因追溯需求扩大数据可见范围。
- 状态：无记录、筛选无结果、加载、失败、无权限。MVP 不提供导出和独立审计详情页。

### 4.10 后续候选页面（planned，未立项）

| 候选能力 | 页面骨架定位 | 前置依赖 | 与 MVP 的关系 |
| :--- | :--- | :--- | :--- |
| 数据源连接管理 | 系统集成/映射页 | 外部数据源、账号、网络与配置责任正式确认 | 复用批次导入接口，不改写不可变批次 |
| 评价/退款原因分析 | 售后证据与优化任务页 | 明细数据、口径、权限与业务责任人就绪 | 作为新证据源，不伪装成 MVP 的 SPU 汇总值 |
| 广告明细决策 | 广告证据/执行页 | 广告明细、平台 API 与责任边界已确认 | 扩展动作类型，不影响 MVP 的 SPU 主动作 |
| 外部系统自动写入 | 集成任务/回执页 | 对方 API、幂等协议、账号凭据、审批与回滚责任已确认 | 动作事件预留外部回执引用，MVP 仍是人工执行 |
| SKU 级决策 | SKU 工作台/详情页 | SKU 数据、聚合口径、规则与责任经重新立项 | 预留通用决策对象引用，MVP 业务逻辑仍严格限定 SPU |

### 4.11 后续不可逆约束

- 批次、输入快照、规则版本和已发布决策不可覆盖，新数据或新规则通过新批次产生。
- 决策与动作引用使用稳定 ID，为外部回执和后续对象类型预留扩展字段，但不在 MVP 实现 SKU 规则。
- 钉钉、LiteLLM 与后续外部系统通过适配器边界接入，不让外部协议渗入固定规则核心。
- 审核状态机与两条动作状态机独立建模，后续增加外部回执时不将“已人工确认”偷换为“外部系统已成功”。

## 5. 通用交互范式

### 5.1 列表

- 服务端分页，默认 20 条/页，允许切换 20/50/100；密集表头固定，不使用无限滚动。
- 搜索、筛选、排序改变 URL 查询参数，详情返回时保留上下文。
- 首版不做批量操作和导出，避免绕过建议整体审核与分动作执行边界。

### 5.2 表单

- 必填项明显标记；失焦做局部校验，提交时做完整校验，错误同时靠近字段显示并在页顶给出汇总。
- 导入、审核、执行均属于有业务副作用的事务表单，不自动保存；备注/结果未提交时离开会拦截。
- 所有状态变更提交携带 version；不能通过前端本地更新伪造成功。

### 5.3 反馈

- Toast：仅用于已完成且可恢复的轻量反馈，如筛选重置或备注保存成功。
- 确认弹窗：用于建议通过/驳回、动作完成和结果提交，明示对象与后果。
- 页内强提示：用于数据质量降级、AI 降级、批次失败和并发冲突；不使用易消失 Toast 承载严重问题。
- 不建设站内信中心；待办通过工作台与清单统一呈现。

## 6. 视觉风格锚点

- 明暗：MVP 仅浅色模式。这是需要长时间读取数据、比对阈值和填写结果的内部工具，不按值守大屏设计。
- 风格：Linear 式冷静 SaaS 骨架 + 企业数据密度，避免 HUD、拟物和过度大卡片。
- Category：Enterprise Data / Operations（企业数据与经营协作）。
- 情绪：冷静、可信、有压力感但不刺激；红/橙只标记业务风险与错误，不作装饰。
- 主色：白色/浅灰中性底，深海军蓝与铉蓝作主交互色，红/橙/黄/绿作语义色。
- 交互哲学：统一使用“色彩响应”；选中、悬停、警报和当前状态通过边框/底色/文字色反馈，不混用大阴影提升或物理位移。
- 字体：中文优先系统无衬线字体栈，数字使用等宽数字特性；不依赖境外 Web Font。
- 设计签名：“行动罗盘”——每条建议以一条细长优先级色轨标识风险，旁边并列规则依据筹码和双动作状态；截图能一眼识别“风险→依据→行动”。

## 7. 数据与集成

### 7.1 核心实体

- 身份与权限：AuthenticatedActor、RoleMapping。
- 批次与输入：ImportBatch、SpuSnapshot、ImportError、DataQualityFlag。
- 规则与决策：RuleVersion、DecisionRecord、AIExplanation。
- 协作与追溯：ActionItem、ActionResult、ReviewEvent、ActionEvent。
- 异步任务：ProcessingJob，仅承载批次处理和 LiteLLM 解释状态，不改变业务真值源。

### 7.2 外部对接与责任

| 能力 | 对接方式 | 配置责任 | 同步/失败策略 |
| :--- | :--- | :--- | :--- |
| 周度 SPU 经营表 | 运营在产品上传 XLSX | 数据支持部门供数，运营核对期间与截止日 | 每周批次同步；无新表时保留历史，不伪造新结论 |

| 现有 LiteLLM 网关 | 服务端适配器调用 | 运维管理 deployment secret、轮换与撤销 | 规则结果发布后异步请求；失败/越界回到结构化兜底 |

## 8. 技术栈、架构与部署

- 架构：模块化单体。按身份权限、导入批次、指标规则、建议 AI、审核动作、追溯事件分模块，单一事务数据库；不为首轮 10—20 个 SPU 过早拆微服务。
- 前端：React + TypeScript + Vite，使用成熟企业级无障碍组件基础与项目 tokens 定制；确切包与版本在阶段 II 用官方源实时核验后写入《技术方案》。
- 后端：Python + FastAPI；XLSX 解析、字段语义校验和固定规则计算均在服务端执行。
- 数据库：PostgreSQL，用唯一约束承载指纹幂等，用事务承载决策与事件原子性，用 version 乐观锁防并发覆盖。
- 异步：PostgreSQL 任务表 + 独立 Worker 进程，通过行锁/租约抢占批次处理与 AI 任务；幂等与重试状态入库。MVP 不引入 Redis/Celery 作为必选运行依赖。
- 部署：容器化部署在公司网络可稳定访问的 Linux 环境，与现有 LiteLLM 网关互通；普通用户不可见 deployment secret。
- 文件存储：MVP 解析后不长期保留原 XLSX，因此不引入对象存储；临时目录需有持久化无关的清理与容量上限。
- 国内可达：应用运行、依赖安装与字体不依赖中国大陆无法稳定访问的海外托管、CDN 或 SaaS。

## 9. 安全与运维

### 9.1 认证与数据安全

- 会话：服务端换取钉钉身份后签发安全会话，使用 HttpOnly、Secure、SameSite Cookie 与 CSRF 防护；登录态过期参数化，不在设计蓝图虚构企业尚未确认的固定时长。
- 二次验证：MVP 不再增独立短信/TOTP，继承企业钉钉身份策略；建议审核使用业务确认弹窗而非新的认证体系。
- 上传：校验扩展名、MIME/文件特征、大小上限、解压资源上限和表格结构；文件名不直接作为服务器路径。
- 脱敏：LiteLLM 只接收生成解释所需的白名单业务值，不发送钉钉凭据、deployment secret 或不相关人员信息；日志禁止记录密钥和完整认证票据。

### 9.2 备份、日志与可恢复性

- 备份：PostgreSQL 每日自动加密备份，保留 30 天；上线前完成一次恢复演练，之后定期演练。原 XLSX 不属于长期备份对象，可追溯依赖已入库快照与原行定位。
- 审计：记录批次建立/处理、规则版本、建议审核、动作状态/结果、权限拒绝、并发冲突和 AI 状态；状态改变与事件追加在同一事务中成功或失败。
- 可观测：结构化应用日志、健康检查、批次/异步任务指标、权限拒绝数、并发冲突数、AI 兜底使用率；MVP 不强制引入新付费监控 SaaS。
- 可逆性：MVP 不提供批次、决策、审核事件或动作事件删除；已完成审核/执行不直接撤销，需用新批次或后续追加事件纠正，保留原始事实链。

## 11. 失败模式与缓解

| 风险 | 具体失败模式 | 蓝图缓解 |
| :--- | :--- | :--- |
| 页面过度集中 | 批次详情和建议详情信息过密，用户找不到当前任务 | 批次用主题 Tab，建议详情用首屏四要素 + 固定操作区 + 分轨时间线；阶段 II 需做 1440/1280 可视检查 |
| 权限泄露 | 采购通过列表字段、追溯记录或直链看到利润/推广/售后 | 独立服务端采购读模型、默认拒绝、通用越权响应；追溯不扩权 |
| 高优先动作被 AI 淹没 | AI 长文看起来比固定规则结论更权威 | 规则结论始终位于首屏主层级，AI 为次级折叠增强，越界输出过滤并回退兜底 |
| 并发状态覆盖 | 主管或两个执行人将旧页面结果写回，丢失先前操作 | version 乐观锁、冲突拒绝、刷新后重试，状态和事件同事务提交 |
| 单体后台任务阻塞请求 | XLSX 或 LiteLLM 请求占满 Web 进程，用户误以为批次失败 | 数据库任务表 + 独立 Worker，可观察处理状态，规则发布不等待 AI |

## 12. 总确认闸门

进入阶段 II 前需一次性确认：

1. MVP 的 9 个页面、页面调用关系和 F01—F08 落点完整。
2. 角色工作台、钉钉认证、采购最小数据可见范围与审核/分动作状态没有读偏。
3. 浅色企业数据风格、“行动罗盘”设计签名、模块化单体与国内可达部署可以作为后续施工基线。
4. 后续候选只保留不可逆扩展边界，不提前建设外部账号、付费服务、自动写入或 SKU 业务。

用户总确认后，Design Master 进入阶段 II，中途不再重复询问已确认项；只有首次发现必须新增的外部服务、付费资源、平台账号或部署依赖时，才回到阶段 I 补充确认。
