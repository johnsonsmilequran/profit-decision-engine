## 1. 这是什么

面向趣然电商内部运营和运营主管的周度 SPU 经营行动清单工具：统一读取经营数据，用固定利润规则决定加投、观察、止损、清仓、补货或禁补，再由 AI 解释依据；责任运营通过 OA 协调相关人员并闭环，运营主管审核确认。

## 2. 为什么做

销售、推广、库存、退款和利润数据分散，运营发现亏损后若未同步采购，可能继续补货。真实的布乐迪“忙碌屋”515 案例约延迟两个月才发现明显亏损，随后约滞销三千件、占用库存金额十万元并产生利润损失六万元。（来源：用户确认的 515 案例，详见 PRD §1）

## 3. 给谁做

- 运营：导入与查看完整经营数据，执行加投、观察、SPU 推广止损、清仓和证据支持的优化动作。
- 运营主管：查看完整依据，对整条建议批准或驳回；在动作未执行时可填写理由，将规则建议改判为新的生效经营/库存动作。
- 采购、仓库等相关人员：不是产品直接角色，只接收运营发出的 OA 最小必要协同消息并在线下反馈。
- 事业部负责人：决定试点范围与资源，不作为日常用户。
- 不服务消费者，不处理 SKU，不自动改广告或采购系统。
- 运营、运营主管通过钉钉独立登录；事业部负责人在产品外审批角色，唯一 Admin 在产品内核验审批依据并执行配置；运维只维护身份接入和部署恢复。
- 唯一 Admin：使用独立本地密码 + TOTP 管理待处理身份、角色生命周期、恢复与审计；管理身份默认不能读取经营数据。

## 4. MVP 怎么工作

1. 每周一导入数据支持部门提供的 SPU XLSX，按批次校验并保存不可变快照。
2. 固定规则按上一个完整自然月销售额、经营准利润率、最近七天品退率和库存可售天数生成唯一经营主动作及库存动作；AI 只解释，不覆盖、不阻塞。
3. 运营主管整体审核；若不采纳规则建议，在未执行时可先完成必填理由、库存动作重新确认和追加审计的人工改判；通过后由责任运营执行经营动作并通过 OA 协调相关人员。
4. 清仓动作跨周保持不变时沿用原任务；运营填报实际清仓完成时间并提交主管确认，未确认前系统每天通过 OA 催办责任运营，主管确认后闭环。
5. 钉钉认证成功但无唯一角色时幂等进入待处理；Admin 核验双属性和审批依据后原子配置唯一角色、撤销旧会话并引导用户重新登录目标工作台。

## 5. MVP 边界

- 完成 F01—F09 才完成产品范围；F09 只做单 Admin、固定双业务角色、产品外审批、五态和最小审计，不做通用 IAM、OA 审批引擎、批量授权、统计大屏或高级治理。
- 首轮用玩具事业部十至二十个真实 SPU 验收；该数量不是运行硬上限。
- 至少识别三个真实经营问题；每条建议必须含具体对象、发现问题、关键依据和推荐动作。
- 当前不做评价文本、退款原因、广告计划明细、SKU 级经营、自动投放、自动下单和自动库存调整。

## 6. 关键功能

| 功能组合 | 解决的问题 | MVP 结果 |
| :--- | :--- | :--- |
| F01—F02 数据入口与指标 | 人工拉表、口径不一 | 周度批次、字段级校验、统一经营指标 |
| F03 固定规则决策 | 依赖个人经验、动作冲突 | 唯一经营主动作；止损/清仓同步禁补 |
| F04—F05 解释与清单 | 发现问题后难以理解和排序，同动作周周重复建任或看不清前序建议当时为何生成 | 四要素建议、固定优先级、经营状态筛选、最近前序独立建议快照、生命周期时间与跨周任务续接 |
| F06 审核执行 | 运营止损与跨部门补货脱节 | 建议整体审核、责任运营统一闭环、清仓完成时间主管确认和每日 OA 催办 |
| F07—F08 权限与溯源 | 信息越权、无法复盘 | 双角色权限、OA 消息最小可见、批次规则状态全链路留痕 |
| F09 Admin 管理闭环 | 无角色用户无人承接、系统无法初始使用 | 唯一 Admin 初始化/恢复、待处理、唯一角色配置、五态、不可变审计与 10 分钟首用闭环 |

首轮验收责任人为运营：运营依据上述试点规模、真实问题、建议四要素、规则追溯和轻闭环结果，确认建议能否用于首轮业务评审；事业部负责人只负责范围与资源投入。

F01—F08 原始 V0 未做阶段 2 年度财务拍板；F09 增量价值论证为约 72 万元/年、三年约 216 万元，其中 12 次/年及三年持续性是待真实台账验证的假设，不得表述为已节省。

## 8. 关键依赖与风险

1. 数据缺口：当前样本缺 SPU 库存、在途和最近十四天销量。缓解：不生成补货建议，但止损/清仓仍生成禁补。
2. 品退周期不可信：当前样本不能证明为最近七天。缓解：不以该值触发观察或加投条件，显示未校验。
3. AI 或密钥故障：LiteLLM 不可用可能导致解释失败。缓解：固定规则清单、审核和执行继续工作；部署密钥仅由运维维护。
4. 身份接入或角色映射异常：钉钉认证失败时拒绝；认证成功但无角色时进入 F09 待处理，不再停在通用错误页。
5. 唯一 Admin 单点与恢复风险：采用保存型恢复码、独立审批的部署恢复、长期凭据本人单次绑定、旧会话撤销和非静默通知补偿；不共享密码。

## 9. 当前拍板状态

产品范围和规则无 P0/P1 阻塞项。F09 已定版为唯一 Admin 管理闭环：事业部负责人审批，Admin 核验并配置，运维维护身份接入与部署恢复。真实双属性、岗位联系人、证据目录、开发/线上物理隔离和恢复演练仍是生产启用硬门禁，未齐全时可开发但不得宣称生产可用。
