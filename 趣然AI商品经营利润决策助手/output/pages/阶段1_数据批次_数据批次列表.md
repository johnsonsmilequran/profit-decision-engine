## 2. 页面概述

### 2.1 一句话定位

为授权用户提供不可变数据批次的统一历史入口，使其能快速确认每周经营表是否处理成功、数据质量如何、对应行动清单是否就绪，并进入批次详情继续复核。

### 2.2 存在理由

1. 没有批次列表，运营无法确认重复提交是否命中既有批次，容易误以为产生了第二份清单。
2. 没有历史入口，新批次会遮蔽旧批次及其清单状态，无法解释某条历史建议使用了哪份数据。
3. 没有处理与质量摘要，用户必须逐个进入详情才能发现失败、拒绝行或字段降级，增加周一导入后的排查成本。

### 2.3 页面目标（可衡量）

| 目标维度 | 具体指标 |
| :--- | :--- |
| 批次可发现性 | 授权用户可从列表找到全部有权查看的历史批次，新批次不得覆盖旧批次 |
| 批次唯一性 | 同一批次指纹重复提交时，列表只出现第一次成功建立的批次 |
| 状态可判断 | 每行均能看见处理状态、有效/拒绝/降级数量与清单状态，不依赖打开详情判断是否可用 |
| 检索效率 | 用户可通过批次编号/文件名搜索及状态、期间筛选定位目标批次 |
| 分页稳定性 | 默认每页 20 条，可切换 20/50/100 条；翻页和返回列表时不改变历史记录顺序或筛选上下文 |
| 审计完整性 | 每行持续显示导入人和导入时间，历史状态不被后续批次覆盖 |

### 2.4 不做什么（范围边界）

- **不做**文件上传或字段校验——由新建数据导入页与数据批次详情承载，避免把事务表单塞进历史列表。
- **不做**批次编辑、删除、覆盖或重新生成——批次及其历史清单不可变；修正数据必须形成不同指纹的新批次。
- **不做**批量操作、导出或错误文件下载——MVP 未承诺这些能力，避免绕过追溯边界。
- **不做**规则结果、SPU 指标或建议明细展开——点击批次进入批次详情查看。
- **不做**角色管理或导入授权配置——角色由 IT 维护的钉钉映射决定，本页只消费当前权限结果。

## 3. 用户与场景

### 3.1 目标用户

| 维度 | 运营 | 运营主管 |
| :--- | :--- | :--- |
| 角色目标 | 查找历史批次、确认本周处理结果并发起新导入 | 复核批次状态、质量摘要与历史清单来源 |
| 使用频率 | 每周一集中使用，周内按需回查 | 周度审核前后按需查看 |
| 技术熟练度 | 中等，熟悉表格和内部系统 | 中等，熟悉经营报表和审核流程 |
| 使用设备 | 公司 PC 浏览器 | 公司 PC 浏览器 |
| 使用姿势 | 长时间桌面操作，快速扫描密集列表 | 桌面阅读和跨页核对 |
| 权限差异 | 可查看批次并看到“新建数据导入”入口 | 可查看批次，不显示新建导入入口 |

采购计划不以本页为任务入口；其业务入口是角色化工作台和行动清单。无批次页面权限的身份访问本路由时进入无权限状态，不返回批次数据。

### 3.2 核心使用场景

**场景 A：定位本周批次并继续复核（主场景）**

- 时机：每周一运营导入经营表后，或运营主管准备审核本周建议时。
- 前置条件：用户已通过钉钉登录并具备批次查看权限；目标批次已建立。
- 用户动作：打开数据批次列表 → 查看最新批次的期间、处理状态和质量摘要 → 点击批次进入详情。
- 用户情绪：希望快速确认“这周数据是否就绪”，不愿在多个文件或页面间猜测。

**场景 B：回查历史批次与历史清单（兜底场景）**

- 时机：用户需要解释旧建议、对比修正批次，或确认新数据是否覆盖了历史。
- 前置条件：系统中存在多个历史批次，用户具备相应查看权限。
- 用户动作：设置数据期间/状态筛选或搜索批次编号、源文件名 → 翻页定位旧批次 → 进入详情查看其固化快照与清单。
- 用户情绪：重视可信和可追溯，希望看到当时事实而非当前数据改写后的结果。

**场景 C：处理失败后判断下一步（异常场景）**

- 时机：列表显示批次处理失败、无有效行或清单未发布。
- 前置条件：批次身份已建立，但校验或规则处理未完成成功。
- 用户动作：点击失败批次 → 在批次详情查看失败原因、拒绝行与降级信息 → 依据问题准备新的修正文件；不编辑或覆盖原批次。
- 用户情绪：有压力但需要明确恢复路径，不希望失败被伪装为空结果。

### 3.3 用户核心诉求（优先级排序）

1. **可信**：每个批次和清单只有一个稳定身份，历史不可覆盖。
2. **快**：不进入详情也能判断批次是否就绪及数据质量风险。
3. **可找**：通过搜索、筛选和分页快速定位目标周次或文件。
4. **可恢复**：失败时能进入详情看到原因并明确应创建修正批次。
5. **权限清楚**：只有运营看到导入入口，未授权身份不能通过直链获得数据。

## 4. 信息架构

### 4.1 区域划分

1. 全站导航与顶部上下文区
2. 页面标题与主操作区
3. 筛选与搜索区
4. 批次列表区
5. 分页区
6. 全页状态与反馈区

### 4.2 区域内容

**1. 全站导航与顶部上下文区**

- 左侧导航中“数据批次”为当前入口。
- 顶部持续显示当前业务角色、当前批次上下文（存在时）与钉钉身份。

**2. 页面标题与主操作区**

- 页面名称“数据批次”。
- 简要说明“按批次保留每周数据、校验与行动清单历史”。
- 仅运营显示“新建数据导入”，进入 `PAGE-F01-02`；运营主管不显示。

**3. 筛选与搜索区**

- 关键词：批次编号或源文件名。
- 处理状态：全部、处理中、清单就绪、失败。
- 清单状态：全部、未生成、生成中、已就绪、生成失败。
- 数据期间：按起止日期筛选；只筛选，不改变批次固化期间。
- 筛选条件摘要、重置筛选。

**4. 批次列表区**

- 每行展示批次编号、事业部、数据期间、业务截止日、源文件名、处理状态、有效行数、拒绝行数、降级字段数、清单状态、导入人、导入时间。
- 整行可进入对应数据批次详情；任何状态的已建立批次均可查看，失败批次也不能从历史中消失。
- 默认按导入时间倒序；同一时间使用稳定批次编号保持确定顺序。

**5. 分页区**

- 显示总记录数、当前页、总页数。
- 默认 20 条/页，可切换 20/50/100 条；提供上一页、下一页和明确页码跳转。

**6. 全页状态与反馈区**

- 无批次、筛选无结果、加载失败、会话失效、无权限分别呈现，不以同一空白状态混淆。
- 轻量操作成功（如重置筛选）可即时反馈；严重错误保留页内提示与重试入口。

## 6. 交互流程

### 6.1 页面加载与初始化

1. 用户进入页面后，系统先校验有效登录态、业务角色与批次查看权限。
2. 认证或权限有效时，从 URL 恢复搜索、筛选、页码与每页条数；没有参数时使用默认条件。
3. 默认加载全部有权查看的批次，按导入时间倒序、稳定批次编号兜底排序，每页 20 条。
4. 加载期间保留表头与筛选结构，避免用户把未完成加载误认为没有批次。
5. 加载完成后分别进入有结果、无批次或筛选无结果状态。

### 6.2 核心操作流程

```text
进入数据批次列表
    │
    ├─ 会话无效 / 无页面权限 → 不请求或不展示批次数据 → 登录/无权限恢复路径
    │
    └─ 权限有效 → 按 URL 条件加载批次
          │
          ├─ 无任何历史批次 → 展示角色化空状态
          │      └─ 运营点击“新建数据导入” → PAGE-F01-02
          │
          ├─ 当前筛选无结果 → 展示筛选条件 → 重置后回第一页重载
          │
          └─ 有结果 → 查看状态与质量摘要
                 │
                 ├─ 搜索/筛选/切换每页条数 → 更新查询条件 → 回第一页加载
                 ├─ 翻页 → 保留搜索与筛选 → 加载目标页
                 └─ 点击批次 → 携带批次 ID 进入 PAGE-F01-03
```

**历史回查流程**

```text
设置期间或状态条件 → 定位历史批次 → 进入批次详情
        │
        └─ 返回列表 → 恢复原搜索、筛选、页码与每页条数
```

### 6.3 辅助操作

- 按 Enter 可提交关键词搜索；输入变化本身不自动触发连续请求。
- 重置筛选后回到第一页，并保留默认每页条数。
- 浏览器前进/后退应恢复 URL 中的查询上下文。
- 列表刷新只获取最新批次状态，不改变任何批次、清单或历史事件。

## 7. 状态与边界

### 7.1 页面状态全景

| 状态 | 触发条件 | 页面表现 |
| :--- | :--- | :--- |
| 初始化态 | 权限已通过，尚未开始拉取列表 | 展示页面框架与默认筛选，不显示旧账号数据 |
| 加载态 | 首次加载、翻页或筛选请求进行中 | 保留表头/筛选上下文，列表区域显示加载中，阻止重复发起相同请求 |
| 有结果态 | 当前条件返回至少一条批次 | 展示批次行、总数与分页，行可进入详情 |
| 无批次态 | 授权范围内从未建立批次 | 展示角色化说明；仅运营显示新建导入主操作 |
| 筛选无结果态 | 系统存在批次，但当前条件无匹配 | 明示“当前筛选无结果”，显示生效条件与重置入口，不显示“暂无批次” |
| 部分更新态 | 列表可用，但某批次仍在处理 | 该行显示处理中和待统计字段；其他行保持可读，不阻断进入详情 |
| 成功刷新态 | 用户刷新或重新加载成功 | 使用服务端最新状态替换当前投影，历史批次身份和排序规则不变 |
| 加载失败态 | 网络或服务异常导致列表请求失败 | 显示页内错误、失败条件与“重试”，不把失败呈现为空列表 |
| 会话失效态 | 登录态过期或认证不可用 | 不显示批次数据，引导重新发起钉钉认证 |
| 无权限态 | 已登录但无批次页访问权 | 不返回批次身份或数量，进入通用无权限恢复路径 |

### 7.2 边界与容错

| 边界场景 | 处理策略 |
| :--- | :--- |
| 网络异常 | 保留当前筛选和页码，显示加载失败与重试；若已有旧列表，不把旧内容标成最新成功结果 |
| 会话过期 | 立即停止展示/请求经营数据，进入重新钉钉认证路径；认证恢复后可回到原列表查询上下文 |
| 连续加载错误 | 每次失败均保留明确重试入口和最近一次失败状态；不自动无限重试、不将失败降级成空列表 |
| 异常搜索输入 | 去除首尾空白；只有空白时按无关键词处理；输入不得改变或写入批次数据 |
| 期间筛选起止倒置 | 不提交筛选，指出“开始日期不能晚于结束日期”，保留用户输入供修正 |
| 并发新增批次 | 当前页不自动插入导致行位移；用户刷新后按稳定排序看到新批次，原批次不被覆盖 |
| 并发状态更新 | 某批次从处理中变为就绪时，刷新显示最新状态；不改变该批次编号、导入时间或历史身份 |
| 指纹重复提交 | 列表只显示第一次成功建立的批次；重复请求不增加批次、建议、清单或状态事件 |
| 失败批次 | 仍保留批次行及失败状态，可进入详情查看原因；不得隐藏或复用其编号伪装新成功批次 |
| 页码越界 | 历史数据变化导致当前页超过总页数时，回到最后一个有效页并保留筛选条件 |
| 当前页最后一条变化 | 新状态或权限变化导致当前页无结果时，重新计算有效页码，不显示永久空页 |
| 源文件名异常字符 | 按显示文本呈现，不解释为路径或操作指令；列表不暴露本地绝对路径 |
| 窄屏或浏览器缩放 | 保留批次编号、期间、处理/清单状态等关键语义；密集字段可横向查看，不压缩到不可读 |
| 无权限直链 | 返回通用无权限状态，不泄露批次是否存在、总数、文件名、导入人或处理状态 |

## 8. 业务规则与校验

### 8.1 字段定义

| 字段 | 说明 |
| :--- | :--- |
| `batch_id` | 批次稳定身份；指纹首次成功建立后不可复用或改写 |
| `business_unit` | 批次所属事业部；V0 为玩具事业部 |
| `period_start` / `period_end` | 批次声明并固化的数据期间，首批为 2026-06-01 至 2026-06-30 |
| `business_date` | 批次业务截止日，用于历史新品年龄判断，建立后冻结 |
| `source_name` | 源文件显示名，不含本地绝对路径 |
| `batch_status` | 批次处理状态：处理中、清单就绪或失败等可观察状态 |
| `valid_row_count` | 通过必要身份校验并保留为 SPU 快照的行数 |
| `rejected_row_count` | 因必要身份缺失或 SPU ID 重复而不进入计算的行数 |
| `degraded_field_count` | 未拒绝整行、但停止对应依赖判断的字段问题数 |
| `list_status` | 该批次唯一行动清单的当前状态，不代表 AI 解释状态 |
| `created_by` / `created_at` | 第一次成功建立批次的导入人与时间 |
| `batch_fingerprint` | 事业部、数据期间、业务截止日和文件内容共同形成的唯一性依据；本页不展示原始摘要值 |

### 8.2 校验规则

| 校验项 | 时机 | 规则 | 失败反馈 |
| :--- | :--- | :--- | :--- |
| 关键词 | 提交搜索时 | 去除首尾空白；空值等同清除搜索 | 空值不报错，展示全部匹配批次 |
| 处理状态 | 选择时 | 仅使用页面提供的受控状态 | 非法/过期值恢复为“全部”，不发送未知状态 |
| 清单状态 | 选择时 | 仅使用页面提供的受控状态 | 非法/过期值恢复为“全部” |
| 数据期间 | 提交筛选时 | 开始日期不得晚于结束日期 | “开始日期不能晚于结束日期” |
| 页码 | 翻页或恢复 URL 时 | 必须落在当前结果有效页范围 | 自动回到有效页，并提示结果已更新 |
| 每页条数 | 切换或恢复 URL 时 | 仅允许 20、50、100 | 非法值使用默认 20 条/页 |
| 批次详情入口 | 点击行时 | 必须有有效批次 ID 且当前用户有查看权限 | 无权或对象不可用时使用通用错误，不暴露额外批次字段 |

### 8.3 特殊业务规则

- **历史不可变**：新批次、规则变化或状态更新不得覆盖旧批次身份、固化期间、业务截止日、源文件名、历史清单与已记录事件。
- **指纹幂等**：相同事业部、期间、业务截止日和文件内容再次提交，只返回原批次及既有清单状态；本列表不得出现重复业务批次。
- **每批次一份清单**：列表中的清单状态是该批次唯一行动清单的投影，不提供再次生成第二份清单的操作。
- **AI 状态隔离**：AI 等待或失败不得把固定规则已完成的批次改为失败，也不得阻止清单就绪。
- **导入权限**：仅运营显示并可使用新建导入入口；仅隐藏按钮不能替代服务端权限检查。
- **读取权限**：只有具备批次查看权限的身份可获得列表；未授权错误不返回总数或任何批次摘要。
- **失败可追溯**：失败批次仍保留在历史中并可进入详情查看失败原因，不得删除或改写为成功。
- **稳定排序**：默认按导入时间倒序，时间相同时按稳定批次编号确定顺序；刷新不使用不稳定随机顺序。

### 9.2 与其他模块的关系

- 与新建数据导入关联：本页只提供运营入口；导入提交与校验不在列表内完成。
- 与数据批次详情关联：所有批次行，包括处理中和失败状态，均以稳定批次 ID 进入详情。
- 与行动清单关联：本页仅展示清单汇总状态；建议和动作内容由批次详情/行动清单承载。
- 与追溯模块关联：批次身份、固化期间和建立时间是后续建议追溯的入口依据，列表本身不展开事件明细。
- 与认证权限隔离：钉钉身份与 IT 角色映射决定页面和导入入口；本页不管理账号或角色。

### 9.3 扩展预案

| 扩展方向 | 触发条件 | 改造点 |
| :--- | :--- | :--- |
| 数据源连接批次 | 外部数据源和配置责任正式立项并补齐 REQ/AC | 保持 ImportBatch 身份和列表入口一致，新增可识别来源类型，不覆盖 XLSX 历史 |
| 修正批次关系 | PRD 正式定义修正原因和用户可见关系 | 在列表增加“修正自/被修正”只读关联；修正仍建立新批次 |
| 更大历史规模 | 真实使用证明现有筛选不足并补齐需求 | 增加经确认的筛选或归档视图，继续使用服务端分页和稳定排序 |
| 批次导出 | 后续明确导出范围、权限与脱敏 AC | 新增受控导出入口；不得借导出绕过采购或其他角色数据边界 |
