## 2. 页面概述

### 2.1 一句话定位

建议详情是单条 SPU 决策的完整协作与追溯入口：先呈现不可被 AI 改写的固定规则结论和结构化四要素，再让运营主管整体审核，并由运营与采购计划在各自轨道执行、记录结果。

### 2.2 存在理由

1. 没有独立详情，关键指标、规则路径、审核后果和双动作状态会挤在列表行内，主管无法在完整证据下拍板。
2. 没有分轨执行，运营止损与采购禁补可能被误认为同一动作，重现“运营已止损、采购仍补货”的协作断点。
3. 没有固化快照和事件记录，历史建议可能被新数据、当前规则或后续状态覆盖，无法解释当时为什么得出该结论。
4. 没有角色裁剪的同一详情入口，采购可能通过直链、历史或错误反馈旁路看到完整利润、推广、品退和售后信息。

### 2.3 页面目标（可衡量）

| 目标维度 | 具体指标 |
| :--- | :--- |
| 四要素完整性 | AI 等待、失败或越界过滤时，授权用户看到的建议仍 100% 包含具体对象、发现问题、关键依据和推荐动作 |
| 规则可信度 | 商品类型、唯一主动作、补货/禁补结论、触发规则、规则版本和固化关键值均可在本页复核，且不随 AI 或后续批次变化 |
| 审核一致性 | 每条待审核建议只允许一次建议级通过或驳回；通过同时激活既有动作，驳回不激活动作 |
| 分轨正确性 | 经营动作与采购动作分别显示责任角色、状态、结果和事件，任一轨道更新不覆盖另一轨道 |
| 并发保护 | 基于旧 version 的后续提交 100% 被拒绝覆盖，并展示最新状态、最新操作人、时间和刷新入口 |
| 最小可见 | 采购视图、错误信息和追溯内容中出现完整利润、推广、品退或售后数据的次数为 0 |
| 降级可用 | AI 等待、超时、失败或越界过滤时，固定规则建议仍可按当前审核/动作状态正常操作 |

### 2.4 不做什么（范围边界）

- **不做**规则编辑、阈值调整或人工改动作——本页只读展示版本化固定规则结论，防止审核或执行改写决策。
- **不做**AI 手动重生成、模型选择或解释版本浏览——AI 是异步次级增强，失败时直接使用结构化兜底。
- **不做**分别审核经营动作与采购动作——运营主管对整条建议一次通过或驳回，两个动作不能出现互相矛盾的审核结果。
- **不做**批量审核、批量执行或批量结果回填——本页只处理一个稳定建议身份，确保用户阅读完整依据后提交。
- **不做**广告计划、关键词、素材、评价主题、退款原因或 SKU 级结论——当前数据只支持 SPU 汇总粒度。
- **不做**自动修改广告、采购或库存系统——页面记录的是人工执行与结果，不表述为外部系统回执。
- **不做**删除、撤销或覆盖历史快照和事件——更正通过新批次或后续追加记录完成，原事实链继续保留。

## 3. 用户与场景

### 3.1 目标用户

| 角色 | 使用目标 | 技术熟练度 | 使用设备 | 使用姿势 | 可见与操作边界 |
| :--- | :--- | :--- | :--- | :--- | :--- |
| 运营主管 | 阅读完整指标、规则与数据限制，对整条建议一次通过或驳回，并查看双动作进度 | 中高，熟悉经营指标与审核 | 公司 PC 浏览器 | 集中审核、跨部门复核 | 可见完整经营信息；仅待审核时开放建议级审核，不代替运营或采购执行 |
| 运营 | 理解完整建议，执行加投、观察、SPU 整体推广止损或清仓，并记录经营结果 | 中等，熟悉表格与经营动作 | 公司 PC 浏览器 | 周内持续处理和回填 | 可见权限内完整经营信息；只操作经营动作与经营结果，不审核建议 |
| 采购计划 | 查看被分配的补货/禁补任务及必要库存、销量依据，并记录采购动作结果 | 中等，熟悉库存与采购计划 | 公司 PC 浏览器 | 按已通过任务执行和回填 | 仅任务关联时可进入裁剪详情；不返回完整利润、推广、品退、售后或经营结果 |

### 3.2 核心使用场景

**场景 A：运营主管依据完整证据审核建议（主场景）**

- 时机：新批次完成固定规则决策，建议处于待审核状态。
- 前置条件：用户已通过钉钉登录且角色为运营主管；建议身份、规则快照和四要素已可用。
- 用户动作：核对 SPU 与批次 → 阅读固定规则结论、关键指标、数据限制和规则路径 → 查看两条待激活动作 → 选择通过或填写非空原因后驳回 → 确认提交。
- 用户情绪：需要快速但谨慎，希望明确这次审核会同时决定经营动作和采购动作是否激活。

**场景 B：运营与采购分别完成动作闭环（协作场景）**

- 时机：建议已通过，经营动作和补货/禁补动作分别进入待执行。
- 前置条件：当前用户是对应责任角色，且操作前看到的动作 version 仍有效。
- 用户动作：运营更新经营动作状态并记录销售额、利润或库存结果；采购只更新补货/禁补动作及其结果；两者分别回看本轨时间线。
- 用户情绪：职责清晰、互不覆盖，同时能确认另一轨道的汇总进度。

**场景 C：AI 等待、失败或越界后继续处理（兜底场景）**

- 时机：LiteLLM 正在生成、超时、不可用，或返回与固定规则冲突/超出数据粒度的内容。
- 前置条件：固定规则决策和结构化四要素已经生成。
- 用户动作：查看 AI 状态和降级原因 → 继续使用四要素、指标与规则路径完成审核或执行；越界内容不进入建议正文。
- 用户情绪：不会因 AI 故障停工，且清楚当前显示内容仍是可信规则结果。

**场景 D：提交时发现 version 冲突（兜底场景）**

- 时机：另一名主管或责任人已先完成同一建议/动作的状态更新，当前页面仍保留旧 version。
- 前置条件：用户基于旧状态填写了备注或结果并尝试提交。
- 用户动作：看到冲突强提示和最新操作人、时间、状态 → 刷新本页 → 重新核对最新事实；不能选择强制覆盖。
- 用户情绪：虽然提交被拒绝，但能理解原因且不会担心他人成功记录被覆盖。

### 3.3 用户核心诉求（优先级排序）

1. **先看确定结论**：固定规则动作和四要素必须先于 AI 长文本可用。
2. **看懂为什么**：关键值、周期、阈值、比较关系、数据限制和规则版本必须可复核。
3. **职责不混淆**：整体审核、经营执行、采购执行和结果记录边界清楚。
4. **历史不被改写**：新批次、新规则、AI 状态和后续动作不能覆盖生成时快照。
5. **冲突不丢数据**：旧 version 提交被拒绝且明确展示最新事实和恢复动作。
6. **只看所需数据**：采购能完成任务，但不接触职责之外的经营敏感信息。

## 4. 信息架构

### 4.1 区域划分

1. 全站导航与顶部身份上下文区
2. 面包屑、建议身份与批次摘要区
3. 固定规则结论与结构化四要素区
4. 关键指标与数据质量区
5. 规则路径与固化快照区
6. AI 解释状态与增强内容区
7. 建议级审核区
8. 经营动作与采购动作双轨区
9. 分轨追溯时间线区
10. 角色化固定操作与全页反馈区

### 4.2 区域内容

**1. 全站导航与顶部身份上下文区**

- 固定左侧导航：工作台、行动清单、数据批次、追溯记录。
- 当前钉钉身份、业务角色和来源批次上下文。

**2. 面包屑、建议身份与批次摘要区**

- 来源页面与返回入口；返回时保留原列表的批次、筛选、页码上下文。
- 稳定建议 ID、SPU ID、SPU 名称、店铺、平台、责任运营、生成时间。
- 导入批次、事业部、数据期间、业务截止日和规则版本。

**3. 固定规则结论与结构化四要素区**

- 商品类型、唯一经营主动作、补货/不补货/禁止补货或不生成结论。
- 四要素：具体对象、发现问题、关键依据、推荐动作。
- 数据限制与动作责任角色；AI 状态不改变该区内容。
- 采购裁剪为 SPU 身份、库存/销量问题、必要依据及补货/禁补动作，不展示完整经营四要素。

**4. 关键指标与数据质量区**

- 上一个完整自然月净销售额及实际期间。
- 表内经营准利润率及“源表值、未按旧公式重算”说明。
- 最近 7 天品退率、分子分母、周期与验证状态。
- 仓内库存、在途库存、最近 14 天销量/日均销量、库存可售天数及状态。
- 上架日期、业务截止日、新品年龄判断；字段原值、采用值和质量标记。
- 采购只见补货判断必要的销量、库存、可售天数和相关质量状态。

**5. 规则路径与固化快照区**

- 商品类型判定路径、命中阈值、比较关系和未命中分支。
- 主动作按“清仓＞止损＞观察＞加投＞维持”唯一化的结果。
- 止损/清仓与禁补原子约束；新品不生成补货；加投与补货可并存。
- 生成时规则版本、触发规则引用、关键输入快照和数据限制，全部只读。

**6. AI 解释状态与增强内容区**

- AI 状态：等待、生成中、已生成、生成失败、越界被过滤。
- 已生成且通过边界校验时，显示不改写固定动作的次级增强说明。
- 失败或越界时显示结构化兜底继续有效的说明；不提供手动重生成。

**7. 建议级审核区**

- 待审核、已通过、已驳回状态，审核人、审核时间和备注。
- 仅运营主管在待审核状态看到“通过”“驳回”；通过备注可选，驳回原因必填。
- 确认信息明确整条建议审核会同时激活或关闭既有经营与采购动作。

**8. 经营动作与采购动作双轨区**

- 经营轨：动作、责任运营、执行状态、执行时间、备注、结果周期和可用经营结果。
- 采购轨：补货/禁补动作、责任角色、执行状态、执行时间、备注和采购结果。
- 两轨共享建议关联但状态独立；无采购动作时明确“本建议无采购执行任务”。
- 采购只获得采购轨及必要依据，不获得经营轨完整结果。

**9. 分轨追溯时间线区**

- 建议生成与整体审核轨、经营动作轨、采购动作轨分组显示。
- 每个成功状态事件显示前后状态、操作者、时间、备注/结果和固化快照引用。
- AI 失败、越界过滤和 version 冲突作为不改变固定决策或成功状态的追溯标记保留；不得删除既有成功事件。

**10. 角色化固定操作与全页反馈区**

- 主管：仅待审核时开放整体通过/驳回。
- 运营：仅建议已通过且经营动作处于允许状态时开放本轨更新与结果记录。
- 采购：仅有任务关联、建议已通过且采购动作处于允许状态时开放本轨更新与结果记录。
- 加载失败、局部失败、会话失效、对象不存在/无权限、version 冲突使用不同恢复路径。

## 5. 界面内容

### 5.1 元素清单

**面包屑与返回入口**

- 内容：来源模块、来源批次或列表名称、当前建议。
- 文案：末级使用 SPU 名称或稳定建议 ID；返回操作使用“返回行动清单”“返回批次详情”或“返回追溯记录”。
- 数据来源：进入本页时的来源上下文与建议身份。
- 显示条件：始终显示；来源上下文失效时返回对应模块默认入口。

**建议与 SPU 身份**

- 内容：建议 ID、SPU ID、SPU 名称、店铺、平台、责任运营、生成时间。
- 数据来源：生成时固化的决策快照。
- 显示条件：运营和运营主管完整显示；采购仅在有权处理该建议的采购任务时显示完成任务所需的 SPU 身份，不显示责任运营等非必要人员信息。

**批次与规则摘要**

- 内容：批次编号、玩具事业部、数据期间、业务截止日、规则版本。
- 数据来源：建议生成时固化的批次与规则引用。
- 显示条件：授权详情始终显示；采购只显示完成采购任务与解释库存口径所需的批次、期间和规则版本引用。

**固定规则结论**

- 内容：商品类型、唯一经营主动作、补货/不补货/禁止补货或不生成、责任角色、数据限制。
- 文案：使用“清仓”“止损”“观察”“加投”“维持”“补货”“不补货”“禁止补货”“未生成补货判断”等稳定业务术语。
- 数据来源：版本化固定规则结果。
- 显示条件：运营和主管完整显示；采购只显示补货/禁止补货结论及必要的任务状态，不显示完整经营主动作或其敏感依据。

**结构化四要素**

| 要素 | 内容 | 数据来源 | 显示条件 |
| :--- | :--- | :--- | :--- |
| 具体对象 | SPU ID、名称、店铺，以及当前结论对象 | 固化身份快照 | 授权详情始终显示；采购按必要身份裁剪 |
| 发现问题 | 与固定规则结论一致的问题描述；数据不足时明确缺少哪类证据 | 规则结果与质量标记 | AI 任意状态均显示；采购只显示库存/补货任务相关问题 |
| 关键依据 | 实际值、周期、阈值、比较关系和数据限制 | 固化关键值与触发规则 | AI 任意状态均显示；采购仅显示销量、库存必要依据 |
| 推荐动作 | 唯一经营主动作及补货/禁补动作、责任角色 | 固定规则结果 | AI 不可改写；采购仅显示采购动作 |

**关键指标与数据质量**

| 指标/信息 | 内容与口径 | 状态显示 | 采购可见性 |
| :--- | :--- | :--- | :--- |
| 上月净销售额 | 扣除退款后的上一个完整自然月净销售额及实际期间 | 有效值或缺失/非法原因 | 不可见 |
| 经营准利润率 | 直接采用源表值，并说明未按旧公式重算 | 有效值或缺失/单位不清 | 不可见 |
| 最近 7 天品退率 | 品退件数÷已销售件数，显示周期与验证状态 | 已验证、未校验、无可计算销量或字段异常 | 不可见 |
| 上架与新品年龄 | 上架日期、业务截止日、未满/已满 2 个自然月 | 可判定或日期异常 | 不可见 |
| 库存与销量 | 仓内库存、在途库存、最近 14 天销量/日均销量 | 有效、缺失、负数异常或无近期销售 | 可见必要字段 |
| 库存可售天数 | （仓内库存+在途库存）÷最近 14 天平均日销量 | 有效天数、库存数据不足/异常或无近期销售 | 可见 |
| 数据质量标记 | 字段原值、采用值、周期、验证状态与降级原因 | 有标记逐项显示，无标记明确“本规则所需数据已校验” | 仅显示与采购依据相关标记 |

**规则路径**

- 内容：分类路径、实际命中值、阈值、比较关系、主动作优先级、补货冲突约束、规则版本和数据限制。
- 数据来源：生成时的触发规则引用与关键输入快照。
- 显示条件：运营和主管可见完整路径；采购只见补货/禁补任务成立所需的库存与禁补约束摘要。
- 操作能力：全部只读，不显示编辑、重算或切换规则版本入口。

**AI 状态与增强解释**

- 状态文案：等待时“AI 解释等待中，固定规则建议可继续处理”；失败时“AI 解释暂不可用，已保留结构化建议”；越界时“部分 AI 内容超出规则或数据范围，已过滤”；成功时“AI 增强解释已生成”。
- 内容：只显示与固定规则一致、仅使用已固化值且不超出 SPU 粒度的次级说明。
- 数据来源：LiteLLM 解释状态及通过边界校验的增强内容。
- 显示条件：运营和主管可见；采购不显示完整 AI 文本或由此旁路获得受限信息。
- 操作能力：不提供重新生成、版本选择或模型配置入口。

**建议级审核**

- 内容：审核状态、审核人、审核时间、审核备注。
- 主操作：“通过建议”“驳回建议”。
- 数据来源：建议级审核状态与审核事件。
- 显示条件：主管在待审核状态看到操作；运营和采购只读查看对本人动作生效所需的审核状态；已通过或已驳回后所有角色不再看到可提交审核控件。
- 表单规则：通过备注可选；驳回原因必填；提交前确认对象、固定动作及审核后果。

**经营动作轨**

- 内容：主动作、责任角色、执行状态、执行时间、执行备注、结果周期、销售额/利润/库存结果或明确未提供。
- 主操作：“更新经营动作”“记录经营结果”，只允许在对应状态出现。
- 数据来源：经营 ActionItem、ActionResult 与事件。
- 显示条件：运营和主管可见；运营可在本人职责和合法状态下操作，主管只读；采购不获得完整经营结果。
- 观察边界：证据不足时只允许记录已观察或已有证据支持的价格、内容、详情页优化，不允许填写无证据的具体归因。

**采购动作轨**

- 内容：补货或禁止补货、执行状态、执行时间、备注、补货结果或“已确认禁补”等人工结果。
- 主操作：“更新采购动作”“记录采购结果”，只允许在对应状态出现。
- 数据来源：采购 ActionItem、ActionResult 与事件。
- 显示条件：存在补货/禁补任务时显示；采购可在本人职责和合法状态下操作，运营和主管只读汇总；无任务时说明原因。
- 语义边界：“已确认禁补”只代表本产品内人工确认，不表示外部采购系统已收到或完成。

**version 冲突提示**

- 内容：当前提交未保存、最新状态、最新操作人、最新操作时间和“刷新查看最新状态”。
- 数据来源：提交时检测到的最新建议或动作状态。
- 显示条件：用户基于旧 version 提交或网络重试已存在成功结果时出现。
- 操作能力：只允许刷新核对，不提供强制保存或覆盖已有结果。

**分轨时间线**

- 内容：建议生成/审核、经营动作、采购动作三个分组；每项包含事件名称、前后状态、操作者、时间、备注/结果、关联批次和规则/对象 version。
- 数据来源：固化快照、审核事件、动作事件、结果记录及可见的失败审计标记。
- 显示条件：授权用户始终可查看本角色范围内的历史；已驳回、部分执行、AI 失败或冲突不删除之前事件。

### 5.2 辅助信息

- 规则声明：“本页经营结论由固定规则生成，AI 仅提供解释，不改变商品类型、动作或阈值。”
- 期间声明：月销售额与经营准利润率显示实际自然月；品退与库存分别显示 7 日、14 日统计窗口，不混称“本周数据”。
- 历史声明：“本页展示生成建议时的固化快照，后续批次或规则更新不会覆盖。”
- 人工执行声明：“执行状态为本产品内人工记录，不代表广告、采购或库存系统回执。”
- 时间按产品当前业务时区展示；当前为 `Asia/Shanghai` 实现假设，不在页面宣称为用户已确认事实。

## 6. 交互流程

### 6.1 页面加载与初始化

1. 用户进入独立建议详情后，系统先校验有效钉钉登录态、当前业务角色、建议任务关联和对象读取权限。
2. 无有效会话时不读取经营数据，进入重新认证路径；无访问权或对象不存在时使用不泄露对象存在性的通用结果。
3. 运营与运营主管加载完整授权视图；采购只有在建议包含其有权查看的补货/禁补任务时加载最小必要投影。
4. 页面以建议生成时固化的批次、规则和关键值初始化，不以当前规则或新批次重算历史。
5. 固定规则结论和结构化四要素先可用；AI 解释独立显示等待、成功、失败或越界过滤状态。
6. 页面读取建议审核 version 与两条动作各自的 execution version，用于后续提交冲突校验。
7. 若某次级区域加载失败，保留已成功读取的固定结论并明确失败区域；不能把失败数据展示为空或 0。

### 6.2 核心操作流程

```text
进入建议详情
    │
    ├─ 会话无效 → 不返回经营数据 → 重新钉钉认证
    │
    ├─ 对象不存在 / 无任务关联 / 无访问权
    │       └─ 通用无权限结果，不返回建议身份或状态
    │
    └─ 授权成功 → 按角色加载固化快照、四要素、状态与时间线
            │
            ├─ AI 等待/失败/越界 → 显示状态与结构化兜底 → 业务继续
            │
            ├─ 运营主管 + 建议待审核
            │       ├─ 通过 → 可选备注 → 确认整条建议 → 激活既有双动作
            │       └─ 驳回 → 必填原因 → 确认整条建议 → 动作随建议关闭
            │
            ├─ 运营 + 建议已通过 + 经营动作可操作
            │       └─ 更新经营动作 → 确认 → 可继续记录经营结果
            │
            └─ 采购 + 有任务关联 + 建议已通过 + 采购动作可操作
                    └─ 更新补货/禁补动作 → 确认 → 记录采购结果

任一提交
    │
    ├─ version 有效且状态合法 → 保存状态/结果并追加对应事件 → 刷新本轨
    ├─ 已存在同一成功结果 → 返回既有结果，不新增重复事件
    └─ version 已变化 → 拒绝覆盖 → 显示最新状态/操作人/时间 → 用户刷新核对
```

### 6.3 辅助操作

- 点击批次编号进入对应数据批次详情；不将历史建议切换到当前批次。
- 点击“查看全部追溯”进入追溯记录并预置当前建议或 SPU 条件；采购仍沿用本页最小权限。
- AI 增强解释可展开或收起，默认不影响固定规则结论与主要操作的阅读顺序。
- 返回来源列表时恢复原批次、搜索、筛选、页码与每页条数。
- 备注或结果已填写但未提交时离开页面，提示尚未保存；纯浏览不触发离开确认。

## 7. 状态与边界

### 7.1 页面状态全景

| 状态 | 触发条件 | 页面表现 |
| :--- | :--- | :--- |
| 初始加载态 | 首次进入且权限校验、详情尚未返回 | 保留页面结构，显示正在加载，不呈现任何未经授权的旧数据 |
| 可审核态 | 规则完成、建议待审核、当前角色为运营主管 | 完整依据可读，整体通过/驳回可用；动作轨仍为待审核激活 |
| 已通过态 | 主管成功通过整条建议 | 审核操作关闭；已有经营与采购动作按角色进入待执行，无动作的轨道显示不适用 |
| 已驳回态 | 主管填写非空原因并驳回 | 保留原规则、四要素与驳回原因；全部动作随建议关闭，不可执行 |
| 分轨执行中 | 建议已通过且至少一条动作未完成 | 分别显示经营和采购轨当前状态，建议汇总只读显示“执行中” |
| 已执行待结果态 | 某动作已执行但尚未记录结果 | 对应责任角色可记录结果；另一轨道状态不受影响 |
| 已记录结果态 | 某动作结果已成功保存 | 显示结果周期、记录人、时间和备注；该轨历史不可覆盖 |
| AI 等待/生成中 | 规则已可用但解释未完成 | 四要素与业务操作正常；AI 区显示等待或生成中 |
| AI 已生成 | 增强解释通过边界校验 | 在次级区域显示增强内容，固定规则结论不变 |
| AI 失败态 | LiteLLM 超时、不可用、限流或返回失败 | 显示失败说明和结构化兜底；审核、执行与结果仍可用 |
| AI 越界过滤态 | AI 返回冲突动作、虚构值或不支持粒度结论 | 越界内容不展示；说明已过滤，固定规则字段保持不变 |
| 冲突态 | 提交时 version 已变化或重试命中既有成功结果 | 当前提交不覆盖；强提示最新状态、操作人、时间及刷新入口 |
| 部分失败态 | 固定结论已加载，但 AI、时间线或次级数据读取失败 | 保留可信区域并标明失败区域，可单独重试；不显示为无数据 |
| 整页失败态 | 授权后核心详情读取失败 | 不展示残缺结论，显示明确失败和整页重试；返回来源入口可用 |
| 会话失效态 | 登录态过期或角色映射失效 | 清除经营内容，提供重新钉钉认证或联系 IT |
| 对象不存在/无权限态 | 建议不存在、采购无任务关联或角色无读取权限 | 统一通用结果，不返回建议身份、状态或受限字段 |

### 7.2 边界与容错

| 边界场景 | 处理策略 |
| :--- | :--- |
| 网络异常 | 浏览失败时保留已成功区域并提供重试；状态提交未收到成功确认时不得本地显示成功，重试按 version 返回既有结果或冲突 |
| 会话过期 | 立即停止业务读取/提交并进入重新认证路径；未提交的经营数据不写入持久状态，页面不继续展示受限详情 |
| 连续错误或重复提交 | 提交期间禁用同一操作；重复请求命中既有成功结果时返回现状，不新增重复审核、动作或结果事件 |
| 异常输入 | 驳回原因为空时阻止提交；结果周期起止非法、数值不可解释或备注超出产品允许范围时就地提示，不用默认值或单位猜测 |
| 并发操作 | 建议审核、经营动作和采购动作分别校验当前 version；旧 version 拒绝覆盖并展示最新状态、操作人、时间和刷新入口 |
| 两名主管同时审核 | 第一个合法提交成功；后续提交进入冲突态，不能把已通过改成已驳回或反向覆盖 |
| 双动作并发 | 两条动作使用各自状态和 version，经营提交不覆盖采购，采购提交不覆盖经营；建议汇总只读聚合 |
| 未审核或已驳回即执行 | 拒绝动作更新并显示“建议尚未通过”或“建议已驳回”；不追加成功事件 |
| 非责任角色操作 | 服务端拒绝并保持状态不变；页面隐藏不属于该角色的操作，错误响应不返回额外字段 |
| 采购直链无任务关联 | 显示通用无权限结果，不确认该建议是否存在，也不返回 SPU、审核状态或动作状态 |
| 品退数据缺失或分母为 0 | 显示“品退数据未校验”或“无可计算销量”；不触发观察或依赖低品退的加投，利润清仓/止损仍可保留 |
| 库存数据缺失、异常或无近期销售 | 不生成补货/不补货判断并显示对应原因；止损/清仓生成的禁止补货不受影响 |
| AI 长时间等待或失败 | 结构化四要素、审核、执行与结果始终可用；AI 状态独立，不把建议标记为失败 |
| AI 返回越界内容 | 舍弃冲突动作、虚构数值、广告/评价/退款原因、SKU 等越界内容，保留固定规则结果并记录过滤状态 |
| 历史规则或源表已变化 | 继续展示建议生成时固化的规则版本与关键值，不使用当前值覆盖；新事实通过新批次进入 |
| 时间线局部读取失败 | 不删除或折叠已加载事件；明确该轨暂不可用并提供重试，不用空时间线表示从未发生 |

## 8. 业务规则与校验

### 8.1 字段定义

| 字段 | 说明 |
| :--- | :--- |
| `decision_id` | 单条建议的稳定身份；同一批次同一 SPU 只有一条决策记录 |
| `batch_id` | 生成建议的不可变导入批次标识 |
| `spu_id` / `spu_name` | 当前唯一决策粒度的 SPU 身份；MVP 不生成 SKU 级结论 |
| `period_start` / `period_end` | 月销售额与经营准利润率对应的上一个完整自然月实际期间 |
| `business_date` | 新品年龄判断所使用的批次业务截止日，建议建立后冻结 |
| `rule_version` | 生成当前分类、动作与阈值的版本化固定规则引用 |
| `category` | 新品、大爆款、小爆款、淘汰商品或因数据不足无法分类 |
| `main_action` | 唯一经营主动作：清仓、止损、观察、加投、维持或无法判定 |
| `replenishment_action` | 补货、不补货、禁止补货、不生成补货判断或无采购动作 |
| `key_input_snapshot` | 生成时固化的原值、采用值、周期、阈值、比较关系和质量状态 |
| `ai_status` | 等待、生成中、已生成、生成失败或越界被过滤；不控制规则、审核或动作状态 |
| `review_state` | 待审核、已通过或已驳回；建议级唯一审核状态 |
| `review_version` | 审核提交基于的当前版本；成功审核后变化，旧版本不可覆盖 |
| `operation_action_state` | 经营动作的待审核激活、随建议驳关闭、待执行、已执行、已记录结果 |
| `procurement_action_state` | 采购动作的待审核激活、随建议驳关闭、待执行、已执行、已记录结果；无动作时不适用 |
| `execution_version` | 每条动作各自的执行版本，用于执行和结果提交并发保护 |
| `review_note` | 主管审核备注；通过可空，驳回必填 |
| `action_note` | 对应责任角色的执行备注，不得改写原动作 |
| `action_result` | 与动作及角色匹配的结果、观察周期、记录人和记录时间 |
| `event_record` | 建议生成、审核、动作、结果、AI 状态或冲突的追加记录；按角色裁剪展示 |

### 8.2 校验规则

| 校验项 | 时机 | 规则 | 失败反馈 |
| :--- | :--- | :--- | :--- |
| 建议读取权限 | 页面进入与每次刷新 | 运营/主管按完整权限读取；采购必须有当前建议的采购任务关联 | 通用“无法查看该内容”，不返回对象是否存在或任何经营字段 |
| 建议审核角色 | 点击通过/驳回 | 仅运营主管且建议为待审核 | “当前角色或建议状态不允许审核” |
| 驳回原因 | 主管提交驳回 | 去除首尾空白后必须非空 | “请填写驳回原因” |
| 通过备注 | 主管提交通过 | 可空；填写时作为审核备注保存 | 内容不符合输入规则时提示修正，不影响备注可选性质 |
| 审核 version | 提交审核 | 页面读取的 review version 必须等于最新 version | “建议状态已变化，请刷新后重新确认”，并显示最新操作人和时间 |
| 动作责任角色 | 更新动作或结果 | 运营仅经营轨；采购仅采购轨；主管无动作代办权限 | “你无权更新该动作” |
| 动作前置状态 | 更新动作 | 建议必须已通过，且该动作当前状态允许迁移 | “建议尚未通过/已驳回，或动作状态已变化” |
| 动作 version | 提交执行或结果 | 当前动作 execution version 必须等于最新 version | “动作状态已变化，请刷新后重试”，不覆盖既有结果 |
| 经营结果 | 运营提交结果 | 结果周期起止合法；销售额、利润、库存仅保存可用值，缺数可明确未提供 | 对应字段提示具体可修正原因，不猜测单位或补零 |
| 观察记录 | 运营提交观察动作 | 证据不足时不得记录未经证据支持的具体归因或优化结论 | “当前证据仅支持记录观察，请删除无依据的具体结论” |
| 采购结果 | 采购提交结果 | 只能记录补货或禁补动作结果；禁补可记“已确认禁补”，不得宣称外部回执 | “请按当前采购动作记录结果” |
| AI 内容边界 | AI 解释展示前 | 动作须与规则一致，数值须来自输入，且不得含广告明细、评价/退款原因、SKU 结论 | 越界内容不展示；状态显示“部分内容已过滤” |

### 8.3 特殊业务规则

- **指标口径**：非新品分层使用扣除退款后的上一个完整自然月净销售额；经营准利润率直接采用源表值，不按旧公式重算。
- **品退口径**：仅最近 7 天品退件数与已销售件数有效且分母大于 0 时计算；数据未经校验时不参与相关分支。
- **库存口径**：仅仓内库存、在途库存与最近 14 天销量有效且平均日销量大于 0 时计算库存可售天数。
- **商品分类**：未满 2 个自然月为新品；已满 2 个自然月后，净销售额 `≥100,000 元` 为大爆款，`≥20,000 且 <100,000 元` 为小爆款，`<20,000 元` 为淘汰商品。
- **主动作唯一化**：同一 SPU 按“清仓＞止损＞观察＞加投＞维持”只保留一个主动作；相同输入快照和规则版本重复处理必须得到相同结果。
- **边界值**：大爆款利润率 `0%` 为止损、`5%` 不因低利润止损、`10%` 且品退率 `≤1.5%` 可加投；小爆款利润率 `5%` 为止损、`10%` 不因低利润止损、`15%` 且品退率 `≤1.5%` 可加投；品退率等于 `1.5%` 不观察；新品利润率等于 `-20%` 加投；库存可售天数等于 `30` 天不补货。
- **动作组合**：止损或清仓必须同步生成不可被补货覆盖的禁止补货；新品不生成补货动作；其他非新品库存可售天数 `<30` 天补货，`≥30` 天不补货；加投可与补货并存。
- **整体审核**：主管一次审核完整建议；通过激活已存在的动作项，不二次创建；驳回关闭动作执行但保留原始规则、数据和备注。
- **分轨执行**：运营处理经营动作与经营结果，采购处理补货/禁补动作与采购结果；两轨独立状态不得互相覆盖。
- **AI 降级**：AI 任意状态都不得改变分类、动作、补货结论和阈值；失败或越界时保留四要素并继续审核执行。
- **历史不可变**：建议持续引用生成时批次、业务截止日、期间、规则版本、关键值和触发规则；当前规则、源表或后续状态不覆盖快照。
- **权限默认拒绝**：页面、提交、错误和追溯统一按服务端角色裁剪；采购不可见完整利润、推广、品退、售后或经营结果。
- **凭据保密**：页面不存在 LiteLLM deployment secret 查看或配置入口，AI 错误不得返回密钥、网关凭据或可恢复内容。

### 9.1 流转图

```text
角色化工作台 / 行动清单 / 数据批次详情 / 追溯记录
                         │
                         ▼
                建议详情 PAGE-F05-03
                         │
        ┌────────────────┼────────────────┐
        │                │                │
        ▼                ▼                ▼
  批次与规则复核     整体审核/分轨执行    分轨追溯查看
        │                │                │
        ▼                ▼                ▼
数据批次详情       留在本页刷新当前状态   追溯记录（预置条件）

返回来源列表 → 恢复原批次、筛选、页码与每页条数
会话失效 → 钉钉登录
对象不存在或无权限 → 通用无权限结果
```

### 9.2 与其他模块的关系

- **角色化工作台**：提供角色化待审核、待执行或待记录结果入口；详情提交成功后，工作台汇总读取同一建议和动作状态。
- **行动清单**：建议详情使用清单中的稳定建议身份；返回时恢复批次与筛选上下文，详情操作不创建第二份清单。
- **数据批次详情**：本页批次、指标、规则和质量信息来自同一固化批次；可回到批次详情查看该批次全量结果。
- **追溯记录**：本页时间线显示当前建议分轨历史；全量追溯页按当前建议/SPU 预置筛选，不设置独立审计详情副本。
- **认证与权限**：钉钉身份和 IT 角色映射决定读取与操作范围；前端隐藏不替代权限检查。
- **AI 解释**：异步增强只更新解释状态，和建议审核、两条动作状态互相隔离。

### 9.3 扩展预案

| 扩展方向 | 触发条件 | 改造点 |
| :--- | :--- | :--- |
| 外部动作回执 | 广告、采购或库存系统 API、账号、幂等与回滚责任正式确认 | 在现有动作轨追加外部回执引用与状态；不得把历史人工确认偷换为系统回执 |
| 广告明细决策 | 广告计划/单元/关键词/素材数据、规则和权限重新立项 | 新增证据与动作类型，当前 SPU 整体主动作及历史快照保持不变 |
| 评价与退款原因分析 | 明细数据、统计口径、权限和责任人就绪 | 作为新增证据区进入新需求，不把 MVP 汇总品退率解释成具体原因 |
| SKU 级决策 | SKU 数据、费用分摊、规则和责任完成重新立项 | 增加新的决策对象类型；当前 `decision_id` 对应 SPU 事实不迁移或覆盖 |
| 更正与追加说明 | 业务确认需要对已完成动作补充说明 | 追加新的更正事件并引用原事件，不开放编辑或删除历史记录 |

| :--- | :--- | :--- | :--- |
| 建议 ID、审核决定、审核备注、review version | 主管确认通过或驳回 | 运营主管 | 一次性保存建议级审核结果；驳回原因必填，通过备注可选 |
| 建议 ID、经营动作 ID、目标执行状态、执行备注、execution version | 运营确认经营动作 | 运营 | 只更新经营动作并追加对应事件 |
| 经营结果、观察周期、可用销售/利润/库存值、备注、execution version | 运营记录经营结果 | 运营 | 把经营结果关联原建议和经营动作 |
| 建议 ID、采购动作 ID、目标执行状态、执行备注、execution version | 采购确认补货或禁补动作 | 采购计划 | 只更新采购动作并追加对应事件 |
| 采购动作结果、备注、execution version | 采购记录任务结果 | 采购计划 | 保存补货结果或人工“已确认禁补”，不代表外部回执 |

### 10.3 明确排除的数据

- 不需要或提交 SKU 身份、SKU 利润分摊或 SKU 动作。
- 不需要广告计划、单元、关键词、素材等明细对象。
- 不需要评价文本、差评主题、退款/退货原因或消费者个人信息。
- 不向普通用户返回 LiteLLM deployment secret、钉钉凭据、完整认证票据或密钥配置。
- 不向采购返回完整利润、推广、品退、售后、经营结果或非必要人员信息。
- 不提交用户改写后的商品类型、主动作、补货结论、阈值或规则版本。
- 不提交“外部系统已完成”回执；MVP 只有本产品内人工状态与结果记录。
- 不需要当前源表或当前规则来覆盖历史建议快照。

## 11. 验收标准

### 11.1 功能验收

| 编号 | 验收点 | 通过标准 |
| :--- | :--- | :--- |
| F-01 | 四要素常驻 | 固定规则生成建议后，无论 AI 为等待、成功、失败或越界过滤，授权用户均能看到具体对象、发现问题、关键依据和推荐动作 |
| F-02 | 指标口径 | 月净销售额显示扣除退款后的实际自然月期间；经营准利润率标明采用源表值；品退和库存指标分别显示周期与质量状态 |
| F-03 | 规则路径 | 页面显示商品分类、实际值、阈值、比较关系、主动作唯一化、补货冲突约束和规则版本，且全部只读 |
| F-04 | AI 越界过滤 | AI 返回冲突动作、虚构数值、广告/评价/退款原因或 SKU 内容时，相关内容不展示，固定分类、主动作、采购动作和阈值不变 |
| F-05 | AI 失败降级 | LiteLLM 等待、超时或失败时，固定规则与四要素仍可审核和执行，页面显示对应 AI 状态 |
| F-06 | 整体通过 | 主管通过待审核建议后只保存一次建议级已通过结果，同时激活既有经营和采购动作，不二次创建动作项 |
| F-07 | 整体驳回 | 驳回原因为空时无法提交；填写非空原因后保存已驳回、备注和时间，不激活动作且保留原规则与快照 |
| F-08 | 经营动作轨 | 运营只能更新经营动作及经营结果；提交成功后只改变经营轨并追加对应操作者、时间、备注/结果事件 |
| F-09 | 采购动作轨 | 采购只能更新其补货/禁补任务及结果；“已确认禁补”明确为人工记录，不显示为外部回执 |
| F-10 | version 冲突 | 两个用户基于同一旧状态提交时只接受首个合法变更；后续显示最新状态、操作者、时间和刷新入口，不覆盖或新增重复成功事件 |
| F-11 | 历史快照 | 打开历史建议时继续显示生成时批次、期间、业务截止日、规则版本、触发规则和关键值，不被当前数据、规则或状态更新覆盖 |
| F-12 | 分轨追溯 | 审核、经营动作和采购动作分别显示前后状态、操作者、时间、备注/结果和快照引用；已驳回、部分执行、冲突与 AI 失败不删除既有事件 |

### 11.2 体验验收

| 编号 | 验收点 | 通过标准 |
| :--- | :--- | :--- |
| U-01 | 首要信息可理解 | 用户进入授权详情后，无需展开 AI 内容即可识别 SPU、固定主动作、采购动作、问题、关键依据和当前审核状态 |
| U-02 | 期间不混淆 | 月度净销售额/利润、最近 7 天品退、最近 14 天销量与库存截点分别显示实际周期，不以“本周”统称 |
| U-03 | 审核后果明确 | 主管确认前能看到整条建议、经营动作和采购动作，以及通过会同时激活、驳回会同时关闭执行的说明 |
| U-04 | 双轨可辨识 | 同一建议一轨已完成、另一轨待执行时，两轨状态分别可见，建议总览不得显示“全部完成” |
| U-05 | 降级不伪装 | AI 失败、次级区域失败、数据缺失和无历史事件使用不同说明，不以空白、0 或“无问题”代替 |
| U-06 | 冲突可恢复 | version 冲突提示持续可见，明确当前提交未保存、最新操作人/时间/状态，并提供刷新；不存在强制覆盖入口 |
| U-07 | 返回上下文 | 从工作台、清单、批次详情或追溯记录进入后，返回可恢复原批次、筛选、页码与每页条数 |
| U-08 | 离开保护 | 审核备注、动作备注或结果已填写但未提交时离开页面有明确提醒；纯浏览不产生多余拦截 |
| U-09 | 1280px 可用 | 在最低支持宽度下，关键金额、百分比、阈值、状态和角色责任的完整语义可读取，操作区不会遮挡提交或刷新入口 |
| U-10 | 恢复路径 | 网络失败、会话失效、对象不存在/无权限和局部失败均有各自明确的重试、重新认证、返回或联系 IT 路径 |

### 11.3 安全验收（产品层）

| 编号 | 验收点 | 通过标准 |
| :--- | :--- | :--- |
| S-01 | 采购最小投影 | 有任务关联的采购只看到 SPU 必要身份、补货/禁补、库存、销量、可售天数、采购状态/结果及必要追溯，不出现完整利润、推广、品退、售后或经营结果 |
| S-02 | 越权直链 | 采购无任务关联、未知角色或无读取权访问详情时，显示通用无权限结果，响应与页面均不确认建议是否存在或返回任何身份/状态字段 |
| S-03 | 操作隔离 | 运营不能审核，主管不能代替运营或采购执行，采购不能更新经营动作；越权提交被拒绝且业务状态不变 |
| S-04 | 会话失效保护 | 登录态或角色映射失效后不继续返回或显示经营详情，提供重新钉钉认证或联系 IT，不自动赋予默认角色 |
| S-05 | 凭据保密 | 页面、AI 状态、错误信息和时间线中均无 LiteLLM deployment secret、钉钉凭据、完整票据或可恢复内容，也不存在普通用户配置入口 |
| S-06 | 历史不可篡改 | 页面无删除、编辑历史快照、覆盖成功事件或直接撤销已完成审核/执行的入口；更正只能追加新事实链 |
| S-07 | 并发不覆盖 | 旧 review/execution version 的提交不能覆盖现有成功状态，且不会生成第二条成功审核、动作或结果事件 |
| S-08 | AI 数据边界 | AI 展示不包含输入中不存在的数值、消费者个人信息、内部凭据或不支持粒度结论；越界内容被过滤且不改变固定规则 |
| S-09 | 错误不扩权 | 网络、对象不存在、权限拒绝、AI 失败和 version 冲突的错误信息均按当前角色裁剪，不通过错误详情泄露受限字段 |
| S-10 | 追溯按角色裁剪 | 同一建议的时间线和追溯入口延续当前角色权限；采购不能通过审核事件、备注或历史结果旁路读取受限经营内容 |
