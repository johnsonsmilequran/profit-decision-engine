## 2. 页面概述

### 2.1 一句话定位

本页是产品的唯一身份入口：让运营、运营主管和采购计划通过各自的钉钉身份完成认证，并在 IT 已配置唯一有效业务角色后进入角色化工作台。

### 2.2 存在理由

1. 在任何经营数据返回前完成统一身份校验，防止未认证或无角色人员进入业务页面。
2. 将钉钉身份与 IT 维护的业务角色映射关联，使后续页面、操作和历史路径能够使用同一角色权限。
3. 为认证失败、登录态失效及无有效角色映射提供明确且不泄露经营数据的恢复路径。

### 2.3 页面目标（可衡量）

| 目标维度 | 具体指标 |
| :--- | :--- |
| 入口唯一性 | 页面只提供 1 个认证主入口，即“使用钉钉登录” |
| 身份门禁 | 未完成有效钉钉认证的访问 100% 不进入业务页 |
| 角色门禁 | 未匹配到运营、运营主管或采购计划唯一有效角色的访问 100% 不进入业务页 |
| 权限一致性 | 每次成功登录建立的登录态 100% 关联钉钉身份与当前有效业务角色 |
| 恢复可达 | 认证失败、登录态失效及无有效角色映射三类结果均提供重新认证或联系 IT 的下一步指引 |
| 数据保护 | 本页所有失败、异常和恢复状态返回的经营数据字段数量为 0 |

### 2.4 不做什么（范围边界）

- **不做账号密码登录**——上游已确认钉钉是唯一统一身份入口，不得降级为产品自建凭据。
- **不做注册、找回密码或共享账号**——账号生命周期由公司钉钉身份体系承担，本产品不扩大认证范围。
- **不做页面内角色选择或切换**——业务角色来自 IT 维护的唯一有效映射，用户不能自行提升或改变权限。
- **不做角色管理后台**——角色配置责任属于 IT，本页只消费认证与映射结果。
- **不展示经营摘要或待办预览**——身份与角色门禁完成前不得返回 SPU、销售、利润、推广、品退、库存或任务数据。
- **不提供 LiteLLM 配置入口**——模型网关凭据与认证页面无关，且普通用户不可见。

## 3. 用户与场景

### 3.1 目标用户

| 维度 | 描述 |
| :--- | :--- |
| 角色 | 运营、运营主管、采购计划；三者均使用本人钉钉身份 |
| 人数 | 单次操作 1 人；不同岗位可在各自设备或浏览器会话中并行使用 |
| 技术熟练度 | 中等，熟悉公司钉钉登录与常规 PC 内部系统操作 |
| 使用设备 | 公司可访问产品与钉钉认证的 PC 浏览器 |
| 使用姿势 | 每周经营表导入、建议审核或动作处理前的短时身份门禁操作 |

### 3.2 核心使用场景

**场景 A：已配置角色的用户正常登录（主场景）**

- 时机：运营、运营主管或采购计划首次打开产品，或主动从收藏的产品入口进入。
- 前置条件：用户拥有可用的本人钉钉身份，且 IT 已为该身份配置唯一有效的业务角色。
- 用户动作：点击“使用钉钉登录” → 在钉钉完成统一身份认证 → 返回产品 → 进入角色化工作台。
- 用户情绪：明确、顺畅，对进入后的角色和权限有信心。

**场景 B：登录态失效后重新认证（兜底场景）**

- 时机：用户停留在业务页期间登录态失效，或再次打开已过期的历史链接。
- 前置条件：当前登录态已失效，业务页已停止返回经营数据并重定向到本页。
- 用户动作：看到“登录状态已失效”说明 → 点击“重新使用钉钉登录” → 认证成功后进入当前角色的工作台。
- 用户情绪：不困惑，知道数据未丢失且只需重新认证。

**场景 C：认证成功但没有有效角色映射（兜底场景）**

- 时机：新员工首次使用、岗位调整后映射尚未完成，或映射结果不是三个有效业务角色之一。
- 前置条件：钉钉身份认证成功，但系统未取得唯一有效业务角色。
- 用户动作：看到“未配置有效业务角色，请联系 IT” → 按组织提供的联系指引处理 → 配置完成后重新发起钉钉认证。
- 用户情绪：被明确告知阻塞原因与责任方，不误以为经营数据不存在。

### 3.3 用户核心诉求（优先级排序）

1. **安全进入**：未经本人钉钉认证和有效角色映射，任何人都不能看到经营数据。
2. **一步发起**：无需输入产品账号、密码或选择角色，只需从唯一钉钉入口开始。
3. **结果明确**：能区分认证进行中、认证失败、登录态失效和无角色映射。
4. **恢复可行**：失败后知道是重新认证还是联系 IT，不陷入无响应状态。
5. **权限可信**：成功后进入与本人当前业务角色一致的工作台，后续路径不沿用旧角色权限。

## 6. 交互流程

### 6.1 页面加载与初始化

1. 用户进入本页时，系统先判断当前登录态是否仍有效。
2. 登录态有效且存在唯一有效业务角色时，不停留本页，直接进入角色化工作台。
3. 登录态无效或不存在时，展示钉钉登录主操作，不请求或展示任何经营数据。
4. 若来源表明登录态刚刚失效，展示对应说明，同时保留重新认证入口。
5. 若页面处于钉钉回调处理阶段，展示“正在确认登录身份”，直到得到成功、失败或无有效角色映射结果。

### 6.2 核心操作流程

```text
用户进入钉钉登录页
        │
        ├─ 已有有效登录态 + 唯一有效角色
        │        └─ 直接进入角色化工作台
        │
        └─ 无有效登录态
                 │
                 ▼
          点击“使用钉钉登录”
                 │
                 ▼
          前往钉钉完成身份认证
                 │
          ┌──────┴──────────────┐
          │                     │
       认证失败              认证成功
          │                     │
   留在本页并可重试        校验 IT 角色映射
                                │
                    ┌───────────┴───────────┐
                    │                       │
             唯一有效业务角色          无有效角色映射
                    │                       │
           建立关联身份与角色的登录态   拒绝进入业务页
                    │                       │
            进入角色化工作台          联系 IT / 重新认证
```

### 6.3 辅助操作

- 认证失败、网络异常、回调无效或登录态失效后，用户可点击“重新使用钉钉登录”再次发起完整认证流程。
- 无有效角色映射时，用户可使用“联系 IT”指引处理，页面不提供临时角色或自助配置。
- 用户从需要登录的业务地址被重定向到本页时，认证成功后统一进入角色化工作台；不直接恢复到未经重新权限校验的受限对象。

## 7. 状态与边界

### 7.1 页面状态全景

| 状态 | 触发条件 | 页面表现 |
| :--- | :--- | :--- |
| 初始化态 | 页面首次打开，正在检查当前登录态 | 展示产品身份与检查提示，不请求经营数据 |
| 未登录态 | 不存在有效登录态 | 展示唯一“使用钉钉登录”主操作 |
| 认证发起态 | 用户点击登录，正在前往钉钉 | 显示“正在前往钉钉认证…”，主操作不可重复触发 |
| 回调处理态 | 用户从钉钉返回，身份与角色结果待确认 | 显示“正在确认登录身份…”，不展示业务内容 |
| 成功态 | 钉钉认证成功且映射唯一有效角色 | 建立登录态并进入角色化工作台，本页不继续停留 |
| 认证失败态 | 钉钉认证未成功或认证结果不可用 | 显示通用失败说明、重新认证与联系 IT 指引 |
| 登录态失效态 | 业务访问所用登录态已失效 | 显示“登录状态已失效”，拒绝业务数据并提供重新认证 |
| 无角色映射态 | 身份有效但没有唯一有效业务角色 | 显示联系 IT 指引，不建立可进入业务页的登录态 |
| 网络异常态 | 发起或确认认证时网络不可用或超时 | 显示网络异常与重试入口，不把未知结果视为成功 |

### 7.2 边界与容错

| 边界场景 | 处理策略 |
| :--- | :--- |
| 网络中断或超时 | 不把认证状态展示为成功；保留本页，提示网络异常并允许重新发起钉钉认证 |
| 登录态在业务访问中失效 | 立即停止返回经营数据并回到本页；说明登录态失效，重新认证后再按当前角色进入工作台 |
| 连续认证失败 | 每次均显示同一类不泄露细节的可恢复反馈；可重新认证或联系 IT，不在页面自行发明锁定次数或冷却阈值 |
| 回调参数缺失、过期或无法确认 | 视为认证未完成，不建立登录态；提示重新发起完整钉钉认证，不展示内部参数或错误堆栈 |
| 重复点击登录 | 首次认证发起得到明确结果前，主操作不可再次触发，避免同时启动多条认证流程 |
| 多标签页并行完成认证 | 只接受当前仍有效且可验证的认证结果；后续页面均重新确认当前角色，不沿用另一标签页保存的旧权限 |
| 认证成功但无角色映射 | 默认拒绝进入业务页，不自动赋予运营角色；展示联系 IT 与重新认证路径 |
| 角色映射不是唯一有效角色 | 不让用户在页面选择角色；按无有效角色处理并联系 IT，由 IT 修正映射 |
| 钉钉认证服务暂不可用 | 显示服务暂不可用的通用说明；不切换到账号密码、共享账号或其他临时登录方式 |
| 用户后退回到回调地址 | 不重复建立业务身份或重复记录成功结果；根据当前登录态进入工作台或回到可重新认证状态 |

## 8. 业务规则与校验

### 8.1 字段定义

| 字段 | 说明 |
| :--- | :--- |
| `authentication_status` | 当前钉钉认证结果：未发起、处理中、成功或失败 |
| `session_status` | 产品登录态状态：不存在、有效或失效 |
| `actor_ref` | 与本人钉钉身份关联的内部用户标识；页面不展示认证凭据 |
| `role_mapping_status` | IT 维护的业务角色映射结果：唯一有效或无有效映射 |
| `current_role` | 成功登录后使用的运营、运营主管或采购计划角色；本页不可编辑 |
| `return_reason` | 进入本页的产品级原因，如未登录、登录态失效或认证失败；不得包含敏感认证内容 |
| `support_guidance` | 组织配置的 IT 联系指引，用于持续认证失败或无角色映射的恢复 |

### 8.2 校验规则

| 校验项 | 时机 | 规则 | 失败反馈 |
| :--- | :--- | :--- | :--- |
| 当前登录态 | 页面初始化及进入业务页前 | 只有有效登录态才可继续；失效或不存在时停留本页 | “登录状态已失效，请重新使用钉钉登录”或展示初始登录入口 |
| 钉钉认证结果 | 回调确认时 | 只有可确认的成功结果才进入角色映射校验 | “暂时无法完成钉钉登录，请重新尝试” |
| 回调完整性 | 回调处理时 | 缺失、过期或无法确认的结果不得建立登录态 | “登录未完成，请重新使用钉钉登录” |
| 业务角色映射 | 认证成功后 | 必须匹配运营、运营主管、采购计划中的唯一有效角色 | “未配置有效业务角色，请联系 IT” |
| 角色时效 | 进入业务页及后续访问时 | 使用当前权威角色映射，不沿用已失效的页面角色 | 当前映射无效时停止进入并引导重新认证或联系 IT |
| 重复认证发起 | 认证处理中 | 已有认证流程未得出结果前不重复发起 | 保持处理中提示，不创建第二个认证流程 |

### 8.3 特殊业务规则

- **唯一认证方式**：MVP 只允许钉钉统一身份认证；无论何种失败均不得出现账号密码、注册、找回密码或共享账号降级。
- **默认拒绝**：无有效认证、登录态失效、无有效角色或角色映射不唯一时，均不得进入业务页或获得任何经营数据。
- **角色不可自选**：当前角色只来自 IT 维护的映射，用户不能通过页面改成运营、运营主管或采购计划。
- **权限重新确认**：认证成功只代表身份有效，进入业务页还必须取得当前权威权限结果；后续访问不得沿用过期角色。
- **失败信息最小化**：用户只看到可恢复的产品级原因，不展示钉钉票据、内部认证参数、角色配置明细或经营对象存在性。
- **认证与业务隔离**：本页不预取工作台、建议、批次或追溯数据；成功后由业务页面按角色获取其有权数据。

### 9.2 与其他模块的关系

- **角色化工作台**：只有钉钉认证成功且 IT 映射唯一有效角色后才能进入；工作台显示当前角色并按角色聚合待办。
- **无权限页**：认证成功但无有效映射，或后续访问不属于当前角色的页面时，承载统一拒绝与恢复入口；不展示受限对象摘要。
- **所有业务页面**：业务页不能仅凭页面已显示的角色放行，登录态失效或角色变化后必须回到门禁流程。
- **IT 角色维护**：是本页的外部前置能力，不在产品内形成角色配置页面。
- **钉钉身份体系**：提供统一身份认证；本页不保存或展示用户认证凭据。

## 10. 数据需求

### 10.1 页面需要什么数据

| :--- | :--- | :--- |

| 业务角色映射状态 | IT 维护的角色映射结果 | 判断是否存在唯一有效的运营、运营主管或采购计划角色 |
| 当前业务角色 | 角色映射结果 | 成功后建立与角色关联的登录态并进入角色化工作台 |

| IT 联系指引 | 组织支持配置 | 在持续认证失败或无有效角色映射时提供恢复路径 |

### 10.2 页面提交什么数据

| 数据 | 触发时机 | 用途 |
| :--- | :--- | :--- |
| 钉钉认证发起意图 | 点击“使用钉钉登录” | 启动唯一统一身份认证流程 |
| 钉钉认证返回结果 | 用户从钉钉返回产品时 | 确认身份并继续校验 IT 角色映射；页面不采集账号密码 |
| 重新认证意图 | 认证失败、登录态失效或角色映射修正后点击重试 | 重新启动完整认证流程，不沿用无法确认的旧结果 |

### 10.3 明确排除的数据

- 不采集或提交产品账号、密码、短信/邮件验证码、注册资料或找回密码信息。
- 不提交用户自行选择的角色；当前角色只能来自 IT 维护的映射。
- 不读取 SPU、批次、建议、销售、利润、推广、品退、库存、售后或动作结果数据。
- 不读取或展示 LiteLLM 网关地址、deployment secret 或模型配置。
- 不把钉钉认证凭据、回调敏感内容或内部错误细节作为页面可见数据。

## 11. 验收标准

### 11.1 功能验收

| 编号 | 验收点 | 通过标准 |
| :--- | :--- | :--- |
| F-01 | 唯一认证入口 | 未登录状态下页面只出现“使用钉钉登录”认证主操作，不出现账号密码、注册、找回密码或其他登录方式 |
| F-02 | 有效身份与角色登录 | 用户完成钉钉认证且 IT 配置唯一有效角色后，建立与该身份和角色关联的登录态并进入 PAGE-F05-01 角色化工作台 |
| F-03 | 已登录用户直达 | 已有有效登录态且角色映射仍有效时访问 `/login`，不重复要求认证，直接进入角色化工作台 |
| F-04 | 认证失败恢复 | 钉钉认证失败时不进入业务页，页面展示重新认证及联系 IT 指引 |
| F-05 | 登录态失效恢复 | 业务页登录态失效后回到本页，显示失效原因并可重新发起钉钉认证 |
| F-06 | 无角色映射拒绝 | 认证成功但没有唯一有效业务角色时，不建立可进入业务页的登录态，不自动赋予角色，并展示联系 IT 指引 |
| F-07 | 重复发起保护 | 认证处理中连续点击主操作，不启动第二条并行认证流程 |
| F-08 | 回调异常处理 | 回调缺失、过期或无法确认时不建立登录态，页面提示重新发起完整认证 |

### 11.2 体验验收

| 编号 | 验收点 | 通过标准 |
| :--- | :--- | :--- |
| U-01 | 路径简洁 | 正常用户在产品页无需填写任何产品字段，只需发起一次钉钉登录并在钉钉完成认证 |
| U-02 | 处理中可感知 | 认证发起和回调确认期间分别显示明确处理中说明，用户不会看到空白页或误判已登录 |
| U-03 | 失败可行动 | 认证失败状态同时说明未登录成功和下一步操作，用户可直接重新认证或按指引联系 IT |
| U-04 | 会话失效可理解 | 登录态失效进入本页时明确显示“登录状态已失效”，不与首次未登录混淆 |
| U-05 | 角色问题可定位 | 无有效角色映射时明确指出由 IT 处理，不要求用户在产品内猜测或选择角色 |
| U-06 | 异常可恢复 | 网络恢复后无需刷新整个产品即可从本页重新发起钉钉认证 |
| U-07 | 文案一致 | 初始、失败、失效和无角色映射状态均将钉钉描述为唯一认证方式，不出现相互矛盾的临时登录建议 |

### 11.3 安全验收（产品层）

| 编号 | 验收点 | 通过标准 |
| :--- | :--- | :--- |
| S-01 | 未认证默认拒绝 | 无有效钉钉认证时访问任一业务地址，均不能进入业务页或获得经营数据 |
| S-02 | 无角色默认拒绝 | 身份有效但无唯一有效角色时，页面、错误和后续路径均不返回 SPU、批次、建议或经营字段 |
| S-03 | 禁止认证降级 | 钉钉不可用、认证失败或角色缺失时，不出现账号密码、共享账号、默认角色或仅靠页面放行的替代路径 |
| S-04 | 错误信息最小化 | 认证失败、回调异常和无角色映射的页面反馈不展示认证票据、内部参数、角色配置明细、受限对象身份或经营状态 |
| S-05 | 身份角色绑定 | 每个成功登录态都关联完成认证的钉钉身份及 IT 当前映射的唯一有效业务角色，页面不可修改该角色 |
| S-06 | 失效权限不沿用 | 登录态失效或角色映射变化后再次访问业务页，旧页面角色不能继续读取或提交业务数据 |
| S-07 | 异常回调不建会话 | 缺失、过期、重复或无法确认的认证返回结果均不能建立新的有效登录态 |
| S-08 | 认证页零经营数据 | 在初始化、未登录、认证中、失败、失效、无角色和网络异常各状态下检查页面，经营数据字段均为 0 |
