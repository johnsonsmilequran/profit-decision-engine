# F09 Admin 管理后台方案 V1

> 状态：V1 方向及第一版范围均已由用户确认，可作为正式 PRD 的权威输入。

## 1. 结论

F09 首版建设一个**单应用内部授权闭环**，不是通用 IAM：

```text
钉钉确认身份 → 无唯一角色进入待处理 → 外部负责人审批
→ 唯一 Admin 核验身份与审批依据并配置固定角色
→ 旧业务会话撤销 → 用户重新登录正确工作台 → 全程审计
```

F09 解除的是“身份已确认但无人能配置业务角色”的产品启用阻塞。它不单独认领整套经营产品的收入或利润价值。

## 2. 不变边界

- 仅一名 Admin，不提供第二 Admin、备用 Admin、委派、共享管理权限或管理员角色树。
- Admin 使用独立本地用户名、密码、TOTP、Cookie、令牌秘密和认证中间件，不依赖钉钉。
- Admin 管理权与运营/运营主管业务角色正交；默认不能读取经营数据。
- 业务角色固定为运营、运营主管，同一身份最多一个有效角色。
- 事业部负责人审批，Admin 只核验并执行，不获得审批权。
- 无角色用户只进入待处理，不自动授权；首个钉钉用户也不会自动成为 Admin。
- 首版不接 OA API，不做通用 IAM/IGA、目录同步、批量授权、可配置权限集或审批编排。

## 3. 产品最小闭环（首发代码范围）

### 3.1 唯一 Admin 初始化

```text
校验一次性 setup 口令
→ 设置用户名/密码
→ 绑定并实码验证 TOTP
→ 单次展示恢复码并确认保存
→ 数据库事务内创建唯一 Admin、消费 setup 口令、写审计
→ 跳转正式登录
→ 首次正式登录作为初始化验收，不作为创建事务前置
```

- setup 口令限定目标环境、版本、签发、到期和单次消费。
- 数据库唯一约束与事务防止并发创建第二 Admin。
- 刷新、返回、重复提交或网络中断不能产生半成品；提交结果未知时按幂等请求查询真实结果。

### 3.2 独立 Admin 登录

- 用户名 + 密码 + TOTP；登录失败采用账号/来源双维度渐进限速和短时冷却，不永久锁死唯一 Admin。
- `/api/admin/*` 只读取 Admin Cookie；业务 API 只读取业务 Cookie。禁止 fallback、身份转换或共享令牌秘密。
- 管理写操作要求 CSRF token、严格 Origin 校验和预期内容类型。
- 密码/TOTP/持有人变更后递增凭据代次并撤销全部旧 Admin 会话。

### 3.3 两级恢复

**保存型恢复码**：必须先通过用户名和密码，仅替代一次 TOTP；单次消费后强制重新绑定并实码验证 TOTP。成功后旧 TOTP、旧恢复码和旧 Admin 会话失效；不能用它重设密码。

**部署恢复口令**：正常凭据全部不可用时，由运维依据独立恢复审批生成；可重设密码与 TOTP。数据库事务原子写入新凭据代次、会话撤销、口令消费、不可变审计和持久通知任务（outbox），任一步失败则凭据不变。

- 外部通知投递不伪装为数据库原子事务；outbox 可重试、状态可查、失败告警并留审计。
- 禁止静默恢复。通知通道不可用时，只允许公司认可的“独立审批人确认 + 恢复执行人执行 + 可追溯工单/线下通知证据”补偿路径，不能因单一通知系统故障永久锁死 Admin。
- 快照恢复后，服务开放前必须轮换部署口令、相关保护材料并撤销旧 Admin 会话。
- 本流程不宣称符合 NIST AAL2。

### 3.4 待处理用户状态与责任承接

- 以“身份提供方 + 钉钉企业作用域 + 稳定用户标识”幂等登记；重复登录不重复建单，不创建业务会话或返回经营数据。
- 产品在角色提交前无法验证外部审批是否完成，因此不持久化虚假的“已审批待配置”中间态。Admin 在单次授权表单中核验并提交审批依据，成功后直接进入“已配置待重新登录”。

| 状态 | 用户结果 | Admin 动作 |
|---|---|---|
| 待处理 | 明示系统不知道外部审批进度；展示申请时间、具体负责岗位、有效联系方式和下一步 | 首页按等待时长展示新申请/最老待处理；取得材料后打开授权表单 |
| 已配置待重新登录 | 告知角色及重新登录动作 | 核对首次成功进入结果 |
| 已授权 | 进入对应工作台 | 查看当前角色和历史 |
| 已停用 | 进入明确停用状态页，不出现通用 403/登录循环 | 按新审批决定是否恢复 |
| 配置冲突 | 不创建业务会话，展示可操作指引 | 解决身份、审批、角色或并发冲突后重试 |

- 联系岗位/联系方式来自环境级非秘密配置；缺失时生产上线检查失败，不为此建设通用配置中心。
- 六阶段分析模型在 V1 收敛为五个持久状态与一个授权表单步骤，不建设六套页面或审批引擎。

### 3.5 可靠身份核验

- 授权键使用身份提供方、企业作用域和稳定用户标识，姓名仅用于展示。
- 授权界面必须额外展示至少两个能与审批材料交叉核验的权威组织属性，候选为姓名 + 部门或员工编号；字段与来源必须在开发前用真实钉钉权限实测确认。
- 若当前最小权限无法取得两个可靠属性，则 F09 不满足“错误授权为 0”，阻塞生产上线；不得用自由备注、同名猜测或 opaque ID 绕过。
- V1 不虚构当前代码已经取得这些字段；需由钉钉当前用户响应/获批的最小用户详情权限，或由包含稳定钉钉标识的组织认可审批证据提供。

### 3.6 审批依据与角色操作

- 一次提交必填：审批人、审批时间、目标角色、证据类型、证据引用、身份核验结果。
- 公司认可和禁止的证据类型在生产上线前确认；首版不上传附件、不调用 OA API。
- 新增、变更、停用、恢复分别使用不同确认文案，突出目标人员、稳定身份摘要、两个核验属性、前后角色、审批依据和会话影响；首版禁止批量授权。
- 角色状态、审批记录、该身份业务会话撤销和管理审计在同一事务完成；按身份锁或版本控制并发。与钉钉回调并发时，旧会话既不可用，也必须被标记撤销。
- 统一身份详情只聚合当前身份、角色、审批依据、历史和最近审计，不扩展为组织目录或权限治理中心。

### 3.7 不可变管理审计

- 覆盖初始化与失败、登录限速、两类恢复、角色新增/变更/停用/恢复、身份/审批拒绝、会话撤销和安全配置变化。
- 不记录密码、setup/recovery 口令、TOTP 密钥、恢复码或完整令牌。
- Admin 只读；应用运行身份无审计更新、删除或 DDL 权限；高权限动作审计写入失败则整体回滚。
- 审计页面提供必要分页与筛选，不做首发高级导出/SIEM。期限由公司治理责任人确定，不能按三年价值周期倒推。

### 3.8 最小错误与恢复状态

`/admin/setup`、恢复码流程、`/admin/recovery` 均具备：初始、校验中、可继续、提交中、成功、短时限流、可重试失败和结果未知。页面给合法用户可执行下一步，但不暴露口令到底“不存在/已消费/已过期”的精确安全状态；精确原因只进受限审计。

TOTP 时钟异常、密码不合规、通知待投递/失败、网络中断均有明确落点；刷新和重试通过幂等请求恢复真实结果。

## 4. 生产上线门禁（不是额外后台功能）

- 登记唯一 Admin 当前持有人、交接责任、事业部审批岗位、恢复审批岗位、恢复执行岗位、安全通知接收岗位、审计治理岗位和价值台账岗位。
- 联系方式、审批证据目录、通知主通道和非静默补偿路径为必填配置；未就绪时系统显示“尚未完成启用配置”，不让用户进入无人承接的申请流程。
- 开发与线上使用物理独立的配置源、秘密、基础设施和启动/运维命令；不允许用线上部署栈选择性启动冒充开发环境。
- 初始化/恢复/TOTP/会话秘密不进入仓库、镜像、前端包、日志或通用默认值。
- TOTP 密文携带保护密钥版本；轮换、回滚与备份恢复后换新完成演练。
- 真实钉钉链路已证明稳定标识和两个核验属性可得；首位用户审批材料与 TOTP 工具已就绪。
- 初始化、恢复码、部署恢复、通知失败补偿、旧会话撤销、角色变更与登录并发、双 Cookie 隔离、快照恢复后口令换新均通过真实浏览器 + PostgreSQL 演练。
- 首次正式登录成功只是 setup 后验收；10 分钟目标需在上述前置均就绪时真实测量。
- 联系人、具体 SLA、证据目录、通知通道、安全参数和审计期限由对应责任人填写；PRD 不虚构这些组织事实。

### 唯一 Admin 交接

只保留一条 Admin 账号，但禁止共享或直接传递旧密码、旧 TOTP、旧恢复码。交接通过受控凭据重置完成，记录原持有人、新持有人、交接依据和凭据代次，撤销全部旧会话/恢复材料并留审计。

## 5. 验收指标与价值口径

| 指标 | 目标/状态 | 口径 |
|---|---:|---|
| 首次初始化授权闭环 | ≤10 分钟（待实测） | 首位用户、有效审批、两个核验属性、TOTP 工具均已就绪；服务端初始化开始到正确业务会话访问工作台 |
| 日常产品内配置时间 | 先记录真实分布 | 有效审批材料可用到角色配置成功 |
| 完整授权周期 | 先记录真实分布 | 待处理身份产生到进入工作台，包含外部审批等待 |
| 无角色用户闭环完成率 | 记录 | 待处理用户最终进入正确工作台的比例 |
| 错误业务授权 | 0 | 错人、错角色、双角色、作用域错误均计入 |
| 高权限审计覆盖率 | 100% | 初始化、恢复与角色生命周期逐类核对 |
| 恢复后旧 Admin 会话 | 0 | 全部旧会话不可用且标记撤销 |

- 72 万元/年是 `6 万元/次 × 12 次/年待验证假设` 的潜在风险暴露；216 万元是连续三年假设成立时的可支撑价值上限，不是已节省金额、承诺 ROI 或 F09 独占价值。
- F09 只纳入“正当访问需求 + 直接因角色缺失/错误/失效被阻塞 + F09 实际解除 + 有经营动作延误证据 + 利润影响可核验”的事件。
- 数据/规则、尚未审批、主管审核、业务执行、采购、外部系统、网络或非角色登录故障均排除。
- 价值台账岗位在上线 30 天输出真实申请、处理时间、错误授权、恢复演练和可归因事件结论；年度按真实事件重算。

## 6. 范围停止线与重评

首发不做多 Admin、批量授权、可配置角色、OA/HR/IDaaS 集成、目录同步、周期复核、审计高级导出、SIEM、多应用权限包或价值分析后台。

以下只触发重新拍板，不自动扩功能：第二生产环境、第三业务角色、跨事业部/多级审批、30 天数据证明单人无法承接、唯一 Admin 交接、首次演练/真实恢复失败、身份源增加、公司决定接入 OA/IDaaS。

若上线 30 天真实无角色申请极少且没有可归因经营影响，则不启动 OA 集成、周期复核、导出或其他高级治理投资。

## 7. 主要风险

1. **身份属性不可得，所有授权被安全规则阻断**：开发前真实验证钉钉最小权限；不可得则停止上线并由用户决定增加权限或调整证据流程。
2. **恢复通知服务故障导致再次锁死或静默接管**：事务内持久 outbox、重试/告警，以及组织认可的独立审批 + 执行 + 可追溯补偿路径。
3. **四方要求叠加导致小型 IAM**：产品闭环与上线门禁分层；门禁不建设通用配置/审批/安全控制台；30 天数据决定是否继续投资。
4. **单 Admin 离岗造成运营中断**：受控凭据交接而非共享旧凭据；恢复岗位链和重评触发器提前登记。
5. **角色变更并发残留旧权限**：角色/审批/撤销/审计原子事务，并对钉钉回调并发做真实数据库验收。

## 8. V1 方向判断

V1 已关闭 Round 3 的三类主要矛盾：

- 初始化改为“先原子创建，再正式登录验收”，不存在未建账号先登录。
- 恢复改为“数据库事务 + 持久通知任务 + 可追踪补偿”，不伪造跨系统原子性，也不因单一通知故障永久锁死。
- 删除不可达的“已审批待配置”持久状态，审批核验与角色配置在一个提交中完成。

方案仍然只做一个能安全开门、不会错授、有人承接且可恢复的最小闭环，不建设身份治理平台。

## MVP 划分（已与企业家确认）

### 第一版最小可用范围

| 范围项 | 第一版结论 | 必须交付的结果 |
|---|---|---|
| F09-SCOPE-01 唯一 Admin 初始化与独立登录 | MVP | 一次性初始化、单 Admin、密码 + TOTP、独立管理会话及初始化后正式登录 |
| F09-SCOPE-02 待处理用户状态与责任承接 | MVP | 无有效唯一角色的用户进入真实待处理状态；用户看见责任岗位、有效联系方式和下一步；Admin 能发现新申请与积压 |
| F09-SCOPE-03 身份/审批核验与唯一角色生命周期 | MVP | 可靠身份交叉核验、结构化审批依据、角色新增/变更/停用/恢复、旧业务会话撤销及禁止双角色 |
| F09-SCOPE-04 两级恢复与非静默安全通知 | MVP | 保存型恢复码、部署恢复口令、旧凭据/旧会话撤销，以及通知或可追溯的非静默补偿 |
| F09-SCOPE-05 不可变管理审计 | MVP | 初始化、登录安全、两类恢复、授权变化、拒绝操作和会话撤销均追加式记录；Admin 只能基本查询，不能修改或删除 |
| F09-SCOPE-06 授权时效与价值观察 | MVP | 记录关键时间点、验证 10 分钟目标、观察日常处理周期并支持上线 30 天人工复盘 |

### 明确后置

第一版不建设统计大屏、价值分析后台、多 Admin、批量授权、可配置角色、OA/HR/IDaaS 集成、目录同步、周期复核、审计高级导出、SIEM、多应用权限包或通用审批编排。

### 第一版完成定义

只有上述六项产品能力通过真实浏览器、PostgreSQL、钉钉身份闭环验收，并且身份双属性真实可得、开发与线上环境物理隔离、岗位联系人和审批证据规则已配置、两级恢复与非静默通知可用、关键恢复与会话撤销场景完成演练，第一版才算完成。功能代码完成但生产上线门禁未满足，不算完成。

核心闭环必须真实证明：

```text
无有效唯一角色的钉钉用户登录 → 产生待处理申请 → Admin 核验身份与审批依据
→ 配置唯一正确角色并撤销旧业务会话 → 用户重新登录进入正确工作台
```

同时满足：错误业务授权为 0、高权限操作审计覆盖率 100%、恢复后旧 Admin 会话为 0；在全部前置条件已就绪时，首次初始化至已审批用户进入正确工作台不超过 10 分钟。用户已确认第一版范围没有补充或删减。
