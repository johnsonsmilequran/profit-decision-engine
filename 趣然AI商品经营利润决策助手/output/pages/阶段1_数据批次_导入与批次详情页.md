## 2. 页面概述

### 2.1 一句话定位

让运营声明玩具事业部、上一个完整自然月期间和批次业务截止日，上传数据支持部门提供的 XLSX 经营表；随后在同一页面查看处理阶段、可定位的校验结果、不可变批次摘要及 SPU 冻结指标，批次成功后进入其唯一行动清单。

### 2.2 存在理由

1. 若不显式声明数据期间和业务截止日，系统可能把错误表头“上一周”当成业务口径，或因处理日期变化而改变新品分类。
2. 若所有字段错误都整行丢弃，会漏掉仍可由有效销售或利润事实判定的经营问题；若缺失值被补成 0，则可能产生错误清仓、止损或库存结论。
3. 若错误不能定位到源表行、字段和原始值，运营无法让数据支持部门准确修正下一批数据。
4. 若重复点击、网络重试或并发导入生成多个批次，会产生多份清单、重复审核和相互冲突的执行记录。
5. 若批次指标随新文件或后续重算覆盖，主管和执行人将无法追溯建议当时使用的事实。

### 2.3 页面目标（可衡量）

| 目标维度 | 具体指标 |
| :--- | :--- |
| 批次信息完整 | 100% 成功建立的批次显示事业部、数据期间、业务截止日、批次标识、文件名、提交人和时间 |
| 幂等一致 | 同一批次输入因重复点击、网络重试或并发提交再次到达时，新增批次、建议和状态事件数量均为 0 |
| 错误可定位 | 100% 行级错误显示源工作表、行号、字段、原始值、原因、影响范围和处理结果 |
| 降级准确 | 必要身份错误只拒绝对应行；其他经营字段错误只停止依赖该字段的判断，不删除仍可判定结果 |
| 缺失诚实 | 销售、利润、品退、库存及销量字段缺失或不可计算时，以 0 代填的数量为 0 |
| 快照一致 | 同一批次、同一规则版本重复查看时，冻结指标、质量状态和后续规则输入逐项一致 |
| 清单唯一 | 固定规则处理完成后，每个批次只能进入一份与该批次关联的行动清单 |

### 2.4 不做什么（范围边界）

- **不做 CSV、在线表格或多数据源导入**：MVP 只接收数据支持部门提供的 XLSX 经营表。
- **不做 SKU 识别、分摊或指标计算**：唯一经营对象是商品链接对应的 SPU。
- **不按旧利润公式重算利润率**：本页直接采用源表“经营准利润率”，并保留来源说明。
- **不把源表合计行作为 SPU 数据**：表头或汇总行只可形成警告，不参与 SPU 决策，也不向明细分摊差额。
- **不在缺数时猜测或补 0**：缺失、未校验、异常和无近期销售必须分别呈现。
- **不增加手动“生成清单”步骤**：可判定数据完成校验后自动进入指标与固定规则处理。
- **不提供导出、错误文件下载或外部系统同步**：这些能力没有进入当前稳定需求范围。

## 3. 用户与场景

### 3.1 目标用户

| 维度 | 描述 |
| :--- | :--- |
| 主要角色 | 运营：声明批次上下文、上传 XLSX、查看校验和冻结指标、进入行动清单 |
| 次要角色 | 运营主管：可查看完整批次与指标结果，不可在本页发起导入 |
| 人数 | 单次通常由一名运营导入；可能因重复点击、网络重试或多窗口形成并发提交 |
| 技术熟练度 | 中等，能核对经营表、日期口径、字段异常和 SPU 指标 |
| 使用设备 | 宽度不低于 1024px 的办公电脑 |
| 使用姿势 | 每周一收到数据支持部门经营表后建立新批次，周内按需复核批次与指标证据 |

### 3.2 核心使用场景

**场景 A：导入本周经营表并生成新批次（主场景）**

- 时机：数据支持部门每周一提供新的 SPU 经营表。
- 前置条件：当前用户为运营；已获得可读 XLSX；能确认数据对应的完整自然月和批次业务截止日。
- 用户动作：确认玩具事业部 → 填写期间和业务截止日 → 选择 XLSX → 提交导入 → 查看处理阶段和校验摘要。
- 系统结果：建立不可变批次，按 SPU 校验并冻结可用指标；规则处理成功后开放该批次唯一行动清单入口。
- 用户情绪：有把握，知道系统采用了哪一批、哪个期间的数据。

**场景 B：复核字段级降级和 SPU 冻结指标（主场景）**

- 时机：批次校验完成，部分 SPU 存在上架日期、销售、利润、品退或库存字段问题。
- 前置条件：批次至少有一条必要身份有效的 SPU 行。
- 用户动作：查看有效、拒绝、降级数量 → 按批次错误、身份错误和经营字段警告分组检查 → 根据源表行定位原始值 → 打开 SPU 证据详情核对采用值、周期和数据限制。
- 系统结果：必要身份错误行被拒绝；其他字段只影响依赖判断；所有缺数保留为明确状态，不补 0。
- 用户情绪：可解释，知道哪些结果仍可信、哪些需要后续补数。

**场景 C：修正批次级错误后重新提交（兜底场景）**

- 时机：期间不是完整自然月、日期顺序非法、业务截止日非法，或文件不可读取。
- 前置条件：批次尚未发布依赖该期间的行动清单。
- 用户动作：根据原位反馈修正期间、截止日或文件，再次提交。
- 系统结果：非法输入不发布清单；修正后的不同输入可建立新批次，原失败状态保持可追溯。
- 用户情绪：不迷茫，能够根据具体原因修正。

**场景 D：重复提交命中既有批次（兜底场景）**

- 时机：用户重复点击、网络重试、多窗口提交相同输入，或再次上传完全相同的批次内容。
- 前置条件：第一次提交已经成功建立批次。
- 用户动作：再次提交相同事业部、期间、业务截止日和文件内容。
- 系统结果：返回第一次建立的批次、既有处理状态和既有清单，不新增第二批次、建议或状态事件。
- 用户情绪：稳定，不担心重复操作制造重复任务。

### 3.3 用户核心诉求（优先级排序）

1. **口径正确**：期间、截止日和指标周期不能靠表头或当前日期猜测。
2. **错误可修**：每个错误都能定位到源表位置，并说明影响了哪项判断。
3. **缺失诚实**：缺失不是 0，未校验与无近期销售也不能混为一类。
4. **重复无害**：重试或并发操作不产生第二份批次与行动清单。
5. **证据冻结**：后续建议始终能回到该批次当时采用的指标和规则输入。
6. **成功可继续**：规则完成后能直接进入该批次行动清单，不再手动生成。

## 4. 信息架构

### 4.1 区域划分

1. 页面与批次上下文区
2. 导入声明区
3. 处理阶段区
4. 批次摘要与校验汇总区
5. 分组错误与源表定位区
6. SPU 冻结指标区
7. 指标证据详情区
8. 后续行动区

### 4.2 区域内容

**1. 页面与批次上下文区**

- 新建导入模式或既有批次详情模式。
- 当前角色、事业部、批次标识和页面来源。
- 既有批次下显示数据期间、业务截止日和当前处理状态。

**2. 导入声明区**

- 事业部：玩具事业部。
- 数据期间：起始日、结束日及“上一个完整自然月”口径。
- 批次业务截止日：新品年龄与统计窗口解释的业务基准日。
- XLSX 文件选择、已选文件名和提交导入操作。
- 导入开始后，事业部、期间、截止日和文件锁定为本批次输入。

**3. 处理阶段区**

- 待提交、接收中、校验中、指标处理中、固定规则处理中、清单就绪或处理失败。
- 每一阶段说明当前正在处理什么，以及用户此时能否继续操作。
- AI 解释不属于批次成功前置条件，不影响“清单就绪”。

**4. 批次摘要与校验汇总区**

- 批次标识、事业部、数据期间、业务截止日、文件名、提交人、提交时间、规则版本。
- 识别行数、身份有效行数、拒绝行数、字段级降级行数和警告数。
- 试点规模说明：10—20 个 SPU 显示符合首轮验收规模，其他数量只提示范围差异，不判定文件无效。

**5. 分组错误与源表定位区**

- 批次级错误：期间、业务截止日、文件读取和必要结构问题。
- 身份错误：SPU ID、链接名称、店铺、平台、责任运营缺失，或 SPU ID 批次内重复。
- 经营字段警告：上架日期、销售、利润、品退、库存和近 14 天销量缺失或异常。
- 每项显示源工作表、行号、字段、原始值、错误原因、影响范围和处理结果。
- 支持按错误分组、处理状态和字段收窄结果，不改变原错误记录。

**6. SPU 冻结指标区**

- 每行一个必要身份有效的 SPU。
- 展示 SPU ID、名称、店铺、平台、责任运营、上架日期/新品状态、上一个完整自然月净销售额、经营准利润率、最近 7 天品退率、库存可售天数和数据质量状态。
- 所有值均绑定当前批次、实际期间、统计周期和质量状态。
- 缺失或不可计算时显示具体原因，不显示 0。

**7. 指标证据详情区**

- 当前 SPU 的源工作表与行号。
- 各指标原始值、采用值、统计期间、公式输入、质量状态和降级影响。
- 经营准利润率明确标注“采用源表值，不按旧公式重算”。
- 品退率和库存可售天数展示实际计算依据；不可计算时展示缺失项或异常项。

**8. 后续行动区**

- 清单就绪后提供“进入行动清单”。
- 批次失败或规则未完成时不开放行动清单入口，并说明当前阻塞原因。
- 返回数据批次列表的入口。

## 5. 界面内容

### 5.1 元素清单

**事业部字段**

- 内容：玩具事业部。
- 数据来源：V0 试点范围。
- 显示条件：新建导入时必须确认；导入开始后只读展示。

**数据期间字段**

- 内容：起始日、结束日，以及“上一个完整自然月”说明。
- 数据来源：运营根据数据支持部门经营表声明。
- 显示条件：新建导入时必填；批次建立后只读冻结。
- 首批样例：`2026-06-01` 至 `2026-06-30`，明确标识为上一个完整自然月，而非“上一周”。

**批次业务截止日字段**

- 内容：用于新品年龄和滚动周期解释的业务基准日。
- 数据来源：运营根据本批次业务口径确认。
- 显示条件：新建导入时必填；批次建立后只读冻结。

**XLSX 文件选择**

- 内容：选择文件、文件名和待提交状态。
- 数据来源：数据支持部门提供的经营表。
- 显示条件：新建导入且当前用户有导入权限。
- 限制：只接受可读取、未加密且明细结构可识别的 XLSX。

**提交导入操作**

- 文案：“导入并校验”。
- 显示条件：事业部、期间、业务截止日和 XLSX 均已提供且当前未在提交。
- 操作结果：进入处理阶段；不增加第二个“生成清单”操作。

**处理阶段说明**

- 内容：当前阶段、阶段说明、已完成阶段和失败原因。
- 数据来源：批次处理状态。
- 显示条件：提交导入后或查看既有批次详情时。

**批次摘要**

- 内容：批次标识、事业部、期间、业务截止日、文件名、提交人、提交时间、规则版本和批次状态。
- 数据来源：成功建立的不可变批次。
- 显示条件：已建立批次，包括处理中的批次。

**校验数量摘要**

- 内容：识别明细、身份有效、拒绝、字段级降级和警告数量。
- 数据来源：当前批次校验结果。
- 显示条件：校验产生结果后。

**试点规模提示**

- 文案：10—20 个 SPU 时显示“符合首轮验收规模”；其他数量显示“不属于首轮验收规模，但不会仅因数量阻断合法批次”。
- 数据来源：身份有效 SPU 数量。
- 显示条件：完成明细识别后。

**错误分组切换**

- 内容：批次级错误、身份错误、经营字段警告及对应数量。
- 数据来源：当前批次校验记录。
- 显示条件：至少存在一项错误或警告。

**错误明细行**

- 内容：源工作表、行号、SPU 标识（可识别时）、字段、原始值、原因、影响范围和处理结果。
- 数据来源：当前批次校验记录与源表定位信息。
- 显示条件：当前错误分组下存在记录。

**错误筛选**

- 内容：错误分组、处理状态和字段条件。
- 数据来源：当前批次错误记录中的受控值。
- 显示条件：存在错误或警告；筛选无结果时显示“当前条件无记录”，不表示批次无错误。

**SPU 冻结指标行**

- 内容：SPU 身份、上架日期/新品状态、月度净销售额、经营准利润率、7 天品退率、库存可售天数及数据质量。
- 数据来源：当前批次冻结的 SPU 指标快照。
- 显示条件：必要身份有效的 SPU 已完成相应指标读取或计算。

**查看指标证据操作**

- 文案：“查看证据”。
- 结果：展示该 SPU 的源表位置、原始值、采用值、期间、计算输入、质量标记和降级影响。
- 显示条件：当前用户有权查看该批次完整指标。

**进入行动清单操作**

- 文案：“进入行动清单”。
- 结果：进入 `PAGE-F05-02` 并固定为当前批次。
- 显示条件：当前批次固定规则处理完成且唯一行动清单已就绪。

### 5.2 辅助信息

- 期间说明：“销售额和经营准利润率使用本批次声明的上一个完整自然月。”
- 利润说明：“经营准利润率直接采用源表值，不按旧利润公式重算。”
- 品退说明：“仅周期可证明为最近 7 天且已销售件数大于 0 时参与计算。”
- 库存说明：“库存可售天数＝（仓内库存＋在途库存）÷最近 14 天平均日销量。”
- 缺失说明：“未提供、待补数、品退数据未校验、无可计算销量、库存数据不足、库存数据异常、无近期销售均不是 0。”
- 合计说明：“源表汇总行不参与 SPU 决策；汇总与有效明细不一致时以有效明细重新汇总并保留警告。”
- 试点说明：“10—20 个 SPU 是首轮验收规模，不是运行时硬限制。”

### 5.3 当前高保真明确呈现状态

- 视觉基线使用用户真实 `商品链接.xlsx` 经生产 API→Worker→PostgreSQL 形成的 `BATCH-20260630-4EC92F6A`：期间 `2026-06-01—2026-06-30`、业务截止日 `2026-06-30`、文件 SHA-256 `af37a29543bf5a37117985e70619bee2534190a22655359d6e005ea80058cf5f`、有效 `10`、拒绝 `0`、降级 `10`、批次警告 `1`、规则版本 `RULE-V1.0`。
- HTML 明确呈现 10 条真实 SPU 冻结指标；真实源表未提供可信最近 7 天品退与仓内/在途/最近 14 天销量，全部按“品退数据未校验 / 库存数据不足”显示，不补 `0`。两个 SPU 的上架日期原值非法，停止依赖分类的判断。
- 问题明细使用真实 `Sheet2` 行号与错误语义；HTML 只展开首屏代表记录并明确总数，完整 23 条定位记录、筛选和翻页由真实批次 API 与行为验收覆盖，不为视觉基线增造身份错误、汇总行或可计算库存。
- 生产 React 与本状态保持同一数据绑定：批次 API 驱动不可变摘要、六阶段处理轨、五项校验汇总、试点规模提示、唯一行动清单入口、问题明细和 SPU 冻结快照；处理中、失败和清单未就绪状态不显示可执行入口。

## 6. 交互流程

### 6.1 页面加载与初始化

1. 新建导入模式下，页面确认当前角色是否有导入权限；运营可填写并提交，运营主管进入既有批次时只读查看，其他无权角色不加载完整批次数据。
2. 新建导入默认显示玩具事业部，期间、业务截止日和文件等待用户确认，不从文件名、表头、上传日或当前日期猜测。
3. 既有批次详情模式下，加载批次摘要、处理阶段、校验结果和已生成的冻结指标；这些内容保持原批次语义，不使用新文件覆盖。
4. 错误分组默认显示各组数量；SPU 指标只展示必要身份有效行。
5. 清单已就绪时开放当前批次行动清单入口；处理中或失败时显示具体阶段与阻塞原因。
6. 页面加载失败不显示为空批次，也不把未完成处理标为成功。

### 6.2 核心操作流程

```text
运营进入新建导入
    │
    ├─ 确认玩具事业部
    ├─ 声明上一个完整自然月期间
    ├─ 声明批次业务截止日
    └─ 选择 XLSX 文件
            │
            ▼
       提交“导入并校验”
            │
            ├─ 批次级输入非法
            │      └─ 原位显示期间、截止日或文件错误，不发布清单
            │
            └─ 输入可接收
                   │
                   ├─ 与既有批次输入相同
                   │      └─ 返回原批次、原处理状态与原清单
                   │
                   └─ 新输入
                          │
                          ├─ 建立并冻结批次摘要
                          ├─ 忽略汇总行，识别 SPU 明细
                          ├─ 校验必要身份与经营字段
                          ├─ 冻结可用 SPU 指标和质量状态
                          └─ 对可判定 SPU 自动进入固定规则处理
                                   │
                         ┌─────────┴─────────┐
                         │                   │
                    处理失败             清单就绪
                         │                   │
                  显示失败原因       进入当前批次唯一行动清单
```

字段处理顺序：

1. 先识别源表明细，忽略合计或汇总行。
2. 必要身份字段为 SPU ID、链接名称、店铺、平台和责任运营；任一缺失或 SPU ID 在批次内重复时，拒绝对应行。
3. 上架日期、净销售额、经营准利润率、品退、仓内库存、在途库存或最近 14 天销量异常时，保留 SPU 身份，仅停止依赖该字段的分类、动作或补货判断。
4. 对仍可计算的指标保存原始值、采用值、期间、公式输入和质量状态。
5. 固定规则处理完成后形成该批次唯一清单，无需用户再次触发生成。

### 6.3 辅助操作

- 错误分组支持按分组、处理状态和字段筛选；选择某条记录后查看源表位置和影响范围。
- SPU 指标支持查看证据详情；关闭详情后仍回到原批次与原列表位置。
- 处理中的页面可重新获取当前状态，但不能用刷新动作建立第二批次。
- 重复提交相同输入时直接进入既有批次详情，显示“已存在相同批次，本次未重复创建”。
- 批次清单就绪后选择“进入行动清单”；从清单返回时恢复当前批次详情。
- 离开尚未提交的导入表单前提示用户存在未提交内容；短表单不自动保存草稿。

## 7. 状态与边界

### 7.1 页面状态全景

| 状态 | 触发条件 | 页面表现 |
| :--- | :--- | :--- |
| 初始态 | 运营首次进入新建导入 | 显示事业部、期间、业务截止日和 XLSX 字段，提交操作尚不可用 |
| 填写态 | 用户正在确认期间、截止日或文件 | 保留已填内容并进行可修正校验；未提交前不建立批次 |
| 提交态 | 用户提交完整输入 | 锁定事业部、期间、截止日和文件，进入接收与校验阶段，防止重复提交 |
| 校验中 | 文件已接收，正在识别明细和校验字段 | 显示当前阶段；不提前展示成功清单或伪造指标 |
| 指标与规则处理中 | 校验已有结果，正在冻结指标或执行固定规则 | 可查看已完成的校验摘要；行动清单入口不可用 |
| 清单就绪态 | 固定规则结果与该批次唯一清单已建立 | 显示冻结指标、质量状态和“进入行动清单” |
| 批次级失败态 | 期间、截止日、文件或批次必要结构不合法 | 显示明确原因；不发布依赖该输入的行动清单 |
| 部分降级态 | 至少一条 SPU 身份有效，但部分经营字段缺失或异常 | 显示有效、拒绝、降级和警告数量；仍处理不受影响的判断 |
| 无有效 SPU 态 | 所有明细都因必要身份问题被拒绝 | 显示无可处理 SPU 及逐行原因，不生成清单 |
| 幂等返回态 | 相同输入已建立批次 | 返回原批次、原状态和原清单，不产生新记录 |
| 加载异常态 | 既有批次详情或处理状态暂时无法加载 | 明确加载失败并允许重试，不显示空批次或 0 指标 |
| 无权限态 | 当前角色无权导入或查看完整批次 | 不展示文件内容、错误原值或完整经营指标，进入权限恢复 |

### 7.2 边界与容错

| 边界场景 | 处理策略 |
| :--- | :--- |
| 网络中断 | 未确认成功前不显示批次建立成功；用户重试时按同一输入返回原批次或继续既有状态，不重复创建 |
| 会话过期 | 停止提交与完整数据展示，进入认证恢复；重新认证后回到已建立批次详情，未建立批次则要求重新确认表单 |
| 连续文件或字段错误 | 每次保留具体错误与源表定位，不自动猜测字段、不自行放宽规则，也不把异常值转为 0 |
| 期间缺失、起止顺序非法或不是完整自然月 | 显示批次级期间错误，不发布依赖该期间的行动清单 |
| 业务截止日非法或早于数据期间结束日 | 阻止建立可用于规则处理的批次，并提示重新确认业务截止日 |
| 文件损坏、加密、非 XLSX 或明细结构不可识别 | 显示文件级原因，不生成清单；允许更换文件重新提交 |
| 重复点击、网络重试或多窗口并发提交 | 相同输入只接受第一次成功建立的批次，其他请求返回相同批次与既有状态 |
| SPU ID 缺失或批次内重复 | 拒绝所有受影响行并显示原始位置；其他有效行继续 |
| 链接名称、店铺、平台或责任运营缺失 | 拒绝对应行，避免生成对象或责任不完整的建议 |
| 上架日期、销售、利润、品退或库存异常 | 保留必要身份有效行，仅停止依赖字段的分类、动作或补货判断 |
| 品退分母为 0 或周期未经校验 | 显示“无可计算销量”或“品退数据未校验”，不计算为 0%，不触发观察或依赖低品退率的加投 |
| 库存字段缺失、为负或近 14 天日均销量为 0 | 分别显示“库存数据不足”“库存数据异常”或“无近期销售”，不生成补货/不补货判断 |
| 源表合计与有效明细不一致 | 忽略合计，以有效明细重新汇总并保留警告，不分摊差额 |
| 有效 SPU 数量不在 10—20 | 仅提示不属于首轮验收规模，不因数量本身拒绝合法批次 |
| 新批次数据与历史不同 | 建立新的独立批次；历史冻结指标、校验记录和清单不被覆盖 |

## 8. 业务规则与校验

### 8.1 字段定义

| 字段 | 说明 |
| :--- | :--- |
| `business_unit` | 事业部；V0 试点为玩具事业部 |
| `period_start` / `period_end` | 本批次使用的上一个完整自然月起止日 |
| `business_cutoff_date` | 新品年龄与统计窗口解释的不可变业务基准日 |
| `xlsx_file` | 数据支持部门提供的可读取经营表 |
| `batch_id` | 成功建立后唯一识别本批次的标识 |
| `batch_status` | 待提交、接收、校验、指标处理、固定规则处理、清单就绪或失败 |
| `source_sheet` / `source_row` | 错误或指标在源工作表中的位置 |
| `spu_id` / `spu_name` | SPU 的必要身份；SPU 等同商品链接，不是 SKU |
| `store` / `platform` / `operator_ref` | 店铺、平台与责任运营，均为必要身份字段 |
| `launch_date` | 上架日期；用于基于批次业务截止日判断新品 |
| `net_sales_prev_month` | 扣除退款后的上一个完整自然月净销售额 |
| `operating_profit_rate` | 直接采用源表“经营准利润率”的值 |
| `quality_return_count_7d` / `sold_units_7d` | 最近 7 天品退件数和已销售件数 |
| `quality_return_rate_7d` | 最近 7 天品退件数除以已销售件数；仅周期与分母有效时存在 |
| `warehouse_qty` / `in_transit_qty` | 仓内库存和在途库存 |
| `sales_units_14d` / `average_daily_sales_14d` | 最近 14 天销量及平均日销量 |
| `inventory_days` | （仓内库存＋在途库存）÷最近 14 天平均日销量 |
| `data_quality_status` | 有效、拒绝、待补数、未校验、数据不足、数据异常或无近期销售等受控状态 |
| `rule_version` | 处理当前批次时使用并随结果固化的固定规则版本 |

### 8.2 校验规则

| 校验项 | 时机 | 规则 | 失败反馈 |
| :--- | :--- | :--- | :--- |
| 事业部 | 提交时 | 必须明确为当前试点事业部 | “请选择事业部” |
| 数据期间 | 失焦及提交时 | 起止日完整、顺序合法，且能解释为本批次使用的完整自然月 | “请选择完整自然月的数据期间”或对应日期错误 |
| 业务截止日 | 失焦及提交时 | 日期合法且不得早于数据期间结束日 | “请确认不早于数据期间结束日的业务截止日” |
| XLSX 文件 | 选择及提交时 | 文件可读取、未加密、类型为 XLSX，明细结构可识别 | 显示文件不可读取、已加密、类型不支持或结构无法识别 |
| 批次重复 | 接收输入时 | 相同事业部、期间、截止日和文件内容只对应原批次 | “已存在相同批次，本次未重复创建” |
| 汇总行 | 识别明细时 | 合计或汇总行不得作为 SPU 参与计算 | “已忽略源表汇总行；批次汇总以有效明细为准” |
| 必要身份 | 行校验时 | SPU ID、名称、店铺、平台、责任运营均不可缺失 | 显示字段、源表行号、原始值及“该行不进入计算” |
| SPU ID 唯一性 | 行校验时 | SPU ID 在当前批次内必须唯一 | 显示所有冲突行位置及“重复 SPU 行均被拒绝” |
| 月度净销售额 | 指标读取时 | 值须可解析并绑定本批次完整自然月 | “销售数据待补数”或“销售数据异常”；不得补 0 |
| 经营准利润率 | 指标读取时 | 值须可解析并直接采用源表口径 | “利润数据待补数”或“利润数据异常”；不得用旧公式重算 |
| 最近 7 天品退率 | 指标计算时 | 周期、分子、分母有效且已销售件数大于 0 | “品退数据未校验”或“无可计算销量” |
| 库存可售天数 | 指标计算时 | 库存、在途、最近 14 天销量均有效且平均日销量大于 0 | “库存数据不足”“库存数据异常”或“无近期销售” |

### 8.3 特殊业务规则

- **批次指纹幂等**：同一事业部、期间、业务截止日和文件内容重复提交时，返回原批次、原清单和原状态链。
- **批次不可变**：批次建立后，事业部、期间、业务截止日、源文件身份和已固化指标不得被后续数据覆盖。
- **行拒绝最小化**：只有必要身份缺失或 SPU ID 重复时拒绝整行；其他字段按依赖降级。
- **缺失不等于零**：任何缺失、异常、未校验或不可计算状态都必须保留具体语义，不得用 0 参与规则。
- **利润口径**：经营准利润率采用源表值，不按旧公式重算。
- **品退口径**：最近 7 天品退件数÷已销售件数；分母为 0 或周期未校验时不计算。
- **库存口径**：库存可售天数＝（仓内库存＋在途库存）÷最近 14 天平均日销量；平均日销量为 0 时显示无近期销售。
- **汇总行排除**：源表合计不参与 SPU 决策，批次汇总只使用必要身份有效明细。
- **试点规模非硬限制**：10—20 个 SPU 只用于首轮验收提示，不作为批次合法性条件。
- **确定性**：同一冻结数据快照和同一规则版本被重复处理时，指标质量状态及后续分类、经营动作和库存动作必须一致。
- **清单唯一**：一个批次固定规则处理完成后只对应一份行动清单；AI 解释状态不影响清单就绪。

### 9.2 与其他模块的关系

- 与数据批次列表的关系：`PAGE-F01-01` 提供新建入口和历史批次定位；本页负责一次导入声明、处理状态、校验详情和冻结指标。
- 与指标模块的关系：本页提供批次级 SPU 指标总表和证据详情；建议详情引用同一冻结快照，不建立另一套指标事实。
- 与固定规则的关系：可用指标和质量状态完成后自动进入固定规则处理；页面不允许用户手工改写指标或规则结果。
- 与行动清单的关系：同一批次只形成一份清单；清单就绪后本页进入 `PAGE-F05-02` 并固定当前批次。
- 与建议追溯的关系：后续建议必须保留本批次、期间、业务截止日、规则版本、原始关键值和生成时间。
- 与权限的关系：运营可导入并查看完整结果，运营主管可只读复核完整批次；其他无权角色不得通过直接地址获取文件、错误原值或完整经营指标。

### 9.3 扩展预案

| 扩展方向 | 触发条件 | 改造点 |
| :--- | :--- | :--- |
| 新数据源类型 | PRD 新增稳定 REQ/AC，并明确数据责任、字段版本和验收标准 | 在不改变历史批次身份与快照的前提下增加来源类型；当前不预置 CSV 或在线表格入口 |
| 新经营证据类型 | PRD 确认评价、退款原因或广告明细数据粒度与责任人 | 以版本化证据扩展 SPU 快照，不覆盖既有批次字段或历史建议 |
| SKU 级数据 | PRD 重新立项并明确 SPU—SKU 关系与费用分摊规则 | 将 SKU 作为 SPU 下级对象扩展，不改变历史 SPU 主键与快照 |
| 批次更正流程 | PRD 明确更正权限、原因、验收和历史关联 | 新建独立修正批次并关联前序批次，不覆盖原批次 |

## 10. 数据需求

### 10.1 页面需要什么数据

| 数据 | 来源 | 用途 |
| :--- | :--- | :--- |
| 当前用户角色与身份 | 已认证的内部身份 | 决定是否可导入或只读查看，并记录提交人 |
| 事业部 | V0 业务范围 | 建立批次归属 |
| 数据期间与业务截止日 | 运营声明的批次上下文 | 解释上一个完整自然月、新品年龄和滚动周期 |
| XLSX 文件名与可读取内容 | 数据支持部门经营表 | 识别 SPU 明细与经营字段；页面只显示文件名，不显示本地绝对路径 |
| 批次标识、状态、提交人和时间 | 当前批次 | 展示处理进度并支持追溯 |
| 源工作表、行号、字段和原始值 | 当前批次校验记录 | 定位批次、身份和经营字段问题 |
| 有效、拒绝、降级和警告数量 | 当前批次校验结果 | 汇总本次数据质量与处理影响 |
| SPU 身份与经营指标 | 当前批次冻结快照 | 展示月度、7 天、14 天指标及质量状态 |
| 规则版本与清单状态 | 当前批次规则结果 | 判断是否可进入唯一行动清单，并支持确定性追溯 |

### 10.2 页面提交什么数据

| 数据 | 触发时机 | 用途 |
| :--- | :--- | :--- |
| `business_unit` | 提交导入时 | 声明批次事业部归属 |
| `period_start` / `period_end` | 提交导入时 | 声明本批次使用的完整自然月 |
| `business_cutoff_date` | 提交导入时 | 固化新品判断和统计周期解释基准 |
| `xlsx_file` | 提交导入时 | 提供本批次 SPU 经营事实 |
| 当前批次上下文 | 选择“进入行动清单”时 | 打开该批次唯一行动清单 |

页面不提交用户编辑后的指标、默认补值、手工分类或手工经营动作；这些结果只能由已确认数据口径和固定规则产生。

### 10.3 明确排除的数据

- 不需要 SKU、SKU 映射、SKU 利润分摊或 SKU 库存数据。
- 不需要评价文本、退款/退货原因、广告计划、广告单元、关键词或素材明细。
- 不需要账号密码、消费者姓名、手机号、地址或评价者身份。
- 不需要 LiteLLM 部署密钥、网关地址或模型配置。
- 不需要用户填写旧利润公式的成本项来重算经营准利润率。
- 不需要把源表合计值分摊到 SPU，也不需要为缺失指标生成默认 0。

## 11. 验收标准

### 11.1 功能验收

| 编号 | 验收点 | 通过标准 |
| :--- | :--- | :--- |
| F-01 | 合法批次导入 | 运营选择玩具事业部、合法完整自然月、合法业务截止日和可读 XLSX 后，页面建立批次并显示批次摘要与处理阶段 |
| F-02 | 首批期间口径 | 首批样例显示 `2026-06-01` 至 `2026-06-30` 并标识“上一个完整自然月”，不显示为“上一周” |
| F-03 | 重复提交幂等 | 相同输入因重复点击、网络重试或并发提交再次到达时，返回第一次成功建立的批次及既有清单状态，不新增批次、建议或状态事件 |
| F-04 | 批次级期间错误 | 期间缺失、顺序非法或不是完整自然月时，页面显示批次级错误且不发布依赖该期间的行动清单 |
| F-05 | 必要身份拒绝 | SPU ID、名称、店铺、平台或责任运营缺失，或 SPU ID 重复时，对应行不进入计算并显示源表定位与原因 |
| F-06 | 字段级降级 | 上架日期、销售、利润、品退或库存异常时，只停止依赖字段的分类、动作或补货判断，其他仍可判定结果继续处理 |
| F-07 | 月度指标展示 | 有效净销售额按扣除退款后的上一个完整自然月展示，经营准利润率明确采用源表值且不按旧公式重算 |
| F-08 | 品退指标展示 | 最近 7 天品退分子、分母和周期有效且分母大于 0 时，显示品退率及周期；否则显示未校验或无可计算销量 |
| F-09 | 库存指标展示 | 库存、在途和最近 14 天销量有效且平均日销量大于 0 时显示库存可售天数及周期；否则显示对应缺失或异常状态 |
| F-10 | 汇总行排除 | 源表汇总行不参与 SPU 决策；合计与明细不一致时，以有效明细重新汇总并保留警告 |
| F-11 | 冻结指标追溯 | 任一 SPU 指标证据可显示批次、期间、截止日、源表位置、原始值、采用值、质量状态和规则版本，后续批次不覆盖这些内容 |
| F-12 | 唯一清单流转 | 固定规则处理完成后开放“进入行动清单”，并进入与当前批次一一对应的 `PAGE-F05-02` |

### 11.2 体验验收

| 编号 | 验收点 | 通过标准 |
| :--- | :--- | :--- |
| U-01 | 填写目标清楚 | 新建导入时，运营能明确看到事业部、完整自然月、业务截止日和 XLSX 四类必需输入及其业务含义 |
| U-02 | 处理进度可理解 | 提交后能区分接收、校验、指标处理、固定规则处理、清单就绪和失败，不把处理中显示为空白或成功 |
| U-03 | 错误定位完整 | 每条行级错误能直接看到源工作表、行号、字段、原始值、原因、影响范围和处理结果 |
| U-04 | 分组便于修正 | 用户能按批次级错误、身份错误和经营字段警告查看问题，并按状态或字段收窄结果 |
| U-05 | 缺失语义明确 | 页面分别显示待补数、品退未校验、无可计算销量、库存不足、库存异常和无近期销售，任何一种都不显示为 0 |
| U-06 | 重复操作可预期 | 命中既有批次时明确告知未重复创建，并进入原批次详情而不是显示不明失败 |
| U-07 | 试点规模不误阻断 | 有效 SPU 数量不在 10—20 时只显示规模提示，用户仍可继续查看合法批次结果 |
| U-08 | 成功路径连续 | 清单就绪后无需再次生成，用户能从本页直接进入当前批次行动清单 |
| U-09 | 返回上下文保持 | 从行动清单返回时仍显示原批次、原错误条件和原指标查看位置 |

### 11.3 安全验收（产品层）

| 编号 | 验收点 | 通过标准 |
| :--- | :--- | :--- |
| S-01 | 导入权限 | 只有运营可以提交事业部、期间、业务截止日和 XLSX 建立批次；运营主管只读查看，其他角色无导入入口 |
| S-02 | 直接地址访问 | 无权角色直接访问本页时，不返回文件内容、错误原值、完整 SPU 指标或行动清单身份 |
| S-03 | 批次数据隔离 | 页面展示和提交始终绑定当前批次；新批次不能覆盖或混入历史批次的冻结指标、校验结果和清单状态 |
| S-04 | 错误信息最小化 | 错误明细只展示定位当前批次问题所需的源表位置、字段和原始值，不展示本地绝对文件路径或无关敏感内容 |
| S-05 | 不接受业务篡改 | 页面不提供手工修改冻结指标、质量状态、商品分类、规则版本或行动结论的入口 |
| S-06 | 会话与角色失效 | 会话失效或角色变化后，页面停止提交和完整数据展示，并进入统一认证或权限恢复流程 |
| S-07 | 缺失值保护 | 页面和后续处理不得把缺失、异常、未校验或不可计算值转换为 0 后参与规则 |
| S-08 | 审计完整 | 成功建立的批次必须保留事业部、期间、业务截止日、文件名、提交人、提交时间和规则版本；缺少这些追溯信息时不得显示为清单就绪 |
