## 2. 页面概述

### 2.1 一句话定位

主管工作台是运营主管进入产品后的审核与完成事实总览：以最新成功批次为上下文，集中呈现待审核建议、待确认清仓完成时间、动作风险、异常与冲突，并引导主管进入详情逐条审核或确认/退回完成时间。

### 2.2 存在理由

1. 没有统一的主管工作台，主管需要在完整行动清单中反复筛选待审核建议，容易遗漏高优先级的清仓或止损问题。
2. 如果不固定展示当前批次、业务期间和业务截止日，主管可能把历史建议当成本周建议审核。
3. 如果把异常、状态冲突和普通“无待办”混为一类，主管可能误以为本周已处理完成，实际却是批次仍在处理或数据加载失败。
4. 如果在工作台直接快速或批量审核，主管可能在未查看完整经营依据的情况下拍板，并增加重复审核与状态冲突风险。

### 2.3 页面目标（可衡量）

| 目标维度 | 具体指标 |
| :--- | :--- |
| 批次明确 | 页面 100% 显示当前事业部、最新成功批次、业务期间、业务截止日和最后更新时间 |
| 待办准确 | 待审核列表中 100% 为当前批次、建议级审核状态为“待审核”的建议 |
| 风险对账 | 清仓、止损、观察、加投四类风险数量按建议主动作统计，合计与当前批次待审核建议总数一致 |
| 排序稳定 | 待审核建议 100% 先按清仓、止损、观察、加投、补货层级排序，同层使用规则明确的代理指标或稳定 SPU 次序 |
| 审核完整 | 工作台中直接通过、驳回或批量审核入口数量为 0；每条待审核建议均进入详情后整体审核 |
| 状态可辨 | 无待审核、规则处理中、加载失败、无权限和状态冲突均有独立可识别结果，不互相伪装 |

### 2.4 不做什么（范围边界）

- **不做首页快速审核或批量审核**：主管必须进入建议详情查看完整经营信息后，才能对整条建议执行一次通过或驳回。
- **不做动作拆分审核**：经营动作和补货/禁补动作属于同一建议，只能共享一个建议级审核结果。
- **不代运营执行或对接外部相关人员**：责任运营负责经营动作、库存/钉钉协同与状态回填；主管负责建议审核及清仓完成事实确认。
- **不做自由排序或 AI 排序**：首页沿用固定动作优先级和稳定次序，避免排序改变业务判断。
- **不做跨批次趋势分析**：本页聚焦最新成功批次；历史复核进入历史与追溯页面。
- **不做数据导入**：主管可查看批次上下文，但经营表导入由运营在数据批次模块完成。

## 3. 用户与场景

### 3.1 目标用户

| 维度 | 描述 |
| :--- | :--- |
| 角色 | 运营主管 |
| 人数 | 单次由一名运营主管使用；可能存在多名主管先后或并发查看同一待审核建议 |
| 技术熟练度 | 中等，熟悉商品经营指标、固定规则和建议审核流程 |
| 使用设备 | 宽度不低于 1024px 的办公电脑 |
| 使用姿势 | 每周新批次生成后集中审核，周内持续查看剩余待办、冲突提醒和最近审核结果 |

### 3.2 核心使用场景

**场景 A：处理最新批次待审核建议（主场景）**

- 时机：每周新数据完成固定规则决策并形成可审核清单后。
- 前置条件：当前用户为运营主管；存在最新成功批次和待审核建议。
- 用户动作：确认批次与期间 → 查看风险分布和待审核列表 → 按固定优先级打开某条建议详情 → 阅读完整依据并审核。
- 用户情绪：聚焦、可控，先处理风险最高的问题。

**场景 B：复核最近审核结果（主场景）**

- 时机：主管审核过部分建议后，需要确认哪些建议已经通过或驳回。
- 前置条件：当前批次存在已完成的建议级审核记录。
- 用户动作：查看最近审核记录 → 核对结果、审核人和时间 → 按需打开对应建议详情复核原始依据与备注。
- 用户情绪：确定、可追溯，避免重复处理。

**场景 C：当前批次没有待审核建议（兜底场景）**

- 时机：当前批次所有建议均已处理，或当前批次没有需要审核的建议。
- 前置条件：批次已完成固定规则处理且待审核数量为 0。
- 用户动作：查看“本批次待审核已处理完成”的说明和最近审核记录；按需进入行动清单或历史与追溯。
- 用户情绪：安心，能够确认是确无待办而非加载失败。

**场景 D：处理状态冲突或异常提醒（兜底场景）**

- 时机：主管此前打开的建议已被他人审核、最新批次仍在规则处理中，或工作台数据加载异常。
- 前置条件：存在受控冲突或异常状态。
- 用户动作：阅读影响范围与最新状态 → 刷新当前上下文或进入对应详情核对；网络异常时重试。
- 用户情绪：不慌乱，能够区分业务已变化与系统暂不可用。

### 3.3 用户核心诉求（优先级排序）

1. **不漏高风险建议**：清仓和止损优先，风险数量与待审核列表能够对账。
2. **不审错批次**：始终知道当前事业部、批次、期间、截止日和更新时间。
3. **证据完整**：从工作台进入建议详情后再拍板，不被摘要替代完整经营依据。
4. **状态可信**：已处理、处理中、失败和冲突必须明确区分。
5. **审核可追溯**：能快速看到最近由谁、何时通过或驳回了哪条建议。

## 4. 信息架构

### 4.1 区域划分

1. 当前身份与业务上下文区
2. 审核待办摘要区
3. 清仓完成时间确认区
4. 动作风险分布区
5. 异常与冲突提醒区
6. 待审核建议区
7. 最近审核/完成确认记录区
8. 任务去向区

### 4.2 区域内容

**1. 当前身份与业务上下文区**

- 当前角色：运营主管。
- 当前事业部：玩具事业部。
- 最新成功批次、业务期间、业务截止日、规则版本和最后更新时间。
- 若已有更新批次仍在处理，明确说明当前展示仍对应哪个成功批次。

**2. 审核待办摘要区**

- 当前批次待审核建议总数。
- 当前批次已通过、已驳回数量，用于区分剩余待办和已处理结果。
- 进入当前批次全部待审核建议的入口。

**3. 清仓完成时间确认区**

- 展示责任运营已提交、等待主管确认的实际清仓完成时间。
- 每项显示 SPU、稳定任务、责任运营、提交时间、实际完成时间、最近 OA 催办和跨周续接状态。
- 进入建议详情确认，或填写退回原因要求责任运营修正；工作台不提供批量确认。

**3. 动作风险分布区**

- 按唯一经营主动作统计的清仓、止损、观察、加投待审核数量。
- 每类数量进入行动清单并带入当前批次、待审核状态和对应动作条件。
- 同一建议只按唯一主动作计入一个风险分组；补货或禁补作为建议内库存动作，不重复计入主动作分布。

**4. 异常与冲突提醒区**

- 最新批次仍在规则处理中、工作台加载失败、待审核状态已变化等提醒。
- 每条提醒说明影响对象范围、当前状态和可执行恢复动作。
- 不把异常计入“本批次无待审核”。

**5. 待审核建议区**

- 当前批次待审核建议列表。
- 每条显示 SPU 身份、主动作、库存动作、关键依据摘要、责任运营、生成时间和审核状态。
- 按清仓、止损、观察、加投、补货固定层级及稳定次序排列。
- 每条只提供“查看并审核”入口，审核操作位于建议详情。

**6. 最近审核记录区**

- 最近完成的通过或驳回记录。
- 每条显示 SPU、审核结果、审核人、审核时间和备注摘要。
- 可进入对应建议详情复核完整依据和审核记录。

**7. 任务去向区**

- 行动中心：查看当前批次全部建议或带条件的待审核清单。
- 数据批次：查看批次处理与数据上下文，不提供主管导入操作。
- 历史与追溯：查看历史批次建议与审核记录。

## 5. 界面内容

### 5.1 元素清单

**当前批次摘要**

- 内容：事业部、批次标识、业务期间、业务截止日、规则版本、最后更新时间。
- 数据来源：最新成功批次及其固化上下文。
- 显示条件：存在最新成功批次时显示；无成功批次时改为对应空状态。

**待审核总数**

- 文案：“待审核建议”。
- 内容：当前批次建议级审核状态为“待审核”的建议数量。
- 数据来源：当前批次行动清单。
- 显示条件：批次已具备可审核清单时显示实际数量，包括 0。

**已通过与已驳回数量**

- 内容：当前批次已经完成的两类建议级审核结果数量。
- 数据来源：当前批次审核状态。
- 显示条件：批次已具备可审核清单时显示。

**动作风险分布**

- 内容：清仓、止损、观察、加投四类待审核建议数量。
- 数据来源：当前批次待审核建议的唯一主动作。
- 显示条件：批次已具备可审核清单时显示；数量为 0 的分组仍保持可识别。

**异常与冲突提醒**

- 内容：提醒类型、影响范围、当前状态、发生或发现时间、推荐恢复动作。
- 文案示例：“新批次规则处理中，当前仍展示上一成功批次”“建议状态已变化，请刷新后查看最新结果”“工作台加载失败，请重试”。
- 数据来源：批次处理状态、页面加载结果和审核状态变化。
- 显示条件：存在对应异常或冲突时显示；无异常时不制造提醒。

**待审核建议行**

- 内容：SPU ID、SPU 名称、店铺、责任运营、唯一主动作、补货/禁补动作、关键依据摘要、生成时间、审核状态。
- 数据来源：当前批次待审核建议及固定规则结果。
- 显示条件：当前批次存在待审核建议。

**查看并审核入口**

- 文案：“查看并审核”。
- 数据来源：当前建议身份与审核状态。
- 显示条件：当前用户仍为运营主管且建议仍为待审核；状态变化后改为“查看详情”。

**查看全部待审核入口**

- 文案：“查看全部待审核”。
- 结果：进入 `PAGE-F05-02`，保留当前批次与待审核条件。
- 显示条件：批次已具备可审核清单。

**最近审核记录**

- 内容：SPU ID/名称、审核结果、审核人、审核时间、备注摘要。
- 数据来源：已完成的建议级审核记录。
- 显示条件：存在已通过或已驳回记录；没有记录时显示独立空状态。

**查看历史与追溯入口**

- 文案：“查看历史与追溯”。
- 结果：进入 `PAGE-F08-01`。
- 显示条件：运营主管已认证且角色有效。

### 5.2 辅助信息

## 6. 交互流程

### 6.1 页面加载与初始化

1. 用户进入页面后，系统确认当前登录角色仍为运营主管；不满足时不加载主管经营信息并进入认证或权限恢复流程。
2. 获取最新成功批次，并同时识别是否有更新批次处于校验或规则处理中。
3. 使用同一当前批次汇总待审核、已通过、已驳回数量，生成动作风险分布、待审核建议和最近审核记录。
4. 待审核建议按清仓、止损、观察、加投、补货的固定层级排列；同一层级按规则版本指定且已校验的影响代理指标排序，无法使用代理时采用稳定 SPU ID 或批次内稳定序号。
5. 批次处理中、加载失败和状态冲突分别进入对应状态，不显示为“无待审核”。
6. 页面初始化只展示审核任务摘要，不在本页提交审核结果。

### 6.2 核心操作流程

```text
运营主管进入工作台
        │
        ├─ 无最新成功批次 → 显示尚无可审核批次及数据批次去向
        │
        └─ 存在最新成功批次
                │
                ├─ 新批次仍在规则处理中
                │      └─ 明确提示当前展示仍对应上一成功批次
                │
                └─ 加载当前批次审核汇总
                        │
                        ├─ 待审核数量为 0
                        │      └─ 显示本批次已处理完成及最近审核记录
                        │
                        └─ 存在待审核建议
                               │
                               ├─ 查看动作风险分布或固定排序列表
                               ├─ 选择一条建议“查看并审核”
                               ▼
                        PAGE-F06-03 建议详情页
                               │
                               ├─ 通过整条建议
                               └─ 填写驳回原因并驳回整条建议
                                      │
                                      ▼
                         返回工作台后更新待办、分布和最近审核
```

通过与驳回的业务结果：

- 通过：整条建议只形成一次“已通过”结果，并同时激活经营动作与补货/禁补协同动作，均进入责任运营待执行/待协同。
- 驳回：驳回原因必须非空；整条建议进入“已驳回”，不激活动作执行任务，原始规则、数据与动作结论继续保留。

### 6.3 辅助操作

- 选择某一动作风险分组后进入 `PAGE-F05-02`，查看当前批次、待审核且匹配该主动作的建议。
- 选择“查看全部待审核”进入当前批次行动清单，并保留待审核条件。
- 选择最近审核记录进入 `PAGE-F06-03` 查看已完成审核的建议，不再次开放审核操作。
- 选择“查看历史与追溯”进入 `PAGE-F08-01`，复核其他批次的审核记录。
- 加载失败时可在原区域重试；重试期间保留明确的当前批次上下文，不把失败结果改为空状态。

## 7. 状态与边界

### 7.1 页面状态全景

| 状态 | 触发条件 | 页面表现 |
| :--- | :--- | :--- |
| 初始加载态 | 首次进入主管工作台 | 显示正在获取当前批次与审核任务，不提前显示 0 条待审核 |
| 正常待办态 | 当前批次可审核且存在待审核建议 | 显示批次上下文、待办摘要、风险分布、固定排序列表、提醒和最近审核 |
| 本批次已处理态 | 当前批次可审核、加载成功且待审核数量为 0 | 显示“本批次待审核已处理完成”，保留已通过/已驳回统计和最近审核 |
| 首次无批次态 | 尚无成功批次 | 显示“尚无可审核批次”及数据批次去向，不显示伪造的风险数量 |
| 新批次处理态 | 有更新批次仍在校验或规则处理中 | 明确处理状态；如存在上一成功批次，清楚标识当前展示仍属于上一批次 |
| 加载失败态 | 当前批次、建议或审核记录加载失败 | 显示失败范围和重试入口，不显示“无待审核” |
| 冲突提醒态 | 页面中的建议已被其他主管审核或状态已变化 | 显示最新审核状态、操作者和时间；原“查看并审核”改为“查看详情” |
| 会话失效态 | 登录态失效 | 不继续展示经营数据，进入认证恢复流程 |
| 角色失效态 | 当前用户不再是运营主管或无有效角色 | 拒绝主管工作台访问，不保留审核入口或主管数据 |
| 受限设备态 | 访问宽度低于 1024px | 显示“请使用电脑访问”，不允许在信息可能不完整时进入审核流程 |

### 7.2 边界与容错

| 边界场景 | 处理策略 |
| :--- | :--- |
| 网络中断或局部加载失败 | 标明失败区域和当前批次，提供重试；不得把缺失数据解释为 0 条待审核 |
| 会话过期 | 立即停止展示主管经营信息，进入认证恢复；重新认证成功且仍有主管权限后返回本页 |
| 连续加载失败 | 保持明确失败状态和重试入口，不自行声称本周已处理完成；持续失败时按统一恢复指引处理 |
| 当前批次上下文缺失或不可识别 | 不混用其他批次数量；显示当前上下文不可用，并引导查看数据批次状态 |
| 两名主管并发处理同一建议 | 已成功的首个审核结果保留；本页收到状态变化后显示最新结果、操作者和时间，不继续提供审核入口 |
| 页面停留期间产生新成功批次 | 显示“已有新批次”并要求主管切换后再处理；当前列表继续明确标注原批次，禁止静默混合 |
| 风险分布与待审核列表来源时点不同 | 不展示无法对账的组合；统一刷新到同一批次和更新时间后再显示完整汇总 |
| 重复点击“查看并审核” | 只进入同一建议详情，不创建审核结果；实际审核仍需在详情确认 |
| 建议已被驳回或通过但旧列表仍显示待审核 | 进入前重新确认当前状态；改为只读详情，不开放第二次审核 |
| 无待审核但存在处理异常 | 优先展示异常，不出现“本批次已处理完成”结论 |
| 低于 1024px 的设备 | 提示使用电脑，不让金额、阈值、动作或状态可能被截断后继续审核 |

### 8.2 校验规则

| 校验项 | 时机 | 规则 | 失败反馈 |
| :--- | :--- | :--- | :--- |
| 当前角色 | 页面加载及每次进入详情前 | 仅有效运营主管角色可访问本页和审核入口 | “当前身份无权访问主管工作台”并进入权限恢复 |
| 当前批次 | 汇总审核任务前 | 所有数量、分布、列表和最近记录必须明确归属于同一当前批次 | “当前批次上下文不可用，请查看数据批次状态” |
| 待审核状态 | 展示“查看并审核”前 | 建议当前审核状态必须为待审核 | 状态已变化时显示最新结果并改为“查看详情” |
| 风险分布对账 | 汇总展示前 | 四类主动作数量合计必须等于当前批次待审核建议总数 | 暂不展示不一致汇总，提示刷新当前批次数据 |
| 固定排序 | 列表生成时 | 先按清仓、止损、观察、加投、补货层级；同层使用规则明确代理或稳定 SPU 次序 | 不允许 AI 或自由排序替代固定顺序 |
| 整体审核 | 进入审核详情时 | 一个建议只能整体通过或整体驳回，不能拆分主动作与库存动作 | “该建议需整体审核，请查看完整建议” |
| 驳回原因 | 建议详情提交驳回时 | 驳回备注必须非空 | “请填写驳回原因” |
| 通过备注 | 建议详情提交通过时 | 备注可选 | 无必填失败提示 |

### 8.3 特殊业务规则

- **最新成功批次优先**：工作台默认使用最新成功批次；更新批次仍在处理时，不用未完成数据替换已成功批次。
- **固定风险层级**：待审核建议按清仓、止损、观察、加投、补货排列；AI 不能改变层级或同层稳定次序。
- **建议只计一次**：风险分布按唯一主动作统计；同一建议即使还包含补货或禁补，也不重复计入主动作数量。
- **整体审核**：运营主管只对整条建议执行一次通过或驳回，不能分别审核经营动作与库存动作。
- **通过后同时激活**：建议通过后，已经随规则结论生成的经营动作与补货/禁补动作同时激活；审核时不二次创建动作。
- **驳回后不激活**：建议驳回后保留原始规则、数据、动作和备注，但不生成运营或采购执行待办。
- **工作台只导航审核**：本页不直接改变审核状态；正式操作必须在 `PAGE-F06-03` 查看完整经营信息后完成。
- **无待办判定**：只有数据加载成功、批次可审核且待审核数量确为 0，才能显示本批次已处理完成。

 PAGE-F05-02  PAGE-F06-03 PAGE-F01-01 PAGE-F08-01

       │          │

       │                 │
       └─────────────────┴────→ 返回主管工作台并刷新同批次汇总

### 9.2 与其他模块的关系

- 与行动中心的关系：工作台展示最新成功批次的审核摘要；`PAGE-F05-02` 承载当前批次全部建议、条件筛选和完整列表。
- 与建议闭环的关系：`PAGE-F06-03` 承载完整经营信息、规则依据和正式整体审核；工作台不能替代详情审核。
- 与数据批次的关系：工作台读取批次上下文和处理状态；运营主管可查看批次，但不在本页导入数据。
- 与历史追溯的关系：工作台只展示最近审核摘要；跨批次检索与完整历史进入 `PAGE-F08-01`。
- 与运营执行职责隔离：主管不能从本页代责任运营执行经营或库存/钉钉协同动作，也不能切换身份代办。
- 与权限模块的关系：角色失效、会话失效或无权访问时，不展示主管经营信息并进入统一恢复流程。

### 9.3 扩展预案

| 扩展方向 | 触发条件 | 改造点 |
| :--- | :--- | :--- |
| 新风险分组 | PRD 新增稳定主动作或新的审核维度，并提供对应 REQ/AC | 增量调整风险分布与固定排序，不把无需求候选预置到当前工作台 |
| 批量审核 | PRD 明确批量审核的风险控制、证据要求和审计验收 | 重新设计审核确认与冲突处理；当前不预埋批量入口 |
| 跨批次趋势 | PRD 明确趋势分析指标、口径和验收标准 | 在历史模块新增能力，不把当前批次工作台变成趋势报表 |
| 新日常管理角色 | PRD 新增角色、审批责任和数据权限边界 | 回到权限与工作台地图增量设计，不在当前页面提供角色切换 |

### 10.1 页面需要什么数据

| 数据 | 来源 | 用途 |

| 当前事业部 | 当前业务上下文 | 明确本页处理范围 |

| 待审核建议摘要 | 当前批次行动清单 | 展示 SPU、主动作、库存动作、关键依据、责任运营和状态 |
| 异常与冲突状态 | 批次处理及审核状态 | 告知影响范围、最新状态与恢复动作 |

### 10.2 页面提交什么数据

本页不提交通过或驳回等业务状态变更，只提交页面流转所需的上下文：

| 数据 | 触发时机 | 用途 |
| :--- | :--- | :--- |
| 当前批次与待审核条件 | 进入行动清单时 | 打开同一批次的待审核建议范围 |
| 当前批次、主动作与待审核条件 | 选择风险分组时 | 打开对应主动作的待审核建议范围 |
| 建议身份与来源上下文 | 选择“查看并审核”或最近审核记录时 | 打开对应建议详情，并支持返回同一工作台上下文 |

正式审核数据由 `PAGE-F06-03` 提交：通过时备注可选；驳回时提交非空驳回原因。该行为不属于本页直接操作。

### 10.3 明确排除的数据

- 不需要在本页填写或提交审核备注、通过结果或驳回结果。
- 不需要运营动作执行状态变更或经营结果表单数据。
- 不需要采购补货、禁补执行结果或外部采购系统回执。
- 不需要 SKU、评价文本、退款/退货原因或广告计划、关键词、素材明细。
- 不需要跨批次趋势指标、预测结果或 AI 生成的审核结论。
- 不需要角色配置、账号密码或 LiteLLM 部署密钥。

## 11. 验收标准

### 11.1 功能验收

| 编号 | 验收点 | 通过标准 |
| :--- | :--- | :--- |
| F-01 | 当前批次上下文 | 存在最新成功批次时，页面显示同一批次的事业部、期间、业务截止日、规则版本和最后更新时间 |
| F-02 | 审核数量汇总 | 待审核、已通过、已驳回数量均来自当前批次，待审核列表只包含建议级状态为待审核的建议 |
| F-03 | 风险分布对账 | 清仓、止损、观察、加投数量按唯一主动作统计，合计与当前批次待审核建议总数一致 |

| F-08 | 最近审核记录 | 已完成审核时，页面能显示对应 SPU、审核结果、审核人、审核时间和备注摘要，并可进入详情复核 |
| F-09 | 条件流转 | 选择某风险分组或“查看全部待审核”后，行动清单保留当前批次、待审核状态及相应动作条件 |
