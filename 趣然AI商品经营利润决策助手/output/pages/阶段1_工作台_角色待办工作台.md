## 2. 页面概述

### 2.1 一句话定位
登录后的角色任务总入口，让用户先看到本周批次、风险、本人待办和利润—库存跨部门卡点，再进入真实业务对象。

### 2.2 存在理由
1. 没有聚合入口，主管、运营与采购必须分别翻找批次和建议。
2. 双动作进度不一致容易再次形成“运营止损、采购仍补货”的断点。
3. 最新批次异常若不可见，用户可能误把旧清单当成本周结论。

### 2.3 页面目标（可衡量）
| 维度 | 指标 |
| :--- | :--- |
| 定位效率 | 用户 1 次点击进入任一首要待办 |
| 风险完整性 | 最新批次中的清仓、止损及跨部门卡点均有计数与入口 |
| 角色准确性 | 页面只聚合当前角色可读、可处理的任务 |

### 2.4 不做什么（范围边界）
- 不在工作台审核或执行——操作在建议详情及独立表单完成。
- 不展示全量建议——清单列表承载检索、分页和筛选。
- 不提供角色切换或维护——角色由 IT 映射。
- 不展示 AI 密钥或模型设置——由运维在部署环境维护。

## 3. 用户与场景

### 3.1 目标用户
| 角色 | 熟练度 / 设备 / 姿势 |
| :--- | :--- |
| 运营主管 | 中等；办公 PC；周一集中审核、周内追踪 |
| 运营 | 中等；办公 PC；导入、执行并记录经营结果 |
| 采购计划 | 中等；办公 PC；仅处理补货/禁补任务 |

### 3.2 核心使用场景
**场景 A：周一进入本周闭环（主场景）**
- 时机：新经营表完成导入和规则处理后
- 前置：用户已通过钉钉认证且存在当前角色可见任务
- 动作：核对最新批次 → 查看风险与本人待办 → 进入清单或建议
- 情绪：明确、有掌控感

**场景 B：数据未就绪或无本人待办（兜底场景）**
- 时机：尚无成功批次、处理中、加载失败或筛选后无待办
- 前置：用户已登录
- 动作：查看原因与恢复路径 → 运营进入批次页，其他角色等待或查看历史
- 情绪：不误判、不焦虑

### 3.3 用户核心诉求（优先级排序）
1. 先处理高风险、超时和跨部门卡点。
2. 只看本人能处理的任务与必要信息。
3. 明确数据属于哪个批次和业务期间。
4. 一步抵达真实落点，不在聚合卡片里重复操作。

## 4. 信息架构

### 4.1 区域划分
1. 应用壳与面包屑；2. 当前角色与最新批次；3. 风险概览；4. 本人待办；5. 跨部门卡点；6. 快捷入口。

### 4.2 区域内容
- 最新批次：事业部、期间、截止日、规则/AI/清单状态。
- 风险概览：清仓、止损、观察、加投及补货/禁补计数。
- 本人待办：待审核、待执行、待记录结果，按角色裁剪。
- 跨部门卡点：同一建议两条动作轨道进度不同的记录。
- 快捷入口：数据批次、行动清单、历史追溯。

## 5. 界面内容

### 5.1 元素清单
- **角色标识**：当前钉钉身份对应业务角色；登录后始终显示。
- **批次状态卡**：显示最近批次及“查看详情”；无批次时给运营“前往导入”，其他角色只给说明。
- **风险卡**：显示当前最新可审核清单的动作数量；点击带筛选进入清单。
- **待办列表**：对象、动作、状态、负责人、业务期间与进入详情入口；采购不返回利润/推广/售后。
- **利润—库存双轨卡点**：经营动作和采购动作分别显示状态；点击进入有权详情。

### 5.2 辅助信息
- 所有计数注明所属批次；处理中的计数不冒充最终结果。
- 页面更新时间与业务截止日分开表达。

## 6. 交互流程

### 6.1 页面加载与初始化
校验登录态与角色 → 拉取当前角色聚合 → 默认采用最新有权批次 → 展示风险、待办和卡点；无角色转认证门禁。

### 6.2 核心操作流程
```text
点击风险/待办/卡点 → 系统保留 batch_id 与对应筛选 → 进入清单或建议详情
点击最新批次 → 进入批次详情
点击历史追溯 → 进入历史索引
```

### 6.3 辅助操作
- “查看全部”进入对应列表，不在本页无限展开。
- 刷新后仍以服务端当前角色重新裁剪。

## 7. 状态与边界

### 7.1 页面状态全景
| 状态 | 页面表现 |
| :--- | :--- |
| 初始 / 加载 | 保留应用壳，任务区显示加载中 |
| 正常 | 最新批次、风险、待办、卡点完整显示 |
| 无批次 | 说明尚无业务批次并给有权入口 |
| 无待办 | 明确“当前角色暂无待办”，保留风险与历史入口 |
| 批次处理中 | 显示当前阶段，不提前展示最终风险计数 |
| 失败 / 无权限 | 页内失败重试；越权不返回对象信息 |

### 7.2 边界与容错
| 边界 | 策略 |
| :--- | :--- |
| 网络异常 | 保留批次上下文并提供重试，不显示零任务 |
| 会话过期 | 返回钉钉认证门禁，不渲染经营数据 |
| 连续加载错误 | 始终显示明确失败状态与历史入口，不静默空白 |
| 异常聚合数据 | 对无法勾稽的计数标记不可用，不自行求和修正 |
| 并发状态变化 | 进入详情时读取最新状态，工作台计数只作导航参考 |
| 角色变化 | 下一次请求按新角色重裁剪，旧卡片不可继续读取 |

## 8. 业务规则与校验

### 8.1 字段定义
| 字段 | 说明 |
| :--- | :--- |
| `current_role` | IT 映射的当前唯一业务角色 |
| `latest_batch` | 当前角色可见的最新批次摘要 |
| `risk_counts` | 按固定主动作聚合的计数 |
| `task_counts` | 待审核、待执行、待结果计数 |
| `cross_role_blockers` | 双动作进度不一致的建议摘要 |

### 8.2 校验规则
| 校验 | 时机 | 失败反馈 |
| :--- | :--- | :--- |
| 登录态与角色有效 | 初始化 | 重新认证或联系 IT |
| 批次访问权 | 点击批次 | 权限不足，不返回批次字段 |
| 建议访问权 | 点击待办 | 权限不足，不返回建议身份或状态 |
| 聚合与批次一致 | 展示计数 | 标记数据暂不可用并允许刷新 |

### 8.3 特殊业务规则
- 主管聚合待审核；运营聚合经营动作和经营结果；采购只聚合补货/禁补任务。
- 卡点来自建议内分动作状态，不创造新业务状态。
- AI 失败不影响规则风险、审核或执行入口。

| :--- | :--- | :--- |

## 10. 数据需求

### 10.1 页面需要什么数据
当前身份角色、最新批次摘要、按动作风险计数、本人任务摘要、双动作进度与最近事件时间。

### 10.2 页面提交什么数据
本页不提交业务状态；仅提交导航筛选和刷新请求。

### 10.3 明确排除的数据
不需要原始 XLSX、LiteLLM 密钥、角色维护数据；采购聚合不需要利润、推广、品退或售后字段。

## 12. 生产实现映射

- 前端路由：`apps/web/src/pages/WorkspacePage.tsx`；应用壳：`apps/web/src/components/AppShell.tsx`；真实数据由 TanStack Query 调用 `/api/workspace`。
- 服务端聚合：`apps/api/src/routes/workspace.ts`，从最新有权批次、冻结建议与两条 action item 实时聚合，不在前端硬编码计数。
- 角色裁剪：主管返回待审核与双轨卡点；运营返回经营待执行/待结果与双轨卡点；采购仅返回库存动作计数和采购任务，响应中不包含经营动作、利润、推广、品退或售后字段。
- 状态对应：无批次、处理中、无待办、加载失败与正常态均有独立呈现；网络失败不会冒充“零任务”。
