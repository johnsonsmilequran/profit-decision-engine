# F09 Admin 管理后台方案 V0.5

> 状态：Lead PM 对 Round 1 四方意见逐项裁决后的修订稿，供 Round 3 相互 challenge。未改变用户已确认边界。

## 1. Lead PM 裁决摘要

| 评审主题 | 裁决 | V0.5 处理 |
|---|---|---|
| 恢复凭据只是环境变量 | 接受 | 增加环境作用域、版本/指纹、签发、到期、消费状态；快照恢复后服务开放前强制换新 |
| 恢复通知为 P1 | 接受 | 升为 P0 与上线门禁；不可静默完成恢复 |
| 两种恢复语义混淆 | 接受 | 恢复码仅在密码正确时替代一次 TOTP；部署恢复可重设密码/TOTP，并全量撤销旧会话 |
| 登录失败可能永久锁死 | 接受 | 渐进限速与短时冷却，不永久锁死；部署恢复单独限流与审计 |
| 角色、会话、审批、审计不一致 | 接受 | 四者作为原子操作，审计失败即全部回滚 |
| 双 Cookie 串权 | 接受 | 两类路由只读各自 Cookie，禁止 fallback、身份转换或共享秘密，并纳入必测 |
| 身份不足仍可授权 | 接受 | 稳定作用域主键 + 至少两个可核验组织属性；缺失或冲突时禁止授权 |
| 开发与线上秘密未物理分离 | 接受 | 不同配置源、秘密和值守命令，禁止进入仓库、镜像、前端包、日志或通用默认值 |
| 10 分钟计时模糊 | 接受 | 服务端事件计时；有效审批已具备，从初始化开始到正确业务会话访问工作台 |
| 审计留存 3 年 | 接受原则，期限暂缓 | 删除价值周期推导，期限由公司治理责任人拍板 |
| 待审批仍无人承接 | 接受 | 责任岗位、联系指引、Admin 首页新申请/积压可见均升 P0 |
| 状态机不真实 | 接受 | 明确六状态，产品不自行假定外部审批已经完成 |
| 初始化/恢复异常流不足 | 接受 | 强制 TOTP 实码验证、恢复码保存确认、幂等、防半成品和可操作错误恢复 |
| 单 Admin 责任与 SLA | 部分接受 | 岗位与联系人为上线门禁；当前不虚构具体人或未确认 SLA |
| 价值归因过宽 | 接受 | 72 万元/年为待验证风险暴露；216 万元为三年假设下可支撑价值上限，F09 不独占 |
| V0 滑向小型 IAM | 接受 | 首发只保留安全开门必需能力，导出、周期复核、OA 集成等后置 |
| 单 Admin 长期不可逆 | 部分接受 | 当前仍单 Admin，仅设置重评触发器，不预埋多 Admin 功能 |

具体安全参数、组织认可的审批证据目录、通知通道、日常 SLA、审计期限与具体责任人等待对应责任人拍板，不由 Lead PM 编造。

## 2. 产品定义与边界

F09 是整套经营决策助手的启用能力：

```text
钉钉认证 → 无唯一角色 → 待处理身份 → 外部业务审批
→ 唯一 Admin 核验身份与审批证据 → 配置唯一角色
→ 撤销旧业务会话 → 用户重新登录正确工作台 → 不可变审计
```

- 仅一名 Admin，不创建第二名 Admin，不提供委派或管理员角色树。
- Admin 使用独立本地用户名、密码、TOTP 和独立会话，不依赖钉钉。
- Admin 管理权与运营/运营主管业务角色正交，默认不能读取经营数据。
- 两个固定业务角色互斥且唯一有效；事业部负责人审批，Admin 只执行。
- 无角色身份只进入待处理，不自动授权。
- 首版不接 OA API，不做通用 IAM、IGA、目录同步、批量授权或可配置权限集。

## 3. 首发必做能力

### 3.1 唯一 Admin 初始化

- 仅系统不存在 Admin 时开放；口令限定环境、版本、有效期和单次消费。
- 创建用户名与密码、绑定并实码验证 TOTP、仅当次展示恢复码并确认保存、用新凭据完成首次登录验证后，才原子创建唯一 Admin、消费口令并关闭入口。
- 刷新、返回、网络中断、重复提交或并发初始化不得产生半成品或第二名 Admin。

### 3.2 独立登录与会话

- 用户名 + 密码 + TOTP；失败采用账号/来源维度渐进限速和短时冷却，不永久锁死。
- Admin 与业务使用独立 Cookie、令牌秘密和认证判断；Admin 路由只读 Admin 会话，业务路由只读业务会话，禁止 fallback 和身份转换。
- 管理写操作要求 CSRF 防护与严格同源校验；具体会话和限速参数在安全设计中固定。

### 3.3 两级恢复

保存型恢复码：只有用户名和密码正确时替代一次 TOTP；单次消费并强制重新绑定、实码验证新 TOTP；成功后旧 TOTP 和旧 Admin 会话失效，不能用它重设密码。

部署恢复口令：仅正常凭据全部不可用时，由运维按内部审批配置。口令具有环境、版本、签发、到期与消费状态。密码重设、新 TOTP 实码验证、新恢复码、凭据版本递增、全量旧会话撤销、口令消费、审计和安全通知原子完成；任何一步失败不得部分恢复。通知不可用时不得静默完成。数据库快照恢复后必须先换新部署口令和相关保护材料再开放服务。本流程不宣称符合 NIST AAL2。

### 3.4 待处理身份与责任承接

- 以“身份提供方 + 企业作用域 + 稳定用户标识”幂等创建/更新，不创建业务会话或返回经营数据。
- 用户看到真实状态、首次申请/最近更新时间、下一步、负责岗位、联系指引以及已配置后的重新登录提示。
- Admin 首页显式展示新申请、等待阶段和积压；重复登录不重复建单。

| 状态 | 系统事实 | 下一动作 |
|---|---|---|
| 待取得外部审批 | 只知道无角色，不知道审批是否完成 | 用户联系事业部负责人；Admin 等待材料 |
| 已取得审批待配置 | Admin 已录入并核验材料，尚未成功配置 | Admin 核验身份并配置唯一角色 |
| 已配置待重新登录 | 角色已生效且旧业务会话已撤销 | 用户重新钉钉登录 |
| 已授权 | 已用正确业务会话访问工作台 | 正常使用 |
| 已停用 | 当前业务授权无效 | 取得新审批后决定是否恢复 |
| 配置冲突 | 身份、审批、角色或状态不一致 | 解决前禁止授权 |

### 3.5 身份核验与审批证据

- 姓名不作为授权主键；页面显示稳定作用域身份摘要，以及至少两个能与审批材料交叉核验的权威组织属性。
- 只有 opaque 标识、只有姓名且存在同名风险、属性缺失/冲突/来源不明、企业作用域不一致时，均禁止授权，不能用自由备注绕过。
- 审批证据结构化记录审批人、审批时间、目标角色、证据类型、证据引用和身份核验结果；公司认可/禁用的证据目录为上线门禁。首版不上传附件、不调 OA API。

### 3.6 角色生命周期与原子性

- 新增、变更、停用、恢复分别使用不同确认流程；突出人员、稳定身份摘要、核验属性、前后角色、审批证据和会话影响。
- 身份/审批校验、角色状态变化、受影响业务会话撤销、审批记录和不可变审计要么全部成功，要么全部失败；首版禁止批量授权。
- 统一身份生命周期详情持续展示状态、核验信息、审批证据、当前角色、历史与最近审计。

### 3.7 单 Admin 自保护与审计

- 唯一 Admin 不能停用/删除自己，不能创建或委派第二名 Admin；人员变更通过组织交接和受控凭据重置迁移责任并留依据。
- 独立审计覆盖初始化/登录安全、两类恢复、角色生命周期、授权拒绝、会话撤销和安全配置变化。
- 不记录任何密码、口令、TOTP 密钥、恢复码或完整令牌；Admin 只读审计。
- 应用运行身份无审计更新、删除或 DDL 权限；高权限动作审计失败则业务动作失败。在线留存/归档/清理期限等待治理拍板。

## 4. 指标与价值归因

| 指标 | 目标/状态 | 口径 |
|---|---:|---|
| 首次初始化授权闭环 | ≤10 分钟 | 有效审批已具备，从服务端初始化开始事件到目标用户访问正确工作台 |
| 日常产品内配置时间 | 先记录 | 有效审批材料可用到角色配置成功 |
| 完整授权周期 | 先记录 | 待处理身份产生到进入正确工作台，包含外部审批等待 |
| 错误业务授权 | 0 | 错人、错角色、双角色、作用域错误均计入 |
| 高权限审计覆盖率 | 100% | 初始化、恢复与角色生命周期逐类核对 |
| 重复待处理身份 | 0 | 同一作用域稳定身份只有一条当前生命周期 |
| 恢复后旧 Admin 会话 | 0 | 全部旧会话不可使用 |

- 72 万元/年是 `6 万元/次 × 12 次/年待验证假设` 得到的潜在风险暴露；216 万元是连续三年假设成立时的可支撑价值上限，不是已节省金额、承诺 ROI 或 F09 独占价值。
- F09 归因必须同时满足：正当业务访问需要；直接原因是缺少/错误/失效角色；F09 授权实际解除阻塞；有证据证明访问延误影响后续经营动作；利润影响可核验。
- 数据未导入、未审批、业务审核/执行/采购延误、外部系统、网络或与角色无关的登录故障均排除。
- 上线 30 天复盘真实申请、处理、错授和恢复演练；年度按真实事件重算。

## 5. 运营责任与上线门禁

上线前必须登记：唯一 Admin 持有人及交接责任、事业部审批岗位、恢复审批岗位、恢复执行岗位、安全通知接收岗位、审计治理岗位、价值台账岗位。具体人选、联系方式和未确认 SLA 不在本稿虚构。

上线门禁：

- Admin 人选、首位用户有效审批材料、TOTP 工具、责任岗位和联系指引就绪。
- 开发/线上配置源、秘密和启动/运维命令物理分离；任何原始秘密不进入仓库、镜像、前端包或日志。
- 初始化、保存型恢复码、部署恢复、旧会话撤销、通知、口令轮换及备份恢复后秘密换新均演练通过。
- 审批证据目录和审计治理责任已确认；期限未定时开发不得擅自自动删除。

## 6. 首发范围收敛

首发保留安全开门必需能力：初始化、独立认证、两级恢复与通知、待处理责任承接、可靠身份核验、结构化审批证据、单人角色生命周期、业务会话撤销、双会话隔离、不可变审计、核心计时和运行手册。

首发不做：多/备用 Admin、委派、批量授权、可配置角色、OA API、HR 自动生命周期、周期访问认证、目录同步、审计高级导出/SIEM、多应用权限包、任何自动角色授予。

## 7. 单 Admin 重评触发器

以下事件只触发重新评估，不自动改变单 Admin：第二生产环境、第三业务角色、跨事业部/多级审批、30 天数据证明单人无法承接、唯一 Admin 离岗/交接、首次演练或真实恢复失败、身份来源超出当前钉钉企业、决定接入 OA/IDaaS。重评必须保护审批证据、角色历史和审计记录的可迁移性；用户重新拍板前保持单 Admin。
