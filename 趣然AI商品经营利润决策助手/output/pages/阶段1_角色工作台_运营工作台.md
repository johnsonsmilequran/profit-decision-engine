## 2. 页面概述

### 2.1 一句话定位

运营登录后的首个行动入口：确认当前批次及导入状态，聚合本人 SPU 的经营动作、库存/钉钉协同、生命周期时间、待确认清仓完成时间与最近处理记录；最近前序待办以原批次独立建议快照保留入口并默认折叠，用户按单条 SPU 展开查看其当时的动作与依据，再按经营状态筛选后进入对应业务页继续处理。

### 2.2 存在理由

1. 没有角色工作台，运营需在批次、清单和详情之间反复查找本周待办，容易遗漏经营动作或结果补录。
2. 没有固定批次上下文，运营可能把历史批次或仍在处理的数据误认为当前清单。
3. 没有集中显示数据限制，品退或库存缺数可能被误读为没有经营风险。

### 2.3 页面目标（可衡量）

| 目标维度 | 具体指标 |
| :--- | :--- |
| 批次识别 | 存在当前成功批次时，100% 显示事业部、批次、业务期间、业务截止日和最后更新时间 |
| 待办覆盖 | 当前批次中分配给运营且已激活的经营动作，100% 归入“待执行”或“待补录结果” |
| 状态真实性 | 规则处理中、确无待办、加载失败和无成功批次四类状态不得互相替代 |
| 任务可达 | 每条经营待办和最近处理记录均可进入其所属建议详情 |
| 关联可见 | 存在历史经营待办的当前 SPU，100% 提供“最近前序待办”折叠入口；展开后完整显示该前序批次自己的主动作、关键依据、库存语境、经营状态、来源批次、产生时间和执行时间 |
| 数据限制可见 | 当前批次影响经营判断的数据限制全部显示受影响范围，不以 0 替代缺失值 |

### 2.4 不做什么（范围边界）

- **不做建议审核**——整体通过或驳回仅由运营主管在建议详情完成。
- **不向采购、仓库等相关人员开放产品角色**——责任运营通过 OA 发起协同、核验反馈并在产品内回填状态。
- **不在工作台直接提交经营动作或结果**——正式提交必须进入建议详情，查看完整依据并接受版本保护。
- **不做独立经营指标中心**——指标核对位于批次详情和建议详情，避免回到“看报表后人工判断”。
- **不做批量执行或批量结果补录**——首版逐条处理，保留清晰的动作与审计责任。
- **不展示 SKU、广告明细、评价或退款原因**——当前决策粒度和数据能力仅到 SPU 汇总层。

## 3. 用户与场景

### 3.1 目标用户

| 维度 | 描述 |
| :--- | :--- |
| 角色 | 运营 |
| 人数 | 单次由一名已映射运营角色的用户使用 |
| 技术熟练度 | 中等，熟悉经营表、商品链接和日常推广/清仓操作 |
| 使用设备 | 办公电脑，浏览器宽度 1024px 及以上 |
| 使用姿势 | 每周导入后集中确认新任务；周内每日查看待执行动作和待补录结果 |

### 3.2 核心使用场景

**场景 A：处理本周经营待办（主场景）**
- 时机：最新批次规则处理完成，建议已由主管通过并激活运营动作。
- 前置：用户以运营角色进入系统；当前成功批次存在；本人有待执行经营动作。
- 动作：核对批次和数据限制 → 查看经营待办 → 进入建议详情查看完整依据并记录执行。
- 情绪：明确、聚焦，知道先处理什么以及依据来自哪个批次。

**场景 B：补录已执行动作的经营结果（主场景）**
- 时机：运营已记录经营动作执行，但销售、利润或库存结果尚未补录。
- 前置：对应经营动作处于已执行且结果未记录状态。
- 动作：打开“待补录结果” → 进入建议详情 → 核对结果周期并填写可用结果或明确未提供。
- 情绪：连续、可追溯，不必重新查找原建议。

**场景 C：新批次仍在处理或数据受限（兜底场景）**
- 时机：周一导入后批次仍在校验/规则处理，或品退、库存数据存在限制。
- 前置：存在正在处理的导入批次，或当前成功批次含字段级降级。
- 动作：查看导入状态与限制原因 → 进入批次详情核对；在新清单就绪前继续明确识别旧批次上下文。
- 情绪：不焦虑，不把处理中或缺数误判为“本周无问题”。

### 3.3 用户核心诉求（优先级排序）

1. **准**：明确当前批次、更新时间和数据限制，不误用旧数据。
2. **快**：首屏直接看到本人待执行和待补录任务。
3. **可执行**：每条待办能进入完整建议详情继续处理。
4. **可追溯**：最近处理能回到原建议及其状态记录。
5. **不误导**：空待办、处理中和加载失败必须清楚区分。

## 4. 信息架构

### 4.1 区域划分

1. 全站导航与角色上下文
2. 当前批次与导入状态区
3. 经营与协同任务摘要区
4. 经营待办与清仓确认区
5. 数据限制区
6. 最近处理区
7. 页面级状态与恢复区

### 4.2 区域内容

**1. 全站导航与角色上下文**
- 左侧任务导航：工作台、行动中心、数据批次、历史与追溯。
- 顶部上下文：事业部、当前批次、当前角色和当前用户。

**2. 当前批次与导入状态区**
- 当前成功批次 ID、业务期间、业务截止日、规则版本和最后更新时间。
- 最近一次导入状态：已接收、校验中、规则处理中、清单就绪或失败。
- 进入数据批次列表或当前批次详情的入口。

**3. 经营任务摘要区**
- 待执行经营动作数量。
- 待补录经营结果数量。
- 待提交/待修正清仓完成时间数量，以及今日 OA 催办发送/失败数量。
- 当前批次经营任务总览状态。

**4. 经营待办区**
- 当前批次分配给运营的待执行动作摘要。
- 支持按经营动作与经营状态筛选；经营状态只匹配经营动作轨。
- 每项常驻显示 SPU、当前经营主动作、稳定任务 ID、首次产生时间、本周关联时间、执行时间、当前关键依据摘要、审核状态、经营动作状态、钉钉协同状态、清仓完成确认状态、最近催办、AI 状态和数据限制；最近前序待办作为独立建议快照默认折叠。
- 进入行动清单全部任务或单条建议详情的入口。

**5. 数据限制区**
- 品退数据未校验、库存数据不足、无近期销售、分类/利润字段异常等限制。
- 每项显示受影响 SPU 数量、被阻断的判断及进入批次详情的入口。

**6. 最近处理区**
- 当前运营最近完成的经营动作或结果记录。
- 每项显示 SPU、动作、最新状态、处理时间及返回建议详情的入口。

**7. 页面级状态与恢复区**
- 无成功批次、规则处理中、确无待办、加载失败、会话失效或权限变化时的说明和唯一恢复动作。

## 5. 界面内容

### 5.1 元素清单

**角色上下文**
- 内容：事业部、当前批次、角色“运营”、当前用户。
- 数据来源：当前登录身份及批次上下文。
- 显示条件：进入业务页后始终显示。

**当前批次摘要**
- 内容：批次 ID、数据期间、业务截止日、规则版本、最后更新时间。
- 数据来源：最新成功批次及其冻结信息。
- 显示条件：存在成功批次时显示；没有时显示首次导入引导。

**导入状态**
- 文案：按实际状态显示“校验中”“规则处理中”“清单就绪”或“导入失败”等；同时注明该状态对应的批次。
- 数据来源：最近一次导入批次状态。
- 显示条件：存在导入记录时显示。

**待执行经营动作**
- 内容：数量与任务摘要；动作仅包括加投、观察、SPU 整体推广止损、清仓。
- 数据来源：当前成功批次中已通过审核、分配给运营且尚未执行的经营动作。
- 显示条件：数量大于 0 时列出任务；为 0 时显示明确空状态。

**待补录经营结果**
- 内容：数量与任务摘要；标明原动作、执行时间和结果待补状态。
- 数据来源：当前成功批次中由运营执行、已执行但尚未记录结果的经营动作。
- 显示条件：存在待补录任务时显示；否则显示“暂无待补录结果”。

**经营待办项**
- 内容：SPU ID/名称、当前主动作、稳定任务 ID、待办首次产生时间、本周关联时间、实际执行时间、当前关键依据摘要、审核状态、经营动作状态、AI 状态、数据限制；存在前序时在当前行下方提供横跨 7 列的“最近前序待办”折叠控制行，展开后增加一条与当前待办列结构完全相同的只读历史行，逐列显示前序来源批次、主动作、关键依据、库存语境、经营状态、产生/执行时间、辅助解释和详情入口。
- 数据来源：行动清单对运营角色的授权投影。
- 显示条件：当前成功批次存在本人待办。
- 时间规则：尚未执行时执行时间显示“—”，不得用最后更新时间、审核时间或本周关联时间替代。
- 折叠规则：每条 SPU 独立控制，默认折叠；展开后的前序行必须复用当前表头的 7 列、相同字段顺序和列宽，不得再使用对象单元格内嵌摘要卡。数据只来自前序批次不可变快照，整行标识“前序批次 · 只读”。点击或键盘 Enter/Space 仅切换前序整行，不进入建议详情。刷新、筛选、分页或从详情返回后恢复折叠，不持久化展开状态；首次无前序时显示“无前序待办”，不渲染空折叠控件。

**经营状态筛选**
- 选项：全部经营状态、待审核、变更待确认、待执行、已执行、待记录结果、待提交清仓完成时间、待主管确认、完成时间待修正、已确认完成、已记录结果、已关闭。
- 数据来源：经营动作轨状态枚举。
- 行为：与经营动作筛选、SPU 搜索共同收窄当前工作台待办；刷新和从详情返回后恢复。

**数据限制摘要**
- 内容：限制类型、受影响 SPU 数量、受影响判断和批次详情入口。
- 文案：使用“未提供”“数据不足”“无近期销售”“品退数据未校验”等明确状态。
- 数据来源：当前成功批次的字段质量与降级记录。
- 显示条件：存在任一数据限制时显示；不存在时显示“本批次未发现数据限制”。

**最近处理记录**
- 内容：SPU、经营动作、前后状态、处理时间、结果记录状态。
- 数据来源：当前运营有权查看的最新经营动作及结果事件。
- 显示条件：存在记录时显示；没有时说明“暂无处理记录”。

**任务入口**
- 文案：“查看全部行动”“查看建议”“查看批次详情”“导入新批次”“查看历史”。
- 显示条件：按批次、任务状态和当前权限显示；不在工作台直接显示正式执行或结果提交按钮。

**清仓完成与 OA 催办摘要**
- 当前动作仍为清仓且主管尚未确认最终完成时间时，显示责任运营、提交状态、最近一次催办时间和送达/失败状态。
- 同一稳定任务跨周仍为清仓时沿用原确认流程，不新建第二条待办；进入建议详情提交或修正实际完成时间。
- OA 发送失败提供人工补发入口，但补发成功不得自动把清仓标记为完成。

### 5.2 辅助信息

- 当前任务所属批次必须与任务同时出现，历史批次需明确标识。
- AI 状态只说明解释生成状态，不改变经营动作或任务排序。
- 页面时间采用统一业务时区展示，并显示最后更新时间，避免把缓存内容理解为实时新结论。

- 视觉基线使用真实 RC2 的 `BATCH-20260630-4EC92F6A` 与运营缘一：工作台 API 返回 2 条本人当前批次任务，其中 SPU `932592549424` 的经营轨/库存轨均待执行，SPU `683939339441` 的经营轨已关闭且库存轨待执行；“待执行经营动作”只统计经营轨，因此为 `1`。

- 当前只有一个真实业务期间，两条任务均无最近前序，HTML 不呈现虚构折叠入口或前序行；跨周折叠/展开保持为 MD/TDD 行为契约，以真实 PostgreSQL 多期集成测试验收。

## 6. 交互流程

### 6.1 页面加载与初始化

1. 确认当前用户仍具备运营角色；无有效权限时不加载经营数据并进入受控恢复。
2. 读取最新成功批次作为经营任务上下文，同时读取最近一次导入批次的处理状态。
3. 聚合当前批次中分配给运营的待执行经营动作和待补录结果。
4. 按事业部与 SPU/商品链接精确加载稳定经营任务及最近前序待办记录；当前任务的首次产生、本周关联和实际执行时间常驻，最近前序从原批次不可变决策与指标快照加载，按独立建议快照默认折叠。
5. 恢复经营动作、经营状态与 SPU 搜索条件，再读取当前批次数据限制与当前运营最近处理记录。
6. 若最近导入仍在处理，保留并标明当前任务来自哪个已成功批次，不用处理中批次替换现有清单。

### 6.2 核心操作流程

```text
运营进入工作台
    │
    ├─ 无成功批次 → 显示首次导入引导 → 进入数据批次/导入页
    │
    ├─ 最近批次处理中 → 显示处理状态与批次号 → 可进入批次详情查看进度
    │
    └─ 存在成功批次 → 显示当前批次任务
         │
         ├─ 选择待执行经营动作 → 进入建议详情查看依据并逐条记录执行
         ├─ 选择待补录结果 → 进入建议详情补录结果周期与可用结果
         ├─ 查看全部行动 → 进入行动清单并保留当前批次
         └─ 查看数据限制 → 进入批次详情核对冻结指标与降级原因
```

### 6.3 辅助操作

- 从最近处理记录进入建议详情时，定位到该建议的经营动作与业务时间线。
- 从其他页面返回工作台时，刷新任务聚合并保留当前批次的明确标识。
- 点击“查看历史”进入历史与追溯列表；历史建议只读，不在工作台复现旧动作按钮。

## 7. 状态与边界

### 7.1 页面状态全景

| 状态 | 触发条件 | 页面表现 |
| :--- | :--- | :--- |
| 加载态 | 首次进入或手动恢复加载 | 保留角色与批次位置，任务区显示加载中，不提前显示 0 |
| 首次无批次 | 尚无任何成功导入批次 | 说明暂无经营清单，提供进入数据批次/导入页的入口 |
| 导入处理中 | 最近批次处于已接收、校验中或规则处理中 | 显示批次和当前阶段；已有成功批次时继续明确旧批次任务来源 |
| 就绪有待办 | 当前成功批次存在待执行或待补录任务 | 显示任务数量、摘要和详情入口 |
| 就绪无待办 | 当前成功批次确无运营待办 | 显示“当前批次暂无待处理经营动作”，仍保留批次、数据限制和最近处理 |
| 数据受限 | 当前批次存在字段级降级 | 显示限制类型、影响范围和批次详情入口，不把缺失值显示为 0 |
| 导入失败 | 最近导入批次失败 | 显示失败批次和进入批次详情的恢复入口；不覆盖上一个成功批次 |
| 加载失败 | 工作台数据请求失败 | 显示加载失败和重试入口，不显示误导性空待办 |
| 会话失效/无权限 | 会话过期或运营角色失效 | 不展示经营数据，进入认证恢复或本人有权页面 |

### 7.2 边界与容错

| 边界场景 | 处理策略 |
| :--- | :--- |
| 网络异常 | 保留已显示的批次标识并标记内容可能过期；提供重试，不把请求失败改写为“暂无待办” |
| 会话过期 | 停止加载经营数据，重新钉钉认证；认证恢复后返回本页并重新校验角色与批次 |
| 连续加载错误 | 每次均显示失败事实和重试入口，不自动切换到历史批次或使用伪造的 0 数量 |
| 异常批次输入 | URL 或返回来源携带不存在、失败或无权批次时，不建立该批次上下文；回到最新有权成功批次并明确提示 |
| 并发状态变化 | 任务已被其他页面或会话处理时，刷新为最新状态并从待办移出；不在工作台回写旧状态 |
| 新批次尚未就绪 | 继续标明当前任务来自上一成功批次，同时单独显示新批次处理状态，二者不得混合 |
| AI 生成失败 | 保留固定规则形成的任务、关键依据摘要和详情入口；AI 失败不隐藏待办 |
| 品退或库存缺数 | 显示数据限制及被阻断判断；不以 0 补齐，也不生成无依据的观察、加投或补货 |
| 当前批次无经营待办 | 显示真实空状态，仍展示数据限制和最近处理，不跳转到历史任务 |
| 低于 1024px | 正式产品仍以电脑端为目标；本高保真评审页取消全屏设备限制，沿用收起侧栏的 PC 布局直接显示，必要时由内容区滚动，不代表完成手机适配 |

## 8. 业务规则与校验

### 8.1 字段定义

| 字段 | 说明 |
| :--- | :--- |
| `business_unit` | 当前事业部；V0 为玩具事业部 |
| `batch_id` | 当前成功批次的唯一标识；所有待办必须归属一个明确批次 |
| `period_start / period_end` | 当前批次使用的上一个完整自然月期间 |
| `business_date` | 批次业务截止日，用于冻结当时判断语境 |
| `batch_status` | 最近导入批次的已接收、校验中、规则处理中、清单就绪或失败状态 |
| `last_updated_at` | 工作台任务与状态的最后更新时间 |
| `pending_execution_count` | 已审核通过、分配给运营且尚未执行的经营动作数量 |
| `pending_result_count` | 经营动作已执行但结果尚未记录的数量 |
| `main_action` | 固定规则给出的唯一经营主动作：加投、观察、止损或清仓 |
| `business_action_state` | 经营动作当前状态：待审核、变更待确认、待执行、已执行、待记录结果、已记录结果或已关闭 |

| `current_linked_at` | 当前批次关联稳定待办的时间；与产生、执行时间分开 |
| `previous_todo` | 最近前序经营待办只读投影，含来源批次、产生/执行时间，以及原批次主动作、关键依据（指标/周期/阈值/比较/限制）、库存语境（仓内/在途/14天销量/可售天数/库存动作）和经营状态 |
| `business_executed_at` | 成功经营执行事件的时间；未执行为空并显示“—” |
| `ai_status` | AI 解释的生成中、已生成、失败或内容未采用状态；不改变规则动作 |
| `data_limit` | 品退未校验、库存数据不足、无近期销售或字段异常等质量标记 |
| `recent_event` | 当前运营最近的经营动作或结果事件，含 SPU、状态变化和时间 |

### 8.2 校验规则

| 校验项 | 时机 | 规则 | 失败反馈 |
| :--- | :--- | :--- | :--- |
| 运营角色 | 页面加载及每次刷新 | 当前用户必须仍具备运营角色 | 不返回经营数据，进入认证恢复或本人有权页面 |
| 当前批次 | 初始化 | 任务必须绑定最新有权成功批次；处理中批次不能冒充成功批次 | “当前批次尚未就绪，以下任务来自批次 {batch_id}” |
| 待执行归属 | 聚合任务时 | 仅包含分配给运营、建议已通过且经营动作待执行的任务 | 不符合条件的记录不计入待执行 |
| 待补录归属 | 聚合任务时 | 仅包含运营经营动作已执行且结果未记录的任务 | 不符合条件的记录不计入待补录 |
| 固定排序 | 展示经营待办时 | 按清仓、止损、观察、加投、补货的固定层级；运营工作台不单列采购补货任务 | 无有效稳定次序时按稳定 SPU 标识，不使用 AI 改序 |
| 经营状态筛选 | 选择或恢复筛选时 | 只匹配经营动作轨 `business_action_state`，并与动作、搜索条件组合 | 无效值恢复“全部经营状态”，不使用审核或聚合状态替代 |
| 最近前序关联 | 展示任务关系时 | 仅按同一事业部与 SPU 选择业务时间最近且早于当前的一条经营待办记录；从其原批次快照投影主动作、关键依据、库存语境、经营状态和时间并默认折叠 | 首次建任显示“无前序待办”且不渲染空折叠；前序字段缺失按原批次显示不足，不跨 SPU 猜测或用当前周回填 |
| 生命周期时间 | 展示任务时 | 产生、关联、执行时间分别取稳定任务、周度关联和成功执行事件 | 未执行显示“—”；异常缺失明确提示，不用更新时间填补 |
| 数据限制 | 展示指标摘要时 | 缺失、未校验和无近期销售必须保留原状态 | 使用明确限制文案，不显示为 0 或“正常” |
| 详情可达 | 点击任务或最近记录时 | 目标必须属于当前用户有权查看的建议 | 无权或不存在时不返回对象信息，进入受控恢复 |

### 8.3 特殊业务规则

- **一个批次一份清单**：工作台只聚合该批次唯一行动清单，不创建第二套工作台任务身份。
- **动作权威不变**：工作台展示固定规则动作；AI 仅解释，不能修改动作或固定排序。
- **按动作责任聚合**：运营只在本人工作台处理经营动作与经营结果；库存协同动作状态可作为建议上下文存在，但不提供采购执行入口。
- **正式写操作不在本页**：工作台只导航；动作与结果必须在建议详情依据当前版本逐条提交。
- **历史不覆盖当前**：新批次不覆盖旧批次记录；最近处理引用原事件和原建议。
- **SPU 稳定锚点**：经营待办只按事业部与 SPU/商品链接关联；相同动作续接稳定任务，最近前序记录作为默认折叠、按需展开的原批次独立建议快照，而不是仅含关系元数据的摘要。
- **经营状态独立**：筛选只作用于经营动作轨，不把建议审核、库存协同动作或工作台聚合状态当作经营状态。
- **纯维持不入待办**：唯一主动作是维持且无补货/禁补的 SPU 不进入行动清单，也不计入运营待办。

   └── 查看历史 ────────────→ 历史与追溯 PAGE-F08-01

### 9.2 与其他模块的关系

- **高保真联调**：全站导航和已给出页面目标的任务入口必须执行真实跨页跳转；仅无目标的演示控件保留当前页提示。
- **数据批次**：提供当前批次、最近导入状态和数据限制；工作台不复制导入校验明细。
- **行动中心**：提供当前批次唯一清单、固定排序和运营角色任务投影；工作台只展示任务摘要。
- **建议闭环**：承载完整规则依据、经营动作执行、结果补录、版本冲突和时间线；工作台不直接改变状态。
- **历史与追溯**：承载历史建议检索；工作台最近处理仅作为回看入口。
- **权限**：工作台面向运营角色，不开放主管审核或采购执行能力。

### 9.3 扩展预案

| 扩展方向 | 触发条件 | 改造点 |
| :--- | :--- | :--- |

| 评价、退款原因或广告明细 | 具备可信明细数据且重新立项 | 增加版本化证据摘要；不在当前工作台预埋空入口 |
| 外部系统写回 | PRD 明确动作回执与责任后 | 在最近处理与动作状态中识别外部回执，不把当前人工记录冒充回执 |

## 10. 数据需求

### 10.1 页面需要什么数据

| 数据 | 来源 | 用途 |
| :--- | :--- | :--- |

| 最新成功批次摘要 | 数据批次 | 显示任务所属批次、期间、截止日、规则版本和更新时间 |
| 最近导入批次状态 | 数据批次 | 区分处理中、就绪与失败，并提供批次详情入口 |
| 运营经营动作摘要 | 当前批次行动清单 | 聚合待执行经营动作和关键依据摘要 |
| 稳定任务、最近前序关联与生命周期时间 | SPU 稳定任务、决策任务关联、原批次决策/指标快照、经营动作事件 | 常驻展示当前任务 ID、产生/关联/执行时间；最近前序独立建议快照默认折叠，并支持当前经营状态筛选 |
| 运营结果待补录摘要 | 经营动作与结果记录 | 聚合已执行但尚未记录结果的任务 |
| 数据质量限制 | 当前批次冻结快照与校验记录 | 显示限制类型、影响范围和受阻断判断 |
| AI 状态 | 建议解释状态 | 说明解释是否可用，不改变规则任务 |
| 最近经营事件 | 当前用户有权查看的动作与结果事件 | 展示最近处理并返回原建议 |

### 10.2 页面提交什么数据

本页不提交审核、经营动作或经营结果。页面只提交导航上下文：

| 数据 | 触发时机 | 用途 |
| :--- | :--- | :--- |
| `batch_id` | 进入行动清单或批次详情 | 保持批次上下文，不混用新旧清单 |
| `decision_id` | 打开待办或最近处理记录 | 进入对应建议详情 |
| `business_state` | 选择经营状态筛选 | 收窄经营动作轨结果并在刷新、返回后恢复 |
| `return_source` | 离开工作台进入下游页 | 完成后返回运营工作台 |

### 10.3 明确排除的数据

- 不需要或提交主管审核备注、通过/驳回结果。
- 不需要或提交采购补货、禁补状态与协同结果。
- 不在工作台提交销售、利润、库存结果值；结果表单位于建议详情。
- 不需要 SKU、广告计划/关键词/素材、评价文本或退款原因明细。
- 不需要 LiteLLM 部署密钥、原始请求、被过滤输出或原始完整 XLSX。
- 不把缺失品退、库存和销量字段转换为 0。
