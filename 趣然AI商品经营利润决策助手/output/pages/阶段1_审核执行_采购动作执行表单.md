## 2. 页面概述
### 2.1 一句话定位
让采购计划仅基于库存、销量必要依据，确认补货或禁补的人工执行事实与最小结果。
### 2.2 存在理由
1. 让运营止损/清仓与采购禁补真正形成跨部门闭环。
2. 在完成采购职责时不泄露利润、推广、品退和售后。
3. 将人工确认与外部采购系统回执明确区分。
### 2.3 页面目标（可衡量）
| 维度 | 指标 |
| :--- | :--- |
| 最小可见 | 采购页面受限经营字段出现次数 0 |
| 禁补闭环 | 禁补动作可记录“已确认禁补”及时间/备注 |
| 独立并发 | 采购更新覆盖经营动作次数 0 |
### 2.4 不做什么（范围边界）
- 不展示完整利润、推广、品退或售后数据。
- 不允许把禁补改成补货，或编辑规则动作。
- 不自动下采购单、不读取采购系统回执。
- 不记录完整经营结果。

## 3. 用户与场景
### 3.1 目标用户
| 维度 | 描述 |
| :--- | :--- |
| 角色 | 采购计划 |
| 技术熟练度 | 中等，熟悉补货计划流程 |
| 设备/姿势 | PC，处理审核通过后的采购待办 |
### 3.2 核心使用场景
**场景 A：确认禁补（主场景）**
- 时机：止损或清仓建议已通过；前置：禁补动作待执行且分配给当前采购角色；动作：核对 SPU 与禁补结论，填写时间、备注和“已知悉/已停补”结果；情绪：明确、避免继续扩大库存。

**场景 B：越权访问无关联任务（兜底场景）**
- 时机：通过旧链接打开其他建议；前置：当前采购角色无该任务关联；动作：仅看到权限不足，不获取对象或状态；情绪：知道访问被拒绝且无数据暴露。
### 3.3 用户核心诉求（优先级排序）
1. 快速识别补货还是禁补及必要库存销量依据。
2. 明确记录人工处理结果。
3. 不被无关经营数据干扰。

## 4. 信息架构
### 4.1 区域划分
1. 应用壳与面包屑；2. SPU 最小身份；3. 采购动作与必要依据；4. 执行表单；5. 提交摘要；6. 冲突提示。
### 4.2 区域内容
- 身份：SPU ID、名称、店铺、平台。
- 必要依据：补货/禁补、仓内/在途、近14日销量、可售天数及数据状态；不显示利润轨细节。
- 表单：确认结果、执行时间、备注、最小采购结果。

## 5. 界面内容
### 5.1 元素清单
| 元素 | 内容/文案 | 数据来源 | 显示条件 |
| :--- | :--- | :--- | :--- |
| 采购动作 | 补货/禁止补货 | ActionItem 快照 | 有任务关联 |
| 必要依据 | 库存、在途、近14日销量、可售天数/缺数状态 | 角色裁剪快照 | 有任务关联 |
| 确认状态 | 补货“确认已执行”；禁补“确认已禁补” | 用户选择 | 待执行 |
| 执行时间 | 日期时间 | 用户输入 | 待执行 |
| 备注 | “记录补货或停补处理事实” | 用户输入 | 待执行 |
| 最小结果 | 补货处理结果或“已知悉/已停补” | 用户输入 | 待执行 |
### 5.2 辅助信息
- 禁补说明：“已确认禁补是人工记录，不代表采购系统已回执。”
- 库存缺失时不会出现补货任务；规则派生禁补仍可确认。

## 6. 交互流程
### 6.1 页面加载与初始化
- 先校验角色与 action 关联，再返回最小身份和必要依据；未关联直接转权限不足。
- 校验建议已通过、动作待执行，读取 procurement execution_version。
### 6.2 核心操作流程
```text
核对采购动作/依据 → 选择确认结果 → 填写时间、备注、最小结果 → 摘要确认
  ├─ 当前 version → 仅更新采购动作并追加事件 → 返回详情
  └─ 旧 version/重复 → 不覆盖 → 显示既有结果或最新状态并保留输入
```
### 6.3 辅助操作
- 取消返回角色裁剪后的建议详情；有输入时离开确认。
- 提交期间禁用；键盘焦点按字段顺序移动。

## 7. 状态与边界
### 7.1 页面状态全景
| 状态 | 触发条件 | 页面表现 |
| :--- | :--- | :--- |
| 初始态 | 采购动作待执行 | 显示最小身份、动作和必要依据 |
| 输入态 | 填写时间/备注/结果 | 失焦校验，本地会话保留 |
| 提交态 | 确认提交 | “记录中”，禁用重复操作 |
| 成功态 | 保存成功 | 返回详情并更新采购轨 |
| 失败态 | 校验/服务失败 | 保留输入，显示可修正原因 |
| 异常态 | 网络/version 冲突 | 显示最新状态、操作者和刷新入口 |
| 无权限态 | 无任务关联 | 不返回身份、状态或依据 |
### 7.2 边界与容错
| 边界场景 | 处理策略 |
| :--- | :--- |
| 网络异常 | 不显示成功，保留输入可重试 |
| 会话过期 | 返回钉钉门禁，不泄露缓存业务数据 |
| 连续/重复提交 | 请求中禁用；重试返回既有结果 |
| 异常时间/空结果 | 阻止提交并定位字段 |
| 并发操作 | 旧 version 拒绝，不新增事件 |
| 无任务关联 | 权限不足且不返回建议身份或状态 |
| 禁补试图改成补货 | 无编辑入口；接口也拒绝动作变更 |

## 8. 业务规则与校验
### 8.1 字段定义
| 字段 | 说明 |
| :--- | :--- |
| `confirmation` | 补货已执行或已确认禁补 |
| `executed_at` | 人工处理时间 |
| `execution_note` | 采购处理备注 |
| `procurement_result` | 最小结果，不含完整经营字段 |
| `execution_version` | 采购动作版本 |
### 8.2 校验规则
| 校验项 | 时机 | 规则 | 失败反馈 |
| :--- | :--- | :--- | :--- |
| 确认结果 | 提交 | 必须与冻结动作同类 | “请选择当前采购动作的处理结果” |
| 执行时间 | 失焦/提交 | 合法且不为无效未来时间 | “请填写有效处理时间” |
| 最小结果 | 提交 | 去空白后非空 | “请记录补货或禁补处理结果” |
| 关联/version | 服务端 | 当前角色关联且版本一致 | “任务状态已变化或无访问权限” |
### 8.3 特殊业务规则
- 禁补统一展示“已确认禁补”；“已知悉/已停补”只作为结果内容。
- 仅更新采购 action_id；人工记录不伪装为外部回执。

## 9. 页面流转
### 9.1 流转图
`采购待办/建议详情 → 本页 → 摘要确认 → 裁剪后的建议详情（采购动作已执行）`。
### 9.2 与其他模块的关系
- 建议通过后由 F06 激活；F07 决定字段裁剪；F08 追加采购事件。
- 经营动作可处于不同进度，但本页不可更新它。
### 9.3 扩展预案
| 方向 | 触发条件 | 改造点 |
| :--- | :--- | :--- |
| 采购系统回执 | 阶段2接口与审批责任明确 | 挂接稳定 action_id 追加外部回执 |

## 10. 数据需求
### 10.1 页面需要什么数据
| 数据 | 来源 | 用途 |
| :--- | :--- | :--- |
| SPU 最小身份、采购动作 | 裁剪后的快照 | 确认对象与任务 |
| 库存/销量必要依据 | MetricSnapshot 裁剪视图 | 复核采购动作 |
| action 关联、状态、version | 服务端授权投影 | 授权与并发 |
### 10.2 页面提交什么数据
| 数据 | 触发时机 | 用途 |
| :--- | :--- | :--- |
| action_id、confirmation、time、note、result、version | 确认提交 | 追加采购执行记录 |
### 10.3 明确排除的数据
- 不需要也不返回利润、推广、品退、售后、LiteLLM 信息和经营动作详情。

### 10.4 实施同步
生产执行 API 对采购仅匹配 inventory 轨 action_id，并强制提交的 confirmation 与冻结的 `restock/block_restock` 动作一致；无任务或错误轨道统一拒绝。接口保存人工处理时间、备注和最小结果，不表示外部系统回执；经营动作状态/version 不变，成功事件仅关联该库存 action_id。

## 11. 验收标准
### 11.1 功能验收
| 编号 | 验收点 | 通过标准 |
| :--- | :--- | :--- |
| F-01 | 补货执行 | 补货可保存状态、时间、备注和最小结果 |
| F-02 | 禁补确认 | 禁补保存为“已确认禁补”且不表示外部回执 |
| F-03 | 动作不可改 | 禁补不能经页面或接口改成补货 |
| F-04 | 独立更新 | 采购提交不改变经营 action 状态/version |
| F-05 | 并发保护 | 旧 version 不覆盖且不产生重复事件 |
### 11.2 体验验收
| 编号 | 验收点 | 通过标准 |
| :--- | :--- | :--- |
| U-01 | 最小首屏 | 首屏可识别 SPU、采购动作和必要依据 |
| U-02 | 禁补说明 | 清楚区分人工确认与外部回执 |
| U-03 | 字段聚焦 | 无完整经营字段干扰采购任务 |
| U-04 | 输入保留 | 失败或冲突后已填内容不丢失 |
| U-05 | 双轨进度 | 返回详情后只更新采购轨，经营轨保持现状 |
### 11.3 安全验收（产品层）
| 编号 | 验收点 | 通过标准 |
| :--- | :--- | :--- |
| S-01 | 任务关联 | 无关联采购任务时不返回对象和状态 |
| S-02 | 受限字段 | 页面、接口、错误中均无利润推广品退售后字段 |
| S-03 | 服务端操作授权 | 直接提交仍校验采购角色与 action 关联 |
| S-04 | 默认拒绝 | 无角色/会话失效不能读取或提交 |
| S-05 | 审计最小化 | 采购仅见经裁剪的本任务成功事件 |
