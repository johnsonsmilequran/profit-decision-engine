## 2. 页面概述

### 2.1 一句话定位

行动清单是授权用户按批次处理 SPU 经营问题的统一入口：默认展示最新成功批次，按固定业务优先级稳定排序，并按当前角色裁剪筛选项、字段和可见建议。

### 2.2 存在理由

1. 没有统一清单，运营、运营主管和采购计划会继续依据各自表格处理，止损与补货可能再次互相冲突。
2. 没有固定排序和筛选，高风险清仓、止损建议可能被低优先事项淹没，且 AI 可能被误当作排序裁决者。
3. 没有历史批次入口，新批次会遮蔽旧建议及其审核、动作与结果记录，无法还原当时事实。
4. 没有角色化数据投影，采购可能经列表字段、筛选条件或直链旁路接触完整利润、推广、品退与售后信息。

### 2.3 页面目标（可衡量）

| 目标维度 | 具体指标 |
| :--- | :--- |
| 清单唯一性 | 每个批次仅展示一份行动清单，同一批次不存在第二套建议身份 |
| 默认可用性 | 存在最新成功批次时，首次进入页面自动显示该批次及其授权范围内建议 |
| 排序确定性 | 相同批次、规则版本和授权角色重复打开时，建议顺序逐项一致 |
| 筛选准确性 | 任一有效筛选生效后，列表 100% 只显示匹配建议且不改写建议内容 |
| 历史完整性 | 切换到任一有权查看的历史批次时，显示该批次固化清单和历史状态，不被最新批次覆盖 |
| 权限隔离 | 采购列表、筛选、空态、错误与直链上下文中出现完整利润、推广、品退或售后字段的次数为 0 |
| 分页稳定性 | 默认 20 条/页，可切换 20/50/100；翻页及详情返回后筛选和批次上下文保持一致 |

### 2.4 不做什么（范围边界）

- **不在列表内审核、执行或记录结果**——有业务副作用的操作统一进入建议详情，确保用户先看到完整依据并接受状态版本校验。
- **不提供批量审核、批量执行或批量改状态**——建议按整体审核、分动作执行，批量操作容易绕过职责与并发边界。
- **不提供导出**——MVP 未承诺导出，避免把受限字段带出权限边界。
- **不使用无限滚动**——采用稳定分页，便于返回详情后恢复位置并保持历史顺序可复核。
- **不开放用户自定义业务排序**——固定动作层级和规则版本定义的代理指标是唯一优先级来源，AI 不参与改序。
- **不展示纯“维持”且无补货或禁补的 SPU**——该对象不属于待处理清单；完整决策仍留在追溯记录。
- **不生成第二份清单或提供“重新生成”按钮**——清单是批次下既有决策与动作的唯一投影。

## 3. 用户与场景

### 3.1 目标用户

| 角色 | 核心目标 | 技术熟练度 | 使用设备 | 使用姿势 |
| :--- | :--- | :--- | :--- | :--- |
| 运营 | 找到高优先级经营建议及本人待执行/待记录结果动作 | 中等，熟悉经营表格与内部工具 | 公司 PC | 每周新批次后集中处理，周内多次回访 |
| 运营主管 | 筛出待审核建议并掌握经营、采购两条动作进度 | 中高，熟悉利润与审核流程 | 公司 PC | 批次生成后集中审核，周内复查阻塞 |
| 采购计划 | 只查看补货/禁补任务及库存、销量必要依据 | 中等，熟悉采购计划与库存数据 | 公司 PC | 建议通过后按任务处理并回填结果 |

### 3.2 核心使用场景

**场景 A：处理最新批次高优先事项（主场景）**

- 时机：运营每周导入的新批次已完成固定规则决策并形成清单。
- 前置条件：用户钉钉登录态和业务角色有效；存在最新成功批次。
- 用户动作：进入行动清单 → 确认当前批次 → 按默认固定顺序查看 → 使用角色允许的筛选收窄结果 → 点击建议进入详情审核或处理本人动作。
- 用户情绪：希望快速、可信地确定先做什么，不想重新解释表格或猜测优先级。

**场景 B：主管筛选待审核与分轨进度（协作场景）**

- 时机：清单已就绪，部分建议尚待审核或通过后仅完成一条动作轨道。
- 前置条件：当前角色为运营主管，具备完整经营信息查看权。
- 用户动作：选择“待审核”或经营/采购执行状态 → 查看匹配建议 → 进入建议详情核对完整依据与分轨状态。
- 用户情绪：需要全局掌控，同时避免把部分完成误认为全部闭环。

**场景 C：采购处理最小必要任务（权限场景）**

- 时机：主管通过建议，补货或禁补动作被激活。
- 前置条件：当前角色为采购计划；建议确有分配给其角色且有权查看的采购任务。
- 用户动作：查看补货/禁补清单 → 按采购执行状态筛选 → 阅读库存与销量必要依据 → 进入裁剪后的建议详情处理任务。
- 用户情绪：职责清晰、信息够用，不被无关经营数据干扰。

**场景 D：回查历史批次（兜底场景）**

- 时机：用户需要解释旧建议、复核旧动作或从详情返回旧批次清单。
- 前置条件：目标历史批次仍在授权范围内。
- 用户动作：切换历史批次 → 查看其固化期间、规则版本和清单 → 使用筛选定位旧建议 → 进入历史建议详情。
- 用户情绪：希望确信看到的是当时事实，而不是最新数据覆盖后的结果。

**场景 E：默认批次或列表加载失败（兜底场景）**

- 时机：最新批次不存在、批次切换失败或网络异常。
- 前置条件：用户身份仍有效，或会话刚刚失效。
- 用户动作：区分“无批次”“清单为空”“筛选无结果”和“加载失败” → 重试、重置筛选、切回原批次或重新登录。
- 用户情绪：能明确判断是没有任务还是系统未成功读取，不被误导。

### 3.3 用户核心诉求（优先级排序）

1. **先处理高风险**：固定层级把清仓、止损放在观察、加投和补货之前。
2. **只看自己的职责**：筛选、字段、建议集合和详情入口均按角色裁剪。
3. **状态不混淆**：建议审核、经营执行、采购执行分别可见，双动作进度不互相覆盖。
4. **历史能复核**：切换批次后仍看到该批次原清单、规则和状态事实。
5. **异常可判断**：空清单、筛选无结果、加载失败和无权限不能呈现为同一种空白。

## 4. 信息架构

### 4.1 区域划分

1. 全站导航与身份上下文区
2. 页面标题与批次切换区
3. 批次摘要与清单汇总区
4. 搜索、筛选及已选条件区
5. 角色化建议列表区
6. 分页区
7. 空态、错误与恢复区

### 4.2 区域内容

**1. 全站导航与身份上下文区**

- 左侧导航中“行动清单”为当前入口。
- 顶部持续显示钉钉身份、当前业务角色和当前批次。
- 当前角色只读，不提供用户自由切换。

**2. 页面标题与批次切换区**

- 页面标题“行动清单”。
- 默认选中最新成功批次；可选择有权查看的历史批次。
- 批次选项显示可区分的批次编号、数据期间和状态，不以文件名作为唯一身份。

**3. 批次摘要与清单汇总区**

- 事业部、数据期间、业务截止日、规则版本及数据限制摘要。
- 当前授权视图的建议总数，以及按角色有意义的待审核、待执行、待记录结果汇总。
- 汇总仅投影当前批次和当前角色可见建议，不把动作数冒充建议数。

**4. 搜索、筛选及已选条件区**

- 关键词：SPU ID 或 SPU 名称。
- 运营与运营主管：主动作、店铺、责任运营、建议审核状态、经营执行状态、采购执行状态。
- 采购计划：补货/禁补动作、店铺、采购执行状态；不出现完整经营信息相关筛选。
- 已生效条件以可移除项展示，并提供重置。

**5. 角色化建议列表区**

- 运营、运营主管使用完整经营投影；运营无审核操作，主管无代执行操作。
- 采购仅使用任务必要投影，不返回利润、推广、品退、售后与完整经营结果。
- 点击授权建议进入 `PAGE-F05-03`；本页不直接改状态。

**6. 分页区**

- 显示总记录数、当前页、总页数、上一页/下一页及页码。
- 默认 20 条/页，可切换 20/50/100；不使用无限滚动。

**7. 空态、错误与恢复区**

- 无最新成功批次、批次清单为空、筛选无结果、加载失败、批次切换失败、会话失效和无权限分别说明。
- 恢复操作包括重试、重置筛选、切回原批次、进入数据批次或重新登录，按当前角色裁剪。

## 5. 界面内容

### 5.1 元素清单

**批次选择器**

- 内容：最新成功批次及用户有权查看的历史批次。
- 默认值：最新成功批次。
- 数据来源：不可变批次与该批次唯一清单。
- 显示条件：存在至少一个授权成功批次；无批次时显示独立空状态。
- 操作结果：切换后重新加载该批次摘要、筛选选项、列表和分页，不混合两个批次数据。

**当前批次摘要**

- 内容：批次编号、玩具事业部、数据期间、业务截止日、规则版本、数据限制。
- 数据来源：选中批次固化信息。
- 显示条件：批次切换成功；失败时保留原批次身份并明确新批次未加载成功。

**关键词搜索**

- 占位文案：“搜索 SPU ID 或商品名称”。
- 数据来源：用户输入。
- 显示条件：当前批次清单可读取。
- 行为：提交后回到第一页；仅空白输入等同清除关键词。

**角色化筛选器**

| 店铺 | 显示 | 显示 | 显示 |

- 内容：当前批次下已生效的搜索和筛选条件。
- 操作：移除单项条件或全部重置；任一变化后回到第一页。
- 显示条件：至少一个非默认条件生效。

**建议详情入口**

- 文案：“查看建议”或“查看任务”。
- 数据来源：稳定建议 ID 与选中批次 ID。
- 显示条件：服务端确认当前角色对该建议有读取权限。
- 操作结果：进入建议详情；返回时恢复批次、筛选、页码和每页条数。

**分页控件**

- 内容：总数、页码、上一页/下一页、20/50/100 条每页。
- 数据来源：当前批次、当前角色和当前筛选结果。
- 显示条件：有结果时显示；单页仍显示总数。

### 5.2 辅助信息

- 排序说明：“按清仓、止损、观察、加投、补货固定层级排列；同层按规则版本定义的已校验指标或稳定 SPU ID 排列。”
- 历史说明：“历史批次保留当时规则、建议和状态，不被新批次覆盖。”
- 数量说明：同一 SPU 同时有经营与采购动作时仍计一条建议；两个动作状态分别展示。
- 采购说明：“当前仅展示完成采购任务所需信息。”
- AI 降级说明：AI 等待或失败不影响规则清单、审核和执行，列表继续显示结构化四要素。

## 6. 交互流程

### 6.1 页面加载与初始化

1. 校验当前钉钉登录态、唯一有效业务角色和页面读取权限。
2. 查找最新完成固定规则决策且清单可用的授权批次；存在时作为默认批次。
3. 从 URL 恢复有效的批次、搜索、筛选、页码和每页条数；无有效批次参数时使用最新成功批次。
4. 按当前角色取得筛选选项、字段投影与建议集合，默认每页 20 条。
5. 服务端按固定动作层级、规则版本定义的有效代理指标和稳定 ID 返回确定顺序。
6. 加载期间不显示“0 条”结论；完成后进入有结果、清单空或筛选无结果状态。

### 6.2 核心操作流程

```text
进入行动清单
    │
    ├─ 会话无效/无角色/无页面权限 → 不展示经营数据 → 重新登录或无权限页
    │
    └─ 权限有效 → 选择默认批次
         │
         ├─ 无最新成功批次 → 显示“尚无可用批次”及角色化恢复入口
         │
         └─ 有最新成功批次 → 按角色加载唯一清单
              │
              ├─ 清单本身无行动项 → 显示“本批次无待处理建议”
              ├─ 当前筛选无匹配 → 显示筛选无结果与重置入口
              └─ 有结果 → 固定排序展示 → 点击授权建议 → PAGE-F05-03
```

**切换历史批次**

```text
选择历史批次
    │
    ├─ 加载成功 → 更新批次摘要 → 清空不适用于新批次的筛选 → 回到第一页
    ├─ 对象不存在/已失权 → 不返回批次身份 → 通用不可用结果
    └─ 网络失败 → 保留原批次及其列表 → 明示切换未成功 → 可重试
```

**筛选与分页**

```text
提交搜索/筛选 → 更新查询上下文 → 回到第一页 → 按固定排序加载
翻页/切换每页条数 → 保留批次和筛选 → 加载目标页
从建议详情返回 → 恢复原批次、筛选、页码、每页条数 → 核对最新状态
```

### 6.3 辅助操作

- 按 Enter 提交关键词搜索；输入变化不连续自动请求。
- 单个筛选项可移除；“重置”清除全部搜索和筛选但保留当前批次。
- 浏览器前进/后退恢复 URL 中的批次和列表上下文，不改变业务状态。
- 刷新仅获取最新审核与动作状态，不重算规则、不生成第二份清单。
- 本页不提供任何状态变更快捷操作。

## 7. 状态与边界

### 7.1 页面状态全景

| 状态 | 触发条件 | 页面表现 |
| :--- | :--- | :--- |
| 初始化态 | 权限有效，尚未读取默认批次 | 展示页面框架、当前身份与角色，不展示旧账号或旧批次数据 |
| 加载态 | 首次读取、筛选、翻页或批次切换进行中 | 保留当前查询上下文并标明加载中，不用空列表代替未完成结果 |
| 正常有结果态 | 当前批次与条件返回授权建议 | 显示批次摘要、角色化字段、固定顺序和分页 |
| 无最新批次态 | 授权范围内不存在成功批次 | 明示“尚无可用数据批次”；运营可进入新建导入，其他角色可查看批次进度 |
| 清单空态 | 批次成功但没有需处理的建议 | 明示“本批次无待处理建议”；不把纯维持或不补货创建为任务 |
| 筛选无结果态 | 清单有建议，但当前条件无匹配 | 显示生效条件与重置入口，不显示“本批次无问题” |
| 批次切换失败态 | 新批次加载失败 | 原批次列表保持可识别且不冒充目标批次，提示切换未成功并可重试 |
| 加载失败态 | 当前列表请求因网络或服务错误失败 | 显示失败批次/条件、重试入口；不把失败显示为空清单 |
| 状态刷新态 | 从详情返回或数据可能被其他用户更新 | 保持位置，重新核对受影响行；成功后显示最新合法状态 |
| 会话失效态 | 登录态过期或认证不可用 | 停止展示新的经营数据，进入重新钉钉认证路径 |
| 无权限态 | 无有效角色、无页面权限或越权读取 | 不返回批次、建议、数量或状态，进入通用无权限路径 |

### 7.2 边界与容错

| 边界场景 | 处理策略 |
| :--- | :--- |
| 网络异常 | 保留当前批次、筛选和页码，显示加载失败与重试；已有旧内容不得标成目标请求的最新成功结果 |
| 会话过期 | 立即停止新请求和业务数据展示，跳转重新登录；恢复后重新按服务端角色加载，不沿用旧角色投影 |
| 连续错误 | 连续加载失败时维持明确失败状态和人工重试入口，不无限自动重试、不重复堆叠提示、不降级为空清单 |
| 异常搜索/筛选输入 | 去除关键词首尾空白；非法筛选值不发送，恢复为角色允许的默认项并提示条件已失效 |
| 并发状态变化 | 其他用户审核或执行后，本页刷新为最新状态；旧列表只读，不覆盖成功状态，也不生成事件 |
| 最新批次变化 | 用户停留期间出现新成功批次时提示存在新批次；只有用户切换后才更新上下文，不把两个批次混合 |
| 历史批次不存在 | 不返回该批次身份或清单摘要；回到可用批次或给出通用不可用结果 |
| 采购无任务关联 | 不展示建议身份、状态和数量；通过搜索、筛选或直链均不能推断对象是否存在 |
| AI 等待或失败 | 继续展示结构化四要素和固定规则排序；AI 状态仅作降级提示，不阻断进入详情 |
| 双动作进度不一致 | 分别显示经营与采购状态，建议总览只能显示执行中等只读聚合，不标为全部完成 |
| 纯维持或仅不补货 | 不进入清单；不得为了填充页面创建经营或采购任务 |
| 页码越界 | 筛选、权限或数据变化使页码失效时回到最后一个有效页，并保留其他有效条件 |
| 详情返回时已失权 | 不恢复受限行内容，进入通用无权限状态；旧页面缓存不作为权限依据 |
| 窄屏/缩放 | 关键 SPU、动作、审核和分动作状态保持完整可读；密集字段可横向查看，不裁掉语义 |

## 8. 业务规则与校验

### 8.1 字段定义

| 字段 | 说明 |
| :--- | :--- |
| `batch_id` | 当前清单所属的不可变批次身份；每批次仅一份清单 |
| `decision_id` | 一条 SPU 整体建议的稳定身份，同批次同 SPU 仅一条 |
| `spu_id` / `spu_name` | SPU/商品链接身份；首版不拆 SKU |
| `store` / `platform` / `operator_ref` | 店铺、平台、责任运营；采购不获得责任运营筛选 |
| `main_action` | 唯一经营主动作：清仓、止损、观察、加投；纯维持默认不进入清单 |
| `replenishment_action` | 补货、禁止补货、不补货或不生成；不补货不单独建立采购任务 |
| `review_state` | 建议级待审核、已通过或已驳回 |
| `operation_execution_state` | 经营动作的待审核、待执行、已执行、已记录结果或已关闭 |
| `procurement_execution_state` | 采购动作的待审核、待执行、已执行/已确认禁补、已记录结果或已关闭 |
| `summary_state` | 基于建议和各动作状态的只读聚合，不覆盖分动作事实 |
| `priority_proxy` | 规则版本明确且数据已校验的同动作层影响代理指标；可能为空 |
| `stable_order_key` | 无有效代理指标时使用的稳定 SPU ID 或批次内生成序号 |
| `data_quality_flags` | 品退未校验、库存不足等限制标记 |
| `ai_status` | 待生成、生成中、已生成或生成失败；不控制清单可用性 |

### 8.2 校验规则

| 校验项 | 时机 | 规则 | 失败反馈 |
| :--- | :--- | :--- | :--- |
| 批次选择 | 切换时 | 必须是当前用户有权查看且清单可用的真实批次 | “该批次暂不可用”，不泄露批次或建议详情 |
| 关键词 | 提交搜索时 | 去除首尾空白；空值等同清除 | 空值不报错，恢复无关键词状态 |
| 筛选项 | 选择或恢复 URL 时 | 只接受当前角色可见的受控选项 | 非法或越权条件被移除，并按当前角色重新加载 |
| 页码 | 翻页或恢复 URL 时 | 必须在当前结果有效范围内 | 回到最后有效页并提示结果已更新 |
| 每页条数 | 切换或恢复 URL 时 | 只允许 20、50、100 | 非法值使用默认 20 |
| 建议详情入口 | 点击行时 | 建议必须属于当前批次且当前角色有权查看 | 通用无权限/不可用结果，不返回对象身份与状态 |
| 排序代理 | 列表生成时 | 仅使用规则版本明确且数据已校验的代理指标 | 不可用时回退稳定 ID，不由 AI 或空值猜测 |

### 8.3 特殊业务规则

- **每批次唯一清单**：行动清单只投影该批次既有建议和动作，不允许重复生成第二套身份。
- **固定排序**：第一层严格为清仓、止损、观察、加投、补货；同一层使用规则版本定义的有效代理指标降序，否则使用稳定 ID/序号。AI 不得改变层级或结果。
- **收录规则**：纯维持且无补货/禁补不进入；数据完整得到“不补货”不单独创建采购任务；加投与补货并存仍为一条建议。
- **历史不可覆盖**：新批次、当前规则或当前源表不得改写历史清单、审核、动作与结果。
- **状态分层**：主管对整条建议一次审核；通过后经营与采购动作分别执行。列表必须分别显示，不以总览状态替代事实。
- **角色裁剪**：运营和主管可见完整经营信息但只有主管审核；运营只执行经营动作；采购只见任务必要投影并只处理补货/禁补。
- **AI 非阻塞**：AI 等待或失败时继续显示结构化对象、问题、依据和动作，并允许进入既有业务流程。
- **只读列表**：筛选、分页、搜索、批次切换和刷新均不得产生审核、执行、结果或事件写入。

### 9.1 流转图

```text
角色化工作台 / 左侧导航 / 批次详情
                │
                ▼
       行动清单 PAGE-F05-02
                │
        选择批次、筛选、分页
                │
                ├─ 授权建议 → 建议详情 PAGE-F05-03
                │                  │
                │                  └─ 返回 → 恢复原批次与列表上下文
                │
                ├─ 无最新批次 → 数据批次列表 / 新建导入（仅运营）
                └─ 会话失效/越权 → 钉钉登录 / 无权限页
```

### 9.2 与其他模块的关系

- **数据批次**：本页按 `batch_id` 展示唯一行动清单；从批次详情进入时预选该批次。
- **固定规则与 AI**：固定规则决定收录、动作和排序；AI 只解释，等待或失败不改变列表。
- **审核与执行**：本页显示建议与分动作状态，但状态变更只能在建议详情完成。
- **权限**：服务端按钉钉映射角色返回不同列表投影；前端隐藏不是权限边界。
- **追溯**：历史批次及状态保留；需要完整规则路径和事件时进入建议详情或追溯记录。

### 9.3 扩展预案

| 扩展方向 | 触发条件 | 改造点 |
| :--- | :--- | :--- |
| 外部执行回执 | 外部系统 API、幂等、凭据、审批与回滚责任正式立项 | 在既有动作状态旁增加外部回执引用，不把当前人工确认改称外部成功 |
| 广告明细动作 | 广告计划/单元/关键词/素材数据和责任边界具备 | 新增经批准的动作类型与筛选，不改写 SPU 主动作历史 |
| SKU 决策清单 | SKU 数据、SPU-SKU 口径、规则与责任人重新立项 | 使用新对象类型及独立页面，不把 MVP SPU 清单静默拆分 |
| 批量操作或导出 | 新增稳定 REQ/AC，并确认权限、审计与风险控制 | 增量设计，不在当前列表预埋隐藏入口 |

| 数据 | 触发时机 | 用途 |

### 10.3 明确排除的数据
