## 2. 页面概述

### 2.1 一句话定位

让授权用户按批次、SPU、动作、状态、操作人和时间查回不可覆盖的决策快照与成功/失败事件，还原“什么数据产生了什么结论，谁之后做了什么”。

### 2.2 存在理由

1. 当运营止损与采购补货状态不一致时，需要证明两条动作轨道的真实顺序。
2. 当数据或规则更新时，必须保留历史批次的原始关键值和规则版本。
3. 当 AI 失败、越界或并发冲突时，需要保证已有成功事件不被删除或覆盖。

### 2.3 页面目标（可衡量）

| 目标维度 | 具体指标 |
| :--- | :--- |
| 完整性 | 每条决策可追溯到批次、业务期间、规则版本、关键值、操作人和时间 |
| 事件保留 | 已驳回、部分执行、并发冲突和 AI 失败不删除既有成功事件 |
| 权限隔离 | 采购页面、错误路径和详情跳转中完整利润、推广、售后字段出现数为 0 |
| 定位效率 | 从批次详情带预置筛选进入时，无需重复输入批次条件 |

### 2.4 不做什么（范围边界）

- 不做事件编辑或删除，因为追溯事实只能追加。
- 不做全局导出，因为 MVP 未定义导出权限和脱敏范围。
- 不做独立审计详情页，建议详情时间线已承载单对象语境。
- 不扩大采购数据权限，追溯需求不构成越权理由。
- 不将当前状态当作历史，事件顺序和前后值必须独立展示。

## 3. 用户与场景

### 3.1 目标用户

| 角色 | 使用目的 | 数据边界 |
| :--- | :--- | :--- |
| 运营 | 追溯批次输入、决策、审核和经营动作 | 可看完整经营证据与授权事件 |
| 运营主管 | 复盘整体审核与跨角色执行断点 | 可看完整经营证据与授权事件 |
| 采购计划 | 追溯本任务补货/禁补决策与执行 | 仅看补货/禁补、库存、销量与本角色事件 |

### 3.2 核心使用场景

**场景 A：复盘跨角色执行断点（主场景）**
- 时机：主管发现某建议总览显示“执行中”。
- 前置：建议已通过，至少有两条动作轨道。
- 动作：按 SPU 与状态筛选→查看审核与动作事件顺序→进入建议详情。
- 情绪：能够确定责任断点，不依赖口头追问。

**场景 B：从历史批次还原决策（兜底场景）**
- 时机：新批次与旧批次结论不同。
- 前置：旧批次快照和规则版本仍存在。
- 动作：从批次详情进入→使用预置批次筛选→追溯当时关键值与规则版本。
- 情绪：相信历史可重放，不怀疑系统改写旧结论。

**场景 C：采购查询禁补确认**
- 时机：采购需确认自己是否已停补。
- 前置：其铉铉身份映射为采购计划且对该任务有权。
- 动作：按禁补与本人筛选→查看已授权事件→进入裁剪后建议详情。
- 情绪：清楚任务事实，不接触无关利润信息。

### 3.3 用户核心诉求（优先级排序）

1. **真**：历史事件不被后续状态覆盖。
2. **准**：能精确定位批次、SPU、角色和时间。
3. **安全**：追溯不扩大角色数据可见范围。
4. **可读**：前后状态、操作人和业务备注可快速串联。

- 事件类型、SPU/对象、动作轨道、前状态、后状态、操作人、时间、批次、规则版本、备注/结果摘要。
- 行跳转到建议详情对应时间线；批次引用可返回批次详情。

## 6. 交互流程

### 6.1 页面加载与初始化

1. 验证铉铉会话与当前角色。
2. 校验路由中批次/建议预置条件是否在权限内；越权则进入通用无权限路径。
3. 以默认 20 条/页读取按事件时间倒序的授权记录。
4. 若无预置条件，显示全部授权记录；若无任何记录，进入无记录状态。

### 6.2 核心操作流程

```text
用户选择或调整筛选
        │
        ├─ 条件越权/不可见 → 通用无权限路径，不回传对象摘要
        │
        ├─ 条件合法但无结果 → 筛选无结果，保留条件
        │
        └─ 条件合法且有结果 → 显示事件列表
                                      │
                                      └─ 点击事件→建议详情对应时间线
```

### 6.3 辅助操作

- 删除单个筛选标签或重置全部筛选。
- 从批次引用返回对应批次详情。
- 从建议详情返回时保留页码与筛选上下文。

## 7. 状态与边界

### 7.1 页面状态全景

| 状态 | 触发条件 | 页面表现 |
| :--- | :--- | :--- |
| 初始加载 | 首次进入 | 保留页面框架，列表区显示加载反馈 |
| 正常有数据 | 授权查询返回事件 | 显示筛选、事件行与分页 |
| 无记录 | 当前权限内尚无历史事件 | 说明尚无可追溯记录，不显示错误 |
| 筛选无结果 | 有历史但条件未命中 | 保留标签并提供重置 |
| 加载失败 | 网络或服务失败 | 不伪造空列表，显示可重试反馈 |
| 会话失效 | 铉铉会话过期 | 进入重新登录路径，不保留受限数据 |
| 无权限 | 无映射、越权路由或对象不可见 | 通用无权限页，不证实对象存在 |

### 7.2 边界与容错

| 边界场景 | 处理策略 |
| :--- | :--- |
| 网络中断 | 保留当前筛选，显示重试；不把失败当无记录 |
| 会话过期 | 停止渲染数据并重新登录，成功后再按权限重查 |
| 连续错误/重复点击 | 同一页请求未完成时不重复发起，不自行增加安全锁定阈值 |
| 异常筛选参数 | 拒绝非法时间范围、未知状态或无权批次；不拼接原始查询 |
| 查询期间新事件追加 | 当前页已返回行保持稳定，刷新后再按事件时间与稳定 ID 重排 |
| 事件指向的建议对当前角色不可见 | 不跳转并返回通用拒绝，不展示标题或字段 |
| 并发冲突事件 | 显示冲突请求的操作人/时间与未落状态结果，保留先前成功事件 |
| AI 失败/越界 | 保留规则决策、兜底说明和已有事件，仅标记 AI 独立状态 |
| 历史规则版本已停用 | 继续展示当时版本引用，不用当前规则重算或改写 |
| 采购修改 URL 查询利润/推广事件 | 服务端默认拒绝，页面与错误路径均不返回受限字段 |

## 8. 业务规则与校验

### 8.1 字段定义

| 字段 | 说明 |
| :--- | :--- |
| `event_id` | 事件稳定身份，用于相同时间打破平局 |
| `event_type` | 批次、审核、经营动作、采购动作、结果、AI、冲突或权限拒绝类型 |
| `batch_id` | 不可变来源批次 |
| `decision_id` | 所属建议，用于跳转时间线 |
| `spu_id` | 唯一决策对象，MVP 不使用 SKU |
| `rule_version` | 产生决策时的规则版本 |
| `actor_ref` | 稳定铉铉操作人引用 |
| `occurred_at` | 事件时间，页面按业务时区展示 |
| `before_state` / `after_state` | 状态变更前后值；失败请求的后值为未变 |
| `summary` | 经角色裁剪的备注或结果摘要 |

### 8.2 校验规则

| 校验项 | 时机 | 规则 | 失败反馈 |
| :--- | :--- | :--- | :--- |
| 批次/SPU | 筛选提交 | 必须是当前角色可见对象 | 通用无权限或无结果，不暴露存在性 |
| 时间范围 | 失焦与提交 | 起始不得晚于结束 | “请检查起止时间” |
| 事件类型/状态 | 筛选提交 | 只接受当前产品定义且当前角色可见的枚举 | 移除无效条件并给出可修正提示 |
| 页码/每页数 | 读取时 | 页码为正整数，每页数为 20/50/100 | 回到第 1 页与默认 20 |
| 事件跳转 | 点击行 | 关联建议对当前角色可见 | 不跳转，不显示对象详情 |

### 8.3 特殊业务规则

- 事件只追加，任何页面操作都不得编辑或删除历史事件。
- 状态改变与对应成功事件必须同时存在；失败请求可留审计事件但不改变状态。
- 历史决策只引用当时批次和规则版本，不随当前规则或当前日期重计算。
- 建议已驳回、动作部分执行、AI 失败与并发冲突不得删除既有成功事件。
- 采购追溯数据仍服从最小必要可见，不因审计用途返回完整利润、推广或售后字段。

## 9. 页面流转

### 9.1 流转图

```text
左侧导航 ─────────────┐
批次详情“批次追溯” ──├─→ 追溯记录（本页）
建议详情“完整历史” ──┘            │
                                            ├─ 事件行 → 建议详情对应时间线
                                            └─ 批次引用 → 批次详情
```

### 9.2 与其他模块的关系

- 数据批次提供不可变来源、期间、业务截止日与规则版本上下文。
- 建议与执行提供审核、两条动作轨道和结果事件。
- 权限模块在查询、列表行和跳转目标三处都做角色裁剪。
- AI 模块只追加解释状态，不改写固定规则或审核/动作事件。

### 9.3 扩展预案

| 扩展方向 | 触发条件 | 改造点 |
| :--- | :--- | :--- |
| 外部系统回执 | 外部 API、凭据、幂等、审批和回滚责任正式立项 | 在动作事件增加独立外部回执引用，不改写人工确认事件 |
| SKU 级追溯 | SKU 数据、规则和责任人重新立项 | 增加经确认的对象类型，MVP 的 SPU 快照和 ID 保持不变 |
| 审计导出 | 导出范围、权限、脱敏、保留期和格式有稳定 REQ/AC | 新增受控任务，不在当前列表临时开放 |

## 10. 数据需求

### 10.1 页面需要什么数据

| 数据 | 来源 | 用途 |
| :--- | :--- | :--- |
| 当前操作人与角色 | 铉铉认证与 IT 映射 | 决定页面和数据可见范围 |
| 批次索引 | 批次历史 | 批次筛选与跳转 |
| SPU/建议索引 | 决策快照 | 定位对象和建议详情 |
| 审核与动作事件 | 追加事件 | 显示前后状态、操作人、时间与摘要 |
| 规则与数据快照引用 | 决策记录 | 还原当时依据 |
| 失败审计事件 | 权限、并发与 AI 状态记录 | 说明未改变状态的失败请求 |

### 10.2 页面提交什么数据

| 数据 | 触发时机 | 用途 |
| :--- | :--- | :--- |
| 批次/SPU/动作/状态/操作人/时间条件 | 提交或变更筛选 | 只读查询授权事件 |
| 页码与每页数 | 分页操作 | 返回稳定结果窗口 |
| 事件/建议引用 | 点击行 | 进入授权详情上下文 |

### 10.3 明确排除的数据

- 不提交任何事件编辑或删除数据。
- 不为采购请求完整利润、推广、品退或售后字段。
- 不请求 LiteLLM 凭据、铉铉认证票据或可恢复密钥内容。
- 不请求原 XLSX 文件下载。
- 不请求用当前规则重算历史建议。

## 11. 验收标准

### 11.1 功能验收

| 编号 | 验收点 | 通过标准 |
| :--- | :--- | :--- |
| F-01 | 批次追溯 | 从批次详情进入后自动带入对应批次，不混入其他批次 |
| F-02 | 决策快照 | 每条决策可见当时批次、业务期间、规则版本与关键值引用 |
| F-03 | 审核事件 | 通过/驳回显示操作人、时间、前后状态与备注，驳回原因保留 |
| F-04 | 分动作事件 | 经营与采购动作分别显示，一方完成不覆盖另一方 |
| F-05 | 结果事件 | 已执行后的结果周期、备注与可用销售/利润/库存结果按权限显示 |
| F-06 | 失败保留 | 已驳回、部分执行、并发冲突和 AI 失败不删除已有成功事件 |
| F-07 | 详情流转 | 点击事件进入正确建议的历史上下文，返回时保留筛选 |

### 11.2 体验验收

| 编号 | 验收点 | 通过标准 |
| :--- | :--- | :--- |
| U-01 | 筛选可见 | 已生效条件以明确标签呈现，可单独移除或全部重置 |
| U-02 | 空与错分离 | 无记录、筛选无结果与加载失败使用不同反馈 |
| U-03 | 事件可读 | 一行内能识别事件类型、对象、前后状态、操作人与时间 |
| U-04 | 稳定分页 | 相同条件刷新后使用事件时间和稳定 ID 得到可重现顺序 |
| U-05 | 失败可恢复 | 网络失败后可保留条件重试，不强制重新输入 |
| U-06 | 预置上下文 | 从批次详情进入后 1 次操作内看到该批次事件 |

### 11.3 安全验收（产品层）

| 编号 | 验收点 | 通过标准 |
| :--- | :--- | :--- |
| S-01 | 会话门禁 | 无有效铉铉会话或角色映射时 100% 不返回追溯数据 |
| S-02 | 采购最小可见 | 采购列表、筛选候选、详情跳转和错误中完整利润、推广、售后字段出现数为 0 |
| S-03 | 越权不泄露 | 修改路由或查询参数访问无权对象时，响应不证实对象存在 |
| S-04 | 事件不可改 | 页面不提供编辑/删除，状态更新不能覆盖历史事件 |
| S-05 | 凭据保密 | 页面、列表数据、错误和跳转参数不包含 LiteLLM 密钥、铉铉票据或可恢复内容 |
| S-06 | 历史稳定 | 当前规则更新后，该页仍显示历史批次原规则版本与原关键值引用 |
