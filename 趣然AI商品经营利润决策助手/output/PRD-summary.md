# 趣然 AI 商品经营与利润决策助手 · 摘要版

**版本**：V0 / 阶段 5 正式版  
**完整 PRD**：`output/PRD详细版.md`  
**开发版**：`output/PRD-dev.md`  
**机器需求契约**：`output/requirements.md`

## 1. 这是什么

面向趣然电商内部运营、运营主管和采购计划的周度 SPU 经营行动清单工具：统一读取经营数据，用固定利润规则决定加投、观察、止损、清仓、补货或禁补，再由 AI 解释依据并推动人工轻闭环。

## 2. 为什么做

销售、推广、库存、退款和利润数据分散，运营发现亏损后若未同步采购，可能继续补货。真实的布乐迪“忙碌屋”515 案例约延迟两个月才发现明显亏损，随后约滞销三千件、占用库存金额十万元并产生利润损失六万元。（来源：用户确认的 515 案例，详见 PRD §1）

## 3. 给谁做

- 运营：导入与查看完整经营数据，执行加投、观察、SPU 推广止损、清仓和证据支持的优化动作。
- 运营主管：查看完整依据，对整条建议批准或驳回；在动作未执行时可填写理由，将规则建议改判为新的生效经营/库存动作。
- 采购计划：只查看补货/禁补及必要库存、销量依据，执行或确认补货/禁补。
- 事业部负责人：决定试点范围与资源，不作为日常用户。
- 不服务消费者，不处理 SKU，不自动改广告或采购系统。
- 三类直接用户统一通过钉钉独立登录；角色变更由事业部负责人审批，运维/系统管理员按审批结果配置；产品不提供账号密码或业务侧权限后台。

## 4. MVP 怎么工作

1. 每周一导入数据支持部门提供的 SPU XLSX，按批次校验并保存不可变快照。
2. 固定规则按上一个完整自然月销售额、经营准利润率、最近七天品退率和库存可售天数生成唯一经营主动作及库存动作；AI 只解释，不覆盖、不阻塞。
3. 运营主管整体审核；若不采纳规则建议，在未执行时可先完成必填理由、库存动作重新确认和追加审计的人工改判；通过后由运营和采购计划分别执行生效动作。
4. 同一 SPU 跨周命中相同动作时沿用原任务与状态，不重复建任；动作变化（如清仓变观察）时追加待主管确认的新版本，每周决策快照仍独立留存。

## 5. MVP 边界

- 完成 F01—F08 即完成产品范围：数据导入、指标、规则、AI 解释、行动清单、审核执行、权限、溯源。
- 首轮用玩具事业部十至二十个真实 SPU 验收；该数量不是运行硬上限。
- 至少识别三个真实经营问题；每条建议必须含具体对象、发现问题、关键依据和推荐动作。
- 当前不做评价文本、退款原因、广告计划明细、SKU 级经营、自动投放、自动下单和自动库存调整。

## 6. 关键功能

| 功能组合 | 解决的问题 | MVP 结果 |
| :--- | :--- | :--- |
| F01—F02 数据入口与指标 | 人工拉表、口径不一 | 周度批次、字段级校验、统一经营指标 |
| F03 固定规则决策 | 依赖个人经验、动作冲突 | 唯一经营主动作；止损/清仓同步禁补 |
| F04—F05 解释与清单 | 发现问题后难以理解和排序，同动作周周重复建任 | 四要素建议、固定优先级、可筛选周清单、跨周任务续接 |
| F06 审核执行 | 运营止损与采购补货脱节 | 建议整体审核、主管可追溯人工改判、动作分角色执行与结果记录 |
| F07—F08 权限与溯源 | 信息越权、无法复盘 | 采购最小可见、批次规则状态全链路留痕 |

| 指标 | V0 目标 | 来源 |
| :--- | :--- | :--- |
| 真实 SPU 试点规模 | 十至二十个 | 用户确认 |

| 冲突控制 | 止损/清仓不得出现继续补货动作 | 515 案例与固定规则 |
| 轻闭环 | 主管审核，运营与采购各自更新动作及结果 | 用户确认 |

首轮验收责任人为运营：运营依据上述试点规模、真实问题、建议四要素、规则追溯和轻闭环结果，确认建议能否用于首轮业务评审；事业部负责人只负责范围与资源投入。

阶段 2 未执行，因此不设置年度价值、ROI、六个月或十二个月财务目标。

## 8. 关键依赖与风险

1. 数据缺口：当前样本缺 SPU 库存、在途和最近十四天销量。缓解：不生成补货建议，但止损/清仓仍生成禁补。
2. 品退周期不可信：当前样本不能证明为最近七天。缓解：不以该值触发观察或加投条件，显示未校验。
3. AI 或密钥故障：LiteLLM 不可用可能导致解释失败。缓解：固定规则清单、审核和执行继续工作；部署密钥仅由运维维护。
4. 身份接入或角色映射异常：钉钉认证失败或运维/系统管理员未按审批结果配置有效角色时可能无法进入业务页。缓解：默认拒绝且不返回经营数据，引导重新认证或联系运维/系统管理员，不降级为共享账号。

## 9. 当前拍板状态

产品范围和规则无 P0/P1 阻塞项。身份入口已确认为钉钉，角色变更由事业部负责人审批、运维/系统管理员配置；技术栈和 `Asia/Shanghai` 业务时区参数化仍需在设计阶段确认，但不得改变稳定需求契约。
