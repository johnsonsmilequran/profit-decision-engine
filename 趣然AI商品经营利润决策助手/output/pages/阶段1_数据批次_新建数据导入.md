## 2. 页面概述

### 2.1 一句话定位

让有导入权限的运营声明玩具事业部数据期间与批次业务截止日，提交数据支持部门提供的 XLSX 经营表；系统校验后自动处理可判定 SPU，并把用户带到唯一批次的详情页继续查看结果。

### 2.2 存在理由

1. 没有独立导入页，数据期间、业务截止日和源文件容易被混在列表操作中，历史规则结论将失去可靠业务时间基准。
2. 没有文件、身份字段和经营字段分层校验，单个坏字段可能误伤整行，或错误数据可能进入固定规则并形成不可执行建议。
3. 没有指纹幂等保护，重复点击、网络重试和并发提交可能产生多个批次、清单或状态事件，破坏唯一追溯链。
4. 若校验和规则处理被拆成两个用户按钮，运营可能完成上传却忘记生成清单，形成没有明确下一步的半成品批次。

### 2.3 页面目标（可衡量）

| 目标维度 | 具体指标 |
| :--- | :--- |
| 输入完整性 | 每次提交前，事业部、数据期间、业务截止日和 XLSX 文件四项必填信息均完成校验 |
| 期间正确性 | 非完整自然月、起止顺序非法或与业务截止日无法形成有效口径的提交，行动清单发布数为 0 |
| 批次唯一性 | 同一批次指纹在重复点击、网络重试或并发提交下只对应一个批次，新增重复批次、建议和状态事件均为 0 |
| 降级准确性 | 必要身份异常的行不进入计算；经营字段异常只停止依赖该字段的判断，不误删其他可判定结果 |
| 流程闭环 | 新指纹提交通过文件级校验后自动开始字段校验与固定规则处理，无需第二次点击“生成清单” |
| 可追溯性 | 成功建立的批次均固化事业部、期间、业务截止日、源文件名、导入人和首次建立时间 |
| 恢复明确性 | 文件、期间、网络、会话和权限异常均有与原因匹配的下一步，不以空白页或假成功结束 |

### 2.4 不做什么（范围边界）

- **不做**第二个“生成清单”按钮——校验通过后自动进入固定规则处理，避免上传与计算断裂。
- **不做**批次结果、拒绝行和字段降级的完整明细浏览——这些内容由数据批次详情 `PAGE-F01-03` 承载；本页只提供提交前校验与处理进度。
- **不做**错误文件下载、校验报告导出或在线修表——MVP 未承诺这些能力，运营应修正源 XLSX 后形成不同指纹的新批次。
- **不做**CSV、在线表格、数据库连接或自动同步——V0 仅接收数据支持部门提供的 XLSX。
- **不做**旧批次编辑、覆盖、删除或重新套用当前规则——历史批次不可变；修正数据必须建立新批次。
- **不做**SKU 映射、SKU 级导入或链接级费用分摊——当前唯一决策粒度为 SPU/商品链接。
- **不做**把 10—20 个 SPU 作为上传硬门槛——该数量仅是首轮验收规模，合法数据不因超出范围被拒绝。

## 3. 用户与场景

### 3.1 目标用户

| 维度 | 描述 |
| :--- | :--- |
| 角色 | 运营；运营主管与采购计划不具备本页导入能力 |
| 使用目标 | 每周一接收数据支持部门经营表后，建立可追溯的新业务批次并自动启动本周规则处理 |
| 使用频率 | 每周集中使用；数据修正或网络恢复后按需重试 |
| 技术熟练度 | 中等，熟悉 Excel 和内部经营系统，但不应要求理解字段依赖或幂等技术概念 |
| 使用设备 | 公司 PC 浏览器 |
| 使用姿势 | 桌面近距离操作，先核对业务日期，再选择本地 XLSX 并一次提交 |
| 权限边界 | 只有当前有效角色为运营时可进入和提交；其他角色不展示导入入口，越权直链不返回文件或批次数据 |

### 3.2 核心使用场景

**场景 A：导入本周经营表并自动生成批次结果（主场景）**

- 时机：每周一，运营收到数据支持部门提供的新 SPU 经营表。
- 前置条件：用户已通过身份门禁且当前角色为运营；已向数据支持部门核对上一个完整自然月期间和批次业务截止日；文件为可读 XLSX。
- 用户动作：确认玩具事业部 → 填写数据期间与业务截止日 → 选择 XLSX → 核对口径提示 → 点击“导入并处理” → 系统校验并自动运行固定规则 → 进入数据批次详情。
- 用户情绪：谨慎但希望一步完成，尤其需要确信期间没有填错且系统不会漏掉后续规则处理。

**场景 B：修正期间或文件错误后重新提交（兜底场景）**

- 时机：提交前发现期间不完整，或提交后系统识别到文件损坏、表头无法映射、身份字段错误或经营字段异常。
- 前置条件：尚未产生可发布的行动清单；页面保留用户已填写的非敏感表单内容和明确错误定位。
- 用户动作：按提示修正日期或重新选择文件；若批次已建立则先进入详情查看完整校验结果，再修正源文件并新建不同指纹批次。
- 用户情绪：有压力但不迷茫，能够区分“整个批次不能继续”“某行被拒绝”和“仅部分判断降级”。

**场景 C：网络重试或多窗口重复提交命中原批次（幂等场景）**

- 时机：提交后网络中断，用户刷新页面、再次点击，或在另一个窗口提交完全相同的事业部、期间、截止日和文件内容。
- 前置条件：第一次请求已经成功建立批次，后续请求携带相同业务输入。
- 用户动作：再次提交相同内容 → 系统识别相同指纹 → 告知“已存在相同数据批次” → 进入原批次详情查看原处理与清单状态。
- 用户情绪：先担心是否重复生成，随后能够确认只有一个批次和一条历史链。

### 3.3 用户核心诉求（优先级排序）

1. **不重复**：不论点击、重试还是并发，完全相同的输入只产生一个批次。
2. **口径正确**：数据期间和截止日必须清楚，不能用上传时间代替业务日期。
3. **一步完成**：一次提交自动完成校验与固定规则处理，不再寻找第二个按钮。
4. **错误可修**：知道是文件级、期间级、行级拒绝还是字段级降级，并知道下一步去哪里查看或修正。
5. **不误伤数据**：某个非身份字段错误时，其他仍有依据的判断继续处理。
6. **历史可信**：原批次不被修正文件覆盖，导入人和首次建立时间可追溯。

## 4. 信息架构

### 4.1 区域划分

1. 全站导航与身份上下文区
2. 页面标题与口径说明区
3. 批次业务信息区
4. XLSX 文件选择区
5. 提交前检查与主操作区
6. 解析、校验与自动处理状态区
7. 错误反馈与恢复区

### 4.2 区域内容

**1. 全站导航与身份上下文区**

- 左侧导航中的“数据批次”为当前模块。
- 顶部显示当前业务角色与钉钉身份；角色不可在本页自由切换。
- 提供返回数据批次列表的路径；离开时按未提交内容规则处理。

**2. 页面标题与口径说明区**

- 页面名称“新建数据导入”。
- 说明本次操作将创建或命中一个不可变批次，并自动执行校验和固定规则。
- 提示数据期间必须为本批次使用的上一个完整自然月，业务截止日用于冻结新品年龄判断。
- 提示 10—20 个 SPU 是首轮验收规模而非合法性门槛。

**3. 批次业务信息区**

- 事业部：V0 固定可选“玩具事业部”。
- 数据期间：开始日、结束日和“上一个完整自然月”口径确认。
- 批次业务截止日：独立日期，不使用实际上传日自动替代。
- 字段下方承载局部校验；页面顶部同时提供提交失败汇总，便于一次定位多个问题。

**4. XLSX 文件选择区**

- 文件选择或替换入口，仅接收 XLSX。
- 已选文件摘要：文件名、文件类型和是否可进入解析。
- 文件口径提示：按 SPU/商品链接识别明细，忽略源表汇总行，不接收 SKU 级替代数据。
- 重新选择文件后，清除只属于旧文件的解析错误；保留用户填写的期间和截止日。

**5. 提交前检查与主操作区**

- 检查摘要：必填项、期间关系和文件是否已选择。
- 唯一主操作：“导入并处理”。
- 次操作：“取消并返回数据批次列表”。
- 不出现“仅上传”“保存草稿”“生成清单”或“重新运行规则”等第二条业务路径。

**6. 解析、校验与自动处理状态区**

- 显示当前步骤：提交中、解析文件、校验期间与字段、自动运行固定规则、正在进入批次详情。
- 批次身份已建立后显示稳定批次编号；后续状态变化继续属于该批次。
- 指纹命中时显示原批次编号与既有处理/清单状态，并直接提供进入原批次详情的明确反馈。

**7. 错误反馈与恢复区**

- 表单错误：指出具体字段和修正方式。
- 文件级错误：区分非 XLSX、不可读取、损坏、加密或无法识别明细结构。
- 数据错误摘要：区分批次级期间错误、必要身份导致的拒绝行、经营字段导致的依赖降级和普通警告。
- 网络/会话/权限错误：分别提供重试、重新登录或无权限恢复路径，不使用“无数据”代替。

## 5. 界面内容

### 5.1 元素清单

**页面标题与说明**

- 内容：“新建数据导入”；说明“导入后系统将自动校验并运行固定规则”。
- 数据来源：固定产品文案与已确认流程。
- 显示条件：授权运营进入页面时始终显示。

**事业部字段**

- 内容：玩具事业部。
- 文案：“事业部”。
- 数据来源：V0 试点范围。
- 显示条件：页面正常可用时显示；当前仅一个可选值，不允许填写自由文本。
- 固化规则：提交开始后不可修改，保存为批次身份的一部分。

**数据期间字段**

- 内容：期间开始日、期间结束日；首批合法示例为 `2026-06-01` 至 `2026-06-30`。
- 文案：“数据期间”“用于销售、利润与费用口径，必须是上一个完整自然月”。
- 数据来源：运营依据数据支持部门供数说明填写。
- 显示条件：页面正常可用时始终显示，必填。
- 反馈：展示起止顺序、是否完整自然月及与截止日关系的校验结果，不从文件的自然语言表头猜测期间。

**批次业务截止日字段**

- 内容：一个明确自然日期。
- 文案：“业务截止日”“用于冻结新品年龄及数据窗口解释，不是上传日期”。
- 数据来源：数据支持部门提供业务口径，运营导入时核对。
- 显示条件：页面正常可用时始终显示，必填。
- 固化规则：第一次成功建立批次后不可修改；重试仍使用原值。

**XLSX 文件选择**

- 内容：选择或替换本地 `.xlsx` 文件。
- 文案：“经营数据文件”“仅支持数据支持部门提供的 XLSX”。
- 数据来源：运营本地选择。
- 显示条件：页面正常可用时始终显示，必填。
- 选择后展示：文件显示名和当前选择状态；不展示本地绝对路径。

**文件口径提醒**

- 内容：按商品链接识别 SPU；必要身份包括 SPU ID、链接名称、店铺、平台和责任运营；源表汇总行不参与 SPU 决策。
- 数据来源：F01 导入契约。
- 显示条件：未提交和文件错误后均显示，帮助运营在修表前理解校验原则。

**试点规模提醒**

- 内容：“首轮验收建议使用 10—20 个真实 SPU；数量不在此范围仍可校验和处理。”
- 数据来源：MVP 验收边界。
- 显示条件：页面初始态显示；校验完成后以实际有效 SPU 数更新为“符合/不属于首轮验收规模”提示，不升级为错误。

**导入并处理按钮**

- 文案：“导入并处理”。
- 数据来源：用户操作。
- 显示条件：授权运营始终可见；必填项缺失、存在已知期间错误、未选择可接受文件或正在提交时不可用并说明原因。
- 操作结果：提交一次业务请求；新指纹自动进入校验与固定规则处理，命中指纹则进入原批次。

**取消并返回按钮**

- 文案：“取消并返回”。
- 显示条件：尚未进入不可中断的提交阶段时可用。
- 操作结果：无未提交内容时直接返回 `PAGE-F01-01`；有未提交内容时先确认是否离开，确认后丢弃本页输入但不影响任何已建立批次。

**处理步骤与进度文案**

- 内容：提交中、文件解析中、数据校验中、固定规则处理中、准备进入批次详情。
- 数据来源：当前导入请求或已建立批次状态。
- 显示条件：点击“导入并处理”后显示；仅陈述已确认状态，不显示虚假完成百分比。
- 约束：处理期间不可再次提交同一表单；刷新或网络恢复后按相同指纹回到原批次状态。

**指纹命中提示**

- 文案：“已存在相同数据批次，未重复创建；正在打开原批次。”
- 内容：原批次编号、原处理状态、原清单状态和“查看原批次”。
- 数据来源：事业部、数据期间、业务截止日和文件内容共同形成的匹配结果。
- 显示条件：同一业务输入已成功建立批次时显示。

**错误汇总**

- 内容：错误所属层级、可读原因、影响范围和下一步。
- 数据来源：表单校验、文件解析与批次校验结果。
- 显示条件：存在一个或多个问题时显示；字段旁仍保留对应局部提示。
- 文案原则：区分“不能建立有效处理”“该行不进入计算”“只停止依赖判断”和“普通提醒”。

## 6. 交互流程

### 6.1 页面加载与初始化

1. 用户进入页面后，系统先校验有效登录态、当前业务角色和导入权限。
2. 会话有效且角色为运营时，显示空白导入表单；事业部限定为“玩具事业部”，期间、截止日和文件等待用户填写。
3. 会话失效时不加载或保留文件内容，进入重新登录路径；角色无导入权限时不显示表单与历史批次信息，进入无权限路径。
4. 页面提示上一个完整自然月、业务截止日、XLSX、SPU 粒度和自动处理规则。
5. 页面不自动提交、不自动保存文件草稿，也不根据当前日期替用户静默决定业务截止日。

### 6.2 核心操作流程

```text
进入新建数据导入
    │
    ├─ 会话失效 / 无导入权限
    │      └─ 不展示经营数据或文件内容 → 重新登录 / 无权限页
    │
    └─ 权限有效
           │
           ├─ 填写玩具事业部、完整自然月期间、业务截止日
           ├─ 选择 XLSX
           └─ 点击“导入并处理”
                  │
                  ├─ 表单或期间校验失败
                  │      └─ 留在本页 → 定位字段并修正 → 再次提交
                  │
                  └─ 提交业务输入
                         │
                         ├─ 指纹已存在
                         │      └─ 不创建批次/建议/事件 → 提示命中 → 打开原批次详情
                         │
                         └─ 新指纹
                                │
                                ├─ 文件不可读 / 结构不可识别
                                │      └─ 显示文件级失败 → 不发布清单 → 允许替换文件
                                │
                                └─ 文件可解析
                                       │
                                       ├─ 忽略汇总行并校验 SPU 明细
                                       ├─ 身份异常行拒绝；经营字段异常按依赖降级
                                       ├─ 自动处理仍可判定的 SPU
                                       └─ 自动进入数据批次详情，查看校验、规则与清单状态
```

规则处理一旦被自动启动，页面不得要求用户再点击“生成清单”。AI 解释不属于本页提交完成条件，也不阻断固定规则批次进入后续查看。

### 6.3 辅助操作

- 更换文件：提交前可重新选择 XLSX；重新选择后清除旧文件对应错误，期间与截止日保留。
- 修正日期：失焦时提示明显格式/关系错误，提交时统一完成全量校验。
- 取消返回：存在未提交内容时先确认；确认离开只丢弃本地表单，不删除任何批次。
- 网络恢复重试：沿用当前事业部、期间、截止日和文件内容重新提交；命中已建立批次时直接返回原状态。
- 查看既有批次：指纹命中提示提供唯一的“查看原批次”路径，不提供“仍然新建”。

## 7. 状态与边界

### 7.1 页面状态全景

| 状态 | 触发条件 | 页面表现 |
| :--- | :--- | :--- |
| 初始态 | 运营首次进入且会话有效 | 显示四项输入、口径说明和不可提交的主按钮 |
| 编辑态 | 用户已填写任一字段或选择文件 | 显示已输入内容，按字段反馈可立即判断的问题 |
| 可提交态 | 四项必填完整，期间关系初步合法，已选择 XLSX | “导入并处理”可用；提示提交后自动校验与运行规则 |
| 提交态 | 用户点击主按钮且请求尚未确认 | 主按钮进入处理中并阻止重复提交；显示提交状态 |
| 解析/校验态 | 新指纹已被接收，正在读取文件、校验期间与字段 | 显示当前步骤；已建立时显示批次编号；不可修改已固化输入 |
| 自动规则处理态 | 文件及批次级期间可继续，字段校验已形成可处理结果 | 显示“固定规则处理中”；不出现第二个生成按钮；随后进入批次详情 |
| 指纹命中态 | 相同事业部、期间、截止日和文件内容已建立批次 | 明确说明未重复创建，显示原批次与既有清单状态并打开原详情 |
| 表单失败态 | 必填缺失、日期格式/顺序错误或期间不是完整自然月 | 停留本页，字段定位与顶部摘要同时显示；不提交处理 |
| 文件失败态 | 非 XLSX、损坏、加密、不可读取或无法识别明细结构 | 显示文件级原因，不发布行动清单；允许替换文件重试 |
| 数据降级态 | 文件可读但存在拒绝行、字段级降级或警告 | 自动处理其他可判定结果；进入批次详情查看完整分区结果 |
| 网络异常态 | 提交或查询状态时断网、超时 | 不宣称成功；保留可安全恢复的表单上下文，提供重试；重试遵守指纹幂等 |
| 会话失效态 | 处理前或提交时登录态失效 | 停止展示文件与经营数据，进入重新登录；恢复后重试仍命中既有批次 |
| 无权限态 | 当前角色不是运营或权限已变化 | 不显示表单、文件名或批次数据，进入通用无权限路径 |

### 7.2 边界与容错

| 边界场景 | 处理策略 |
| :--- | :--- |
| 网络在首次提交前断开 | 显示网络异常，不建立假成功状态；用户可在网络恢复后重试 |
| 网络在批次建立后中断 | 不要求重新生成；相同内容重试返回原批次和当前处理状态，不新增批次、建议或事件 |
| 会话在编辑过程中到期 | 提交时停止业务处理并进入重新登录；页面不向未认证状态继续暴露已选文件或批次信息 |
| 连续选择多个错误文件 | 每次只反馈当前所选文件的问题；替换文件后清除旧文件错误，不累计成不可恢复锁定，也不静默放行 |
| 文件扩展名伪装、损坏、加密或不可读取 | 归类为文件级失败，显示可修正原因，不发布清单，不尝试从文件名推断内容 |
| 数据期间缺失、起止颠倒或跨越多个自然月 | 字段和页顶同时提示，不进入依赖该期间的规则处理，不发布行动清单 |
| 业务截止日早于数据期间结束日 | 视为日期关系错误，要求运营核对；不以上传日或系统当前日自动替换 |
| 表内汇总行与明细合计不一致 | 忽略汇总行并仅以有效 SPU 明细处理；形成普通警告供批次详情查看，不把汇总值分摊到 SPU |
| 必要身份列缺失或表头无法唯一映射 | 受影响身份无法建立时拒绝对应行；若无法识别任何有效 SPU，则批次不得发布行动清单，并在详情保留错误证据 |
| 同一 SPU ID 在批次内重复 | 所有冲突行均不进入计算，并保留各自原始行位置；其他唯一 SPU 继续处理 |
| 上架日期、销售、利润、品退或库存值异常 | 保留该 SPU 身份和原始值，只停止依赖该字段的分类、动作或补货判断，不用默认值、其他字段或 AI 补齐 |
| 有效 SPU 少于 10 或多于 20 | 仅提示“不属于首轮验收规模”，不因数量本身拒绝合法批次 |
| 用户连续点击提交 | 第一次请求完成前阻止重复点击；即便重复请求已到达，也按指纹返回第一次成功建立的批次 |
| 两个窗口或两名操作同时提交相同输入 | 所有请求返回同一批次和既有清单状态，只有第一次成功建立行为进入历史 |
| 同期间但文件内容或业务截止日不同 | 形成不同的新批次，不覆盖原批次；是否为修正由批次历史解释，不在本页编辑旧记录 |
| 指纹命中批次仍在处理中或已失败 | 返回原批次的真实当前状态并进入详情，不以新批次绕过失败，也不套用当前规则重算历史 |
| 提交中用户尝试离开 | 若批次身份尚未确认，提示等待或确认离开；若已建立，离开不取消批次处理，后续从批次列表查看原状态 |

## 8. 业务规则与校验

### 8.1 字段定义

| 字段 | 说明 |
| :--- | :--- |
| `business_unit` | 本批次事业部；V0 为玩具事业部，属于批次指纹的一部分 |
| `period_start` | 月度经营数据期间开始日，应为目标自然月首日 |
| `period_end` | 月度经营数据期间结束日，应为同一目标自然月末日 |
| `business_date` | 批次业务截止日；建立后冻结，用于新品年龄和数据窗口解释，不等于上传时间 |
| `source_file` | 数据支持部门提供的 XLSX 经营表；文件内容参与批次指纹 |
| `source_name` | 供用户辨认的文件显示名，不包含本地绝对路径 |
| `batch_fingerprint` | 由事业部、数据期间、业务截止日和源文件内容共同决定的批次唯一业务身份 |
| `batch_id` | 第一次成功建立后分配的稳定批次编号；重复提交返回同一编号 |
| `source_row_ref` | 源工作表与原始行位置，用于定位拒绝行、字段降级和警告 |
| `spu_id` | 商品链接/SPU 唯一标识；必须存在且在批次内唯一 |
| `spu_name` | 链接名称；必要身份字段 |
| `store` | 店铺；必要身份字段 |
| `platform` | 平台；必要身份字段 |
| `operator_ref` | 责任运营；必要身份字段，用于建议分派 |
| `business_fields` | 上架日期、净销售额、经营准利润率、品退、库存等经营字段；异常时按字段依赖降级，不等同于身份拒绝 |
| `validation_summary` | 有效行、拒绝行、字段级降级与警告的批次汇总 |

### 8.2 校验规则

| 校验项 | 时机 | 规则 | 失败反馈 |
| :--- | :--- | :--- | :--- |
| 事业部必填 | 失焦与提交时 | 必须为当前可选的玩具事业部 | “请选择玩具事业部” |
| 数据期间必填 | 失焦与提交时 | 开始日、结束日均存在 | “请填写完整的数据期间” |
| 期间顺序 | 失焦与提交时 | 开始日不得晚于结束日 | “数据期间开始日不能晚于结束日” |
| 完整自然月 | 提交时 | 起止日必须能解释为同一完整自然月；不得使用跨月片段或未知“上一周”表头代替 | “数据期间必须是本批次使用的完整自然月” |
| 截止日必填 | 失焦与提交时 | 必须提供明确自然日期 | “请选择批次业务截止日” |
| 截止日关系 | 提交时 | 截止日不得早于本批次数据期间结束日，且必须能解释该批次的上一个完整自然月口径 | “业务截止日与数据期间不一致，请核对供数口径” |
| 文件必填 | 提交时 | 必须选择文件 | “请选择经营数据 XLSX” |
| 文件类型 | 选择与提交时 | 仅接受 XLSX；文件名后缀不作为内容可读的唯一依据 | “仅支持可读取的 XLSX 文件” |
| 文件可读性 | 解析时 | 文件未损坏、未加密且可识别工作表和明细结构 | “文件无法读取，请检查是否损坏、加密或结构不受支持” |
| 明细与汇总 | 解析时 | 汇总行不得作为 SPU 明细或参与规则；明细汇总与源合计不一致只形成警告 | “已忽略源表汇总行，系统仅按有效 SPU 明细处理” |
| 必要身份 | 字段校验时 | SPU ID、链接名称、店铺、平台、责任运营均需存在 | “该行缺少必要身份字段，不进入计算”并显示字段和原始行位置 |
| SPU 批次内唯一 | 字段校验时 | SPU ID 在同一批次内不得重复 | “SPU ID 在批次内重复，冲突行不进入计算”并显示全部原始位置 |
| 经营字段 | 字段校验时 | 上架日期、销售、利润、品退、库存分别按自身口径校验 | 显示字段、原值、原始行位置和受影响判断；明确“该行仍保留，依赖判断已降级” |
| 试点规模 | 校验汇总时 | 10—20 个有效 SPU 仅用于首轮验收提示 | 符合时提示“符合首轮验收规模”；其他数量提示“不属于首轮验收规模”，不阻断 |
| 批次指纹 | 请求到达时 | 同事业部、期间、截止日和文件内容视为同一批次 | “已存在相同数据批次，未重复创建”并返回原批次状态 |

### 8.3 特殊业务规则

- **指纹幂等**：重复点击、网络重试或并发提交命中相同指纹时，只返回第一次成功建立的批次及其既有清单状态，不新增批次、建议或状态事件。
- **不可变批次**：事业部、期间、业务截止日和源内容一旦建立批次即冻结；新内容或新截止日创建新批次，不覆盖历史。
- **自动处理**：文件级校验通过后，系统自动校验 SPU 字段，并对仍可判定的 SPU 运行固定规则；用户不需要、也不能通过第二个按钮重复生成清单。
- **期间阻断**：期间缺失、顺序非法或不能解释为完整自然月时，不发布依赖该期间的行动清单。
- **身份拒绝**：SPU ID、链接名称、店铺、平台、责任运营任一缺失，或 SPU ID 批次内重复时，对应行不进入指标和规则计算。
- **字段降级**：上架日期、销售、经营准利润率、品退或库存异常不删除整行；只停止依赖该字段的分类、经营动作或补货判断，其他有依据结果继续。
- **禁止猜测补齐**：不得使用默认值、源表汇总、推广费用、其他 SPU 或 AI 推测补齐缺失经营字段。
- **SPU 粒度**：商品链接即 SPU；表内 SKU 或更细粒度信息不建立首版决策对象。
- **汇总行隔离**：源表合计只可产生一致性警告，不参与 SPU 规则，也不向明细分摊。
- **规模非门槛**：有效 SPU 数量不在 10—20 时仍可建立并处理合法批次，只不计为首轮规模达成。
- **追溯保留**：批次建立及后续处理状态应持续关联批次、业务期间、当前规则或对象版本、导入人和时间；后续更新不得覆盖历史事件。

                   ┌───┴────┐

### 9.2 与其他模块的关系

- **角色化工作台**：仅运营从快捷入口进入本页；导入完成后，后续批次和待办会投影到工作台，但本页不展示角色任务。
- **数据批次列表**：作为本页上游和取消返回路径；新建或命中的批次只在列表中出现一个稳定记录。
- **数据批次详情**：承载批次处理进度、校验摘要、拒绝行、字段降级、警告、规则结果和行动清单；本页自动跳转到该处，不复制完整明细。
- **行动清单**：仅由批次固定规则处理自动形成唯一投影；本页没有手工生成、重新生成或直接编辑入口。
- **追溯记录**：导入人与首次建立时间、批次身份和处理状态由后续追溯页面查看；本页不提供审计编辑。
- **权限模块**：本页只供运营导入；无效会话或无权限身份不得通过直链获取表单中的文件、批次或经营信息。

### 9.3 扩展预案

| 扩展方向 | 触发条件 | 改造点 |
| :--- | :--- | :--- |
| 其他事业部导入 | 后续立项并明确事业部数据口径、权限与规则版本 | 将事业部由 V0 唯一选项扩展为授权选项；既有玩具事业部批次指纹和历史保持不变 |
| 自动数据源连接 | 外部数据源、账号、网络、字段映射和配置责任均已确认并形成稳定需求 | 新入口复用批次身份、期间校验和字段降级规则；不在本页预埋未授权连接配置 |
| 修正批次关联 | 后续明确“更正批次”产品流程及验收条件 | 新批次可引用前序批次与修正原因，但仍不得覆盖旧批次 |
| 错误报告下载 | 后续有稳定需求、权限和数据保护规则 | 从批次详情提供受控导出；本页仍只负责提交与恢复 |
| 其他文件格式 | 后续确认真实供数格式和字段映射规则 | 新格式按独立能力增量设计，不把 CSV 等格式伪装成 XLSX 兼容 |

## 10. 数据需求

### 10.1 页面需要什么数据

| 数据 | 来源 | 用途 |
| :--- | :--- | :--- |
| 当前身份与业务角色 | 当前有效登录态和角色映射 | 判断是否允许展示与提交导入表单 |
| 可用事业部 | V0 产品范围 | 显示唯一可选的玩具事业部 |
| 期间口径说明 | 产品业务规则 | 帮助运营填写上一个完整自然月并解释首批示例 |
| 文件接收规则 | F01 导入范围 | 明确仅支持 XLSX、SPU 粒度和必要身份字段 |
| 当前导入处理状态 | 本次提交或已建立批次 | 展示提交、解析、校验、规则处理、失败或指纹命中状态 |
| 既有批次匹配结果 | 相同批次指纹对应的历史批次 | 命中时展示原批次编号及既有处理/清单状态 |
| 校验摘要 | 文件与字段校验结果 | 在进入详情前说明有效、拒绝、降级和警告的总体影响 |

### 10.2 页面提交什么数据

| 数据 | 触发时机 | 用途 |
| :--- | :--- | :--- |
| 玩具事业部 | 点击“导入并处理” | 固化批次业务范围并参与指纹识别 |
| 数据期间开始日、结束日 | 点击“导入并处理” | 解释上一个完整自然月的销售、利润与费用数据，并参与指纹识别 |
| 批次业务截止日 | 点击“导入并处理” | 冻结新品年龄与业务窗口解释，并参与指纹识别 |
| XLSX 文件内容 | 点击“导入并处理” | 识别 SPU 明细、校验字段并形成文件内容指纹 |
| 源文件显示名 | 点击“导入并处理” | 供批次历史与错误定位展示，不保存用户本地绝对路径 |
| 当前操作者身份 | 系统接受提交时 | 记录第一次成功建立批次的导入人和时间 |

### 10.3 明确排除的数据

- 不提交或保存账号密码、短信/邮件验证码、钉钉票据明文或角色配置。
- 不需要 SKU 映射、SKU 级利润、SKU 库存或 SKU 动作字段。
- 不接收评价文本、退款/退货原因、广告计划/单元/关键词/素材明细。
- 不把源表汇总行作为 SPU 事实，也不把错误合计分摊到明细。
- 不提交“生成清单”第二次请求；规则处理属于同一导入批次的自动后续步骤。
- 不提交旧批次 ID 作为覆盖目标；不同内容只能建立新批次，命中指纹则返回原批次。
- 不要求长期保留原 XLSX 才能查看历史；可追溯依赖已固化的批次、原行定位、关键值和质量记录。

## 11. 验收标准

### 11.1 功能验收

| 编号 | 验收点 | 通过标准 |
| :--- | :--- | :--- |
| F-01 | 合法导入 | 运营选择玩具事业部、填写合法完整自然月期间和不早于期间结束日的业务截止日、选择可读 XLSX 后，可提交并建立批次 |
| F-02 | 首批期间 | 首批合法数据期间显示为 `2026-06-01` 至 `2026-06-30`，并明确标识“上一个完整自然月” |
| F-03 | 自动处理 | 新指纹文件级校验通过后，系统自动执行字段校验与固定规则处理并进入批次详情；全程不存在第二个“生成清单”操作 |
| F-04 | 指纹幂等 | 相同事业部、期间、截止日和文件内容因重复点击、网络重试或并发再次提交时，返回第一次成功建立的批次及既有清单状态 |
| F-05 | 无重复副作用 | 指纹命中后新增批次、建议或状态事件的数量均为 0，页面不提供强制新建相同批次的入口 |
| F-06 | 期间阻断 | 期间缺失、起止颠倒、跨越不完整自然月或无法解释为本批次完整自然月时，页面显示批次级错误且不发布依赖该期间的行动清单 |
| F-07 | 身份行拒绝 | SPU ID、链接名称、店铺、平台或责任运营缺失，或 SPU ID 批次内重复时，对应行不进入计算且每个问题可定位到字段与原始行位置 |
| F-08 | 字段级降级 | 上架日期、销售、利润、品退或库存字段异常时，该 SPU 不被整行删除，只停止依赖该字段的分类、经营动作或补货判断 |
| F-09 | 汇总行忽略 | 源表汇总行不参与 SPU 决策；汇总与有效明细不一致时形成警告但不把差额分摊到 SPU |
| F-10 | 文件级失败 | 非 XLSX、损坏、加密、不可读取或无法识别明细结构时，显示文件级原因，不发布行动清单，并允许运营替换文件 |
| F-11 | 规模非阻断 | 有效 SPU 数少于 10 或多于 20 时只显示试点规模提示，不因数量本身拒绝字段和期间均合法的批次 |
| F-12 | 历史不覆盖 | 同期间但文件内容或业务截止日不同的合法输入形成独立新批次，原批次、清单和状态历史保持可见且不变 |

### 11.2 体验验收

| 编号 | 验收点 | 通过标准 |
| :--- | :--- | :--- |
| U-01 | 主路径清晰 | 页面仅有一个推动业务的主操作“导入并处理”，提交前说明会自动校验并运行固定规则 |
| U-02 | 日期语义清楚 | 数据期间与业务截止日使用不同名称和说明，用户不会把上传日期误认为新品判断基准 |
| U-03 | 字段错误可定位 | 任一表单错误同时在对应字段附近显示；多项错误时页面顶部有汇总，用户可逐项修正 |
| U-04 | 分层错误可理解 | 文件级失败、批次级期间错误、整行拒绝、字段级降级和普通警告使用不同业务文案，不都显示为“导入失败” |
| U-05 | 处理状态真实 | 提交、解析、校验和固定规则处理使用明确步骤文案，不显示未经确认的成功或虚假完成百分比 |
| U-06 | 命中反馈明确 | 指纹命中时明确显示“未重复创建”、原批次编号和既有清单状态，并提供进入原批次详情的单一路径 |
| U-07 | 网络恢复可行 | 网络失败后可直接重试；若第一次请求已建立批次，重试自动回到原批次而非要求重新生成 |
| U-08 | 文件替换可恢复 | 错误文件被替换后，只属于旧文件的解析错误被清除，已填写的事业部、期间和截止日继续保留 |
| U-09 | 离开行为可预测 | 有未提交内容时离开会得到明确确认；已建立批次后离开不取消后台处理，用户可从批次列表继续查看 |
| U-10 | 结果去向明确 | 校验可继续时自动进入数据批次详情，拒绝行、降级和警告的完整内容不挤在导入表单中 |

### 11.3 安全验收（产品层）

| 编号 | 验收点 | 通过标准 |
| :--- | :--- | :--- |
| S-01 | 角色门禁 | 只有有效角色为运营的用户可看到并提交导入表单；运营主管、采购计划和未知角色通过入口或直链均不能提交 |
| S-02 | 会话失效保护 | 会话失效后不继续上传、解析或展示文件与批次经营数据，用户被引导重新登录；恢复后按指纹安全重试 |
| S-03 | 越权不泄露 | 无权限响应和页面不返回所选文件名、文件内容、批次编号、处理状态或经营字段 |
| S-04 | 文件类型边界 | 仅接受可读取的 XLSX；扩展名伪装、损坏、加密或无法识别结构的文件不能进入规则处理 |
| S-05 | 本地路径保护 | 页面和后续批次历史只展示源文件显示名，不展示或记录用户设备的本地绝对路径 |
| S-06 | 原值最小暴露 | 导入错误只向有权查看批次的用户显示定位和修正所需原值，不在无权限、会话失效或通用错误路径泄露经营数据 |
| S-07 | 审计完整 | 第一次成功建立批次时记录稳定批次、事业部、期间、业务截止日、导入人和时间；后续处理与状态事件保留关联且不可被覆盖 |
| S-08 | 幂等审计 | 重复点击、网络重试或并发提交只保留第一次合法建立的业务结果，不产生重复成功事件或伪造第二条追溯链 |
| S-09 | 历史不可篡改 | 页面不存在编辑、覆盖或删除旧批次的操作；修正文件必须形成新指纹批次，原批次保持可追溯 |
| S-10 | 敏感认证信息排除 | 页面、错误信息和提交数据不包含账号密码、短信/邮件验证码、钉钉票据明文或角色配置入口 |
