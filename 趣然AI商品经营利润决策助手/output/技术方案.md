# 趣然 AI 商品经营与利润决策助手 · 技术方案

> 决策基线：requirements revision 2、设计决策蓝图。版本于 08-03-2026 通过 npm registry 实测。

## 1. 需求解码与约束

### 1.1 产品形态

一个事业部、10—20 SPU 首轮试点的内部 PC Web 工作台。核心不是预测，而是把周度 XLSX 固化为不可变批次，经确定性规则生成唯一建议，随后整体审核、分动作执行、追加事件追溯。

### 1.2 技术约束

| 约束 | 设计响应 |
| :--- | :--- |
| 同快照与规则版本结果一致 | 规则模块为无副作用纯函数；业务截止日、指标、规则版本随批次固化 |
| 重复导入不建第二批次 | 事业部、期间、截止日、文件 SHA-256 建唯一指纹 |
| 止损/清仓与禁补不可割裂 | 同一数据库事务创建 DecisionRecord 与 ActionItem |
| AI 失败不阻塞 | 固定规则四要素先提交；AIExplanation 独立异步状态 |
| 采购最小可见 | 服务端按角色选择字段与事件，默认拒绝；禁止浏览器仅隐藏 |
| 历史不覆盖 | 快照不可变、AuditEvent 追加写、状态更新使用 version 乐观锁 |
| 国内可达 | 运行组件均可自托管；复用公司钉钉、LiteLLM 与国内基础设施 |
| 不新增账号/付费依赖 | 不引入海外托管、付费 SaaS、对象存储、缓存、队列、搜索或向量库 |

## 2. 技术栈全景与架构

```text
浏览器（PC）
  React + TypeScript + Vite
          │ HTTPS / JSON / secure cookie
Fastify 模块化单体
  auth ─ import ─ metrics ─ rules ─ decisions ─ actions ─ audit ─ ai
          │                         │
 PostgreSQL + Drizzle       既有 LiteLLM 网关
          │
 本地持久化 XLSX 目录（单实例）
```

推荐模块化单体而非微服务：V0 的事务边界横跨批次、建议、动作和事件，拆服务会增加分布式一致性却没有规模收益。批次处理由同进程后台任务承载；服务重启按批次状态恢复。升级外部队列的触发条件是多实例并行、任务超过单次部署窗口或出现可观察积压。

## 3. 前端技术选型

### 3.1 推荐

React 19.2.8 + TypeScript 7.0.2 + Vite 8.2.0；TanStack Router 1.170.18 管理筛选 URL，TanStack Query 5.101.4 管理服务端状态，React Hook Form 7.84.0 + Zod 4.4.3 管理表单与契约校验。

- 决策证据：产品是高密度表格、筛选、详情和角色表单，不需要 SEO、SSR 或多端渲染。
- 当前代价：需要独立 Fastify API 与前后端契约维护。
- 升级触发：若公司已有统一 React 全栈基座，可在保持 API/行为契约不变时迁移构建层。
- 不推荐 Next.js：SSR 与服务端组件对内部单端工作台没有收益，会扩大部署和缓存心智成本。
- 风险：筛选状态分散导致刷新丢失；缓解为所有清单筛选统一写入路由 search schema。

实施同步：`apps/web` 已按该栈建立生产构建，认证门禁、服务端会话守卫、角色应用壳、权限不足页、工作台、F01 三页、F05 两页及 F06 四表单页已接入真实 API；所有身份和业务响应先经 Zod 校验，不提供前端默认角色或硬编码经营计数。React Hook Form 管理导入、审核、执行和结果条件校验，TanStack Router 管理角色门禁、列表 URL 状态与真实对象路由。Fastify 仅允许配置的 Web origin 携带 Cookie 跨域访问。

构建约束同步：Web 内部模块 import 必须显式引用 `.ts/.tsx` 权威源码，且 Vite 解析扩展名保持 TypeScript 优先，防止历史忽略型编译产物覆盖当前实现。生产构建后必须机械检查包内包含当前 F05 页面 ID 与真实行动路由，且不包含旧 `/actions/:decisionId` 路径。

## 4. 后端技术选型

### 4.1 推荐

Node.js 24 LTS 运行时 + Fastify 5.11.2 + TypeScript。按领域模块组织，HTTP 层只做认证、契约、幂等与事务编排；指标和规则以纯函数接收冻结快照并返回结构化结果。

- 决策证据：前后端同语言降低 V0 契约成本；Fastify schema、插件隔离与吞吐适合文件导入和管理端 API。
- 当前代价：XLSX 解析与后台任务会占用进程资源。
- 升级触发：单批文件显著扩大或出现任务积压时，将 importer worker 从相同代码库拆成独立进程并接入公司现有队列。
- 次选 FastAPI：团队 AI/Python 基础更强且需复用 Python 数据管线时采用。
- 不推荐微服务：无法证明其能抵消分布式事务与运维成本。
- 风险：服务重启留下处理中批次；缓解为阶段状态持久化、任务租约和幂等续跑。

### 4.2 MVP API 与处理契约（实施同步）

当前模块化单体以 `/api` 暴露真实 JSON/Multipart API：`POST /api/batches/import` 接收事业部、完整自然月、业务截止日和单个 XLSX；`GET /api/batches` 返回服务端分页批次；`GET /api/batches/:batchId` 返回按角色裁剪的批次、质量问题和指标快照；`GET /api/action-lists/:batchId` 返回固定排序的角色裁剪行动投影；`GET /api/decisions/:decisionId` 返回冻结建议、双轨状态与时间线。所有接口读取数据库会话与当前角色，导入仅允许运营；采购清单和详情使用独立白名单查询，避免先读取受限字段再裁剪。

F06 写契约同步：`POST /api/decisions/:decisionId/review`、`POST /api/action-items/:actionItemId/execute` 与 `POST /api/action-items/:actionItemId/outcome` 均要求数据库角色会话、UUID 幂等键和当前对象 version。服务端在事务内 `FOR UPDATE` 后校验前置状态并同时写状态、操作者、幂等响应和追加审计；冲突返回最新状态，不覆盖首个成功事实。迁移 `003_action_results.sql` 为动作执行结果和经营结果记录人建立独立字段，避免把执行事实混入后续经营指标结果。

日期契约同步：PostgreSQL `date` 在数据库适配层按 OID 1082 保持 `YYYY-MM-DD` 字符串，不转换为带时区的 JavaScript `Date`；自然月、业务截止日和结果期间因此不发生本地时区前后偏移。`timestamptz` 仍按绝对时间序列化并由页面以本地时间展示。

`GET /api/workspace` 从最新有权批次聚合角色待办：主管读取待审核建议，运营读取经营待执行/待结果，采购只读取库存动作及采购任务；采购响应在 SQL 查询和序列化两层均不选择经营动作、利润、推广、品退或售后字段。无会话直接返回 401 且不执行经营聚合。

文件内容先计算 SHA-256，并与事业部、期间、截止日组成唯一指纹；数据库先固化 `received` 批次，文件以指纹命名写入持久化目录，再由同进程后台任务执行表头映射、身份拒绝、字段降级、指标与固定规则事务。重复或并发请求返回原 `batch_id`；进程启动时恢复非终态批次，应用关闭前等待活动任务，禁止生成第二份清单。

## 5. 数据层选型

### 5.1 主数据库

推荐 PostgreSQL + Drizzle ORM 0.45.2 + pg 8.22.0。唯一约束保护批次指纹，事务保护建议与动作原子生成，`version` 条件更新保护并发，AuditEvent 仅追加。

- 决策证据：核心是关系、事务、快照和事件检索；单库即可覆盖。
- 当前代价：需要 DBA/运维实施每日备份和恢复演练。
- 升级触发：历史事件读取达到慢查询阈值时先按 batch_id 建索引/分区，不先引入搜索引擎。

### 5.2 缓存与搜索

直接不激活。首轮数据量不需要 Redis 或 Elasticsearch；筛选由 PostgreSQL 索引完成。只有可测量热点无法通过查询优化解决时才评估缓存。

### 5.3 文件存储

单实例、持久化磁盘、每周小型 XLSX、无客户端直传/CDN需求，因此推荐服务器本地持久化目录，数据库记录路径、原文件名、SHA-256、大小与批次。文件与数据库每日同批次备份，RPO 24 小时、RTO 8 小时、保留 30 天；多实例或临时磁盘才升级公司批准的国内对象存储。

## 6. AI 能力选型

### 6.1 推荐

仅复用既有 LiteLLM HTTP 网关，不在产品内绑定具体模型；使用一次结构化生成完成解释，不引入 Agent 框架、向量库、Embedding 或 RAG。

- 决策证据：AI 只解释已存在的规则结果，不进行工具调用或多步自主决策。
- deployment secret 仅服务端读取，不写页面、响应、审计或业务日志。
- 网关超时、失败或越界时保存独立状态并继续展示结构化四要素；AI 返回不能修改分类、动作、阈值和输入值。
- 当前代价：解释质量受网关模型配置影响。
- 升级触发：只有新需求明确要求多步工具调用并形成稳定验收条件时，才比较 Agent 编排方案。

## 7. 基础设施与安全

### 7.1 部署

推荐 Docker 容器部署到公司现有国内可达单实例基础设施，挂载 PostgreSQL 与上传持久化卷，反向代理终止 TLS。当前不新增云厂商账号或付费平台；多实例是容量证据出现后的升级项。

### 7.2 认证授权

钉钉服务端采用 OAuth2 授权码流程：服务端持久化十分钟有效且一次性消费的随机 `state`，回调后通过钉钉 `userAccessToken` 与本人信息接口取得稳定 `unionId`，仅当 IT 已配置唯一有效角色映射时建立八小时会话。会话 Cookie 使用随机令牌、数据库仅保存 SHA-256 摘要，并设置 HttpOnly、生产环境 Secure、SameSite=Lax；`return_to` 只允许站内路径。每次请求重新校验当前角色。查询、序列化、错误、审计详情四层默认拒绝；无角色、失效会话和越权均不返回对象身份，也不降级为本地账号或默认角色。

### 7.3 可观测与 CI/CD

使用 JSON 结构化日志、健康检查和数据库指标；记录批次耗时/失败、AI 降级、权限拒绝、version 冲突，不记录 deployment secret 和原始整表。复用公司现有日志/监控；无现成平台时先用容器日志与告警脚本，不新增付费 SaaS。CI 执行格式、类型、单元、集成和构建；部署仍需人工批准。

### 7.4 风险

- 钉钉角色变更后旧会话继续有权 → 每次请求重校验角色，失权立即拒绝。
- 备份文件与数据库时间点不一致 → 同一备份任务生成 manifest，并每月恢复演练。
- 日志泄露经营或凭据信息 → 字段白名单、敏感键过滤、日志测试与最小访问权限。

## 8. 实施建议与风险全景

### 8.1 最终技术栈

| 层级 | 主推荐 | 版本 / 备注 |
| :--- | :--- | :--- |
| 前端 | React / TypeScript / Vite | 19.2.8 / 7.0.2 / 8.2.0 |
| 路由与数据 | TanStack Router / Query | 1.170.18 / 5.101.4 |
| 表单契约 | React Hook Form / Zod | 7.84.0 / 4.4.3 |
| 后端 | Node.js LTS / Fastify | 24 / 5.11.2 |
| 数据 | PostgreSQL / Drizzle / pg | 公司支持版 / 0.45.2 / 8.22.0 |
| AI | 既有 LiteLLM 网关 | 模型与地址由运维配置 |
| 部署 | Docker + 公司国内基础设施 | 单实例、持久化卷 |

### 8.2 第一周脚手架

1. 建立前后端 workspace、格式/类型/测试/构建门禁。
2. 建立 PostgreSQL schema、迁移和本地测试库。
3. 完成钉钉认证适配器与三角色默认拒绝中间件。
4. 建立批次、快照、建议、动作、事件和 version 事务契约。
5. 完成 XLSX 指纹、解析、字段质量与幂等集成测试。
6. 以纯函数实现指标和版本化固定规则测试矩阵。
7. 完成结构化四要素、行动清单与角色字段裁剪。
8. 接入异步 LiteLLM 降级、审计与容器部署冒烟。

### 8.3 后续扩展预留

| 扩展点 | 候选阶段 | 预留方式 |
| :--- | :--- | :--- |
| 明细洞察 | 阶段2评价/退款/广告明细 | 以 batch_id、spu_id、decision_id 挂接新事实，不改历史快照 |
| 外部系统写入 | 阶段2自动动作 | 以 action_id 追加 outbound command 与 receipt，不把人工确认冒充回执 |
| SKU 层 | 阶段3 SKU 决策 | 保留 SPU 上层主体，费用分摊和 SKU 快照使用新契约 |
| 多实例处理 | 容量升级 | importer 接口保持幂等，可拆 worker/队列；文件存储升级国内共享存储 |

### 8.4 Top 3 风险

| 风险 | 影响 | 缓解 |
| :--- | :--- | :--- |
| 脏数据或期间错标 | 规则结论错误 | 冻结期间/截止日、字段级降级、展示原始位置，不猜默认值 |
| 权限旁路 | 采购读取受限经营数据 | 服务端字段选择、负向接口测试、错误与审计同样裁剪 |
| 并发与重复请求 | 双批次或状态覆盖 | 唯一指纹、幂等键、事务、version 条件更新、追加事件 |

### 8.5 最终结论

- 是否可以立即开工：有条件开工；需先验证钉钉回调、LiteLLM 连通性与 PostgreSQL/文件备份恢复。
- 最大技术不确定性：真实 XLSX 字段质量与钉钉角色映射接口的稳定 actor_ref。
- 现在最不应该做的事：把 AI 放进动作判定主链，或为候选能力提前引入微服务、队列、向量库和对象存储。
