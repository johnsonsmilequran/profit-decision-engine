## 2. 页面概述

### 2.1 一句话定位

角色化工作台是三类直接用户登录后的统一任务入口：它基于同一批次、同一行动清单和同一审核/动作状态，分别向运营、运营主管和采购计划聚合“现在最需要处理什么”，不建立角色私有副本。

### 2.2 存在理由

1. 若没有角色化首屏，运营主管、运营与采购计划必须在清单中反复筛选，容易遗漏待审核、待执行或跨角色未完成项。
2. 若各角色使用不同数据副本，运营止损后采购仍可能按旧状态补货，重现跨部门信息断点。
3. 若采购直接复用完整经营视图，会暴露其任务不需要的利润、推广、品退和售后信息，违反最小可见原则。

### 2.3 页面目标（可衡量）

| 目标维度 | 具体指标 |
| :--- | :--- |
| 任务定位 | 有本人待办的授权用户进入页面后，首屏可识别当前批次、本人角色和至少一个可进入的待办入口 |
| 数据一致性 | 工作台各汇总数与同一批次行动清单、建议审核状态及分动作状态逐项勾稽，差异数为 0 |
| 角色正确性 | 运营、运营主管、采购计划看到的任务类型和可进入路径 100% 符合职责分工 |
| 最小可见 | 采购计划工作台及其错误、空状态、跳转上下文中出现完整利润、推广、品退或售后字段的次数为 0 |
| 空态可恢复 | 首次无批次、无本人待办、部分数据失败和整页失败均有明确说明及当前角色可执行的恢复入口 |

### 2.4 不做什么（范围边界）

- **不在工作台直接审核建议或提交动作结果**——审核、执行和结果记录均在建议详情完成，避免聚合页绕过完整依据与版本校验。
- **不生成第二份角色专属清单**——工作台只投影唯一批次行动清单及其状态，防止多套业务身份互相覆盖。
- **不展示纯维持且无补货或禁补的 SPU**——此类对象不属于行动清单处理范围，不制造虚假待办。
- **不允许用户在页面内切换或自选业务角色**——当前角色来自有效身份映射，页面只按该角色呈现。
- **不向采购开放完整经营指标、经营结果或审核入口**——采购仅处理补货/禁补任务及其必要库存、销量依据。
- **不提供批量审核、批量执行、导出或站内信中心**——这些能力不属于 MVP，待办统一通过工作台和行动清单承载。

## 3. 用户与场景

### 3.1 目标用户

| 角色 | 使用目标 | 技术熟练度 | 使用设备 | 使用姿势 |
| :--- | :--- | :--- | :--- | :--- |
| 运营 | 识别本周高优先级经营风险，进入本人待执行动作，查看最近结果；必要时发起新数据导入 | 中等，熟悉表格和内部业务系统 | 办公 PC | 每周新批次后集中查看，周内持续回访待办 |
| 运营主管 | 查看待审核建议、高优先级风险和经营/采购两条动作轨道的阻塞，进入建议详情完成审核 | 中高，熟悉经营指标和跨部门协作 | 办公 PC | 批次生成后集中审核，周内复查未闭环事项 |
| 采购计划 | 只查看本人补货/禁补待办及必要库存、销量依据，进入建议详情回填本任务结果 | 中等，熟悉采购计划与库存数据 | 办公 PC | 收到已通过建议后处理采购任务并回填结果 |

### 3.2 核心使用场景

**场景 A：运营主管处理本周待审核建议（主场景）**
- 时机：每周新批次完成固定规则决策并形成唯一行动清单后。
- 前置条件：用户当前角色为运营主管；存在待审核建议；工作台读取到最新成功批次。
- 用户动作：确认当前批次与高优先级建议数量 → 查看待审核列表摘要 → 进入某条建议详情核对完整依据并审核。
- 用户情绪：需要快速掌控风险，同时确信待办来自同一套规则和数据。

**场景 B：运营与采购分别处理已激活动作（协作场景）**
- 时机：运营主管已经通过完整建议，经营动作和补货/禁补动作分别进入待执行。
- 前置条件：运营或采购计划已登录；当前用户被分配到对应角色任务。
- 用户动作：在本人待办区识别动作和状态 → 进入建议详情 → 只更新本人负责的动作及结果 → 返回工作台看到汇总同步变化。
- 用户情绪：希望职责清晰，不被另一角色的信息和操作干扰。

**场景 C：首次尚无可用批次（兜底场景）**
- 时机：试点首次使用，或尚未完成任何有效批次处理。
- 前置条件：用户身份和角色有效，但系统没有最新成功批次。
- 用户动作：查看无批次说明；运营进入新建数据导入，运营主管与采购计划等待运营导入或进入数据批次列表了解进度。
- 用户情绪：不困惑，知道当前不是“没有风险”，而是“尚无可计算数据”。

**场景 D：部分汇总加载失败（兜底场景）**
- 时机：当前批次摘要可用，但某一待办或最近动态区读取失败。
- 前置条件：用户会话和页面权限仍有效。
- 用户动作：继续使用可用区域 → 对失败区域单独重试，或直接进入行动清单核对任务。
- 用户情绪：明确哪些数据可信、哪些暂不可用，不把局部故障误认为零待办。

### 3.3 用户核心诉求（优先级排序）

1. **先知道该做什么**：按角色直接看到本人本周待审核、待执行或待回填结果事项。
2. **确认数据是同一份**：工作台、行动清单和建议详情必须引用同一批次、同一建议与同一状态事实。
3. **看懂跨角色是否卡住**：运营主管能区分经营动作和采购动作的不同进度，不用把“部分完成”误判为全部完成。
4. **只看职责所需内容**：采购不接触完整经营敏感信息，运营和主管也不看到不属于自己的操作入口。
5. **异常时知道下一步**：无批次、无待办、局部失败和会话失效均有不同的解释与恢复路径。

## 4. 信息架构

### 4.1 区域划分

1. 全站导航与身份上下文区
2. 当前批次摘要区
3. 角色任务总览区
4. 高优先级/待办明细区
5. 最近状态与结果区
6. 异常、空态与恢复操作区

### 4.2 区域内容

**1. 全站导航与身份上下文区**
- 一级入口：工作台、行动清单、数据批次、追溯记录。
- 当前钉钉身份、当前业务角色和当前批次标识。
- 角色为只读结果，不提供角色切换或角色编辑。

**2. 当前批次摘要区**
- 最新成功批次编号、事业部、数据期间、业务截止日、规则版本、清单状态。
- 当前工作台全部任务汇总所依据的批次说明。
- 进入数据批次列表或当前批次详情的入口。

**3. 角色任务总览区**
- 运营：本周需处理经营风险数、待执行经营动作数、已执行待记录结果数。
- 运营主管：待审核建议数、高优先级待审核数、跨角色阻塞数。
- 采购计划：待补货数、待确认禁补数、已执行待记录结果数。
- 同一用户只呈现当前角色对应的一组任务总览。

**4. 高优先级/待办明细区**
- 运营：按固定动作优先级展示本人待执行经营动作，包含 SPU 身份、主动作、审核状态和经营动作状态。
- 运营主管：展示待审核建议和高优先级项，包含 SPU 身份、主动作、补货/禁补结论、审核状态及两条动作轨道摘要。
- 采购计划：只展示分配给当前采购角色的补货/禁补任务，包含 SPU 身份、补货结论、必要库存与销量依据、采购动作状态。
- 每项可进入同一建议详情的相应角色裁剪视图。

**5. 最近状态与结果区**
- 运营：本人最近更新的经营动作及经营结果记录状态。
- 运营主管：最近完成的建议级审核及跨角色执行进度。
- 采购计划：本人最近更新的补货/禁补动作及结果记录状态。
- 仅展示本角色有权查看的状态摘要，不借最近动态扩大字段权限。

**6. 异常、空态与恢复操作区**
- 首次无批次、当前角色无待办、局部读取失败、整页失败和无权限分别使用独立说明。
- 恢复操作按场景提供：新建数据导入（仅运营）、进入数据批次列表、进入行动清单、单区重试、整页重试或重新登录。

## 5. 界面内容

### 5.1 元素清单

**当前身份与角色**
- 内容：钉钉身份显示名、当前业务角色。
- 文案：角色使用“运营”“运营主管”“采购计划”稳定名称。
- 数据来源：当前有效登录态及业务角色映射结果。
- 显示条件：进入任一业务页时持续显示；无有效角色时不展示经营数据并离开本页。

**当前批次摘要**
- 内容：批次编号、玩具事业部、数据期间、业务截止日、规则版本、清单状态。
- 文案：明确“当前工作台依据此批次”；无批次时显示“尚无可用数据批次”。
- 数据来源：最新完成固定规则决策且行动清单可用的批次。
- 显示条件：有最新成功批次时显示摘要；没有时显示首次无批次状态，不用全零指标代替。

**任务总览指标**
- 内容：按当前角色定义的待审核、待执行、待记录结果或阻塞数量。
- 文案：使用具体业务对象，如“待审核建议”“待执行经营动作”“待确认禁补”，不使用含混的“待办总数”代替分轨状态。
- 数据来源：当前批次唯一行动清单、建议审核状态和分动作执行状态的实时投影。
- 显示条件：当前批次可用且对应汇总读取成功；某项失败时显示“暂不可用”，不得显示为 0。

**运营待办列表**
- 内容：SPU ID、SPU 名称、店铺、唯一经营主动作、关键依据摘要、建议审核状态、经营动作状态、数据限制标记。
- 文案：主入口为“查看并处理”。
- 数据来源：当前批次中分配给运营且需要处理的经营动作。
- 显示条件：当前角色为运营；纯维持且无补货/禁补的 SPU 不进入；运营主管审核操作不出现。

**运营主管待审核与高优先级列表**
- 内容：SPU 身份、唯一主动作、补货/禁补结论、所用优先级依据、建议审核状态、经营与采购动作摘要。
- 文案：主入口为“查看建议”；待审核项明确提示必须进入详情核对完整依据后操作。
- 数据来源：当前批次唯一行动清单及建议审核状态。
- 显示条件：当前角色为运营主管；只汇总待审核或需主管关注的高优先级建议。

**跨角色阻塞列表**
- 内容：SPU 身份、建议审核状态、经营动作状态、采购动作状态、当前未完成责任角色、最近更新时间。
- 文案：例如“经营已执行，采购待确认禁补”“采购已补货，经营结果待记录”。
- 数据来源：同一建议下的经营动作和采购动作分轨状态。
- 显示条件：当前角色为运营主管，且建议已通过、两条动作轨道进度不一致或任一应执行动作仍未完成；不把纯单动作建议误报为跨角色阻塞。

**采购待办列表**
- 内容：SPU ID、SPU 名称、店铺、补货/禁止补货结论、仓内库存、在途库存、最近 14 天销量或日均销量、库存可售天数、采购动作状态/结果状态。
- 文案：补货任务使用“查看补货任务”，禁补任务使用“确认禁补任务”。
- 数据来源：当前批次中分配给当前采购角色且有权查看的采购动作。
- 显示条件：当前角色为采购计划且任务关联有效；完整利润、推广、品退、售后及完整经营结果不出现。

**最近动态**
- 内容：本角色最近完成或更新的审核、动作、结果摘要，包含对象、状态、操作者和时间。
- 文案：状态采用建议级与动作级稳定标签，不把人工确认描述为外部系统回执。
- 数据来源：当前用户有权查看的审核、动作和结果记录。
- 显示条件：存在本角色可见的最近记录；无记录时显示“暂无最近处理记录”。

**角色化快捷入口**
- 运营：新建数据导入、查看全部行动、查看数据批次。
- 运营主管：查看全部待审核、查看跨角色阻塞、查看追溯记录。
- 采购计划：查看全部采购任务、查看本人任务记录。
- 数据来源：页面清单中已存在的对应业务页面。
- 显示条件：只显示当前角色可进入的入口；不可访问的功能不以置灰方式泄露存在性。

### 5.2 辅助信息

- 当前批次期间说明：显示实际起止日，避免把“本周工作台”误解为全部指标均来自最近 7 天。
- 数据时效说明：工作台反映当前批次以及周内审核、执行、结果状态的最新投影。
- 数量口径说明：同一 SPU 同时包含经营动作和补货动作时，建议数按一条建议计；动作数按各动作轨道分别计。
- 采购权限说明：仅提示“当前仅显示完成采购任务所需信息”，不列举被限制字段的实际值。
- 局部失败说明：指出失败区域及最后成功读取的批次身份，不把失败区展示成“暂无任务”。

## 6. 交互流程

### 6.1 页面加载与初始化

1. 校验当前登录态和业务角色；无有效会话或角色时，不加载经营数据并进入统一恢复路径。
2. 获取最新可用批次；若不存在，进入首次无批次状态。
3. 以该批次的唯一行动清单、建议审核状态和分动作状态生成当前角色投影。
4. 分别加载当前批次摘要、任务总览、待办明细和最近动态；某一区域失败不抹除其他已成功区域。
5. 页面回到前台或用户从详情返回时重新核对关键状态，避免继续显示已经被其他角色处理的旧待办。

### 6.2 核心操作流程

```text
用户进入角色化工作台
    │
    ├─ 会话无效或无业务角色 → 不显示经营数据 → 重新登录/联系 IT
    │
    └─ 身份有效 → 查找最新可用批次
         │
         ├─ 无可用批次
         │    ├─ 运营 → 新建数据导入 / 查看批次
         │    └─ 主管或采购 → 查看批次进度 / 等待新批次
         │
         └─ 有可用批次 → 按当前角色加载同源任务投影
              │
              ├─ 运营 → 选择经营待办 → 建议详情 → 处理经营动作/结果
              ├─ 运营主管 → 选择待审核建议 → 建议详情 → 完成整条建议审核
              └─ 采购计划 → 选择采购待办 → 裁剪后的建议详情 → 处理补货/禁补动作
```

用户从建议详情返回工作台后：

```text
重新读取当前建议与动作状态
    │
    ├─ 状态已成功变化 → 更新对应数量、列表项和最近动态
    ├─ 另一角色仍未完成 → 主管工作台保留跨角色阻塞
    └─ 本人已无待办 → 展示无本人待办状态，不伪装为无批次
```

### 6.3 辅助操作

- 点击当前批次摘要进入数据批次详情，查看批次事实；采购无完整批次详情权限时不显示该入口。
- 点击任务总览中的某项进入行动清单，并带入对应角色允许的状态筛选。
- 点击最近动态中的对象进入建议详情相应时间线；采购仍使用最小必要裁剪视图。
- 局部失败时可单独重试该区域；整页失败时提供整页重试。
- 页面不提供直接改变审核或动作状态的快捷按钮。

## 7. 状态与边界

### 7.1 页面状态全景

| 状态 | 触发条件 | 页面表现 |
| :--- | :--- | :--- |
| 初始化态 | 身份有效，页面刚进入 | 显示页面结构与当前身份上下文，任务数据尚未给出结论 |
| 加载态 | 正在读取批次与角色任务投影 | 各区域标明正在加载；未完成前不展示 0 条或空结论 |
| 正常有待办态 | 最新批次可用且当前角色存在待办 | 显示批次摘要、角色总览、待办明细、最近动态和可进入路径 |
| 首次无批次态 | 尚无成功批次或清单 | 显示“尚无可用数据批次”；运营可进入新建导入，其他角色查看批次进度 |
| 无本人待办态 | 批次存在，但当前角色没有待处理事项 | 显示当前批次和“本角色暂无待办”，保留已授权的历史/清单入口；不等同于无经营问题 |
| 部分失败态 | 批次摘要或部分区域成功，某一区域失败 | 成功区域继续可用；失败区域明确标记“暂不可用”并可单独重试，不以 0 替代 |
| 整页失败态 | 无法取得可信批次或角色任务投影 | 不展示旧汇总为当前结果；显示失败说明、整页重试和已授权的替代入口 |
| 状态刷新态 | 从详情返回或检测到状态可能变化 | 保留当前批次身份，重新核对受影响汇总；完成前防止重复进入已失效操作 |
| 无权限态 | 会话无效、无角色映射或当前角色无本页权限 | 不显示任何经营摘要，进入统一无权限/重新登录路径 |

### 7.2 边界与容错

| 边界场景 | 处理策略 |
| :--- | :--- |
| 网络异常 | 区分局部读取失败与整页失败；保留已确认可用区域，提供对应重试，不把网络失败显示为零待办 |
| 会话过期 | 立即停止读取和展示新的经营数据，进入重新登录路径；恢复后重新按服务端角色加载，不沿用旧角色页面 |
| 连续错误 | 同一区域连续失败时保持明确失败状态和替代入口，不无限自动刷新、不累计重复错误提示，也不以旧数据冒充最新状态 |
| 异常输入/参数 | 收藏或外部链接携带无法识别的批次、筛选或角色参数时，不采用用户传入角色扩大权限；回到当前服务端角色的默认工作台，并说明无效上下文 |
| 并发操作 | 工作台加载后若其他用户完成审核、执行或结果记录，刷新时以最新合法状态更新；旧待办入口不得覆盖已成功状态，也不产生重复事件 |
| 最新批次切换 | 新批次在用户停留期间成为最新批次时，明确提示当前工作台依据已变化，用户确认刷新后切换；不把两个批次的数量拼在一起 |
| 批次仍在处理 | 尚未形成可审核清单时不作为成功工作台批次；提示前往数据批次查看处理进度，不展示推测待办 |
| 双动作进度不一致 | 同一建议一条动作已完成、另一条未完成时，分开显示两条状态；主管视图计入跨角色关注，不把建议标为全部完成 |
| 无库存数据但存在禁补 | 采购仍可看到止损/清仓派生的禁补任务；不得因库存字段缺失隐藏禁补，也不得补造库存值 |
| 采购无任务关联 | 不展示建议身份、状态或摘要；若通过旧链接进入，使用通用无权限结果，避免泄露对象是否存在 |

## 8. 业务规则与校验

### 8.1 字段定义

| 字段 | 说明 |
| :--- | :--- |
| `current_role` | 当前有效业务角色，仅可为运营、运营主管或采购计划；页面不允许自行改写 |
| `current_batch` | 工作台当前依据的最新可用批次，包含批次编号、事业部、数据期间、业务截止日、规则版本和清单状态 |
| `decision_count` | 当前批次符合行动清单收录范围的建议数；同一 SPU 双动作仍按一条建议计 |
| `review_state` | 建议级待审核、已通过或已驳回状态 |
| `business_action_state` | 运营负责的经营动作状态：待审核、待执行、已执行、已记录结果或已关闭 |
| `procurement_action_state` | 采购负责的补货/禁补动作状态：待审核、待执行、已执行/已确认禁补、已记录结果或已关闭 |
| `main_action` | 固定规则产生的唯一经营主动作；工作台不得编辑或让 AI 改写 |
| `replenishment_action` | 固定规则产生的补货、禁止补货、不补货或不生成结论；只有可执行补货/禁补形成采购待办 |
| `priority_basis` | 固定动作层级及同动作内规则版本已明确、已校验的影响代理；无代理时使用稳定次序 |
| `cross_role_blocker` | 已通过且同时存在经营与采购动作，两条轨道进度不一致或其中一条仍待执行/待记录结果的主管关注项 |
| `necessary_procurement_evidence` | 采购任务所需的 SPU 身份、补货/禁补结论、仓内库存、在途库存、最近 14 天销量/日均销量、库存可售天数和任务状态/结果 |
| `last_activity` | 当前角色有权查看的最近审核、动作或结果记录摘要，包含对象、状态、操作者和时间 |

### 8.2 校验规则

| 校验项 | 时机 | 规则 | 失败反馈 |
| :--- | :--- | :--- | :--- |
| 当前角色有效性 | 页面初始化与每次重新加载 | 必须存在唯一有效业务角色；不得采用页面参数指定角色 | “当前账号未配置有效业务角色，请重新登录或联系 IT” |
| 当前批次一致性 | 汇总展示前 | 所有总览和列表项必须属于同一 `current_batch` | “工作台数据已更新，请刷新后查看最新批次” |
| 清单唯一性 | 汇总展示前 | 一个批次只投影一份行动清单，不接受第二清单身份拼接 | “当前批次清单状态异常，请进入数据批次查看” |
| 行动清单收录 | 生成角色待办时 | 纯维持且无补货/禁补不进入；数据完整得出的“不补货”不单独形成采购任务 | 不满足收录规则的对象不显示为待办 |
| 固定排序 | 待办列表展示时 | 先按清仓、止损、观察、加投、补货固定层级；同层使用规则明确的已校验代理，否则使用稳定 SPU ID/序号 | 排序依据不可用时回退稳定次序，不由 AI 猜测 |
| 审核激活 | 形成运营/采购待执行数时 | 只有建议已通过才将原有动作计入待执行；工作台不二次创建动作 | “建议尚未通过，暂不可执行” |
| 责任角色匹配 | 形成角色待办时 | 经营动作归运营，补货/禁补归采购计划，审核归运营主管 | 不属于当前角色的操作入口不显示 |
| 跨角色阻塞 | 主管汇总时 | 仅同时存在两条动作轨道且进度不一致/未闭环的已通过建议计入 | 单动作建议不计入跨角色阻塞 |
| 采购最小字段 | 采购视图展示前 | 只能包含 `necessary_procurement_evidence`；完整利润、推广、品退、售后和经营结果字段必须排除 | 受限字段不显示、不返回，也不在错误信息中出现 |
| 最近动态权限 | 最近状态展示前 | 只展示当前角色有权读取的事件摘要；历史状态更新不能删除既有成功记录 | “部分记录暂不可查看”或通用无权限，不回显受限对象 |

### 8.3 特殊业务规则

- **同源投影**：三个角色视图只能由同一批次行动清单、建议和动作状态投影产生，不保存为独立可修改业务副本。
- **审核与执行分层**：运营主管只看到建议级审核待办；运营与采购只看到建议通过后激活的本角色动作待办。
- **动作独立计数**：经营与采购动作分别计数和显示；其中一项完成不代表整条建议全部完成。
- **固定规则优先**：工作台的动作、优先级和关键依据来自固定规则与已校验数据；AI 状态不改变待办归属或排序层级。
- **历史不覆盖**：工作台默认聚合最新可用批次；进入历史清单查看时不修改当前工作台批次，也不覆盖历史审核、动作和结果。
- **采购最小可见**：采购视图、空态、错误、最近动态及跳转上下文均适用同一最小字段边界。
- **人工结果语义**：采购“已确认禁补”只表示人工确认，不表示外部采购系统已回执；运营结果也只表示本产品内记录。
- **无批次不等于无问题**：没有可用批次时不得展示全零风险或“本周经营正常”。

## 9. 页面流转

### 9.1 流转图

```text
钉钉认证成功
      │
      ▼
角色化工作台（本页）
      │
      ├─ 当前角色=运营
      │    ├─ 新建数据导入 → 新建数据导入页
      │    ├─ 经营待办 → 行动清单 / 建议详情
      │    └─ 最近结果 → 建议详情对应结果记录
      │
      ├─ 当前角色=运营主管
      │    ├─ 待审核/高优先级 → 行动清单 / 建议详情
      │    ├─ 跨角色阻塞 → 建议详情两条动作轨道
      │    └─ 最近审核 → 建议详情时间线 / 追溯记录
      │
      └─ 当前角色=采购计划
           ├─ 补货/禁补待办 → 角色裁剪的行动清单 / 建议详情
           └─ 最近任务结果 → 角色裁剪的建议详情时间线

任一越权直链 / 会话失效
      └─→ 无权限页 / 重新登录
```

### 9.2 与其他模块的关系

- **行动清单**：工作台只做当前角色聚合与入口；完整筛选、分页和历史批次切换在行动清单完成。
- **建议详情**：所有审核、执行、结果记录、规则依据和分轨时间线均在详情完成；工作台不直接提交业务状态。
- **数据批次**：工作台读取最新可用批次身份；运营可发起新导入，其他角色可在权限允许时查看批次状态。
- **追溯记录**：最近动态只提供摘要；完整事件链进入追溯记录或建议详情，并继续按角色裁剪。
- **认证与权限**：当前角色来自统一身份映射；无会话、无角色或越权不在本页降级开放经营数据。

### 9.3 扩展预案

| 扩展方向 | 触发条件 | 改造点 |
| :--- | :--- | :--- |
| 新数据源接入 | 外部数据源、账号、字段口径和配置责任正式立项 | 当前批次摘要继续使用统一批次身份，不让不同来源生成角色私有工作台副本 |
| 外部执行回执 | 广告、采购或库存系统 API、幂等和回滚责任确认 | 在现有动作状态旁增加独立外部回执语义，不把当前人工确认历史改写为外部成功 |
| 售后或广告明细任务 | 明细数据、权限和责任人形成稳定需求 | 新增有证据的任务类型；采购视图仍不继承完整利润、推广和售后字段 |
| SKU 级决策工作台 | SKU 数据、SPU-SKU 口径、规则和责任重新立项 | 使用独立 planned 页面，不把当前 SPU 工作台静默改成混合粒度 |
| 更多业务角色 | 上游明确新角色、职责、数据边界和验收契约 | 扩展角色投影规则；不得通过用户自选角色绕过统一身份映射 |

## 10. 数据需求

### 10.1 页面需要什么数据

| 数据 | 来源 | 用途 |
| :--- | :--- | :--- |
| 当前身份与唯一业务角色 | 当前有效登录态及角色映射 | 决定页面能否进入及加载哪一种角色投影 |
| 最新可用批次摘要 | 数据批次 | 固定本页汇总所依据的批次、期间、业务截止日和规则版本 |
| 当前批次唯一行动清单身份 | 行动清单 | 保证所有建议和动作汇总来自同一份清单 |
| 建议身份、SPU 身份与固定优先级 | 固定规则建议 | 生成运营和主管的高优先级/待审核摘要 |
| 建议审核状态 | 建议审核记录 | 计算主管待审核项，并判断动作是否已激活 |
| 经营动作状态与结果摘要 | 运营动作记录 | 计算运营待执行、待记录结果及最近动态 |
| 补货/禁补动作状态与结果摘要 | 采购动作记录 | 计算采购待办、禁补确认及最近动态 |
| 两条动作轨道的关联状态 | 同一建议下的动作投影 | 识别主管跨角色阻塞，避免部分完成被误判为全部完成 |
| 采购必要库存与销量依据 | 建议固化的采购任务必要投影 | 让采购理解补货/禁补任务，不暴露完整经营信息 |
| 当前角色可见的最近事件摘要 | 审核、动作和结果记录 | 展示最近处理及进入详情/追溯的入口 |
| 各区域读取状态 | 页面数据状态 | 区分加载、空、局部失败和整页失败 |

### 10.2 页面提交什么数据

本页不提交审核、执行或结果等业务状态；点击待办只提交页面导航上下文，由下游页面完成业务操作。

| 数据 | 触发时机 | 用途 |
| :--- | :--- | :--- |
| 当前批次标识 | 进入行动清单、批次详情或追溯记录 | 保持工作台与下游查看同一批次 |
| 建议标识 | 点击某条待办或最近动态 | 打开对应建议详情；下游再次执行权限校验 |
| 角色允许的预置筛选 | 点击某项任务总览 | 在行动清单定位待审核、经营待执行或采购待执行项；筛选不改变建议内容 |

### 10.3 明确排除的数据

- 不需要用户输入或提交角色，角色只能来自当前有效身份映射。
- 不需要在本页提交审核备注、执行备注、经营结果或采购结果。
- 采购视图不需要完整经营准利润率、经营准利润值、推广费用、品退数据、售后信息或完整经营结果。
- 不需要 SKU、广告计划/单元/关键词/素材、评价文本或退款/退货原因明细。
- 不需要 LiteLLM 部署密钥、模型配置或普通用户 AI 重试参数。
- 不需要创建或保存角色专属行动清单副本。

## 11. 验收标准

### 11.1 功能验收

| 编号 | 验收点 | 通过标准 |
| :--- | :--- | :--- |
| F-01 | 当前批次同源 | 有最新可用批次时，页面显示其编号、期间、业务截止日和规则版本；全部汇总项均可追溯到该批次唯一行动清单，不混入其他批次 |
| F-02 | 运营视图 | 运营进入工作台时可见本人待执行经营动作、待记录结果和最近经营结果入口；看不到主管审核操作和采购结果操作 |
| F-03 | 主管视图 | 运营主管进入工作台时可见待审核、高优先级建议和跨角色阻塞；进入建议详情后才能执行整条建议审核 |
| F-04 | 采购视图 | 采购计划只看到分配给当前角色的补货/禁补任务、必要库存销量依据及采购动作状态；不存在完整经营字段 |
| F-05 | 固定收录范围 | 纯维持且无补货/禁补的 SPU 不出现在任何角色待办；“不补货”不单独形成采购执行任务 |
| F-06 | 固定优先级 | 首次加载的待办按清仓、止损、观察、加投、补货层级排列；同层无有效代理时使用稳定 SPU ID/序号，AI 状态不改变顺序 |
| F-07 | 审核后激活 | 待审核建议不计入运营/采购待执行；主管通过后，既有经营与采购动作分别出现在责任角色工作台，且不创建重复动作 |
| F-08 | 双动作独立 | 同一建议的经营动作已执行、采购动作待执行时，运营和采购视图分别反映本轨状态，主管视图显示未闭环，页面不显示全部完成 |
| F-09 | 无批次与无待办区分 | 没有成功批次时显示首次无批次；有批次但本角色无任务时显示无本人待办，两者文案和恢复入口不同 |
| F-10 | 页面只导航不改状态 | 在工作台点击任何任务、总览或最近动态只进入下游页面，不直接产生审核、动作或结果事件 |

### 11.2 体验验收

| 编号 | 验收点 | 通过标准 |
| :--- | :--- | :--- |
| U-01 | 首屏可定位 | 有本人待办时，用户无需切换角色或先设置筛选即可看到当前批次、当前角色和对应待办入口 |
| U-02 | 状态语义清晰 | 建议审核状态、经营动作状态和采购动作状态分别命名；双动作进度不一致时不只显示含混的单一“处理中” |
| U-03 | 空态可行动 | 首次无批次时运营能进入新建导入，主管和采购能进入已授权的批次进度入口；无本人待办时仍能进入历史或全部清单入口 |
| U-04 | 局部失败不误导 | 任一汇总区域读取失败时显示“暂不可用”及重试，不显示为 0；其他已成功区域仍可使用 |
| U-05 | 返回后状态更新 | 用户在建议详情完成合法操作后返回工作台，对应计数、列表项和最近动态按最新状态更新，不继续提供已失效待办入口 |
| U-06 | 批次语境明确 | 页面始终能识别当前工作台所依据的批次和实际数据期间，不把“本周待办”误写为所有指标均来自最近一周 |
| U-07 | 入口职责一致 | 运营、运营主管和采购计划的快捷入口与本角色任务一致；不属于当前角色的能力不出现，状态暂不可操作的任务说明原因 |
| U-08 | 异常可恢复 | 网络失败、批次处理未完成、会话失效和无角色映射分别提供重试、查看批次、重新登录或联系 IT 的对应路径 |

### 11.3 安全验收（产品层）

| 编号 | 验收点 | 通过标准 |
| :--- | :--- | :--- |
| S-01 | 采购字段最小化 | 使用采购计划角色检查页面正文、汇总、待办、最近动态、空态和错误信息，均不出现完整利润、推广、品退或售后字段和值 |
| S-02 | 采购任务关联校验 | 采购访问未分配给自己的任务或无采购动作的建议时，工作台不出现该对象；旧链接跳转后不返回建议身份或状态摘要 |
| S-03 | 无会话默认拒绝 | 无有效登录态访问 `/workbench` 时不返回经营摘要、任务数量或对象信息，只进入重新认证路径 |
| S-04 | 无角色默认拒绝 | 身份有效但无唯一业务角色映射时不自动赋予默认角色，不加载工作台经营数据，并提供联系 IT 指引 |
| S-05 | 角色不可由参数提升 | 在地址或导航上下文中伪造主管/运营角色参数不能改变当前服务端角色，也不能获得对应任务或字段 |
| S-06 | 操作权限隔离 | 运营工作台不出现审核入口，主管工作台不出现代替运营或采购执行入口，采购工作台只进入本任务的采购操作路径 |
| S-07 | 角色变化及时生效 | IT 调整角色或撤销权限后，后续加载和从详情返回时按最新角色重新裁剪；原页面不得继续显示已失权数据 |
| S-08 | 错误路径不泄露 | 无权限、对象不存在、局部失败和整页失败反馈不包含受限 SPU、建议状态、利润、推广、品退或售后信息 |

## 12. 实施同步（2026-08-04）

- 生产实现：`frontend/src/pages/WorkspacePage.tsx`；路由 `/workspace`；数据唯一来源为 `/api/workspace`。
- 工作台保留角色化标题、批次指标、优先待办与空批次状态；采购角色不获得数据批次导航或导入入口。
