## 2. 页面概述

### 2.1 一句话定位

行动清单页把最新成功数据批次中的固定规则结论投影为双角色待办列表：默认让当前用户先看到“待我处理”，并用稳定动作顺序、生命周期时间、经营状态、OA 协同、清仓完成确认、AI 状态和数据限制帮助其进入详情完成下一步；最近前序详细字段默认折叠，按单条 SPU 展开。

### 2.2 存在理由

1. 没有统一清单，运营与主管仍需从分散数据中判断，经营动作、外部协同与最终完成事实容易再次脱节。
2. 没有固定排序与角色待办视图，高风险清仓、止损会被低优先级任务淹没，用户也难以区分“需要我处理”和“只是可查看”。
3. 没有数据限制与 AI 独立状态，用户可能把缺失指标当成 0，或误以为 AI 失败代表固定规则结论不可用。
4. 没有批次和历史只读边界，用户可能在旧数据上执行动作，或误认为新批次覆盖了旧清单。
5. 没有双角色权限和 OA 消息白名单，外部相关人员可能经错误路径接触完整利润、推广、品退和售后信息。

### 2.3 页面目标（可衡量）

| 目标维度 | 具体指标 |
| :--- | :--- |
| 待办聚焦 | 最新成功批次首次打开时，100% 默认进入当前角色“待我处理”视图 |
| 规则一致 | 同一批次、同一规则版本下，列表中的商品类型、经营动作、库存动作和排序结果重复加载时逐项一致 |
| 四要素完整 | 清单内 100% 的建议均能识别具体对象、发现问题、关键依据和推荐动作；AI 等待或失败时仍完整 |
| 双动作同步 | 100% 的止损或清仓建议同时显示禁补结论；加投与补货并存时仍只显示一条 SPU 建议 |
| 数据限制可见 | 任何影响分类、动作或补货判断的数据缺失，100% 以明确限制说明展示，不用 0 或推测值替代 |
| 历史保护 | 切换历史批次后，清单内容和状态保留率为 100%，且不存在审核、执行或结果写入入口 |
| 跨周去重 | 同一 SPU 连续批次命中同一经营或库存动作时，重复任务新建数为 0，原审核和执行状态保留率为 100% |
| 关联可见 | 存在历史经营待办的当前记录，100% 提供“最近前序待办”折叠入口；展开后显示来源批次、动作、状态、产生时间和执行时间 |
| 时间可信 | 任务产生时间、本周关联时间与实际执行时间语义分离；未执行记录 100% 显示“—”而非更新时间 |
| 最小可见 | 外部相关人员产品访问成功数为 0；OA 消息中完整利润、推广、品退和售后字段出现率为 0 |
| 清仓确认 | 清仓动作不变时重复完成待办新建数为 0；主管未确认前每日最多催办责任运营 1 次，确认/改判/终止后不再催办 |

### 2.4 不做什么（范围边界）

- **不在清单页直接审核、执行或记录结果**——本页用于筛选、定位和进入 `PAGE-F06-03`；单条操作及冲突处理在建议详情完成。
- **不支持批量审核、批量执行或批量结果回填**——首版必须逐条核对证据和状态，避免误操作与审计歧义。
- **不提供自由排序**——只使用固定动作优先级及规则版本允许的稳定次序，避免用户把显示排序误当作新经营结论。
- **不让 AI 改写商品类型、主动作、补货结论、阈值或排序层级**——AI 只解释已固化结果。
- **不展示或生成 SKU、广告计划/单元/关键词/素材、评价主题、退款/退货原因结论**——首版数据仅支持 SPU 汇总判断。
- **不把维持且无补货/禁补的 SPU 放进行动清单**——该类决策仅在追溯中保留；数据完整得出的“不补货”也不单独创建库存协同任务。
- **不在历史批次继续业务操作**——历史只用于查看当时清单和进入只读建议详情。
- **不把每周决策快照当成新执行任务**——快照按批次独立留存，稳定任务按 SPU 续接；只有动作变化才追加新版本。

## 3. 用户与场景

### 3.1 目标用户

| 维度 | 运营 | 运营主管 |
| :--- | :--- | :--- |
| 页面目标 | 找到本人 SPU 的经营/OA 协同待办、补录结果和清仓完成确认 | 找到待整体审核建议与待确认清仓完成时间 |
| 可见内容 | 完整销售、利润、推广、品退、库存、规则建议、OA 协同、AI 状态和数据限制 | 审核所需完整经营信息、规则建议、双轨进度、清仓完成提交和数据限制 |
| 可执行操作 | 本页只进入详情；详情中执行经营与协同动作、记录结果、提交清仓完成时间 | 本页只进入详情；详情中整体审核、人工改判、确认或退回清仓完成时间 |
| 使用频率 | 每周新清单生成后集中查看，周内持续跟进，未确认清仓完成时每日响应 OA 催办 | 新清单生成后审核，周内查看进度和完成事实 |
| 使用设备 | 办公电脑 | 办公电脑 |

### 3.2 核心使用场景

**场景 A：运营处理最新批次的经营待办（主场景）**

- 时机：最新成功批次已生成清单，主管已通过部分建议，运营开始执行或补录经营结果。
- 前置：运营已登录；当前批次为最新成功批次；本人有完整经营信息权限。
- 动作：进入行动中心 → 默认查看“待我处理” → 搜索 SPU 或按动作、店铺、责任运营、审核状态、经营状态和任务总进度筛选 → 核对对象、产生/关联/执行时间、问题、关键依据、经营动作、库存动作、数据限制和 AI 状态；需要时展开最近前序待办 → 进入单条建议详情处理。
- 情绪：希望高风险动作优先、证据清楚，不需要重新人工判断整张表。

**场景 B：主管集中定位待审核建议（审核场景）**

- 时机：固定规则清单就绪，AI 解释仍可能生成中或失败。
- 前置：运营主管已登录；批次规则处理完成；存在待审核建议。
- 动作：进入行动中心 → 默认查看“待我处理”中的待审核建议 → 按清仓、止损、观察、加投、补货顺序逐条查看 → 使用筛选定位异常或特定责任运营 → 进入建议详情完成单条整体审核。
- 情绪：希望规则结果稳定，AI 不可用也不耽误拍板。

**场景 C：责任运营通过 OA 协同外部相关人员（协同场景）**

- 时机：建议已通过，补货或禁补协同动作已激活。
- 前置：当前用户是该 SPU 的责任运营；采购、仓库等相关人员不登录本产品。
- 动作：进入建议详情 → 使用最小字段 OA 模板通知相关人员 → 核验其反馈 → 由运营记录协同状态和结果；发送失败时人工补发。
- 情绪：责任边界明确，OA 送达不会被误认作业务完成。

**场景 D：复盘历史批次或处理异常（兜底场景）**

- 时机：用户需要核对旧批次结论，或当前列表发生加载失败、数据更新冲突。
- 前置：用户对目标批次或任务有查看权限。
- 动作：切换到历史批次 → 看到明确只读提示 → 搜索、筛选并进入只读详情；若网络失败则按原批次重试，若状态已被他人更新则刷新为最新状态，不沿用旧状态继续操作。
- 情绪：清楚自己在看历史或最新状态，不担心误写旧数据。

### 3.3 用户核心诉求（优先级排序）

1. **先做该做的**：默认只看当前角色在最新成功批次中尚需处理的事项。
2. **先处理高风险**：清仓、止损优先，固定顺序不会因 AI 或手工排序变化。
3. **看懂为什么**：列表即可看到对象、问题、关键依据、动作和数据限制，详情继续追溯。
4. **不越权**：不同角色只看职责所需字段与任务，搜索和错误路径也不泄露。
5. **不误操作**：历史只读，空状态与加载失败分开，状态冲突可恢复。

## 4. 信息架构

### 4.1 区域划分

1. 页面与角色上下文区
2. 批次上下文与历史切换区
3. 任务页签区
4. 搜索与筛选区
5. 行动清单区
6. 状态反馈与数据限制区
7. 分页区
8. 跨周任务与最近前序待办

### 4.2 区域内容

**1. 页面与角色上下文区**

- 页面名称。
- 当前事业部、当前用户角色和用户身份；仅支持运营和运营主管。

**2. 批次上下文与历史切换区**

- 默认最新成功批次的批次标识、业务期间、业务截止日、规则版本和最后更新时间。
- 最新提交仍在规则处理中或失败时，保留最近成功批次作为默认清单，并单独说明最新提交状态。
- 有权限的历史批次选择入口。
- 选择历史批次后固定显示“历史批次，只读查看”，并关闭一切业务操作去向。

**3. 任务页签区**

- “待我处理”：最新成功批次首次进入的默认页签，按当前角色计算。
- “全部”：显示当前角色在所选批次中有权查看的全部清单建议或库存协同任务。
- “处理中”：显示审核或任一责任动作仍在推进、尚未达到完成条件的记录；AI 生成状态不单独决定是否处理中。
- “已完成”：显示已驳回关闭，或所有有权/必要动作已形成终态及结果记录的记录。
- 每个页签只改变显示范围，不修改建议、审核或动作状态。

**4. 搜索与筛选区**

- SPU 搜索：运营与主管可按 SPU ID 或名称搜索。
- 筛选：动作、店铺、责任运营、建议审核状态、经营状态、清仓确认状态、任务总进度。
- “清除条件”恢复当前页签默认范围，不切换批次。
- 搜索、筛选、页签、批次和页码在刷新或从详情返回后恢复。

**5. 行动清单区**

- 每行代表一个批次内一个 SPU 的唯一建议；双动作不拆成两条建议。
- 完整视图展示四要素摘要、商品类型、经营/库存动作、审核状态、分动作状态、AI 状态和数据限制。
- 外部协同展示责任运营、OA 最近发送状态和由运营核验的协同结果；外部相关人员无产品视图。
- 每行同时显示批次决策与跨周任务的关系：首次命中、延续上周·未重建，或动作变更·待主管确认；存在历史记录时显示“最近前序待办”折叠入口，来源批次、动作、状态、产生时间和执行时间默认收起。
- 每条 SPU 的前序折叠独立控制；点击或键盘 Enter/Space 只切换该条前序详情，不进入建议详情。刷新、筛选、分页或从详情返回后恢复默认折叠，不持久化展开状态；首次无前序时只显示“无前序待办”，不渲染空折叠控件。
- 当前待办显示稳定任务首次产生时间、本周关联时间、当前经营状态和经营动作执行时间；未执行的执行时间显示“—”。
- 清仓任务显示实际完成时间提交/确认状态及最近一次 OA 催办；同动作跨周不重复新建完成待办。
- 进入 `PAGE-F06-03` 的单条建议详情入口；本页不提供行内审核或执行。

**6. 状态反馈与数据限制区**

- 无成功批次、规则处理中、无待办、筛选无结果、加载失败、AI 失败、数据不足、历史只读、状态冲突和无权限反馈。
- 各状态给出不改变业务事实的恢复动作。

**7. 分页区**

- 默认每页 50 条，可切换 20、50、100 条。
- 显示当前匹配总数、当前页和总页数。
- 固定排序完成后再分页，翻页不重复、不遗漏。

## 5. 界面内容

### 5.1 元素清单

**页面标题与角色名称**

- 文案：运营/主管为“行动中心”，外部相关人员为“库存协同任务”。
- 数据来源：当前有效角色。
- 显示条件：通过页面权限校验后显示。

**批次摘要**

- 内容：批次标识、事业部、业务期间、业务截止日、规则版本、清单状态、最后更新时间。
- 数据来源：所选成功批次及其冻结信息。
- 显示条件：存在用户有权查看的成功批次时显示。
- 历史标识：所选批次不是最新成功批次时显示“历史批次，只读查看”。

**最新提交状态**

- 内容：最新提交的批次标识及“规则处理中”或“处理失败”等状态。
- 数据来源：最新提交批次。
- 显示条件：最新提交不是默认成功批次且尚未形成可用清单时显示。
- 约束：不得用处理中或失败批次替换最新成功批次清单。

**批次选择**

- 内容：当前用户有权查看的成功批次及业务期间。
- 数据来源：批次清单历史。
- 显示条件：存在至少两个有权成功批次时显示。
- 角色投影：外部相关人员只出现包含其有权库存协同任务的批次，不返回其他批次身份。

**任务页签**

- 文案：“待我处理”“全部”“处理中”“已完成”。
- 数量：显示当前角色、当前批次、当前搜索与筛选范围内的数量。
- 数据来源：建议审核状态、当前角色动作状态与结果状态的只读聚合。
- 显示条件：成功批次清单可用时显示；历史批次仍可切换页签查看，但保持只读。

**SPU 搜索**

- 文案：“搜索 SPU ID 或名称”。
- 数据来源：当前角色有权清单范围。
- 显示条件：清单可用时显示。
- 校验：去除首尾空白；空值等同未搜索；不得检索或提示无权对象。

**筛选条件**

- 动作：完整视图可筛清仓、止损、观察、加投、补货、禁补；OA 协同视图仅补货、禁补。
- 店铺：仅运营和主管可见。
- 责任运营：仅运营和主管可见。
- 建议审核状态：待审核、已通过、已驳回；OA 协同视图不显示该筛选。
- 经营状态：运营与主管可筛待审核、变更待确认、待执行、已执行、待记录结果、已记录结果、已关闭；只匹配经营动作轨。
- 任务总进度：按建议审核及经营/库存两轨只读聚合的待审核、待执行、执行中、已执行、已记录结果、已驳回。
- 库存协同动作状态：OA 协同视图按本人库存协同动作展示待执行、已执行/已确认禁补、已记录结果、已关闭，不出现经营状态筛选。
- 数据来源：所选批次中当前角色有权字段的可用值。
- 显示条件：成功批次清单可用时显示。

**完整行动清单行（运营、运营主管）**

- 具体对象：SPU ID、名称、店铺、平台、责任运营。
- 发现问题：固定规则形成的结构化问题摘要；AI 成功后可增强表述但不得改变事实。
- 关键依据：实际指标值、统计周期、阈值、比较关系和影响当前动作的数据限制摘要。
- 推荐动作：唯一经营主动作，以及补货、禁补、不补货或不生成的库存结论；可执行动作标明责任角色。
- 商品类型：新品、大爆款、小爆款、淘汰商品或无法分类及原因。
- 状态：建议审核状态、经营动作状态、库存动作状态和只读建议总览状态。
- 跨周关系：稳定任务 ID、首次产生时间、本周关联时间常驻；最近前序待办来源批次/动作/状态/产生时间/执行时间默认折叠。
- 执行时间：经营动作成功进入已执行的真实时间；未执行显示“—”，不得使用更新时间或审核时间代替。
- AI 状态：待生成、生成中、已生成、生成失败或内容未采用。
- 数据限制：品退数据未校验、无可计算销量、库存数据不足、库存数据异常、无近期销售、分类/动作待补数等。
- 详情入口：文案“查看建议”，进入 `PAGE-F06-03`；历史批次进入同页只读模式。
- 数据来源：同一批次冻结快照、固定规则结论、结构化四要素、状态聚合和 AI 独立状态。

**责任运营的库存/OA 协同摘要**

- 与经营动作同一行展示补货/禁补结论、责任运营、OA 最近送达/失败状态、外部反馈核验状态和必要库存依据。
- 外部相关人员没有页面行、搜索范围或详情入口；只收到 OA 白名单消息并向责任运营反馈。
- OA 发送成功只表示送达，不能把协同动作或清仓完成状态自动写为完成。

**固定排序说明**

- 完整视图第一层固定为清仓、止损、观察、加投、补货；维持且无补货/禁补不进入清单。
- 清仓/止损与禁补共存时按经营主动作所在层级展示，不另拆禁补行。
- 加投与补货共存时按加投层级展示，仍保留补货动作状态。
- 只有“维持+补货”的建议进入补货层级；数据完整得出的“不补货”不单独进行动清单。
- 同一层内，若规则版本明确了已校验的影响代理指标，则按该指标降序并显示指标名称和值；否则按稳定 SPU ID 或批次内生成序号排列。
- 采购投影只按可见采购结论确定稳定任务顺序：禁补优先于补货，同组按稳定 SPU ID 或批次内生成序号排列，不使用隐藏经营字段暗示顺序。
- 不提供用户自由排序；AI 不参与动作层级或同层代理结果。

**分页控件**

- 内容：匹配总数、当前页、总页数、上一页、下一页和每页数量 20/50/100。
- 数据来源：当前批次、角色投影、页签、搜索和筛选后的清单结果。
- 显示条件：清单可用时显示；不足一页时仍显示匹配总数。

### 5.2 辅助信息

- 固定规则说明：“商品类型、动作与阈值来自本批次固定规则，AI 仅辅助解释。”
- AI 降级说明：“AI 等待或失败不影响固定规则清单、审核和执行。”
- 数据范围说明：“首版只处理 SPU/商品链接，不提供 SKU 或广告明细动作。”
- 历史说明：“历史批次保留当时规则和状态，仅可查看，不可继续操作。”
- 批量操作说明：“首版不支持批量审核、批量执行或批量结果回填，请进入单条建议处理。”

## 6. 交互流程

### 6.1 页面加载与初始化

1. 进入页面后先校验钉钉登录状态、当前角色和批次/任务对象权限；校验完成前不展示经营数据。
2. 找到当前用户有权查看的最新成功批次，并默认打开“待我处理”。
3. 如果最新提交仍在规则处理中或处理失败，继续展示最近成功批次清单，同时单独提示最新提交状态。
4. 按当前角色生成字段与记录投影：运营/主管加载完整清单，外部相关人员只加载本人库存协同任务必要字段。
5. 应用已保存的批次、页签、搜索、筛选、页码和每页数量；若首次进入则使用最新成功批次、“待我处理”和每页 50 条。
6. 按固定动作层级和稳定同层规则排序后分页。
7. 无成功批次、规则处理中、无待办、筛选空、加载失败、历史只读和无权限必须进入不同页面状态，不得共用同一空白提示。
8. 对新批次每个 SPU 分别比较经营轨和库存轨；同动作只关联原稳定任务并沿用状态，变化动作显示待主管确认，不直接覆盖原生效动作。
9. 按事业部与 SPU/商品链接精确查询最近前序经营待办；首次建任显示“无前序待办”且不渲染空折叠，存在历史时只加载业务时间最近的一条并以默认折叠方式展示。

### 6.2 核心操作流程

**流程一：处理最新成功批次的本人待办**

```text
用户进入行动清单页
        │
        ├─ 无有效登录或角色 → 不返回经营数据，进入认证恢复
        │
        ├─ 无成功批次 → 显示无批次/规则处理中状态
        │
        └─ 有成功批次 → 选择最新成功批次 + “待我处理”
                           │
                           ├─ 确无本人待办 → 显示本批次暂无待我处理
                           │
                           └─ 有待办 → 固定排序并展示角色投影
                                          │
                                          ├─ 搜索/筛选 → 仅改变显示范围
                                          │
                                          └─ 点击单条建议 → PAGE-F06-03
```

**流程二：切换页签、批次与历史只读查看**

```text
用户切换“全部/处理中/已完成”或选择历史批次
        ↓
系统按当前角色、批次和条件重新投影清单
        │
        ├─ 当前成功批次 → 可进入单条详情按角色处理
        │
        └─ 历史批次 → 显示只读提示
                         ↓
                    进入 PAGE-F06-03 只读模式
                         ↓
                    返回时恢复批次、页签、筛选和页码
```

**流程三：AI 异常或状态冲突时继续工作**

```text
规则清单已就绪
        │
        ├─ AI 待生成/生成中/失败/内容未采用
        │      → 保留结构化四要素、固定动作和详情入口
        │
        └─ 列表状态与详情操作后状态不一致
               → 提示“状态已更新”及最新操作者/时间（有权时）
               → 刷新为最新状态，不覆盖成功变更
```

### 6.3 辅助操作

- 输入 SPU 搜索词并提交后回到第一页；清空搜索恢复当前页签与筛选范围。
- 修改任一筛选后回到第一页；同时保留批次和页签。
- 经营状态筛选只作用于经营动作轨；选择后在 URL 保存 `businessState`，刷新和从详情返回时恢复。
- 点击“清除条件”只清除搜索与筛选，不改变当前批次和页签。
- 从建议详情返回时恢复离开前的批次、页签、搜索、筛选和页码。
- 点击“重试加载”仅重新获取当前范围，不生成新清单、不触发 AI 重试、不改变状态。
- 当页面发现状态已被他人更新时，展示最新状态并要求用户重新进入详情判断；本页不尝试自动提交旧操作。
- 首版每次只进入一条建议处理，不显示多选框、全选、批量操作栏或批量确认入口。

## 7. 状态与边界

### 7.1 页面状态全景

| 状态 | 触发条件 | 页面表现 |
| :--- | :--- | :--- |
| 权限校验中 | 刚进入页面，登录、角色或对象关系尚未确认 | 不展示批次、SPU、数量、搜索候选或动作信息 |
| 加载中 | 已有权限，清单尚未返回 | 保留已知批次上下文并提示正在加载，不显示伪造行 |
| 无成功批次 | 当前角色没有可用的成功清单 | 运营可前往数据批次；主管说明等待运营导入；采购说明暂无可处理库存协同任务 |
| 规则处理中 | 最新提交已接收但固定规则尚未生成清单，且没有更早成功批次可用 | 显示当前批次和规则处理中；不得展示空清单或开放审核/执行 |
| 正常有待办 | 最新成功批次存在当前角色待办 | 默认“待我处理”，按固定规则展示清单 |
| 确无待办 | 清单加载成功，但当前角色在默认范围内确实没有任务 | 显示“本批次暂无待我处理”；可切换“全部/处理中/已完成” |
| 同动作续接 | 同 SPU 本周动作与当前生效动作相同 | 显示“延续上周·未重建”及稳定任务 ID；审核、执行和责任人原样保留 |
| 首次无前序 | 当前 SPU 从未产生经营待办 | 显示“本周新任务”“无前序待办”及首次产生时间，不构造历史关系 |
| 最近前序存在 | 当前 SPU 存在历史经营待办 | 显示默认收起的“最近前序待办”入口；展开后显示批次、动作、状态、产生时间与执行时间；更早记录留在追溯页 |
| 动作变更待确认 | 同 SPU 本周规则动作与当前生效动作不同 | 显示“旧动作 → 新动作”和待主管确认；原生效动作在确认前不被覆盖 |
| 筛选无结果 | 清单存在，但当前搜索或筛选没有匹配项 | 显示“当前条件无结果”，提供清除条件；不得表达为本批次无问题 |
| AI 生成中 | 固定规则已就绪，AI 尚未完成 | 结构化四要素、动作和人工流程照常可用，AI 状态显示生成中 |
| AI 失败/内容未采用 | LiteLLM 失败或输出越界 | 显示固定规则兜底及失败/未采用状态，不显示冲突或虚构内容 |
| 数据限制 | 某些字段缺失、异常或周期未校验 | 显示影响范围和不能得出的结论；不把缺失值显示为 0 |
| 历史只读 | 用户选择的不是最新成功批次 | 显示历史只读提示，只允许搜索、筛选、翻页和进入只读详情 |
| 加载失败 | 网络或系统异常导致当前列表不可用 | 显示明确批次及“加载失败，请重试”，不伪装为空清单 |
| 状态冲突 | 列表所见状态在详情操作或他人操作后已变化 | 显示最新状态、最新操作者和时间（按权限），要求刷新或重新进入详情 |
| 会话过期 | 查看期间登录状态失效 | 停止继续展示和请求经营数据，重新钉钉认证后返回原安全位置 |
| 无权限 | 角色、批次或任务关系校验失败 | 返回本人工作台或权限恢复页，不返回目标批次、建议或状态字段 |
| 非支持设备 | 可用宽度低于 1024px | 显示“请使用电脑访问”，不提供会截断关键依据的操作流程 |

### 7.2 边界与容错

| 边界场景 | 处理策略 |
| :--- | :--- |
| 网络中断或请求超时 | 保留当前批次、页签和筛选上下文，显示重试；重试只重新加载，不生成第二份清单或改变状态 |
| 会话过期 | 停止展示后续数据，重新钉钉认证；认证成功且仍有权限时返回原批次和列表位置 |
| 连续加载失败 | 持续显示失败和恢复动作，不把失败转换成“暂无待办”，也不丢失用户当前查询条件 |
| 异常搜索词 | 去除首尾空白；空值恢复未搜索状态；超出当前有权记录范围时只返回“无结果”，不提示无权对象是否存在 |
| 异常筛选值、页签或页码 | 忽略无权/无效条件并回到当前角色可用默认范围；页码回到有效页，不修改业务数据 |
| 同一建议含加投和补货 | 只显示一条 SPU 建议，同时展示经营与库存动作及各自状态；完整视图按加投层级排序 |
| 同一建议含止损/清仓和禁补 | 两个动作必须同时出现且不可被补货覆盖；按止损或清仓层级排序，不拆成两行 |
| 维持且无补货/禁补 | 默认不进入行动清单；不因此删除可追溯决策记录 |
| 数据完整得出不补货 | 不单独创建采购执行任务；若同一建议存在经营动作，完整视图可显示“不补货”结论 |
| 品退周期未校验 | 不触发观察或依赖低品退的加投；利润清仓/止损仍可显示，数据限制明确标注 |
| 库存或 14 日销量不足 | 不生成补货/不补货；止损/清仓仍显示禁补，采购只看到与本任务相关的限制 |
| AI 等待、失败或越界 | 继续显示结构化四要素和固定动作；舍弃冲突、虚构或超粒度内容，不提供普通用户 AI 重试入口 |
| 最新提交处理中，已有旧成功批次 | 默认展示最近成功批次，同时提示最新提交处理中；不得把处理中批次当成空成功清单 |
| 最新提交失败，已有旧成功批次 | 默认展示最近成功批次，同时提示最新提交失败；历史成功清单不被覆盖 |
| 历史批次仍含未完成状态 | 只显示当时状态，不开放继续处理入口；必须从最新成功批次的本人待办进入当前业务操作 |
| 他人更新导致状态冲突 | 不保留或提交旧状态，显示最新状态、操作者和时间后要求用户重新判断；成功事件不被覆盖 |
| 采购直接访问完整行动中心地址 | 只返回其有权库存协同任务投影；没有任务关联时拒绝且不返回建议身份、状态或其他记录数量 |
| 采购使用完整视图筛选条件 | 不接受并不返回受限条件候选，不通过“无结果”之外的信息泄露店铺、责任运营、利润、推广或售后 |
| 角色在会话中被撤销或变更 | 下一次加载、翻页、搜索、筛选或进入详情时重新校验，旧角色数据和能力不再可用 |
| 不足一页或切换每页数量 | 显示真实匹配总数；切换 20/50/100 后回到第一页，固定排序保持不变 |

## 8. 业务规则与校验

### 8.1 字段定义

| 字段 | 说明 |
| :--- | :--- |
| `batch_id` | 当前清单所属唯一批次；一个有效批次只有一份清单 |
| `business_period` / `business_date` | 批次冻结的数据期间与业务截止日，用于解释商品类型和指标周期 |
| `rule_version` | 冻结的固定规则版本；决定分类、动作层级与可用同层代理 |
| `decision_id` | 批次内某 SPU 唯一建议身份；双动作共享该建议 |
| `spu_id` / `spu_name` | 首版唯一商品决策对象，等同商品链接；不含 SKU 结论 |
| `store` / `platform` / `operator_ref` | 完整视图用于定位和筛选的店铺、平台、责任运营；采购不接收这些非必要字段 |
| `category` | 新品、大爆款、小爆款、淘汰商品或无法分类 |
| `main_action` | 清仓、止损、观察、加投、维持或无法判定中的唯一经营主动作 |
| `inventory_action` | 禁止补货、补货、不补货或不生成；加投可与补货并存，止损/清仓必须与禁补并存 |
| `problem_summary` | 由固定规则结构化生成的问题摘要；AI 只能增强表达 |
| `evidence_summary` | 触发指标值、周期、阈值、比较关系和数据限制摘要 |
| `review_state` | 待审核、已通过或已驳回；与动作执行状态分开 |
| `business_action_state` | 经营动作的待审核、待执行、已执行、已记录结果或已关闭 |
| `task_id` / `task_created_at` | 以事业部与 SPU/商品链接锚定的稳定经营待办及其首次产生时间；续接不重置 |
| `current_linked_at` | 当前批次决策与稳定待办建立关联的时间；不是任务产生或执行时间 |
| `previous_todo` | 最近前序经营待办记录，含来源批次、动作、状态、产生时间、执行时间；首次建任为空 |
| `business_executed_at` | 经营动作实际执行时间；未执行为空并展示“—” |
| `inventory_action_state` | 库存协同动作的待审核、待执行、已执行/已确认禁补、已记录结果或已关闭 |
| `summary_state` | 由审核及各动作状态只读聚合出的待审核、已驳回、待执行、执行中、已执行或已记录结果 |
| `ai_state` | 待生成、生成中、已生成、生成失败或内容未采用；不控制清单就绪和业务状态 |
| `data_limitations` | 品退、库存、销量、分类或动作依赖不足的受控说明；采购只接收任务必要限制 |
| `priority_proxy` | 规则版本明确且数据已校验时可用的同层影响代理名称和值；不可用时为空 |
| `stable_order_key` | 同层无可用代理时保持确定顺序的稳定 SPU ID 或批次内生成序号 |

### 8.2 校验规则

| 校验项 | 时机 | 规则 | 失败反馈 |
| :--- | :--- | :--- | :--- |
| 登录与角色 | 页面进入及每次查询时 | 必须具备有效钉钉登录态和运营、运营主管中的唯一有效角色 | 无效或外部相关人员访问时不返回经营数据，进入认证恢复 |
| 批次可用性 | 初次加载或切换批次时 | 默认批次必须是当前角色有权查看的最新成功批次；处理中或失败批次不能冒充成功清单 | “该批次仍在规则处理中”或“该批次处理失败” |
| 历史只读 | 选择非最新成功批次及进入详情时 | 历史批次只允许查询和只读详情，不开放写操作 | “历史批次仅供查看，请返回最新成功批次处理任务” |
| SPU 搜索 | 提交搜索时 | 只在当前角色有权记录中匹配 SPU ID 或名称；空值视为未搜索 | “当前条件无结果” |
| 筛选权限 | 选择或恢复筛选时 | 只接受当前角色可见字段和值；筛选不得修改建议内容 | 无权条件不生效且不返回候选值 |
| 经营状态筛选 | 运营或主管选择筛选时 | 只匹配 `business_action_state`，不读取审核、采购或聚合状态替代 | 无效状态忽略并恢复默认；采购请求该条件不生效且不返回候选 |
| 前序关联 | 展示跨周关系时 | 仅在同一事业部与 SPU 下选择业务时间最近且早于当前的一条记录 | 无前序时显示“无前序待办”；关联冲突时标记数据异常而不跨 SPU 猜测 |
| 生命周期时间 | 展示产生/关联/执行时间时 | 三类时间分别取对应事件；执行时间仅来自成功经营执行事件 | 未执行显示“—”；缺失异常显示“时间记录异常”，不用更新时间填补 |
| 页签范围 | 切换页签时 | 按当前角色、审核及动作状态计算；AI 状态不改变处理中/已完成归属 | 无可用页签时回到“待我处理” |
| 固定排序 | 列表加载和条件变化时 | 完整视图先按清仓、止损、观察、加投、补货；同层按有效代理降序，否则稳定键；采购按禁补、补货及稳定键 | 排序信息不足时使用稳定键，不由 AI 推测 |
| 清单收录 | 生成列表时 | 仅有维持且无补货/禁补的 SPU 不进入；不补货不单独创建库存协同任务 | 记录不展示，但保留追溯身份 |
| 动作组合 | 展示行时 | 止损/清仓必须伴随禁补；加投与补货可共存；同一 SPU 仍只一行 | 组合异常时标记清单数据冲突，不展示为可处理成功 |
| 数据限制 | 展示依据时 | 缺失、异常或未校验必须显示为限制，不得显示为 0 或由 AI 补齐 | 显示具体限制及受影响判断 |
| AI 内容 | AI 状态变化时 | 冲突动作、虚构数值、广告/评价/退款原因/SKU 内容不得进入可见建议 | 保留结构化兜底，显示“内容未采用”或“生成失败” |
| 角色字段投影 | 每次返回列表、候选值或错误时 | 采购只接收 SPU 身份、采购结论、库存销量依据、采购状态与相关限制 | 越权请求拒绝，不返回受限字段或对象身份 |
| 分页 | 翻页或切换每页数量时 | 每页数量仅 20、50、100；排序后分页；页码不得超过当前结果页数 | 回到有效页并保留其他条件 |

### 8.3 特殊业务规则

- **默认范围**：首次进入固定选择当前用户有权查看的最新成功批次和“待我处理”。
- **“待我处理”按角色解释**：主管为待审核建议和待确认清仓完成时间；运营为本人 SPU 已通过且经营/协同动作待执行、结果待记录或清仓完成时间待提交/待修正。
- **“处理中”不受 AI 控制**：只依据建议审核和动作执行/结果进度；AI 待生成或失败不能把已完成业务任务重新归为处理中。
- **“已完成”按业务闭环判断**：建议已驳回，或该建议所有必要动作均已达到终态并已记录结果；明确记录“结果未提供”也属于已完成结果记录，不要求伪造数值。
- **一批一清单**：每个有效批次只存在一份行动清单；页面只是该批次建议与动作的唯一投影，不创建第二套身份。
- **一 SPU 一建议**：一个批次内一个 SPU 最多一条建议；经营与库存双动作在同一行分别显示状态。
- **主动作唯一**：固定优先级为清仓＞止损＞观察＞加投＞维持；AI、人工筛选和页面交互均不能改变。
- **禁补不可覆盖**：止损或清仓必须同步生成禁补；库存数据缺失也不能移除禁补。
- **新品库存边界**：新品首版不生成补货动作；不能因库存可售天数低而额外产生补货任务。
- **数据降级**：缺字段只阻断依赖该字段的判断；清单必须显示仍可确定的动作与受限结论，不用默认值补齐。
- **AI 独立**：结构化四要素先于 AI 可用；AI 失败、等待或内容未采用不阻塞清单、单条审核或单条执行。
- **历史冻结**：历史批次继续显示当时的规则、关键依据、审核与动作状态，不套用当前规则重排或改写。
- **SPU 精确锚定**：跨周经营待办按事业部与 SPU/商品链接匹配，不使用名称、店铺文案或模糊搜索建立关系。
- **最近前序唯一**：当前记录最多展示一条最近前序待办，并默认折叠其详细字段；完整链路在建议详情与历史追溯保留。
- **经营状态独立**：经营状态筛选只匹配经营动作轨，不等同建议审核、库存动作或总览聚合状态。
- **禁止批量业务操作**：本页和详情首版均不得提供批量审核、批量执行或批量结果回填；列表查询、翻页和筛选不属于批量业务操作。

### 9.2 与其他模块的关系

- **角色工作台**：运营和主管工作台分别带入当前角色待办范围；本页继续使用同一最新成功批次和双角色定义。
- **数据批次**：`PAGE-F01-02` 在固定规则完成后进入该批次唯一行动清单；AI 未完成不阻塞跳转。
- **固定规则**：为清单提供冻结分类、主动作、库存动作、阈值、同层排序依据和数据限制；本页不可编辑。
- **AI 解释**：异步补充可读解释和排序说明；本页显示独立状态，不把 AI 当成清单就绪条件。
- **建议详情**：`PAGE-F06-03` 承担完整证据、单条整体审核、分角色执行、结果记录、冲突处理和审计；本页只提供入口。
- **历史与追溯**：历史批次在本页只读；更完整的跨批次检索由 `PAGE-F08-01` 承担，二者都复用同一建议身份与详情页。
- **权限模块**：每次列表、搜索、筛选、候选值、错误和详情跳转均按当前角色与任务关系裁剪。

### 9.3 扩展预案

| 扩展方向 | 触发条件 | 改造点 |
| :--- | :--- | :--- |
| 批量业务操作 | PRD 新增稳定需求、逐项权限、确认策略和审计 AC | 重新设计批量选择、冲突与部分成功规则；当前页面不预埋入口 |

## 11. 验收标准

### 11.1 功能验收

| 编号 | 验收点 | 通过标准 |
| :--- | :--- | :--- |
| F-01 | 默认待我处理 | 双角色首次打开页面均进入其有权最新成功批次的“待我处理”；主管见待审核/待确认清仓完成，运营见本人待执行、待补录结果、待提交/待修正清仓完成时间 |
| F-02 | 最新成功批次 | 最新提交处理中或失败且存在旧成功批次时，默认继续展示旧成功清单并单独提示最新提交状态；没有成功批次时进入对应无批次/处理中状态 |
| F-03 | 四页签范围 | 待我处理、全部、处理中、已完成按角色和业务状态返回正确记录；切换页签不修改任何建议或动作状态 |
| F-04 | SPU 搜索 | 运营/主管可在有权清单内按 SPU ID 或名称搜索；外部相关人员无产品搜索能力，搜索无权对象不泄露其身份或状态 |
| F-05 | 多条件筛选 | 动作、店铺、责任运营、审核状态、经营状态、清仓确认状态和任务总进度任一条件均只显示匹配建议；经营状态只匹配经营动作轨 |
| F-06 | 固定排序 | 完整视图首次打开及每次条件变化后均按清仓、止损、观察、加投、补货排列；同层按有效代理降序，否则按稳定键，AI 状态不改变结果 |
| F-07 | 双动作一行 | 加投+补货、止损+禁补、清仓+禁补均只占一条 SPU 建议，并分别展示两个动作状态；止损/清仓不得出现补货 |
| F-08 | 收录范围 | 维持且无补货/禁补的 SPU 不进入清单；不补货不单独生成库存协同任务，但相关决策仍可追溯 |
| F-09 | 跨周任务续接 | 同 SPU 同动作不新建任务、不重置状态；动作变化追加待主管确认版本，每周决策快照仍可追溯 |
| F-10 | 最近前序待办 | 存在历史经营待办时显示默认收起的折叠入口；点击或键盘展开后完整显示最近前序批次、动作、状态、产生与执行时间，且不触发行跳转；首次建任显示无前序且无空折叠，不跨 SPU 关联 |
| F-11 | 生命周期时间 | 当前待办分别显示首次产生时间、本周关联时间和实际执行时间；未执行显示“—”，不使用更新时间替代 |
| F-12 | AI 降级 | AI 待生成、生成中、生成失败或内容未采用时，运营/主管仍看到完整结构化四要素、固定动作、详情入口和数据限制，清单不被标为失败 |
| F-13 | 数据限制 | 品退未校验、库存不足/异常、无近期销售或分类待补数时，列表显示受影响判断；缺失值不显示为 0，AI 不补齐 |
| F-14 | 历史只读 | 切换任一历史批次后显示只读提示，可搜索、筛选、翻页和进入只读详情，但不存在审核、执行或结果写入入口 |
| F-15 | 分页恢复 | 默认每页 50，可切换 20/50/100；从详情返回或刷新后恢复批次、页签、搜索、筛选、页码和每页数量，记录无重复无遗漏 |
| F-16 | 冲突刷新 | 列表状态被他人更新后显示最新状态、操作者和时间（按权限）；旧状态不覆盖成功变更，也不新增重复事件 |
| F-17 | 禁止批量操作 | 双角色、四个页签和历史模式中均不存在多选、全选、批量审核、批量执行或批量结果回填能力 |
| F-18 | 清仓完成确认 | 清仓动作不变时沿用同一完成确认流程；运营提交/修正，主管确认/退回，确认前每日 OA 最多催办一次，确认/改判/终止后停止 |

### 11.2 体验验收

| 编号 | 验收点 | 通过标准 |
| :--- | :--- | :--- |
| U-01 | 批次不混淆 | 页面始终可识别当前批次、业务期间、业务截止日和规则版本；历史批次明确标记只读 |
| U-02 | 待办直达 | 用户从工作台进入后无需额外选择即可看到本人待处理事项；无待办时能切换全部、处理中或已完成查看 |
| U-03 | 空状态区分 | 无成功批次、规则处理中、确无待办、筛选无结果和加载失败分别使用不同说明与恢复动作，互不伪装 |
| U-04 | 问题可理解 | 运营和主管不进入详情即可识别对象、问题、关键依据、经营/库存动作、审核/执行状态、AI 状态和数据限制 |
| U-05 | 数据限制清楚 | “0”“未提供”“未校验”“不生成”“不补货”和“禁止补货”语义可区分，不会把未知数据误解为安全结论 |
| U-06 | AI 状态不干扰 | AI 生成中或失败时，页面明确说明固定规则仍可用，不遮挡搜索、筛选、翻页和详情入口 |
| U-07 | 查询可恢复 | 切换页签、批次或筛选后刷新，以及从详情返回时，页面恢复原查询上下文和列表位置 |
| U-08 | 网络失败可恢复 | 加载失败时保留明确批次和查询条件，提供重试；成功后恢复真实列表而不是空状态 |
| U-09 | 冲突可理解 | 状态冲突时说明“状态已被更新”、最新状态及下一步，不让用户在旧状态上继续判断 |
| U-10 | 设备边界 | 可用宽度低于 1024px 时显示“请使用电脑访问”，不允许关键数值、阈值、动作和状态被截断后继续处理 |

### 11.3 安全验收（产品层）

| 编号 | 验收点 | 通过标准 |
| :--- | :--- | :--- |
| S-01 | 登录与角色校验 | 页面进入、搜索、筛选、翻页、切换批次和进入详情均重新校验有效钉钉身份与当前角色；失效后不继续返回经营数据 |
| S-02 | OA 字段最小化 | 外部相关人员无产品页面；OA 消息只出现 SPU 标识/链接、协同动作、责任运营、反馈要求和任务引用等白名单字段 |
| S-03 | 外部敏感字段隔离 | OA 消息中完整利润、推广、品退、售后、完整 AI、规则阈值和审核详情均不发送 |
| S-04 | 对象级授权 | 外部相关人员或无权账号访问建议/批次时不建立产品会话，且不返回对象身份、状态、数量或对象是否存在 |
| S-05 | 历史写保护 | 任一历史批次无审核、执行、结果或 AI 重试入口；通过旧地址或过期页面尝试写入也不得改变当前或历史状态 |
| S-06 | 规则字段只读 | 商品类型、主动作、库存动作、阈值、规则版本和排序依据不能被列表交互、AI、搜索或筛选修改 |
| S-07 | 错误信息最小化 | 加载、AI、权限和冲突错误不展示 LiteLLM 密钥、网关配置、原始整表、内部错误详情或无权对象信息 |
| S-08 | AI 越界隔离 | AI 返回冲突动作、虚构数值、广告明细、评价/退款归因或 SKU 结论时，对应内容不可见且固定规则字段保持不变 |
| S-09 | 批量操作禁用 | 页面不提供任何可绕过单条权限、单条状态校验和单条审计的批量审核、批量执行或批量结果回填路径 |
| S-10 | 角色变更即时生效 | 角色撤销或变更后，旧页面的下一次查询或跳转按新权限处理，不沿用缓存候选、记录或操作能力 |
