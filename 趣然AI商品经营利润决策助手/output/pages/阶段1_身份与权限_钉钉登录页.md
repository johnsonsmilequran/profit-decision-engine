# 页面名称：钉钉登录页

## 1. 文档元信息

| 字段 | 内容 |
| :--- | :--- |
| 页面 ID | `PAGE-F07-01` |
| Source IDs | `REQ-F07-03, AC-F07-05, NFR-002` |
| 所属产品 | 趣然 AI 商品经营与利润决策助手 |
| 所属模块 | 身份与权限 |
| 适用端 | PC Web |
| 页面路由 | `/login` |
| 页面类型 | 门禁 |
| 所属阶段 | 阶段1(MVP) |
| 上游来源 | 系统启动、直接访问需认证的业务页面、认证恢复流程重新发起钉钉认证 |

## 2. 页面概述

### 2.1 一句话定位

为趣然内部用户提供唯一的钉钉统一身份入口，并在认证成功且存在唯一有效业务角色后，将用户送入其有权访问的工作台。

### 2.2 存在理由

1. 若没有统一身份门禁，系统无法确定当前用户是运营还是运营主管，也无法执行最小可见的数据隔离。
2. 若认证结果与角色映射脱节，用户可能进入错误工作台；采购、仓库等外部相关人员必须始终被拒绝产品访问。
3. 若失败状态没有明确恢复路径，用户会在钉钉认证失败、登录态失效或角色未配置时反复尝试，且无法判断应重试还是联系运维/系统管理员。

### 2.3 页面目标（可衡量）

| 目标维度 | 具体指标 |
| :--- | :--- |
| 入口唯一性 | 未登录用户在本产品中可见的认证方式 100% 为钉钉统一身份认证 |
| 正确分流 | 钉钉认证成功且存在唯一有效角色时，100% 按运营、运营主管进入对应工作台 |
| 默认拒绝 | 认证失败、登录态无效或无唯一有效角色时，进入业务页面的比例为 0 |
| 数据保护 | 未认证及认证失败路径中展示经营数据的数量为 0 |
| 范围控制 | 页面中的账号密码、注册、找回密码、共享账号和角色选择入口数量均为 0 |
| 恢复明确性 | 所有失败状态均提供与原因匹配的重试或联系运维/系统管理员指引 |

### 2.4 不做什么（范围边界）

- **不做账号密码登录**：钉钉是上游确认的唯一统一身份入口，不增加替代认证方式。
- **不做注册或找回密码**：账号生命周期由钉钉身份体系承载，本产品没有对应需求。
- **不做共享账号**：每位用户必须使用自己的钉钉身份，避免责任与权限无法追溯。
- **不做角色选择或角色编辑**：业务角色来自事业部负责人审批及运维/系统管理员配置，用户不能在登录页自行选择或修改。
- **不展示经营数据或业务待办**：本页只完成认证与分流，业务内容必须在通过角色校验后进入相应工作台查看。

## 3. 用户与场景

### 3.1 目标用户

| 维度 | 描述 |
| :--- | :--- |
| 角色 | 运营、运营主管 |
| 人数 | 单次由一名内部用户使用；角色映射按个人钉钉身份生效 |
| 技术熟练度 | 中等，能够使用钉钉工作台或完成钉钉扫码登录 |
| 使用设备 | 主要使用宽度不低于 1024px 的电脑；低于 1024px 时只提供受控提示 |
| 使用姿势 | 在办公场景进入内部经营工作台，完成周度数据、经营闭环或审核任务 |

### 3.2 核心使用场景

**场景 A：钉钉环境自动授权（主场景）**

- 时机：用户从钉钉工作环境首次进入产品，或需要重新认证。
- 前置条件：用户拥有有效钉钉身份，且运维/系统管理员已依据事业部负责人审批结果配置唯一有效业务角色。
- 用户动作：打开产品并等待自动授权完成。
- 系统结果：认证成功后识别当前业务角色，显示成功状态并进入对应工作台。
- 用户情绪：快速、确定，不需要填写额外凭据。

**场景 B：普通浏览器完成钉钉登录或扫码（主场景）**

- 时机：用户从电脑普通浏览器访问产品。
- 前置条件：用户可使用自己的钉钉身份完成登录或扫码，且已有唯一有效业务角色映射。
- 用户动作：选择钉钉登录或使用钉钉扫码并完成确认。
- 系统结果：认证成功后按当前角色进入对应工作台，不出现角色选择步骤。
- 用户情绪：路径清楚、结果可预期。

**场景 C：认证失败后恢复（兜底场景）**

- 时机：钉钉认证失败、服务暂不可用、网络中断或认证过程未完成。
- 前置条件：系统尚未建立有效登录态。
- 用户动作：阅读失败原因后重新发起钉钉认证；持续不可用时按指引联系运维/系统管理员。
- 系统结果：失败期间不进入业务页、不展示经营数据；需进一步处理时进入 `PAGE-F07-02`。
- 用户情绪：知道发生了什么，也知道下一步该做什么。

**场景 D：身份有效但没有唯一角色（兜底场景）**

- 时机：用户已完成钉钉认证，但角色未配置、角色已失效或同时存在多个有效角色而无法唯一确定。
- 前置条件：钉钉身份有效，但不满足唯一有效业务角色条件。
- 用户动作：按提示进入认证恢复页并联系运维/系统管理员。
- 系统结果：不自动赋予默认角色，不展示任何经营数据，也不提供角色选择。
- 用户情绪：边界明确，不会误以为自己已获得业务权限。

### 3.3 用户核心诉求（优先级排序）

1. **安全进入**：只有本人钉钉身份与已审批角色同时有效时才能进入业务页。
2. **少操作**：钉钉环境自动授权，普通浏览器只完成钉钉登录或扫码。
3. **分流准确**：无需选择角色，系统按唯一有效角色进入正确工作台。
4. **失败可恢复**：失败后明确是重试还是联系运维/系统管理员。
5. **隐私可控**：认证完成前看不到任何经营数据、角色名单或其他用户信息。

## 6. 交互流程

### 6.1 页面加载与初始化

1. 用户进入页面后，系统先判断是否已有有效登录态。
2. 已有有效登录态且当前角色仍唯一有效时，不停留在本页：若存在经过安全确认且当前角色有权访问的原页面，则返回原页面；否则进入当前角色工作台。
3. 没有有效登录态时，系统判断当前是钉钉环境还是普通浏览器。
4. 钉钉环境自动发起统一身份认证，并显示授权进行状态。
5. 普通浏览器展示钉钉登录或扫码入口，等待用户主动完成认证。
6. 页面初始化及认证过程中不请求、不展示任何经营数据。

### 6.2 核心操作流程

```text
用户进入钉钉登录页
    │
    ├─ 已有有效登录态 + 唯一有效角色
    │      └─ 返回当前角色有权访问的原页面，或进入对应工作台
    │
    └─ 没有有效登录态
           │
           ├─ 钉钉环境 → 自动发起钉钉认证
           │
           └─ 普通浏览器 → 用户选择钉钉登录或扫码并完成确认
                         │
                         ▼
                    认证结果
                         │
              ┌──────────┼──────────┐
              │          │          │
         认证失败    身份有效但     身份有效且
                     无唯一角色     角色唯一有效
              │          │          │
              ▼          ▼          ▼
          可重新认证   进入认证恢复页  显示当前角色
          或联系运维   且不展示经营数据  并进入对应工作台
```

角色分流规则：

- 运营 → `PAGE-F05-01` 运营工作台。
- 运营主管 → `PAGE-F06-01` 主管工作台。
- 无角色、未知角色或存在多个有效角色 → 不提供角色选择，进入 `PAGE-F07-02`。

### 6.3 辅助操作

- 认证失败时，用户可选择“重新使用钉钉认证”。
- 钉钉服务持续不可用或角色映射异常时，用户按提示联系运维/系统管理员。
- 用户在其他窗口已完成认证时，本页重新识别有效登录态并按当前角色继续，不要求重复登录。
- 低于 1024px 的设备仅提供“请使用电脑访问”提示，不开放替代登录方式。

## 7. 状态与边界

### 7.1 页面状态全景

| 状态 | 触发条件 | 页面表现 |
| :--- | :--- | :--- |
| 初始检查态 | 页面首次打开 | 显示正在检查登录状态，不展示认证入口或经营数据 |
| 已登录跳转态 | 存在有效登录态及唯一有效角色 | 显示正在进入原安全页面或对应工作台，不要求再次认证 |
| 自动授权态 | 钉钉环境且无有效登录态 | 显示正在通过钉钉确认身份，暂不接受重复发起 |
| 待用户确认态 | 普通浏览器尚未完成钉钉登录或扫码 | 展示钉钉登录或扫码入口及本人身份提示 |
| 认证进行态 | 用户已发起钉钉认证 | 显示正在认证，认证完成前不允许重复提交 |
| 成功态 | 认证成功且存在唯一有效角色 | 显示当前角色与目标工作台，随后完成分流 |
| 认证失败态 | 钉钉拒绝、取消、认证未完成或返回失败 | 显示统一失败说明及重新认证操作，不进入业务页 |
| 服务异常态 | 网络中断或钉钉服务暂不可用 | 显示稍后重试和联系运维/系统管理员指引，不展示经营数据 |
| 角色异常态 | 角色缺失、失效、未知或不能唯一确定 | 不赋予默认角色，不显示角色选择，进入认证恢复页 |
| 设备受限态 | 访问宽度低于 1024px | 显示“请使用电脑访问”，不继续进入业务操作 |

### 7.2 边界与容错

| 边界场景 | 处理策略 |
| :--- | :--- |
| 连续认证失败 | 每次均保持在门禁外并提供重新认证；不在本页面自行设定失败次数、锁定阈值或其他认证方式 |
| 网络中断或钉钉暂不可用 | 明确区分为可恢复异常，允许稍后重试；持续不可用时指引联系运维/系统管理员 |
| 登录态在进入页面前已失效 | 按未登录处理并重新发起钉钉认证；恢复期间不展示原页面经营数据 |
| 无角色、未知角色或多个有效角色 | 统一视为没有唯一有效业务角色，转入认证恢复页；不赋予默认运营角色、不提供角色选择 |
| 重复点击认证入口 | 首次认证完成前不再次发起；页面保持当前认证进行状态 |
| 多窗口并发认证 | 若另一窗口已建立有效登录态，本页识别后按当前唯一有效角色继续；不创建额外身份或绕过角色复核 |
| 原页面已无权访问 | 不返回该页面，改为进入本人角色工作台；失败提示不暴露原对象的身份或状态 |
| 原页面来源不可确认 | 不按该来源跳转，改为进入本人角色工作台 |
| 认证成功后角色配置发生变化 | 进入业务页前以当前有效角色结果为准；已失效或不再唯一时转入认证恢复页 |
| 低于 1024px 的访问 | 提示使用电脑，不让关键信息在受限设备上被截断后继续业务操作 |

## 8. 业务规则与校验

### 8.1 字段定义

| 字段 | 说明 |
| :--- | :--- |
| `login_state` | 当前是否存在有效登录态，以及是否需要重新进行钉钉认证 |
| `access_environment` | 当前为钉钉环境或普通浏览器，用于决定自动授权或展示钉钉登录/扫码入口 |
| `authentication_state` | 检查中、待确认、认证中、成功、失败或服务异常等页面状态 |
| `ding_identity` | 钉钉认证成功后得到的当前个人身份；本页不接收账号密码等替代凭据 |
| `business_role` | 经事业部负责人审批并由运维/系统管理员配置的业务角色，必须是运营、运营主管之一且唯一有效 |
| `return_destination` | 用户认证前希望访问的原页面；只有当前角色有权且来源可确认时才可返回 |
| `failure_type` | 认证失败、服务异常、登录态失效、无唯一有效角色或访问恢复异常等受控失败类型 |

### 8.2 校验规则

| 校验项 | 时机 | 规则 | 失败反馈 |
| :--- | :--- | :--- | :--- |
| 登录态有效性 | 页面初始化及跳转前 | 仅有效登录态可跳过认证 | “登录状态已失效，请重新使用钉钉认证” |
| 钉钉认证结果 | 钉钉认证返回后 | 只有认证成功才能继续校验业务角色 | “钉钉认证未完成，请重新认证” |
| 角色有效性 | 认证成功后及进入业务页前 | 角色必须属于运营、运营主管 | “未获得有效业务角色，请联系运维/系统管理员” |
| 角色唯一性 | 认证成功后及进入业务页前 | 当前身份必须且只能匹配一个有效业务角色 | “业务角色无法唯一确定，请联系运维/系统管理员” |
| 原页面访问资格 | 返回原页面前 | 当前角色必须有权访问该页面或业务对象 | 不返回原页面，进入本人工作台；不透露原对象信息 |
| 认证进行状态 | 用户重复发起时 | 当前认证未结束前不重复发起 | 保持“正在认证”状态，不产生第二次操作 |
| 设备适用性 | 页面加载时 | 主工作区访问宽度需不低于 1024px | “请使用电脑访问” |

### 8.3 特殊业务规则

- **唯一认证方式**：本页只提供钉钉统一身份认证，任何状态下都不出现账号密码、注册、找回密码或其他登录方式。
- **角色不可自选**：角色由审批与配置结果决定；角色缺失、未知或不唯一时默认拒绝。
- **认证与数据隔离**：在有效认证和唯一角色同时成立前，不请求、不展示经营数据。
- **按角色分流**：运营、运营主管分别进入其对应工作台，不能从登录页跨角色选择目标。
- **恢复原页面**：只有原页面来源可确认且当前角色仍有访问权时才返回，否则进入本人工作台。
- **登录态时效**：应用登录态最长 12 小时，连续 2 小时无操作后失效；失效后必须重新进行钉钉认证。
- **身份责任**：用户使用本人钉钉身份进入，不支持共享账号。

## 9. 页面流转

### 9.1 流转图

```text
系统启动 / 访问需认证页面 / 从认证恢复页重新认证
                       │
                       ▼
              PAGE-F07-01 钉钉登录页
                       │
              是否已有有效登录态？
                 ┌─────┴─────┐
                 是           否
                 │            │
      校验唯一角色与原页面   钉钉自动授权或登录/扫码
                 │            │
                 └─────┬──────┘
                       ▼
             认证成功且角色唯一有效？
                 ┌─────┴─────┐
                 否           是
                 │            │
                 ▼            ├─ 运营 → PAGE-F05-01
       PAGE-F07-02 认证恢复    ├─ 运营主管 → PAGE-F06-01
```

若本次来自会话失效后的重新认证，且原页面仍安全、当前角色仍有权访问，则认证成功后优先返回原页面；否则进入对应角色工作台。

### 9.2 与其他模块的关系

- 与 `PAGE-F07-02` 的关系：本页负责发起认证与正常分流；认证失败、无唯一有效角色或无法安全恢复时，由认证恢复页承接解释与后续动作。
- 与三个角色工作台的关系：本页只根据唯一有效角色决定去向，不读取或展示工作台内的业务数据。
- 与全站权限的关系：本页完成身份门禁，但进入后仍按当前角色持续应用页面、数据、错误与历史路径权限。
- 与角色配置责任的关系：事业部负责人审批角色变更，运维/系统管理员执行配置；本页没有角色管理能力。
- 与数据模块的隔离：数据批次、行动清单、建议详情和钉钉协同任务在认证与角色校验完成前均不可见。

### 9.3 扩展预案

| 扩展方向 | 触发条件 | 改造点 |
| :--- | :--- | :--- |
| 新业务角色 | PRD 新增并确认稳定 REQ/AC，且明确审批、配置与权限边界 | 回到 PRD 和权限设计后增量扩展角色分流，不在当前登录页预置角色入口 |
| 新认证方式 | PRD 明确新增认证方式及前置能力 | 重新进行产品与安全评审；当前页面不预埋账号密码或第三方登录入口 |
| 移动端完整使用 | PRD 明确移动端业务场景和验收标准 | 重新设计认证后的业务流程；当前低于 1024px 仍只提示使用电脑 |
| 多身份或多事业部切换 | PRD 明确切换规则、审批责任和数据隔离要求 | 增加独立的身份上下文流程，不把登录页改成未经授权的角色选择页 |

## 11. 验收标准

### 11.1 功能验收

| 编号 | 验收点 | 通过标准 |
| :--- | :--- | :--- |
| F-01 | 钉钉环境自动授权 | 无有效登录态的用户从钉钉环境进入时，页面进入自动授权流程，不要求填写任何凭据 |
| F-02 | 普通浏览器认证入口 | 无有效登录态的用户从普通浏览器进入时，只看到钉钉登录或扫码入口，不出现其他认证方式 |
| F-03 | 角色正确分流 | 认证成功且角色唯一有效时，运营进入 `PAGE-F05-01`、运营主管进入 `PAGE-F06-01`；其他人员不建立产品会话 |
| F-04 | 已登录跳过 | 有效登录态与唯一有效角色仍成立时，访问本页直接恢复有权原页面或进入对应工作台 |
| F-05 | 认证失败恢复 | 认证失败时不进入业务页，展示重新发起钉钉认证的操作；服务持续不可用时给出联系运维/系统管理员指引 |
| F-06 | 无角色默认拒绝 | 身份有效但无角色、角色未知或角色不唯一时，不赋予默认角色、不显示角色选择，进入 `PAGE-F07-02` |
| F-07 | 登录态失效 | 登录态失效后重新进入钉钉认证流程，认证成功且原页面仍有权时恢复原页面 |
| F-08 | 重复认证控制 | 认证进行中重复点击不会产生第二次可见认证流程；其他窗口已完成认证时本页可识别并继续分流 |

### 11.2 体验验收

| 编号 | 验收点 | 通过标准 |
| :--- | :--- | :--- |
| U-01 | 状态可理解 | 检查、待确认、认证中、成功、失败和服务异常均有明确且互不混淆的状态文案 |
| U-02 | 主路径短 | 钉钉环境无需手工填写信息；普通浏览器只需完成钉钉登录或扫码，不增加角色选择步骤 |
| U-03 | 成功去向明确 | 认证成功后展示当前角色及即将进入的工作台，不让用户猜测去向 |
| U-04 | 失败可行动 | 每个失败状态至少提供一种可执行恢复动作：重新认证、稍后重试或联系运维/系统管理员 |
| U-05 | 网络异常不伪装 | 网络中断或钉钉不可用时显示异常，不展示空白页、不误报认证成功 |
| U-06 | 设备受限提示 | 低于 1024px 时明确提示“请使用电脑访问”，不让用户在信息可能不完整的状态下继续业务操作 |
| U-07 | 原页面恢复 | 会话失效后重新认证成功，只有在原页面仍有权限时返回；否则进入本人工作台且不给出误导性失败 |

### 11.3 安全验收（产品层）

| 编号 | 验收点 | 通过标准 |
| :--- | :--- | :--- |
| S-01 | 唯一认证入口 | 页面在所有状态下均不出现账号密码、注册、找回密码、共享账号或其他认证方式 |
| S-02 | 未认证数据隔离 | 初始、认证中、认证失败、服务异常和角色异常状态均不展示或返回任何经营数据 |
| S-03 | 唯一角色门禁 | 只有钉钉身份有效且运营、运营主管中的一个角色唯一有效时才能进入业务页 |
| S-04 | 默认拒绝 | 角色缺失、未知、不唯一或失效时不自动赋予运营等默认角色，也不提供角色选择绕过配置 |
| S-05 | 安全返回 | 原页面来源不可确认或当前角色已无权时，不返回该页面，且提示中不泄露原业务对象身份或状态 |
| S-06 | 错误最小披露 | 认证与角色失败反馈不展示其他角色、其他用户、角色配置详情、业务模块清单或经营字段 |
| S-08 | 受限设备保护 | 低于 1024px 时不展示经营数据，也不开放认证后的关键业务操作入口 |
