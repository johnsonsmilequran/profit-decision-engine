# r1-engineer.md · 工程师主笔章节

## §5 详细功能说明

### 5.1 通用约定

- 决策粒度：所有导入、计算、建议、审核、执行和追溯对象均为 SPU；SPU 即商品链接，首版不读取、展示或生成 SKU 级结论。
- 数据节奏：数据支持部门每周一提供经营表；每个导入批次最多生成一份行动清单；周内只更新审核、执行与结果状态，不基于原批次重复生成新建议。
- 数据期间：商品分类销售额与经营准利润率使用上一个完整自然月；首批样本期间固定显示为 `2026-06-01—2026-06-30`，不得沿用源表“上一周”错误表头。
- 数值展示：金额使用人民币元；经营准利润率、品退率显示百分比并保留源数据精度；库存可售天数允许显示小数，不在界面端重新改变规则比较值。
- 规则与 AI 边界：商品类型、主动作、补货/禁补结论均由固定规则产生；AI 只生成解释、排序说明和不改变主动作的优化提示。
- 状态保留：新批次不覆盖历史批次；建议原始结论、关键值、审核、执行、结果和备注均保留可追溯记录。
- 错误分级：批次级阻断错误禁止生成整批清单；行级错误只排除对应 SPU；非阻断警告允许其他规则继续计算，但必须随建议展示数据限制。

### FR-1（F01）

**功能名称**：数据导入与校验  
**实现用户故事**：US-F01-01  
**对应需求**：REQ-F01-01、REQ-F01-02

**位置**：内部工具的“数据导入”页；导入完成后进入同一批次的“校验结果”页。

**界面元素与展示规则**：

| 元素 | 类型 | 默认态 | 操作后 | 禁用条件 |
|---|---|---|---|---|
| 事业部 | 单选字段 | 玩具事业部 | 记录为本批次范围并显示在批次摘要 | 导入校验开始后不可修改 |
| 数据期间 | 起止日期 | 未选择 | 显示起止日期及“上一个完整自然月”口径 | 起止日期非法或结束日期早于开始日期时禁止导入 |
| XLSX 文件 | 文件选择 | 未选择 | 显示文件名、大小和待校验状态 | 非 XLSX、文件不可读取或未选择事业部/期间时禁止提交 |
| 导入按钮 | 主按钮 | 禁用 | 进入“校验中”，完成后显示校验结果 | 必填项缺失、校验进行中或当前用户无导入权限 |
| 批次摘要 | 信息卡 | 不显示 | 显示批次 ID、事业部、期间、文件名、提交人、提交时间和处理状态 | 无 |
| 校验结果 | 汇总卡+明细表 | 不显示 | 显示有效行、行级错误、警告、忽略的源表合计及每条问题所在行/列 | 校验尚未完成 |
| 生成清单按钮 | 主按钮 | 不显示 | 对通过校验的 SPU 进入指标计算；重复点击不重复生成 | 存在批次级阻断错误、有效明细不在首轮 10—20 个范围内或该批次清单已生成 |
| 下载错误明细 | 次按钮 | 不显示 | 下载当前批次错误位置、字段和原因 | 当前批次没有错误或校验未完成 |

**交互逻辑**：

1. 运营选择玩具事业部、明确数据期间并选择 XLSX 文件后提交。
2. 系统先识别工作表和明细区域，忽略源表合计行，以 SPU 明细重新汇总；不得把第 1 行合计作为本批次经营结果。
3. 系统校验 SPU ID、链接名称、店铺、运营、上架日期、净销售额、经营准利润率、经营准利润值、推广费用、销量及可用的品退和库存字段。
4. SPU ID 缺失或重复、上架日期不可解析、净销售额或经营准利润率缺失/非数值时，系统定位到具体行与字段并排除该行，不用默认值补齐。
5. 品退最近 7 天口径未提供或未确认时，记录非阻断警告；库存、在途库存或最近 14 天销量缺失时，记录“库存数据不足”警告，不阻断该 SPU 的非补货规则。
6. 校验通过后，运营点击“生成清单”；系统只处理有效 SPU，并为批次固化事业部、数据期间、源文件标识和校验结果。
7. 同一事业部、同一数据期间且文件内容完全相同的再次提交视为同一批次：返回已有批次与清单，不重复计算、不新增建议。
8. 同一事业部和期间存在内容不同的文件时，不覆盖既有批次；界面明确提示“同期间已有不同内容批次”，新文件只能形成独立更正批次并保留与原批次的先后关系。

**异常场景**：

- 文件损坏、加密或解析失败：整批标记“导入失败”，不产生批次清单，显示文件级原因。
- 多个工作表或无法唯一识别明细区域：阻断生成清单，显示需由运营确认的数据区域；首版不静默拼接多个结构不同的工作表。
- 表头别名或列错位导致必需字段无法唯一映射：阻断对应字段计算，显示候选列和冲突，不按列位置猜测。
- SPU ID 重复：所有重复行均标出；在用户提供唯一明细前，这些行不进入计算。
- 只有部分行错误：有效行可继续，但错误行数量与 SPU ID 必须在生成清单前向运营展示。
- 源表表头合计与明细不一致：显示警告并忽略合计，只使用通过校验的明细。
- 上架日期出现数字日期、文本日期、`否`、`0` 或错位值：能确定解析的转换为日期；不能确定的行标记错误，不猜测新品身份。
- 导入期间网络中断或页面关闭：未完成批次不得显示为成功；再次提交相同文件按幂等规则恢复或返回既有结果。
- 导入进行中重复点击或多窗口同时提交相同文件：只接受一个有效提交，其余请求返回同一批次状态。
- 无权限用户直接访问导入地址：不展示文件内容与历史批次，返回权限不足。

**明确边界**：

- 首轮每批有效明细为 10—20 个真实 SPU；少于 10 或多于 20 时不生成首轮行动清单，并明确显示范围错误。
- 决策数据只取 SPU/链接明细；任何 SKU 字段即使存在也不参与计算。
- 首版只接收 XLSX；不承诺 CSV、在线表格或外部系统自动同步。
- 同一批次最多一份行动清单；相同内容重复导入返回原批次。
- 首批样本按 `2026-06-01—2026-06-30` 处理，不使用“上一周”字样推断数据期。

### FR-2（F02）

**功能名称**：SPU 经营指标计算  
**实现用户故事**：US-F02-01  
**对应需求**：REQ-F02-01、REQ-F02-02、REQ-F02-03

**位置**：批次处理页的“指标结果”步骤；行动清单的 SPU 详情中展示最终采用的指标、周期和数据状态。

**界面元素与展示规则**：

| 元素 | 类型 | 默认态 | 操作后 | 禁用条件 |
|---|---|---|---|---|
| SPU 身份 | 只读信息 | 来自有效明细 | 显示 SPU ID、名称、店铺、平台、运营 | 无 |
| 上架日期与商品类型状态 | 只读信息+状态标 | 待计算 | 显示上架日期、“新品/非新品待分类”或“日期异常” | 上架日期不可解析时不提供商品类型结论 |
| 上月净销售额 | 金额+期间 | 待计算 | 显示值、`上一个完整自然月`及实际起止日期 | 字段缺失或非数值时显示“待补数” |
| 经营准利润率 | 百分比+来源标 | 待计算 | 显示表内值并标记“采用源表经营准利润率” | 字段缺失或非数值时显示“待补数” |
| 品退率 | 百分比+口径状态 | 未校验 | 数据充分时显示最近 7 天计算值；否则显示“品退数据未校验” | 最近 7 天分子/分母缺失或已销售件数为 0 时不产生品退判断值 |
| 库存可售天数 | 数值+数据状态 | 未计算 | 数据充分时显示计算值；否则显示“库存数据不足”或“无近期销售” | 任一库存字段缺失或最近 14 天平均日销量为 0 时不计算 |
| 指标异常 | 状态列表 | 无异常 | 显示缺数、不可解析、周期未确认和不参与规则的原因 | 无 |

**交互逻辑**：

1. 系统按批次固化的数据期间读取上一个完整自然月净销售额和源表经营准利润率，不按早先自定义利润公式重算。
2. 系统以批次生成日与上架日期比较：生成日早于“上架日期加 2 个自然月”的 SPU 为新品；达到该边界当日及之后转为非新品。
3. 对非新品，使用上一个完整自然月净销售额区分大爆款、小爆款和淘汰商品；分类结果交由 FR-3 固定规则使用。
4. 仅当数据能证明为最近 7 天时，按“最近 7 天品退件数 ÷ 最近 7 天已销售件数”计算品退率；源表仅有未确认周期的品质退货率时，不把该值冒充最近 7 天指标。
5. 仅当仓内库存、在途库存和最近 14 天销量均存在时，先计算最近 14 天平均日销量，再计算 `(仓内库存+在途库存)÷平均日销量`。
6. 每个指标同时保存原始值、采用周期、计算状态和数据限制，供规则、建议和追溯页一致展示。

**异常场景**：

- 净销售额或经营准利润率为空、文本化且不可转为数值：利润相关规则不执行，SPU 标记“待补数”。
- 净销售额为负值：标记数值异常，不按销售额阈值分类，不自行改为 0。
- 经营准利润率超出源表可表达的合理百分比格式或单位不清：标记口径异常，不把 `15` 擅自解释为 `15%` 或 `1500%`。
- 上架日期晚于批次生成日：标记日期异常，不分类。
- 上架日期正好达到 2 个自然月：不再属于新品，进入非新品销售额分类。
- 最近 7 天已销售件数为 0：不做除法，不触发品退观察，显示“无可计算销量”。
- 品退件数为负、品退件数大于已销售件数或周期不等于最近 7 天：标记品退数据异常/未校验，不用于触发观察。
- 仓内库存或在途库存为负：标记库存数据异常，不计算库存可售天数。
- 最近 14 天平均日销量为 0：不做除法，显示“无近期销售”，不生成补货建议。
- 指标计算过程中服务中断：批次保持“处理中/失败”而非展示部分结果为完成；恢复后同批次重算不得改变已固化的输入和期间。

**明确边界**：

- 大爆款下界为净销售额 `≥100,000 元`；小爆款为 `≥20,000 元且<100,000 元`；淘汰商品为 `<20,000 元`。
- 新品边界为不满 2 个自然月；达到 2 个自然月时按非新品处理。
- 品退观察阈值的比较值为 `1.5%`；只有最近 7 天口径可信时参与规则。
- 库存可售天数补货阈值为 `30 天`；`<30` 与 `≥30` 必须得到不同结论。
- 现有样本没有 SPU 仓内库存、在途库存和最近 14 天销量，因此样本试跑不产生自动补货结论。

### FR-3（F03）

**功能名称**：固定规则决策  
**实现用户故事**：US-F03-01  
**对应需求**：REQ-F03-01、REQ-F03-02、REQ-F03-03

**位置**：批次处理页的“规则判定”步骤；SPU 详情的“规则结论”区。

**界面元素与展示规则**：

| 元素 | 类型 | 默认态 | 操作后 | 禁用条件 |
|---|---|---|---|---|
| 商品类型 | 状态标 | 待判定 | 新品/大爆款/小爆款/淘汰商品/数据异常 | 分类依据缺失时仅显示“数据异常” |
| 主动作 | 强状态标 | 待判定 | 清仓/止损/观察/加投/维持/无法判定 | 必要指标缺失时不显示推测动作 |
| 补货动作 | 次状态标 | 待判定 | 补货/不补货/禁止补货/不生成建议 | 新品固定显示“不生成建议”；数据不足时不计算补货 |
| 触发规则 | 只读规则卡 | 未生成 | 显示规则编号/说明、比较值、阈值和命中关系 | 无有效规则结论时显示未命中原因 |
| 数据限制 | 警告标 | 无 | 显示品退未校验、库存不足或关键字段缺失 | 无 |
| 规则版本 | 只读文本 | 待生成 | 显示本批次使用的固定规则版本 | 批次未进入规则判定时不显示 |

**交互逻辑**：

1. 规则引擎只接收 FR-2 固化的指标和数据状态；同一批输入、同一数据期间和同一规则版本必须得到相同商品类型、主动作及补货结论。
2. 系统先判新品，再对非新品按销售额分类；分类失败时不进入动作规则。
3. 主动作按 `清仓>止损>观察>加投>维持` 顺序匹配，命中高优先级动作后不得再输出其他主动作。
4. 大爆款：利润率 `<0%` 清仓；`0%≤利润率<5%` 止损；其余情况下品退率 `>1.5%` 观察；利润率 `≥10%` 且品退率 `≤1.5%` 加投；其他维持。
5. 小爆款：利润率 `<5%` 清仓；`5%≤利润率<10%` 止损；其余情况下品退率 `>1.5%` 观察；利润率 `≥15%` 且品退率 `≤1.5%` 加投；其他维持。
6. 新品：利润率 `≥-20%` 加投；利润率 `<-20%` 观察；首版不生成补货建议。
7. 淘汰商品：固定输出清仓和禁止补货。
8. 对非新品，主动作是清仓或止损时强制输出禁止补货；否则在库存数据充分时，库存可售天数 `<30` 输出补货，`≥30` 输出不补货。
9. 规则计算完成后，界面同时展示结论与触发路径；用户不能在此页面手工改写固定规则结果。

**异常场景**：

- 分类所需日期或净销售额缺失：主动作显示“无法判定”，不得直接把 SPU 归为淘汰商品。
- 利润率缺失：不生成利润相关动作；即使存在推广费用，也不得凭费用单项猜测止损。
- 品退率缺失或周期未校验：不触发品退观察；可以继续执行不依赖品退值的清仓、止损规则；需要品退值才能判定的加投不成立。
- 库存数据缺失：不生成补货/不补货结论，但止损或清仓仍必须输出禁止补货。
- 同一 SPU 同时满足低利润与高品退：按优先级只输出清仓或止损，不并列输出观察。
- 同一 SPU 同时满足加投与补货：允许主动作“加投”与次动作“补货”并存，分别指定执行角色。
- 规则服务失败或版本无法加载：整批不得进入“规则完成”，不调用 AI 猜测结论。
- 重试同一批次：只要输入和规则版本不变，必须复用或重现完全相同的规则结论；已审核内容不因重试被覆盖。

**明确边界**：

- 利润率等于大爆款 `0%` 时为止损，等于 `5%` 时不再因低利润止损；等于 `10%` 且品退率不高于 `1.5%` 时加投。
- 利润率等于小爆款 `5%` 时为止损，等于 `10%` 时不再因低利润止损；等于 `15%` 且品退率不高于 `1.5%` 时加投。
- 品退率等于 `1.5%` 不触发观察；高于 `1.5%` 才触发。
- 新品利润率等于 `-20%` 时加投；低于 `-20%` 时观察。
- 库存可售天数等于 `30` 天时不补货；低于 `30` 天时补货。
- AI 输出、审核意见和执行状态均不得反向改写本批次规则结论。

### FR-4（F04）

**功能名称**：AI 建议解释  
**实现用户故事**：US-F04-01  
**对应需求**：REQ-F04-01、REQ-F04-02、REQ-F04-03

**位置**：规则判定完成后的“建议生成”步骤；行动清单行摘要及建议详情页。

**界面元素与展示规则**：

| 元素 | 类型 | 默认态 | 操作后 | 禁用条件 |
|---|---|---|---|---|
| AI 生成状态 | 状态标 | 待生成 | 生成中/成功/生成失败/结构校验失败 | 固定规则尚未完成时不调用 AI |
| 具体对象 | 结构化只读字段 | 来自 SPU 主数据 | 显示 SPU ID、名称、店铺和责任运营 | SPU 身份缺失时该行已在导入阶段排除 |
| 发现的问题 | AI 文本+规则兜底 | 待生成 | 成功时显示可读问题；失败时显示固定规则结构化问题 | 无规则结论时不生成 |
| 关键依据 | 结构化依据+AI 文本 | 来自固定规则 | 显示关键值、周期、阈值、比较关系和数据限制 | 不允许 AI 添加不存在的数值 |
| 推荐动作 | 规则只读字段+解释 | 来自固定规则 | 显示主动作、补货动作、执行角色及 AI 解释 | AI 不得编辑动作字段 |
| 优化提示 | 可选 AI 文本 | 不显示 | 仅在不改变主动作时显示价格、内容或详情页方向 | 无足够依据、AI 失败或输出越界时不显示 |
| 重新生成解释 | 次按钮 | 可用 | 只重试解释，不重算或改变规则结论 | 正在生成、无权限、规则结论缺失或建议已进入不可重算的历史批次 |

**交互逻辑**：

1. 系统把固定规则结论、SPU 身份、关键值、周期、阈值和数据限制作为结构化输入发送到现有 LiteLLM 网关。
2. AI 返回内容只填充“发现的问题”“依据说明”“动作解释”“排序解释”和可选优化提示；主动作、补货动作、阈值和执行角色直接使用固定规则结果。
3. 系统对 AI 返回进行结构约束检查；如果返回动作与固定规则不一致、出现输入中不存在的经营数值、伪造广告计划/关键词/素材或给出 SKU 级结论，则舍弃冲突内容。
4. AI 正常时，每条建议必须可读地包含具体对象、发现问题、关键依据和推荐动作；AI 不可用时仍展示由规则字段拼装的四段结构。
5. 重新生成只更新解释版本并保留前一版本追溯记录，不改变商品类型、主动作、补货结论、规则版本和关键原始值。

**异常场景**：

- LiteLLM 网关不可用、超时或返回错误：标记“AI 解释生成失败”，保留固定规则结论和结构化依据，行动清单仍可生成和审核。
- 返回为空、非预期结构或字段缺失：使用结构化兜底文案，并记录失败状态。
- 返回内容与固定规则冲突：规则字段优先；冲突 AI 文本不展示为建议结论。
- AI 根据缺失库存、品退或广告明细推断数字/对象：删除推断内容，保留“数据不足”提示。
- AI 输出具体广告计划、单元、关键词、素材或 SKU 动作：判为越界，不展示该部分。
- 网络恢复后重试：只补充解释，不新增第二条规则建议。
- 普通用户尝试查看或修改模型密钥：产品中不存在该入口；不得返回任何密钥值或网关凭据。
- 部署密钥失效：所有受影响调用统一降级，普通用户只看到服务不可用状态和规则兜底，不看到凭据细节。

**明确边界**：

- 首版 AI 不决定、不修改、不合并和不覆盖商品类型、主动作、补货动作或阈值。
- AI 失败不阻断规则清单、审核、执行和追溯。
- LiteLLM 密钥为运维配置的系统级 deployment secret；首版没有管理员后台、设置页、用户自助配置、连接验证、更新或删除密钥界面。
- 优化提示只能到 SPU 的价格、内容或详情页方向，不承诺评价归因、退款原因归因或广告明细级定位。

### FR-5（F05）

**功能名称**：行动清单  
**实现用户故事**：US-F05-01  
**对应需求**：REQ-F05-01、REQ-F05-02、REQ-F05-03

**位置**：登录后的“本周行动清单”页；可进入历史批次与单条建议详情。

**界面元素与展示规则**：

| 元素 | 类型 | 默认态 | 操作后 | 禁用条件 |
|---|---|---|---|---|
| 批次选择 | 下拉/历史入口 | 最新成功批次 | 切换后显示对应期间和历史清单 | 无权限或批次不存在 |
| 批次信息 | 只读摘要 | 最新批次 | 显示事业部、期间、生成时间、规则版本和数据限制 | 无 |
| 筛选器 | 多条件筛选 | 全部动作、店铺、运营、审核状态、执行状态 | 立即收窄列表并显示命中数量 | 当前角色无权查看的筛选字段不展示 |
| 建议列表 | 表格/卡片 | 按默认优先级 | 显示对象、问题摘要、依据摘要、主动作、补货动作、责任人和状态 | 无数据时显示空状态，不显示虚构示例 |
| 优先级 | 序号+标签 | 清仓、止损、观察、加投、补货 | 同动作内按已有代理指标排序 | 相应指标缺失时不进行额外估算 |
| 数据限制 | 警告标签 | 无 | 显示品退未校验、库存不足、AI 失败等 | 无 |
| 建议详情 | 抽屉/详情页 | 关闭 | 展开完整四段建议、规则路径和状态记录 | 当前角色对该字段无权限时隐藏相应内容 |

**交互逻辑**：

1. 每个成功导入批次只生成一份行动清单；历史批次只读保留，不被新批次覆盖。
2. 默认不展示仅有“维持”且没有补货动作的 SPU；清仓、止损、观察、加投或补货任一可执行动作会进入清单。
3. 默认排序为清仓、止损、品退观察、加投、补货；同一动作内只使用本批次已有且可解释的经营准利润绝对值、推广费用、库存金额或销售额排序。
4. 缺少同动作排序代理指标时保持动作优先级和稳定顺序，不由 AI 猜测影响金额。
5. 用户打开详情后，看到具体对象、发现问题、关键依据、推荐动作、执行角色、批次、期间、规则版本和数据限制。
6. 采购计划进入同一清单时，只看到与补货/禁止补货相关的 SPU 和必要库存、销量依据；不通过列表摘要或筛选项泄露利润、推广和售后信息。

**异常场景**：

- 批次尚未完成规则判定：不展示为可审核清单，页面显示处理状态。
- 有规则结论但 AI 失败：显示规则兜底建议和“AI 解释失败”标记，不隐藏该经营问题。
- 过滤后无结果：显示“当前条件下无建议”，保留清除筛选入口。
- 历史批次中的 SPU 在新批次不存在：历史记录仍可打开，不从旧清单删除。
- 列表加载失败或网络中断：不把空白误报为“无问题”，显示加载失败并保留批次标识。
- 用户在不同标签页切换批次：每次审核或执行前以详情中的批次 ID 校验，禁止把动作写入错误批次。
- 采购计划通过地址或导出尝试访问完整建议：系统仍按角色裁剪，不仅依赖前端隐藏。

**明确边界**：

- 一条建议必须包含具体对象、发现问题、关键依据和推荐动作；缺任一项不得标记为完整 AI 建议，但可显示规则兜底版本。
- 同一 SPU 只有一个主动作；加投可与补货并存，清仓或止损必须与禁止补货并存。
- “推广止损”只表示 SPU 整体推广动作，不出现广告计划、单元、关键词或素材级对象。
- 没有库存金额时不估算库存影响；没有相应代理指标时不强行生成同动作影响排序。

### FR-6（F06）

**功能名称**：审核与执行跟踪  
**实现用户故事**：US-F06-01、US-F06-02  
**对应需求**：REQ-F06-01、REQ-F06-02、REQ-F06-03

**位置**：建议详情页的“审核与执行”区；“待我处理”列表；历史状态时间线。

**界面元素与展示规则**：

| 元素 | 类型 | 默认态 | 操作后 | 禁用条件 |
|---|---|---|---|---|
| 当前状态 | 状态标+时间线 | 待审核 | 显示已驳回，或已通过/待执行、已执行、已记录结果 | 无 |
| 审核操作 | 通过/驳回按钮 | 运营主管可用 | 通过后进入待执行；驳回后保留原因并终止本批次执行链 | 非运营主管、非待审核状态或页面版本已过期 |
| 审核备注 | 文本输入 | 空 | 与审核结果、审核人和时间一并保存 | 非待审核状态不可提交新审核 |
| 执行责任人 | 只读字段 | 按动作映射 | 加投/推广止损/清仓为运营，补货为采购计划 | 建议未通过时不开放执行 |
| 执行确认 | 按钮+备注 | 待执行 | 记录已执行、执行人、时间和备注 | 非责任角色、未通过、已驳回、已执行或页面版本已过期 |
| 结果记录 | 状态+备注 | 未记录 | 记录结果状态、内容、记录人和时间 | 建议未执行、非运营或页面版本已过期 |
| 状态版本 | 隐藏校验+冲突提示 | 当前版本 | 每次成功变更后递增并刷新时间线 | 无 |

**交互逻辑**：

1. 建议生成后初始状态为“待审核”。运营主管选择通过或驳回，并可填写备注。
2. 通过后，建议显示“已通过/待执行”，并按动作分配责任角色；驳回后保留固定规则结论、原始数据、驳回人、时间和原因。
3. 运营可确认加投、SPU 整体推广止损和清仓；采购计划可确认补货。若一条建议同时包含加投与补货，两种次级执行分别记录，整体结果不得用一个角色的执行替代另一个角色。
4. 执行确认后记录执行人、执行时间和备注；运营随后可记录销售额、利润或库存结果状态及说明。
5. 每次状态提交必须携带用户打开页面时的状态版本；服务端版本已变化时拒绝覆盖并显示最新状态、最新操作者和刷新入口。
6. 状态变化以追加事件保留；界面上的更正不得删除原事件，必须形成新的可追溯变更记录。
7. 周内允许每日更新状态，但不得因状态更新重新计算规则或生成第二份清单。

**异常场景**：

- 两名运营主管同时审核：第一个成功提交生效；第二个收到并发冲突和最新结果，不得后写覆盖。
- 执行人在主管审核前点击执行：拒绝并提示“建议尚未通过”。
- 已驳回建议被直接执行：拒绝；首版不支持将同一条驳回建议恢复为待审核。
- 非责任角色提交执行：拒绝且不改变状态。
- 加投与补货并存时只有一个动作完成：分别显示各自执行状态，不能将整条建议误标为全部执行完成。
- 网络中断导致用户不确定是否提交成功：再次提交时按状态版本和操作标识返回已有结果，不新增重复状态事件。
- 页面停留过久后提交：检测状态版本过期，展示冲突而非覆盖。
- 结果记录缺少必要说明：保持“已执行”而非“已记录结果”，提示补充结果内容。
- 历史批次被打开：允许查看时间线；只有当前仍待处理且用户有权限的建议可操作。

**明确边界**：

- 主状态顺序为：待审核→已通过/待执行→已执行→已记录结果；已驳回为本批次终止分支。
- 首版不自动修改广告、采购或库存系统；“已执行”是责任人对线下动作的确认记录。
- 运营主管负责审核；运营负责加投、SPU 推广止损、清仓和结果记录；采购计划负责补货执行。
- 已驳回记录不删除；首版不提供对同一建议重新发起审核的状态回退。

### FR-7（F07）

**功能名称**：权限隔离  
**实现用户故事**：US-F07-01  
**对应需求**：REQ-F07-01、REQ-F07-02

**位置**：所有批次、行动清单、建议详情、审核、执行、历史与导出入口；权限本身无普通用户配置页。

**界面元素与展示规则**：

| 元素 | 类型 | 默认态 | 操作后 | 禁用条件 |
|---|---|---|---|---|

| 完整经营信息 | 数据区 | 对运营/运营主管显示 | 可查看销售、利润、推广、品退、库存和全部建议 | 采购计划及其他未授权角色不可见 |

| 补货执行按钮 | 操作 | 采购计划可见 | 可确认补货执行 | 其他角色、禁止补货结论或非对应状态 |
| 密钥配置入口 | 不存在 | 不展示 | 无 | 所有普通用户均无此产品入口 |

**交互逻辑**：

1. 用户进入任一页面或请求任一清单/详情时，系统按当前身份的角色返回允许的数据字段和操作；前端隐藏不能替代服务端权限限制。
2. 运营和运营主管可查看完整销售、利润、推广、品退、库存和建议信息；只有运营主管拥有审核操作。
3. 采购计划只接收补货/禁止补货任务及执行所需的 SPU 身份、库存、销量、库存可售天数和状态，不接收经营准利润、推广费用、品退/售后明细或完整 AI 解释。
4. 事业部负责人是项目范围与资源拍板者，不作为首版日常操作角色；首版不为其增加独立业务操作权限。
5. LiteLLM deployment secret 只由运维在产品部署环境配置、更新和轮换；普通用户界面、接口响应、错误信息和审计明细均不返回密钥值。

**异常场景**：

- 采购计划直接访问完整详情地址：返回裁剪后的采购视图或权限不足，不返回被限制字段。
- 用户角色在页面打开后发生变化：下次请求重新校验角色；已失去权限的提交被拒绝。
- 无角色或角色未知：拒绝进入业务页面，不默认赋予运营权限。
- 运营尝试审核、运营主管尝试代替采购确认补货：按职责拒绝对应写操作。
- 导出、搜索建议、筛选选项或错误信息携带受限字段：按同一权限规则裁剪，避免侧信道泄露。
- LiteLLM 失败错误包含上游地址或凭据片段：普通用户只显示服务状态，不显示敏感配置；详细技术信息仅进入受控运维记录。
- 多角色账号切换：每次操作明确显示当前角色，提交时按当前服务端角色校验，不能沿用切换前权限。

**明确边界**：

- 采购计划可见的必要依据限定为 SPU 身份、补货/禁止补货结论、仓内库存、在途库存、最近 14 天销量/平均日销量、库存可售天数和执行状态。
- 采购计划不可见完整利润、推广和售后信息，也不可通过导出或接口旁路获取。
- 首版不提供角色、权限或 LiteLLM 密钥的业务管理后台。
- 项目数据已确认不包含个人信息；若后续数据范围改变，须先修订需求，不在本版静默扩大处理范围。

### FR-8（F08）

**功能名称**：规则与数据溯源  
**实现用户故事**：US-F08-01  
**对应需求**：REQ-F08-01、REQ-F08-02

**位置**：建议详情的“依据与溯源”页签；批次历史页；审核与执行状态时间线。

**界面元素与展示规则**：

| 元素 | 类型 | 默认态 | 操作后 | 禁用条件 |
|---|---|---|---|---|
| 批次信息 | 只读卡片 | 来自建议 | 显示批次 ID、事业部、数据期间、源文件名/标识、生成时间 | 无 |
| 规则信息 | 只读卡片 | 来自规则判定 | 显示规则版本、商品类型、触发规则、优先级和最终动作 | 无规则结论时显示失败原因 |
| 原始关键值 | 只读表 | 来自有效明细 | 显示字段名、原始值、采用值、周期、阈值和比较结果 | 当前角色无权查看的字段被裁剪 |
| 数据质量记录 | 只读列表 | 无问题 | 显示行级错误、警告、品退口径、库存缺数和被忽略合计 | 无 |
| AI 解释记录 | 版本列表 | 未生成 | 显示成功/失败、解释版本和是否使用规则兜底 | 采购计划不可见完整解释内容 |
| 状态时间线 | 事件列表 | 建议生成事件 | 追加审核、驳回、执行、结果和更正事件 | 无 |
| 操作者与时间 | 事件字段 | 来自系统 | 每个状态事件显示操作者角色、时间和备注 | 按权限裁剪不必要身份信息 |

**交互逻辑**：

1. 建议生成时固化批次、数据期间、规则版本、SPU 身份、原始关键值、采用周期、阈值、比较关系、主动作、补货动作和生成时间。
2. 用户从行动清单进入溯源页，可按“数据→指标→规则→建议→审核→执行→结果”顺序查看同一建议链路。
3. AI 重新生成解释时新增解释版本，不覆盖固定规则输入和先前解释状态。
4. 审核、执行、结果或更正操作均追加事件，记录操作前后状态、操作者、时间与备注；不允许删除原事件来制造单一当前状态。
5. 新批次对同一 SPU 产生新建议时，以新批次独立保存；历史批次仍能复原当时的输入、规则和动作。
6. 权限裁剪贯穿溯源页：采购计划只能追溯其补货任务的必要依据和状态，不能从历史事件看到受限利润、推广或售后字段。

**异常场景**：

- 原始文件后续被移动或删除：已固化的批次标识、关键值和校验结果仍可查看；不得只依赖源文件当前位置完成追溯。
- 规则版本缺失或无法识别：该批次标记追溯不完整，不把当前规则版本冒充历史版本。
- 状态并发冲突：失败的覆盖操作不改变当前状态，并在用户侧显示冲突；成功事件按实际顺序记录。
- AI 解释失败：保留失败状态、规则兜底和后续重试版本，不伪造成功内容。
- 历史关键值与当前源表值不同：显示历史固化值和对应批次，不用当前文件覆盖。
- 权限不足用户访问审计地址或导出：返回裁剪结果或拒绝，不泄露被限制字段。
- 审计记录写入失败：对应业务状态变更不得显示为成功，避免“状态已改但无追溯证据”。

**明确边界**：

- 每条建议至少可追溯到：批次、事业部、数据期间、SPU、规则版本、触发规则、原始关键值、阈值、生成时间和全部状态变更。
- 历史清单不覆盖；相同文件重复导入不形成第二套追溯链。
- 审计只记录本产品内的建议、审核、人工执行确认和结果记录；首版不声称已取得广告、采购或库存外部系统的真实执行回执。
- 采购计划的追溯视图继续遵守最小可见原则。

## §7 边界与异常场景

### 7.1 数据边界

| 场景 | 产品可观察行为 | 不变行为 |
|---|---|---|
| 无有效明细行 | 批次显示“无可处理 SPU”，不生成清单 | 不生成空成功清单，不调用 AI |
| 有效 SPU 少于 10 或多于 20 | 显示首轮范围错误并阻断清单生成 | 已完成的校验结果可查看 |
| SPU ID 缺失/重复 | 明确到行与字段并排除相关行 | 其他有效行不受影响 |
| 日期缺失、错位或不可解析 | 该 SPU 不分类、不生成经营动作 | 不使用默认日期，不自动清仓 |
| 销售额或利润率缺失 | 不生成依赖该值的动作并标记待补数 | 不用推广费、利润值或 AI 推断替代缺失值 |
| 品退数据不是最近 7 天 | 标记“品退数据未校验”，不据此触发观察 | 清仓、止损等不依赖品退值的规则继续 |
| 已销售件数为 0 | 品退率不计算，显示“无可计算销量” | 不除以 0 |
| 库存/在途/近 14 天销量缺失 | 不生成补货建议并显示“库存数据不足” | 止损/清仓仍输出禁止补货 |
| 近 14 天平均日销量为 0 | 不计算可售天数，显示“无近期销售” | 不除以 0，不自动补货 |
| 源表合计与明细不一致 | 忽略源表合计并提示，以有效明细重汇总 | 不把合计差异分摊到 SPU |
| 图片公式不受运行环境支持 | 图片显示不可用或占位，不影响经营数值 | 数值判断继续，不以图片失败阻断批次 |
| 同期间相同内容重复导入 | 返回已有批次及其清单 | 不新增建议、不覆盖状态 |
| 同期间不同内容导入 | 明确提示冲突并形成独立更正批次，不覆盖原批次 | 原批次与历史状态保留 |

### 7.2 并发与用户操作冲突

- 同一文件被多窗口、多人或重复点击同时提交：只产生一个有效批次；其他提交返回该批次当前状态。
- 同一批次被重复点击“生成清单”：只产生一份清单；已有清单 ID 和状态保持不变。
- 两名主管同时审核：只接受基于当前状态版本的首个提交；后续提交显示最新结果与冲突，不后写覆盖。
- 执行人与审核人同时操作：只有已通过状态允许执行；执行请求不得越过审核结果。
- 同一执行人在网络不稳定时重复提交：返回已存在的状态事件，不产生重复“已执行”。
- 页面长时间未刷新：提交时校验状态版本；过期页面只能刷新后重新操作。
- AI 重试与人工审核并发：AI 只能更新解释版本，不改变规则结论和已发生的审核状态。
- 新批次生成与旧批次执行并发：操作必须绑定明确批次 ID；旧批次状态更新不得写入新批次建议。

### 7.3 LiteLLM 与外部能力失败

- LiteLLM 网关不可用、超时、限流或密钥失效：固定规则结论、结构化依据、清单、审核和执行流程继续可用；AI 状态显示失败。
- LiteLLM 返回越界动作、虚构数值、广告明细或 SKU 结论：舍弃冲突内容，保留规则兜底。
- deployment secret 未配置或轮换失败：普通用户只看到 AI 服务不可用，不出现配置入口、密钥值或上游敏感错误。
- 首版没有广告、采购和库存系统写回：任何外部系统不可用均不得被描述为“自动执行失败”；本产品只记录人工确认。
- 源 XLSX 在本地文件选择期间不可访问：阻断提交并要求重新选择，不保留未完成文件内容。

### 7.4 权限与信息边界

- 所有页面、接口返回、筛选项、导出、错误信息和审计详情使用同一角色裁剪规则。
- 采购计划只看补货/禁补及库存销量必要依据；完整利润、推广和售后信息对其不可见。
- 无角色用户不得默认拥有运营权限；直接地址访问不绕过服务端鉴权。
- 事业部负责人不自动获得首版日常操作能力；新增角色能力须后续修订需求。
- 普通用户无 LiteLLM 凭据管理入口；凭据只属于运维部署环境。

### 7.5 平台与设备差异

- PRD V0 未确认特定浏览器、移动端或企业微信作为首版承诺，R1 不擅自增加兼容矩阵。
- 设备无法选择或上传 XLSX 时，导入入口须明确显示“当前设备不支持文件导入”，不得提交空请求；查看与状态更新是否支持该设备仍以最终产品平台范围为准。
- 窄屏或缩放环境下，金额、百分比、阈值、主动作和状态不得因截断造成含义变化；无法完整展示时必须提供详情入口。
- XLSX 中的 `DISPIMG` 图片在不支持的解析环境可显示占位，但不能影响数值导入和规则结论。
- 文件名、SPU 名称和备注包含中文时须原样显示；导出能力未进入 F01—F08，不在本版承诺文件格式和编码。

### 7.6 极端与恢复场景

- 批次处理中服务重启：批次恢复后使用同一固化输入和规则版本继续或重算；不得生成第二份清单。
- 规则判定完成但 AI 调用中断：清单使用规则兜底并标记 AI 失败，不让批次长期停留在不可审核状态。
- 状态写入成功但审计写入失败：整体操作视为失败并保持原状态，避免不可追溯变更。
- 历史数据量增长导致列表无法一次加载：历史批次仍须按批次检索且不覆盖；具体分页/存储方案由后续设计决定。
- 单个异常 SPU 产生超长名称或备注：列表可截断视觉展示，但详情与原始记录不得截断语义；输入长度上限尚未由基线确认，不在 R1 虚构数字。
- 规则版本更新：只影响更新后明确生成的新批次；历史批次继续显示当时规则版本和结论。

## §9 风险与依赖（实现部分）

### 9.1 必须优先控制的实现风险

| 风险 | 失败模式 | 缓解 | 产品监控信号 |
|---|---|---|---|
| XLSX 字段漂移与错位 | 把日期、利润或 SPU 身份读错后产生错误动作 | 字段语义校验、行列级错误、无法唯一映射即阻断，不按列号猜测 | 批次错误率、字段映射冲突数、日期异常 SPU 数 |
| 重复批次与重复清单 | 周一重复提交造成两套建议和两套执行状态 | 相同内容幂等、批次状态唯一、生成操作幂等 | 重复提交命中数、同批次清单数量异常 |
| 规则非确定或版本漂移 | 同一数据重算得到不同分类/动作 | 固化输入、数据期间和规则版本；AI 与人工状态不得影响规则 | 同批次重算差异、缺失规则版本批次数 |
| 权限只在界面隐藏 | 采购计划通过接口、导出或错误信息看到利润推广数据 | 所有返回路径按角色裁剪，未知角色默认拒绝 | 未授权请求数、受限字段返回审计异常 |
| 审核与执行并发覆盖 | 多人操作使审核、执行或结果丢失 | 状态版本校验、冲突拒绝、成功变更追加审计 | 状态版本冲突数、非法状态转换数 |
| 审计与业务状态不一致 | 状态已变更但没有操作者、时间或依据记录 | 状态与审计作为同一次可观察结果提交；审计失败则状态不成功 | 无审计状态变更数、追溯不完整建议数 |

### 9.2 可延后但必须显式保留的技术债

- 当前只支持数据支持部门 XLSX 导入；自动数据连接、字段字典管理和多模板适配不进入 MVP。
- 当前没有广告计划、关键词、素材、退款原因和评价明细；不得用 SPU 汇总字段伪装明细能力。
- 当前没有 SPU 库存和最近 14 天销量样本；补货链路可以具备行为，但首批样本必须明确降级。
- 源表经营准利润率为静态值且未保留公式；首版采用该值并保留来源标识，不自行恢复另一套财务公式。
- 平台与浏览器范围尚未确认；本阶段只定义不丢失关键信息的产品行为，不提前承诺兼容版本。

### 9.3 性能与容量风险

- 首轮容量为每批 10—20 个 SPU，性能目标不应按大规模商品库虚构；实现必须至少保证该范围内的导入、规则判定和清单生成不会因单个异常行阻塞全部有效行。
- LiteLLM 响应时间不可控，AI 调用不得成为规则清单可用性的阻塞依赖；需要区分“规则完成”和“AI 解释状态”。
- 历史批次、解释版本和状态事件持续累积，可能影响历史列表与详情加载；监控批次数、建议数、状态事件数和追溯加载失败，不在此阶段指定未确认的存储方案。
- XLSX 文件包含图片公式或大量无关列时可能增加解析开销；经营判断只处理所需字段，图片能力失败不阻断数值链路。

### 9.4 上线后稳定性风险

| 风险 | 缓解 | 监控 |
|---|---|---|
| LiteLLM 服务波动 | 规则兜底、失败状态、解释可重试且不改规则 | AI 成功/失败数量、越界输出数量、兜底使用数量 |
| deployment secret 失效 | 运维轮换；产品侧降级且不暴露凭据 | AI 鉴权失败、连续失败批次 |
| 周一集中导入 | 批次状态可见、重复提交幂等 | 同时导入数、批次失败数、重复提交数 |
| 数据支持部门改变表头/周期 | 导入校验、期间强展示、未知字段不猜测 | 字段映射失败、期间冲突、错误表头告警 |
| 规则修改影响历史 | 每批固化规则版本，更新只作用新批次 | 无规则版本批次、历史重算差异 |
| 跨角色操作断点 | 通过后明确分配责任角色，止损/清仓同步禁补 | 已通过未执行时长、禁补任务未查看/未更新数量 |

### 9.5 外部依赖

- 数据支持部门每周一提供符合 SPU 粒度的数据表，并明确数据期间与品退、库存字段口径。
- 运维维护现有 LiteLLM 网关和系统级 deployment secret；产品团队不建设用户配置界面。
- 运营主管承担审核；运营承担加投、SPU 整体推广止损、清仓和结果记录；采购计划承担补货执行。
- 若要让首批样本产生补货建议，数据支持部门必须补充 SPU 仓内库存、在途库存和最近 14 天销量；当前样本不具备这些字段。

## §10 验收标准清晰度复核

> 本节只复核 PM 主笔验收条件的触发条件、边界和唯一可观察结果，不定义测试方法、自动化策略、测试数据或覆盖率。

### 10.1 总体复核结论

- AC 必须逐条绑定 ID 注册表中的 REQ；不得把“识别问题、生成建议、权限正确、状态可追溯”等多个结果塞进一个 AC。
- 每个 AC 应明确前置角色、批次状态、输入数据状态、触发操作、唯一产品结果及不变行为。
- 阈值必须写清等号：`100,000`、`20,000`、`0%`、`5%`、`10%`、`15%`、`-20%`、`1.5%` 和 `30 天` 均不得用“大于左右”“较低”等表述。
- 对缺数、AI 失败、权限不足和并发冲突，结果必须是页面/状态上可观察的明确降级或拒绝，不能只写“系统正确处理”。

### 10.2 按 AC 组的清晰度要求

| AC | 必须明确的触发条件 | 唯一可观察结果 | 必须保持不变的行为 |
|---|---|---|---|
| AC-F01-01 | 运营选择玩具事业部、合法期间和可读 XLSX | 生成带批次 ID 的校验结果 | 尚未点击生成时不产生清单 |
| AC-F01-02 | SPU ID 缺失/重复、日期或数值不可解析 | 对应行列显示错误并排除该行 | 其他有效行可继续校验 |
| AC-F01-03 | 相同事业部、期间和文件内容再次提交 | 返回已有批次及状态 | 不新增批次清单和建议 |
| AC-F01-04 | 源表合计与有效明细不一致 | 显示警告并按有效明细汇总 | 不使用或分摊错误合计 |
| AC-F02-01 | 上架日期可解析且生成日未到上架日期加 2 个自然月 | 商品类型显示新品 | 不再按销售额分为爆款/淘汰 |
| AC-F02-02 | 非新品且上月净销售额位于明确边界 | 唯一显示大爆款/小爆款/淘汰商品 | 不出现两个商品类型 |
| AC-F02-03 | 最近 7 天品退分子分母齐全且分母大于 0 | 显示计算品退率和周期 | 不采用未确认周期的源表率 |
| AC-F02-04 | 最近 7 天口径缺失或分母为 0 | 显示未校验/无可计算销量 | 不触发品退观察 |
| AC-F02-05 | 仓内、在途和近 14 天销量齐全且日均销量大于 0 | 显示库存可售天数 | 不使用其他周期销量替代 |
| AC-F02-06 | 库存字段缺失或日均销量为 0 | 显示库存不足/无近期销售 | 不生成补货建议，不影响禁补 |
| AC-F03-01 | 每个商品类型输入落在明确利润和品退边界 | 输出唯一主动作 | 遵守清仓>止损>观察>加投>维持 |
| AC-F03-02 | 同一批输入和同一规则版本重复判定 | 商品类型和动作完全一致 | AI 状态不影响结论 |
| AC-F03-03 | 主动作为清仓或止损 | 同时显示禁止补货 | 库存缺失也不能取消禁补 |
| AC-F03-04 | 非新品、非止损/清仓且可售天数跨越 30 天边界 | `<30` 补货，`≥30` 不补货 | 新品不产生补货建议 |
| AC-F03-05 | 关键分类或利润字段缺失 | 显示无法判定/待补数 | 不由 AI 或默认值补动作 |
| AC-F03-06 | 加投条件与补货条件同时满足 | 主动作加投与次动作补货并存 | 不把二者视为主动作冲突 |
| AC-F04-01 | 固定规则已产生结论且 LiteLLM 返回有效解释 | 建议显示对象、问题、依据、动作 | 动作和阈值仍来自规则 |
| AC-F04-02 | AI 返回越界动作、虚构值或明细对象 | 冲突内容不展示并使用规则字段 | 固定规则结论不变 |
| AC-F04-03 | LiteLLM 不可用或返回失败 | 显示规则兜底及 AI 失败状态 | 清单、审核和执行继续可用 |
| AC-F04-04 | 普通用户访问 AI 配置或错误详情 | 无密钥入口且不返回敏感值 | deployment secret 仍由运维维护 |
| AC-F05-01 | 批次规则完成 | 生成且只生成一份行动清单 | 历史批次不覆盖 |
| AC-F05-02 | 建议进入列表 | 每条完整显示或可展开对象、问题、依据、动作 | 无数据不显示虚构示例 |
| AC-F05-03 | 用户按动作、店铺、运营、审核或执行状态筛选 | 列表仅显示命中项并给出数量 | 筛选不改变原建议 |
| AC-F05-04 | 清单存在不同动作 | 默认按清仓、止损、观察、加投、补货排序 | 缺代理指标时不估算影响 |
| AC-F05-05 | 采购计划打开行动清单 | 只见补货/禁补与必要库存销量依据 | 利润、推广、售后不泄露 |
| AC-F06-01 | 运营主管对待审核建议选择通过 | 状态显示已通过/待执行并分配责任角色 | 规则结论不变 |
| AC-F06-02 | 运营主管选择驳回 | 状态显示已驳回并保留原因和原始依据 | 不删除建议，不允许直接执行 |
| AC-F06-03 | 对应责任人在已通过状态确认执行 | 记录已执行、执行人、时间和备注 | 非责任角色不能改变状态 |
| AC-F06-04 | 运营在已执行状态提交结果 | 状态显示已记录结果并追加结果事件 | 原审核和执行记录保留 |
| AC-F06-05 | 两个操作者基于同一旧状态并发提交 | 仅首个有效提交成功，后者显示冲突和最新状态 | 不后写覆盖 |
| AC-F06-06 | 周内更新审核、执行或结果 | 当前批次状态更新并保留时间线 | 不重新计算规则或新增清单 |
| AC-F07-01 | 运营或运营主管查看授权批次 | 显示完整经营信息及其角色允许的操作 | 运营无审核权 |
| AC-F07-02 | 采购计划查看或请求建议详情 | 仅返回补货/禁补与必要库存销量依据 | 各返回路径均不含受限字段 |
| AC-F07-03 | 未授权角色直接访问页面、接口或导出 | 返回权限不足或裁剪结果 | 不默认赋予运营权限 |
| AC-F07-04 | 普通用户尝试访问 LiteLLM 凭据 | 产品无配置入口且响应无密钥 | 运维 deployment secret 不受影响 |
| AC-F08-01 | 用户打开任一建议溯源 | 显示批次、期间、规则版本、触发规则、关键值和生成时间 | 使用历史固化值而非当前源表值 |
| AC-F08-02 | 审核、执行或结果状态成功变化 | 时间线追加操作者、时间、前后状态和备注 | 原事件不可删除 |
| AC-F08-03 | AI 解释失败后重试成功或再次失败 | 新增解释版本及对应状态 | 不覆盖规则结论和既有状态历史 |
| AC-F08-04 | 采购计划访问历史溯源 | 显示其任务所需的有限追溯字段 | 不从审计事件泄露利润推广售后信息 |

### 10.3 需由合稿阶段保持一致的表述

- “上架两个月内”统一写成“生成日早于上架日期加 2 个自然月；达到边界即非新品”，避免天数口径分叉。
- “同一批数据”统一由事业部、数据期间和文件内容共同识别；相同内容幂等，内容不同不覆盖历史。
- “AI 建议失败”统一表现为规则兜底可用，不得把整批清单标记失败。
- “已通过”和“待执行”在界面上可组合显示为“已通过/待执行”，但状态转换不得跳过审核。
- “执行结果”是人工记录，不等同于外部广告、采购或库存系统回执。

## §12 附录

### 12.1 术语表

| 术语 | 含义 |
|---|---|
| SPU | 本项目中的唯一商品决策粒度，等同于一个商品链接；首版不向下拆 SKU |
| 上一个完整自然月 | 批次生成日前最近一个已经完整结束的自然月；首批样本为 2026-06-01—2026-06-30 |
| 净销售额 | 扣除退款后的销售额，用于非新品商品分类 |
| 经营准利润率 | 直接采用数据支持表中的经营准利润率，首版不按早先自定义公式重算 |
| 品退率 | 最近 7 天品退件数÷最近 7 天已销售件数；周期未确认时不用于触发观察 |
| 库存可售天数 | `(仓内库存+在途库存)÷最近14天平均日销量` |
| 主动作 | 清仓、止损、观察、加投或维持中的唯一结论 |
| 补货动作 | 补货、不补货、禁止补货或因数据/商品类型不生成建议 |
| 轻闭环 | 系统建议、运营主管审核、责任角色人工执行、系统记录结果；不自动修改外部系统 |
| 批次幂等 | 相同事业部、期间和文件内容重复提交时返回既有批次，不重复生成清单或建议 |
| 规则版本 | 生成某批次商品分类和动作时使用的固定规则标识，用于确定性和历史追溯 |
| 结构化兜底 | AI 失败时由固定规则字段组成的对象、问题、依据和动作说明 |
| deployment secret | 运维在产品部署环境维护的 LiteLLM 系统级密钥，普通用户不可见且无配置页面 |

### 12.2 缩写

| 缩写 | 全称 | 含义 |
|---|---|---|
| AI | Artificial Intelligence | 只负责解释、排序说明和非覆盖性优化提示 |
| FR | Functional Requirement | 详细功能说明，与 F01—F08 对应 |
| REQ | Requirement | 可追溯的行为需求 |
| AC | Acceptance Condition | 单一、可观察的产品完成条件 |
| NFR | Non-functional Requirement | 确定性、权限、凭据、降级与审计等质量约束 |
| XLSX | Office Open XML Spreadsheet | 首版数据支持部门提供的导入文件格式 |

### 12.3 功能与非功能约束映射

| NFR | 主要落点 | 工程侧可观察约束 |
|---|---|---|
| NFR-001 固定规则确定性 | FR-2、FR-3、FR-8 | 同批输入和规则版本产生相同分类与动作，历史记录携带规则版本 |
| NFR-002 权限与数据最小可见 | FR-5、FR-6、FR-7、FR-8 | 采购计划在页面、接口、导出和审计中均看不到完整利润、推广和售后信息 |
| NFR-003 凭据保密 | FR-4、FR-7 | 无普通用户密钥页面，响应和错误不暴露 deployment secret |
| NFR-004 AI 失败可降级 | FR-4、FR-5 | AI 失败后规则结论和结构化依据仍可生成、审核与执行 |
| NFR-005 审计可追溯 | FR-1、FR-3、FR-4、FR-6、FR-8 | 批次、期间、规则、关键值、操作者、时间和状态变化均保留 |
