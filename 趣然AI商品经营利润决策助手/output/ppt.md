# 《AI 商品经营与利润决策助手》阶段 6 正式版 PPT 大纲

> 唯一内容源：`output/PRD详细版.md`；稳定行为契约：`output/requirements.md` revision 11。F09 已完成价值确认、竞品调研、四方评审与 MVP 拍板；价值数字按待验证假设呈现，不写成已节省。

## P01｜封面：从分散报表到一张可执行清单

- 标题：AI 商品经营与利润决策助手
- 副标题：用固定规则统一利润、推广与补货决策
- 范围：玩具事业部 · 10—20 个真实 SPU · F01—F09 MVP
- 一句话：用唯一 Admin 打通授权入口，再把固定规则结论送进审核、执行与结果记录。
- 版式：大标题 + 右侧蓝色决策路径场。
- 追溯：PRD §0.1、§1.1。

## P02｜执行摘要：每周形成一次新判断，一周内持续推进动作

- 核心结论：先让无角色用户被发现、审批、配置并进入正确工作台，再以周度固定规则生成唯一经营动作，由运营主管审核、责任运营执行与协同。
- 三个业务结果：系统真正可进入；阻断“止损后继续补货”；保留身份、审批、批次、规则和状态历史。
- 运行节奏：新数据到达才生成新清单；同一周只更新审核、执行和结果状态。
- 版式：三列结果卡 + 周度节奏条。
- 追溯：PRD §1.3、§5.1、§7.1；REQ-F05-01、REQ-F06-01。

## P03｜核心痛点：515 案例中的两次断点叠加成真实损失

- 核心结论：问题不只是利润指标晚看到，更是运营止损后采购仍按旧销量补货。
- 事实链：亏损推广 → 月度利润报表后才发现 → 运营减少推广 → 采购未同步、继续补货。
- 结果：约延迟 2 个月；约 3000 件滞销；约 10 万元库存占用；约 6 万元利润损失。
- 版式：四步断点流程，末端突出损失。
- 追溯：PRD §1.2、§1.4。

## P04｜价值证据：一个安全的授权入口，决定整套产品能否创造价值

- 核心结论：F09 不单独认领经营收益，它解锁 F01—F08 的可用性。
- 价值算式：约 6 万元/次直接利润影响 × 12 次/年待验证假设 = 约 72 万元/年；三年可支撑约 216 万元价值。
- 边界：约 10 万元库存占用只作风险佐证，不重复相加；12 次/年与三年持续性必须用真实事件台账验证，不得表述为已节省。
- 版式：价值算式 + 三年延展 + 一条证据边界。
- 追溯：PRD §1.9—1.13。

## P05｜产品设计 1：固定规则负责判定，AI 负责表达

- 核心结论：把确定性经营规则与生成式能力分层，模型失败或漂移都不能改变主动作。
- 固定规则：新品/大爆款/小爆款/淘汰商品分类；利润和品退阈值；动作优先级；补货冲突。
- AI：把结论组织成对象、问题、依据和动作；排序；给出不覆盖主动作的优化提示。
- 规则优先级：清仓 > 止损 > 观察 > 加投 > 维持。
- 版式：左右职责边界 + 中央不可越界线。
- 追溯：PRD §3.1、§3.4、§6.4；REQ-F03-02、REQ-F04-01～03。

## P06｜产品设计 2：从待处理身份到正确工作台，首用链路不再断在登录后

- 核心结论：钉钉只证明“你是谁”，产品用待处理、审批核验和重新登录完成“你能做什么”。
- 流程：钉钉认证 → 无唯一角色幂等进入待处理 → 事业部负责人产品外审批 → Admin 核验双属性与证据 → 配置唯一角色并撤销旧会话 → 用户重新登录目标工作台。
- 状态：待处理 / 已配置待重新登录 / 已授权 / 已停用 / 配置冲突。
- 版式：六段授权流程 + 五态底栏。
- 追溯：PRD §5.10、FR-9.4—9.5、§7.9；REQ-F09-04—05。

## P07｜产品设计 3：单 Admin 不靠共享密码，靠受控恢复和不可变记录

- 核心结论：唯一 Admin 的单点风险由两级恢复、凭据代次和非静默通知约束，不用第二账号或共享凭据绕过。
- 正常恢复：密码 + 一次使用的保存型恢复码，重绑 TOTP。
- 部署恢复：独立审批、一次性受控交接、Admin 持有人本人输入新密码；恢复执行人不可见长期凭据。
- 安全结果：新凭据、旧会话撤销、材料消费、审计和通知任务同成败；外部通知失败可重试或以认可证据补偿。
- 版式：两级恢复对比 + 事务结果链。
- 追溯：PRD FR-9.1—9.3、FR-9.6；REQ-F09-01—03、06。

## P08｜技术方案 1：SPU 是唯一决策粒度，缺什么就降级什么

- 核心结论：数据边界决定建议边界；字段不足时保留可判定动作，不用默认值或 AI 猜测补齐。
- 关键输入：SPU 身份；上一个完整自然月净销售额与经营准利润率；最近 7 天品退；条件库存与最近 14 天销量。
- 时间确定性：新品年龄使用批次业务截止日，不使用上传日或访问日。
- 降级：库存缺失不生成补货；品退周期未证明时不据此观察/加投；LiteLLM 不可用仍保留结构化规则建议。
- 版式：输入字段 → 确定性规则 → 字段级降级。
- 追溯：PRD §3.2、§5.2～5.3、§8.1；REQ-F01-02、REQ-F02-01～03、NFR-001、NFR-004。

## P09｜技术方案 2：两个身份域、一组原子授权事实，阻止登录成功后串权

- 核心结论：Admin 与业务用户可以是同一自然人，但必须使用不同入口、凭据、Cookie、会话和鉴权中间件。
- 授权事务：唯一角色 + 审批历史 + 旧业务会话撤销 + 五态投影 + 管理审计同成败。
- 写入防护：Admin 会话 + CSRF token + 严格 Origin + 预期 Content-Type；审计表对运行时数据库身份禁止更新、删除和结构变更。
- 并发/重放：映射版本只允许一个角色事务成功；setup、恢复和角色写入使用稳定幂等键返回可判定结果。
- 版式：双身份域架构 + 授权事务链 + 安全门。
- 追溯：PRD §4.8—4.10、FR-9.5—9.6、§9.7；NFR-006—010。

## P10｜完整路线图：先跑通轻闭环，再按数据成熟度扩展

- 核心结论：先让授权与经营任务在真实环境跑通，再按证据扩展数据与治理，不预埋通用 IAM。
- 当前 MVP：F01—F08 经营链 + F09 唯一 Admin、待处理、角色生命周期、两级恢复、不可变审计与时效里程碑。
- 前置补齐：真实钉钉双属性、岗位联系人、审批证据目录、开发/线上物理隔离、恢复与通知演练。
- 后续候选：评价/退款原因、广告明细、外部自动写回、SKU；只在新环境/角色/事业部、申请量或单 Admin 风险触发时重评高级治理。
- 版式：三阶段时间轴，明确“已承诺/上线门禁/候选”。
- 追溯：PRD §0.2—0.5、§9.6—9.7。

## P11｜当前 MVP：用真实业务评审定义“做完”

- 核心结论：第一版完成不看页面数，只看“人能进系统”与“经营动作真正可执行”是否同时成立。
- 产品验收：唯一 Admin 初始化/登录/恢复；无角色用户进入待处理并获得正确角色；10—20 个真实 SPU 识别至少 3 个真实问题，走通审核—执行—结果。
- 安全验收：错误业务授权为 0；秘密不持久化/不回显；旧会话撤销；审计不可变；通知失败不静默。
- 时效验收：生产门禁齐全且七个服务端里程碑完整时，Admin 初始化到正确工作台首次访问不超过 10 分钟。
- 上线门禁：真实双属性、职责人/联系方式、证据目录、环境隔离、恢复/通知演练全部满足，不能以代码完成代替。
- 版式：四项验收清单 + 下一步行动条。
- 追溯：PRD §0.1、§0.2、§11.8。

## 统一视觉契约

- 画布：16:9；HTML 1920×1080；PPTX 宽屏。
- 视觉：Codex Grid；白底、黑字、浅灰面板、细灰线，浅蓝和强蓝只做行动与结论强调。
- 字体：Helvetica Neue、苹方、微软雅黑、Arial；标题不小于 35 pt，正文不小于 16 pt。
- 结构：每页一个核心结论；短句；优先流程、责任边界、证据数字和验收清单，避免装饰性图形。
- 禁止：公司级 ROI 推演、虚构竞品、AI 覆盖固定规则、SKU 粒度、自动改广告或采购系统。
