## 2. 页面概述
### 2.1 一句话定位
让授权用户按不可变批次检索历史建议和事件，并复用批次详情、建议详情查看当时冻结的真实证据。
### 2.2 存在理由
1. 新批次不能遮蔽旧批次的规则、建议及处理事实。
2. 复盘需要从期间与批次快速定位对象和状态历史。
3. 采购历史路径仍需保持最小字段裁剪。
### 2.3 页面目标（可衡量）
| 维度 | 指标 |
| :--- | :--- |
| 历史保留 | 新批次覆盖旧快照或事件次数 0 |
| 追溯落点 | 所有有权历史项均可到达真实批次/建议详情 |
| 权限一致 | 历史路径采购受限字段出现次数 0 |
### 2.4 不做什么（范围边界）
- 不复制第二套历史批次、历史建议实体或详情页面。
- 不提供删除、覆盖、导出或更改历史事件。
- 不用当前规则重算或改写旧建议。
- 不让采购通过历史筛选、错误或时间线看到完整经营字段。

## 3. 用户与场景
### 3.1 目标用户
| 维度 | 描述 |
| :--- | :--- |
| 角色 | 运营、运营主管、采购计划（按任务关联裁剪） |
| 技术熟练度 | 中等，熟悉批次与 SPU |
| 设备/姿势 | PC，按月/周进行经营复盘或查证 |
### 3.2 核心使用场景
**场景 A：主管复盘历史建议（主场景）**
- 时机：规则、数据或执行结果产生差异时；前置：有历史访问权；动作：按期间/批次/SPU 检索，打开建议详情查看冻结规则、关键值和成功事件；情绪：求真、需要完整证据。

**场景 B：采购查看历史禁补任务（兜底场景）**
- 时机：核对过去停补处理；前置：历史建议含分配给当前采购角色的任务；动作：筛选采购动作并打开裁剪详情，仅查看 SPU、库存销量依据和采购事件；情绪：聚焦且放心无无关信息。
### 3.3 用户核心诉求（优先级排序）
1. 按期间、批次和 SPU 快速定位。
2. 确认当时使用的规则与原始关键值未被改变。
3. 看清审核、各动作和结果的先后历史。

## 4. 信息架构
### 4.1 区域划分
1. 应用壳与面包屑；2. 历史搜索/筛选；3. 批次摘要列表；4. 所选批次建议预览；5. 分页与真实详情入口。
### 4.2 区域内容
- 筛选：事业部、完整自然月期间、业务截止日范围、批次 ID、SPU ID/名称、动作、审核/执行状态。
- 批次列表：批次 ID、期间、截止日、规则版本、有效/拒绝/降级统计、建议与状态摘要。
- 建议预览：按当前角色裁剪的 SPU、动作、状态、最近成功事件时间。

## 5. 界面内容
### 5.1 元素清单
| 元素 | 内容/文案 | 数据来源 | 显示条件 |

## 6. 交互流程
### 6.1 页面加载与初始化
- 从 URL 恢复筛选与页码；默认显示最新有权批次，服务端分页每页 20 条。
- 服务端按角色返回批次及建议投影，采购仅返回有关联采购任务的最小信息。
### 6.2 核心操作流程
```text
输入检索/筛选 → URL 更新 → 服务端返回有权历史批次
  → 选择批次 → 查看裁剪后的建议预览
     ├─ 查看批次详情 → PAGE-F01-03
     └─ 查看建议详情 → PAGE-F05-02（继续按角色裁剪）
```
### 6.3 辅助操作
- 清空筛选恢复默认；分页、排序、浏览器前进后退均保持 URL 状态。
- 不提供批量操作、导出或历史编辑。

## 7. 状态与边界
### 7.1 页面状态全景
| 状态 | 触发条件 | 页面表现 |
| :--- | :--- | :--- |
| 初始态 | 首次进入 | 最新有权批次与提示 |
| 输入态 | 编辑搜索/筛选 | URL 同步，提交后查询 |
| 提交态 | 查询加载 | 保留筛选骨架并显示加载反馈 |
| 成功态 | 有匹配记录 | 批次和建议预览分页展示 |
| 失败态 | 当前条件无匹配 | 显示“无匹配历史记录”及清筛选入口 |
| 异常态 | 网络/服务错误 | 明确加载失败与当前条件，可重试 |
| 无权限态 | 目标无访问权 | 权限不足，不返回目标身份状态 |
### 7.2 边界与容错
| 边界场景 | 处理策略 |
| :--- | :--- |
| 网络异常 | 不冒充空历史，保留筛选与页码可重试 |
| 会话过期 | 返回钉钉门禁，认证后恢复合法 URL 条件 |
| 连续错误检索 | 服务端校验格式并给可修正反馈，不查询敏感对象 |
| 异常/超长输入 | 规范化并限制查询，不作为目标存在性探测 |
| 新批次并发生成 | 当前分页保持快照；刷新后出现新批次，不覆盖旧项 |
| 历史目标无权/不存在 | 统一安全拒绝，不泄露差异 |
| AI 失败/建议驳回/部分执行 | 仍保留既有快照与所有成功事件 |

## 8. 业务规则与校验
### 8.1 字段定义
| 字段 | 说明 |
| :--- | :--- |
| `batch_id` | 不可变批次身份 |
| `business_period` | 批次冻结的完整自然月期间 |
| `business_cutoff_date` | 冻结的新品判断基准日 |
| `rule_version` | 建议生成时规则版本 |
| `event_summary` | 按角色裁剪的成功事件摘要 |
### 8.2 校验规则
| 校验项 | 时机 | 规则 | 失败反馈 |
| :--- | :--- | :--- | :--- |
| 日期范围 | 查询 | 起止合法且顺序正确 | “请检查查询日期范围” |
| 批次/SPU 搜索 | 查询 | UTF-8 合法字符串，按服务端规则规范化 | “请输入有效批次或商品标识” |
| 分页 | 查询 | 正整数且在可用范围 | 回到第一页 |
| 访问权 | 服务端 | 当前角色有批次/任务访问权 | 通用权限不足 |
### 8.3 特殊业务规则
- 历史数据、规则快照及成功事件只追加，不由新批次覆盖。
- 冲突/越权失败事件仅向有权追溯角色展示；采购继续最小裁剪。

## 9. 页面流转
### 9.1 流转图
`工作台/左侧导航 → 历史追溯索引 → 批次详情 / 建议详情 → 返回时恢复索引条件`。
### 9.2 与其他模块的关系
- 复用 F01 批次详情和 F05 建议详情作为真实证据落点。
- 读取 F08 快照/事件；F07 授权与字段裁剪覆盖索引及下游。
### 9.3 扩展预案
| 方向 | 触发条件 | 改造点 |
| :--- | :--- | :--- |
| 明细洞察历史 | 阶段2明细形成 REQ | 挂接稳定 batch/spu/decision，不改 MVP 快照 |
| SKU 历史 | 阶段3数据与分摊规则具备 | 以 SPU 为上层主体新增视图 |

## 10. 数据需求
### 10.1 页面需要什么数据
| 数据 | 来源 | 用途 |
| :--- | :--- | :--- |
| 裁剪后的批次索引/计数 | ImportBatch 只读投影 | 历史定位 |
| 裁剪后的建议/动作/事件摘要 | Decision/Action/Audit 投影 | 预览与跳转 |
| 当前角色与访问关联 | 安全会话/授权层 | 全路径裁剪 |
### 10.2 页面提交什么数据
| 数据 | 触发时机 | 用途 |
| :--- | :--- | :--- |
| 搜索、筛选、排序、分页参数 | 查询 | 返回匹配的有权历史投影 |
### 10.3 明确排除的数据
- 不提交业务状态变化；不需要 LiteLLM 密钥、原始整表或外部系统凭据。
- 采购查询响应排除利润、推广、品退、售后及无关事件。
