## 2. 页面概述
### 2.1 一句话定位
让运营主管基于冻结的整条建议，一次性通过或驳回建议，并以版本保护避免并发覆盖。
### 2.2 存在理由
1. 防止经营动作和采购动作被拆开审核而产生冲突。
2. 驳回原因需与原规则结论共同留痕。
3. 多主管并发操作时必须保护第一个成功事实。
### 2.3 页面目标（可衡量）
| 维度 | 指标 |
| :--- | :--- |
| 审核完整性 | 每条待审核建议仅产生一个建议级结果 |
| 激活一致性 | 通过后既有经营、采购动作同时激活率 100% |
| 并发安全 | 旧 version 提交覆盖成功状态次数为 0 |
### 2.4 不做什么（范围边界）
- 不分别审核经营与采购动作——审核对象是整条建议。
- 不编辑商品类型、主动作、补货结论或规则依据——固定规则已冻结。
- 不在审核时新建动作项——动作项由规则阶段原子生成。
- 不提供撤销或删除——成功审核以追加事件保留。

## 3. 用户与场景
### 3.1 目标用户
| 维度 | 描述 |
| :--- | :--- |
| 角色 | 运营主管 |
| 技术熟练度 | 中等，熟悉内部经营后台 |
| 设备/姿势 | PC，坐姿集中处理待审核建议 |
### 3.2 核心使用场景
**场景 A：通过完整建议（主场景）**
- 时机：周度规则清单已就绪；前置：建议为待审核且当前用户为运营主管；动作：复核摘要与双轨动作后选择通过并确认；情绪：谨慎、可控。

**场景 B：并发审核冲突（兜底场景）**
- 时机：另一主管已先提交；前置：本页仍持有旧 version；动作：提交后看到最新结果、操作者及刷新入口，输入备注仍保留；情绪：明确、不担心覆盖同事结果。
### 3.3 用户核心诉求（优先级排序）
1. 先看清整条建议及双动作影响。
2. 一次拍板且结果不可被后写覆盖。
3. 驳回时能留下明确原因。

## 4. 信息架构
### 4.1 区域划分
1. 应用壳与面包屑；2. 建议冻结摘要；3. 利润—库存双轨动作带；4. 审核选择与备注；5. 底部提交区；6. 冲突提示区。
### 4.2 区域内容
- 冻结摘要：SPU、批次、期间、规则版本、具体问题及关键依据。
- 双轨带：经营主动作与补货/禁补动作，明确通过后分别分配给运营和采购计划。
- 审核表单：通过/驳回单选、审核备注、version 隐含上下文。
- 提交区：取消、提交审核；驳回时展示备注必填提示。

## 5. 界面内容
### 5.1 元素清单
| 元素 | 内容/文案 | 数据来源 | 显示条件 |

- 时间按业务时区显示，规则快照不随当前规则更新。

## 6. 交互流程
### 6.1 页面加载与初始化
- 校验运营主管角色、建议访问权与待审核状态；加载冻结快照和当前 review_version。
- 本地会话中已有同 decisionId 的未提交备注时恢复文本，不自动提交。
### 6.2 核心操作流程
```text
选择通过或驳回 → 驳回时校验非空备注 → 展示整条建议结果摘要确认
  ├─ version 当前 → 保存一个审核结果并同时激活动作 → Toast → 返回建议详情
  └─ version 过期 → 不改变状态 → 返回最新结果/操作者 → 保留输入并要求刷新确认
```
### 6.3 辅助操作
- “取消”返回建议详情；有未提交备注时离开需确认。
- `Esc` 仅关闭确认层，不丢弃表单；提交期间禁用重复提交。

## 7. 状态与边界
### 7.1 页面状态全景
| 状态 | 触发条件 | 页面表现 |
| :--- | :--- | :--- |
| 初始态 | 加载成功 | 默认未选审核结果，展示完整快照 |
| 输入态 | 选择结果/填写备注 | 实时更新摘要，驳回备注失焦校验 |
| 提交态 | 确认提交 | 按钮显示“提交中”且禁止重复提交 |
| 成功态 | 审核保存 | Toast 后返回详情 |
| 失败态 | 校验或服务失败 | 页内显示可修正原因，保留输入 |
| 异常态 | 网络/版本冲突 | 保留输入；冲突展示最新状态和刷新入口 |
| 无权限态 | 非主管或对象无权 | 转权限不足，不返回建议业务字段 |
### 7.2 边界与容错
| 边界场景 | 处理策略 |
| :--- | :--- |
| 网络中断 | 不显示成功，保留选择与备注，可重试 |
| 会话过期 | 返回钉钉认证门禁；本地文本保留至会话结束 |
| 连续提交 | 首次未完成前禁用；重复到达返回既有结果 |
| 驳回备注仅空白 | 视为空值，阻止提交并定位字段 |
| 两名主管并发 | 仅首个当前 version 成功；后续显示冲突 |
| 建议已非待审核 | 禁止表单提交，展示现状并引导返回详情 |

## 8. 业务规则与校验
### 8.1 字段定义
| 字段 | 说明 |
| :--- | :--- |
| `review_result` | `approved` 或 `rejected` |
| `review_note` | 审核备注；驳回必填，通过可选 |
| `review_version` | 打开页面时读取的建议审核版本 |
### 8.2 校验规则
| 校验项 | 时机 | 规则 | 失败反馈 |
| :--- | :--- | :--- | :--- |
| 审核结果 | 提交 | 必须二选一 | “请选择通过或驳回” |
| 驳回备注 | 失焦/提交 | 去除首尾空白后非空 | “驳回建议时请填写原因” |
| 当前状态 | 服务端 | 必须仍为待审核 | “建议已被处理，请查看最新状态” |
| version | 服务端 | 与当前 review_version 一致 | “状态已变化，请刷新后确认” |
### 8.3 特殊业务规则
- 通过同时激活已存在的全部动作项，不二次创建；驳回关闭动作激活路径但保留快照。
- 成功审核与 AuditEvent 同时追加；冲突不产生成功事件。

## 9. 页面流转
### 9.1 流转图
`建议详情 → 建议审核表单 → 摘要确认 → 建议详情（已通过/已驳回）`；冲突则留在本页刷新现状。
### 9.2 与其他模块的关系
- 读取 F03 固定规则快照；成功后激活 F06 的经营与采购动作。
- F08 时间线追加审核事件；F07 服务端权限决定可见内容与操作。
### 9.3 扩展预案
| 方向 | 触发条件 | 改造点 |
| :--- | :--- | :--- |
| 审核更正事件 | 新 REQ 明确更正流程 | 追加新事件，不覆盖既有审核 |

## 10. 数据需求
### 10.1 页面需要什么数据
| 数据 | 来源 | 用途 |
| :--- | :--- | :--- |
| 冻结建议与动作快照 | DecisionRecord/ActionItem | 复核完整建议 |
| 当前审核状态、version | 建议状态 | 校验可操作性与并发 |
| 当前用户角色 | 安全会话 | 授权操作 |
### 10.2 页面提交什么数据
| 数据 | 触发时机 | 用途 |
| :--- | :--- | :--- |
| result、note、review_version | 确认提交 | 生成审核结果并保护并发 |
### 10.3 明确排除的数据
- 不提交规则阈值、动作内容或 LiteLLM 信息。
- 不向采购角色返回本页数据。

### 10.4 实施同步
生产 API 已实现 `POST /api/decisions/:decisionId/review`，仅允许主管会话并要求 UUID 幂等键。事务锁定当前建议，校验 pending 与 `review_version` 后一次写入整体通过/驳回；通过把全部既有动作转为待执行，驳回转为驳回关闭，均不创建新 action_id。建议、动作状态、幂等结果与 AuditEvent 同事务提交；重复幂等键返回首次响应，旧 version 返回最新审核状态且不追加事件。

## 11. 验收标准
### 11.1 功能验收
| 编号 | 验收点 | 通过标准 |
| :--- | :--- | :--- |
| F-01 | 整体通过 | 一次通过后既有经营与采购动作同时转待执行 |
| F-02 | 整体驳回 | 非空原因保存，动作不激活，快照保留 |
| F-03 | 备注规则 | 通过备注可空；驳回空白备注不可提交 |
| F-04 | 不新建动作 | 审核前后 action_id 不变 |
| F-05 | 并发保护 | 旧 version 不覆盖首个成功审核且无重复成功事件 |
### 11.2 体验验收
| 编号 | 验收点 | 通过标准 |
| :--- | :--- | :--- |
| U-01 | 冻结摘要 | 提交前可看见对象、依据与双轨动作 |
| U-02 | 整条确认 | 确认层明确审核作用于整条建议 |
| U-03 | 错误定位 | 驳回备注错误聚焦到字段 |
| U-04 | 输入保留 | 网络失败或冲突后选择和备注仍在 |
| U-05 | 恢复路径 | 冲突显示最新结果、操作者和刷新入口 |
### 11.3 安全验收（产品层）
| 编号 | 验收点 | 通过标准 |
| :--- | :--- | :--- |
| S-01 | 角色限制 | 非运营主管无法读取表单业务数据 |
| S-02 | 服务端授权 | 直接调用提交接口仍校验角色与对象 |
| S-03 | 默认拒绝 | 无有效角色不产生审核结果 |
| S-04 | 错误最小化 | 越权响应不含建议身份、状态和字段 |
| S-05 | 审计一致 | 成功审核含 actor、时间、前后状态和 version |
