## 2. 页面概述

### 2.1 一句话定位

采购工作台是采购计划角色登录后的唯一任务总览，用于确认当前数据批次中待补货、待确认禁补和已处理采购任务，并从库存、销量和可售天数等必要依据进入单条任务处理。

### 2.2 存在理由

1. 若没有独立采购工作台，采购人员需要进入完整经营清单查找任务，既增加处理成本，也可能暴露其职责之外的利润、推广、品退和售后信息。
2. 若补货与禁补任务没有统一入口，运营侧已经收缩经营动作后，采购仍可能沿用旧销量和旧计划继续补货。
3. 若不固定展示批次、业务期间和最后更新时间，采购人员可能误把历史任务当作当前任务执行。
4. 若加载失败、确无任务和无权限使用同一种空白反馈，用户无法判断应等待新批次、刷新页面还是停止访问。

### 2.3 页面目标（可衡量）

| 目标维度 | 具体指标 |
| :--- | :--- |
| 任务归属准确 | 页面计数、任务预览和跳转目标中，100% 为当前采购角色有权查看的补货或禁补任务 |
| 必要依据完整 | 每个正常任务均展示 SPU 身份、补货/禁补结论、任务状态，以及现有的库存与销量必要依据；缺失值 100% 明确标记，不以 0 代替 |
| 批次明确 | 正常、空状态和加载失败状态均明确当前批次或说明尚无成功批次，避免把历史任务误认为本周任务 |
| 状态一致 | 用户从详情返回或刷新后，任务计数与最新合法状态一致；过期或重复结果不覆盖已成功状态 |
| 最小可见 | 页面、聚合计数、错误信息和跳转数据中完整利润、推广、品退及售后字段出现数为 0 |

### 2.4 不做什么（范围边界）

- **不展示完整经营建议、经营主动作或 AI 完整解读**——采购只需补货/禁补结论和必要库存、销量依据。
- **不展示完整利润、推广、品退或售后信息**——这些字段超出采购职责，所有可见路径均应排除。
- **不在工作台直接提交补货、禁补或结果**——正式操作进入单条采购裁剪详情，避免绕过证据查看、确认和状态校验。
- **不提供建议审核、经营动作执行或经营结果记录**——采购不能代替其他职责角色操作。
- **不提供批量执行、批量确认或批量回填**——首版逐条处理，避免误操作和审计归属不清。
- **不提供采购系统自动下单或自动停补**——本产品只记录人工轻闭环，不把人工确认表述为外部系统回执。
- **不提供导入、导出或历史全量追溯入口**——采购只从本人任务进入有权的裁剪详情。

## 3. 用户与场景

### 3.1 目标用户

| 维度 | 描述 |
| :--- | :--- |
| 角色 | 采购计划 |
| 人数 | 单次通常由 1 名已完成钉钉认证且具有有效采购计划角色的用户操作 |
| 技术熟练度 | 熟悉日常采购计划和库存数据，可理解补货、禁补、仓内、在途、近 14 天销量和库存可售天数 |
| 使用设备 | 办公电脑，PC Web |
| 使用姿势 | 每周新批次生成后查看新任务；一周内按需进入单条详情处理并复查结果 |
| 核心权限 | 仅查看本人有权的采购任务投影，处理补货或禁补，不接触完整经营信息 |

### 3.2 核心使用场景

**场景 A：处理待补货任务（主场景）**

- 时机：最新成功批次已经过建议审核，并激活了分配给当前采购角色的补货任务。
- 前置条件：用户通过钉钉登录且当前角色为采购计划；任务与当前角色存在有效关联；库存、在途和最近 14 天销量依据有效。
- 用户动作：进入采购工作台 → 查看待补货数量及必要依据摘要 → 选择某个 SPU → 进入采购裁剪详情 → 核对后记录补货任务状态与结果 → 返回工作台查看最新状态。
- 用户情绪：希望快速、确定，不需要在无关经营数据中寻找任务。

**场景 B：确认禁止补货任务（主场景）**

- 时机：某条已通过建议激活了禁止补货任务，需要采购停止继续补货并形成记录。
- 前置条件：用户有权查看该任务；任务状态允许采购处理；禁补结论已经固化且不能被采购改成补货。
- 用户动作：进入“待确认禁补”任务 → 查看 SPU 身份、禁补结论及现有库存/销量依据 → 进入采购裁剪详情 → 记录“已确认禁补”或等价结果、时间和备注 → 返回工作台。
- 用户情绪：需要明确风险动作和责任边界，避免误将“人工确认”理解为外部采购系统已经回执。

**场景 C：任务被其他人先处理（兜底场景）**

- 时机：用户打开工作台后，同一采购任务已在其他窗口或由另一名有权用户完成更新。
- 前置条件：当前页面仍显示旧状态，最新任务状态已经变化。
- 用户动作：打开任务或从详情返回 → 系统显示最新状态、最新操作者和时间 → 用户不再重复提交，按最新状态继续判断。
- 用户情绪：起初可能疑惑，需要清楚知道状态已变化且自己的旧操作没有覆盖成功结果。

**场景 D：当前批次没有采购任务（兜底场景）**

- 时机：最新成功批次没有分配给当前采购角色的补货或禁补任务，或所有任务均已处理。
- 前置条件：批次加载成功且权限校验通过。
- 用户动作：查看空状态及当前批次信息；若任务已全部处理，可进入已处理分组复查本人任务。
- 用户情绪：需要确认“确实无待办”，而不是误以为页面加载失败或权限异常。

### 3.3 用户核心诉求（优先级排序）

1. **P0：任务明确**——立即知道当前批次有哪些待补货和待确认禁补任务。
2. **P0：依据够用**——仅凭 SPU 身份、库存、在途、近 14 天销量和库存可售天数即可核对采购动作。
3. **P0：信息隔离**——不接触职责之外的完整利润、推广、品退和售后信息。
4. **P0：状态可靠**——重复打开、网络重试或并发更新不会造成重复执行或覆盖。
5. **P1：批次清楚**——始终知道正在处理哪个事业部、批次、期间和截止日。
6. **P1：恢复直接**——无任务、加载失败、会话失效和无权限均有不同且明确的下一步。

## 4. 信息架构

### 4.1 区域划分

1. 左侧采购导航区。
2. 顶部业务上下文区。
3. 当前批次与更新时间区。
4. 采购任务摘要区。
5. 当前采购任务预览区。
6. 库存与销量数据限制提示区。
7. 最近已处理采购任务区。
8. 页面状态与恢复反馈区。

### 4.2 区域内容

**1. 左侧采购导航区**

- 只显示“工作台”和“采购任务”。
- 不显示完整行动中心、数据批次、通用历史与追溯或其他角色的工作入口。

**2. 顶部业务上下文区**

- 事业部。
- 当前批次。
- 当前角色“采购计划”。
- 当前用户身份摘要。

**3. 当前批次与更新时间区**

- 批次标识、业务期间、业务截止日、最后更新时间。
- 当前是否为最新成功批次。
- 尚无成功批次时的明确说明。

**4. 采购任务摘要区**

- 待补货数量。
- 待确认禁补数量。
- 已处理采购任务数量。
- 每项摘要只统计当前角色有权查看的任务。

**5. 当前采购任务预览区**

- SPU ID、SPU 名称、店铺/平台。
- 补货或禁止补货结论。
- 仓内库存、在途库存、最近 14 天销量、最近 14 天平均日销量、库存可售天数。
- 当前采购动作状态、最近更新时间和“查看并处理”入口。

**6. 库存与销量数据限制提示区**

- 对缺失、异常或无近期销量的允许字段明确显示“未提供”“数据异常”或“无近期销售”。
- 禁补任务可在库存依据不完整时继续显示已固化的禁补结论，但不得猜测库存值。

**7. 最近已处理采购任务区**

- 只展示当前角色有权查看的已执行、已确认禁补或已记录采购结果任务。
- 显示任务状态、处理时间和采购结果摘要，不显示完整经营结果。

**8. 页面状态与恢复反馈区**

- 区分正在加载、无成功批次、当前批次无采购任务、网络失败、会话失效、无权限和状态已变化。
- 错误反馈不返回无权任务的对象身份或状态。

## 6. 交互流程

### 6.1 页面加载与初始化

1. 用户进入页面后，先确认钉钉登录态、当前有效角色及采购页面权限。
2. 权限有效时，读取最新成功批次的事业部、期间、业务截止日和更新时间；没有成功批次时进入“暂无批次”状态。
3. 系统只统计与当前采购角色存在有效任务关联的补货或禁补任务。
4. 页面分别形成待补货、待确认禁补和已处理任务摘要，并加载当前采购任务预览。
5. 每条任务只获取 SPU 身份、采购结论、库存、销量、可售天数、采购动作状态和采购结果所需字段。
6. 页面不因利润、推广、品退、售后或完整经营结果字段不可用而显示错误，因为这些字段本就不属于本页数据范围。
7. 加载失败时保留已确认的批次上下文并显示失败状态，不用空任务状态代替网络错误。

### 6.2 核心操作流程

**查看并处理补货任务**

```text
采购工作台
    → 查看“待补货”数量和必要依据
    → 选择单条任务
    → 再次校验当前角色与任务关联
        ├─ 无权限或任务已失效：不返回对象身份或状态，进入受控拒绝
        └─ 有权限：进入 PAGE-F06-03 采购裁剪详情
              → 用户核对并提交补货动作状态/结果
              → 返回工作台，显示最新合法状态
```

**查看并确认禁补任务**

```text
采购工作台
    → 查看“待确认禁补”数量和 SPU 身份
    → 选择单条任务进入采购裁剪详情
    → 查看只读“禁止补货”结论和现有库存/销量依据
    → 记录“已确认禁补”或等价结果、时间和备注
    → 返回工作台，任务进入已处理分组
```

**处理状态已变化**

```text
用户打开旧任务或从旧页面返回
    → 获取最新任务状态
        ├─ 原状态仍有效：继续进入采购裁剪详情
        └─ 已被其他合法操作更新：显示最新状态、操作者和时间
             → 不重复提交、不覆盖成功结果
             → 用户按最新状态查看详情
```

### 6.3 辅助操作

- 点击待补货、待确认禁补或已处理摘要，进入 `PAGE-F05-02` 对应采购任务投影，不携带无权字段。
- 点击“查看全部采购任务”，进入采购任务投影并保留当前批次上下文。
- 从详情返回时恢复工作台上下文，并重新获取最新任务计数与状态。
- 网络失败时点击“重新加载”，不需要重新进入页面；重试只刷新可见任务，不生成新动作或事件。
- 会话失效时进入认证恢复；重新认证成功后重新校验角色，仍为采购计划且有页面权限才返回本页。
- 本页不提供任务行内编辑、正式提交、快捷确认或结果回填。

## 7. 状态与边界

### 7.1 页面状态全景

| 状态 | 触发条件 | 页面表现 | 可用动作 |
| :--- | :--- | :--- | :--- |
| 身份与权限确认中 | 刚进入页面 | 仅显示安全加载状态，不显示任务对象或数量 | 等待 |
| 数据加载中 | 角色与页面权限有效，正在加载批次和任务 | 显示批次上下文占位和加载提示，不展示旧任务为最新任务 | 等待 |
| 正常有待办 | 当前批次存在待补货或待确认禁补任务 | 显示三类摘要、任务必要依据和进入详情入口 | 查看并处理、查看全部采购任务 |
| 全部已处理 | 当前批次存在采购任务但没有待执行任务 | 待办摘要为 0，明确显示“本批次采购任务已处理”及已处理任务 | 查看详情 |
| 当前批次无采购任务 | 批次加载成功，但当前角色没有任何补货或禁补任务 | 显示当前批次和“当前批次没有采购任务”，不显示业务对象 | 查看采购任务或等待新批次 |
| 暂无成功批次 | 系统尚无可用的成功批次 | 说明尚未形成采购任务；不提供导入入口 | 等待有权限角色建立新批次 |
| 数据限制 | 有权任务的部分库存或销量依据缺失、异常或无近期销售 | 保留采购结论和状态；字段明确显示未提供/异常/无法计算 | 查看详情，不在本页猜测或修正 |
| 状态已变化 | 当前页面状态落后于最新合法状态 | 显示最新状态、操作者和时间，不保留旧状态为可操作 | 查看最新详情、刷新 |
| 加载失败 | 网络或服务异常，无法完成批次或任务读取 | 显示失败与重新加载，不伪装成无采购任务 | 重新加载 |
| 会话失效 | 当前登录态失效 | 不显示任务数据，进入认证恢复 | 重新认证 |
| 无权限 | 当前角色不再是采购计划，或无本页访问权 | 不显示批次计数、对象身份和任务状态 | 返回本人工作台 |

### 7.2 边界与容错

| 边界类别 | 具体情况 | 处理策略 |
| :--- | :--- | :--- |
| 网络异常 | 加载摘要、任务预览或返回详情后刷新失败 | 明确显示加载失败和批次上下文；允许重试，不将失败显示为 0 个任务 |
| 会话过期 | 页面停留期间登录态失效 | 立即停止返回任务数据，进入认证恢复；认证后重新校验采购角色 |
| 连续错误 | 用户连续多次刷新仍失败 | 保持失败状态和重试入口，不展示缓存任务为最新结果，也不泄露内部错误详情 |
| 异常输入 | 地址中批次、任务分组或筛选参数非法、缺失或被篡改 | 回到当前角色的最新安全采购视图；不回显参数，不返回无权对象 |
| 并发操作 | 同一任务在其他窗口或由另一名有权用户先完成 | 以最新合法状态为准，显示最新操作者和时间；旧状态不再提供处理入口 |
| 重复操作 | 用户重复点击摘要、刷新或详情入口 | 只执行导航或读取，不新建采购动作、结果或重复事件 |
| 角色变化 | 用户查看期间采购角色被撤销或改为其他角色 | 后续读取立即拒绝，不沿用旧页面权限，不显示原任务身份或状态 |
| 对象无权 | 用户直接访问不属于当前采购角色的任务 | 显示权限不足，不返回建议身份、SPU 身份、任务类型或状态字段 |
| 新批次切换 | 页面打开后产生新的成功批次 | 提示有新批次可查看；刷新后整体切换上下文，不把两个批次任务混合统计 |
| 缺失依据 | 禁补任务的库存或销量字段未提供 | 继续显示已固化禁补结论；缺失字段标“未提供”，不得用 0 或推测值替代 |
| 任务数据矛盾 | 补货任务的必要库存或销量依据出现异常或不可计算 | 标记数据异常并进入详情核对；工作台不修改结论、不补值、不提供行内提交 |
| 无近期销量 | 最近 14 天平均日销量为 0，无法计算库存可售天数 | 显示“无近期销售/无法计算”，不展示虚假天数 |
| 低宽设备 | 视口低于 1024px | 显示“请使用电脑访问”，不允许在字段被截断的情况下继续处理 |

## 8. 业务规则与校验

### 8.1 字段定义

| 字段 | 说明 | 采购可见规则 |
| :--- | :--- | :--- |
| `business_unit` | 当前事业部 | 只显示当前任务所属事业部 |
| `batch_id` | 当前成功业务批次标识 | 用于明确任务上下文，不与其他批次混合 |
| `business_period` | 批次业务期间 | 只读展示 |
| `business_date` | 批次业务截止日 | 只读展示 |
| `last_updated_at` | 工作台任务最后更新时间 | 只读展示 |
| `spu_id` | SPU 唯一身份 | 仅有权任务可见 |
| `spu_name` | SPU 名称 | 仅有权任务可见 |
| `store_platform` | 店铺与平台身份 | 仅用于识别有权任务 |
| `procurement_action` | 补货或禁止补货 | 只读，采购不得互相改写 |
| `warehouse_qty` | 仓内库存 | 有权任务的必要库存依据，可缺失 |
| `in_transit_qty` | 在途库存 | 有权任务的必要库存依据，可缺失 |
| `sales_units_14d` | 最近 14 天销量 | 有权任务的必要销量依据，可缺失 |
| `avg_daily_sales_14d` | 最近 14 天平均日销量 | 有权任务的必要销量依据，可缺失 |
| `inventory_days` | 库存可售天数 | 可计算时显示，不可计算时显示原因 |
| `execution_state` | 采购动作当前状态 | 仅显示待执行、已执行、已确认禁补、已记录结果或已关闭等采购状态 |
| `procurement_result_summary` | 补货完成或禁补已确认等采购结果摘要 | 仅当前角色有权查看，不包含完整经营结果 |
| `execution_version` | 当前采购动作状态版本 | 不作为业务数据展示；用于识别页面状态是否过期 |
| `latest_actor/latest_at` | 最新合法更新的操作者与时间 | 正常记录或冲突恢复时显示 |
| `data_limitations` | 库存、销量依据的缺失或异常标记 | 只显示采购必要字段的质量说明 |

### 8.2 校验规则

| 校验项 | 时机 | 规则 | 失败反馈 |
| :--- | :--- | :--- | :--- |
| 当前角色 | 页面进入及每次读取时 | 必须为有效采购计划角色 | 不返回任务数据，进入本人安全页面或认证恢复 |
| 任务关联 | 加载计数、预览或打开详情时 | 任务必须分配给当前采购角色且对象授权有效 | “无权访问此任务”，不返回对象身份或状态 |
| 批次一致 | 统计和展示时 | 同一区域任务必须属于当前选定批次 | 回到当前安全批次，不混合计数 |
| 动作类型 | 展示时 | 只允许补货或禁止补货 | 不展示异常任务内容，提示数据异常 |
| 状态归类 | 展示时 | 待执行、已处理和已关闭按采购动作最新状态归类 | 刷新最新状态，不沿用旧分类 |
| 库存数量 | 展示时 | 有值时应为可解释的非负数；缺失不等于 0 | 显示“未提供”或“数据异常” |
| 最近 14 天销量 | 展示时 | 有值时应为可解释的非负数且带 14 天周期 | 显示“未提供”“数据异常”或“无近期销售” |
| 库存可售天数 | 展示时 | 仅在库存、在途和日均销量均有效且日均销量大于 0 时显示数值 | 显示“无法计算”及允许公开的原因 |
| 状态新鲜度 | 从详情返回、刷新或打开任务时 | 使用最新采购动作状态；旧版本不能继续作为可操作状态 | 显示最新状态、操作者、时间和查看入口 |
| 受限字段 | 所有加载、错误和跳转时 | 不得包含完整利润、推广、品退或售后字段 | 拒绝返回受限内容，页面保持采购最小投影 |

### 8.3 特殊业务规则

- 工作台只聚合已分配给当前采购角色且当前有权查看的补货或禁补任务。
- 补货与禁止补货是互斥的只读规则结论；采购只能记录本人任务状态与结果，不能改写结论。
- 建议通过后采购任务才进入待处理范围；本页不展示或处理建议级审核内容。
- 禁止补货可记录为“已确认禁补”或等价结果，但不表示外部采购系统已返回成功回执。
- 补货与禁补任务分别保留自己的执行状态和结果，不与经营动作状态合并或相互覆盖。
- 工作台总数和任务预览必须使用同一批次、同一角色投影和最新合法状态。
- 并发或重复操作只接受第一条合法状态变化；工作台只展示结果，不创建重复业务事件。
- 缺失库存或销量必须显示为“未提供/无法计算”，不得转为 0；禁补结论不因依据缺失而消失。
- 页面、聚合计数、错误、空状态和跳转均不得通过字段名、文本摘要或数量旁路泄露完整利润、推广、品退及售后信息。

## 10. 数据需求

### 10.1 页面需要什么数据

| 数据 | 来源 | 用途 |
| :--- | :--- | :--- |
| 当前有效角色与用户摘要 | 钉钉认证及已审批角色映射结果 | 判断能否进入采购工作台并显示角色上下文 |
| 事业部、批次标识、业务期间、业务截止日、更新时间 | 最新成功批次 | 防止跨批次误处理，说明当前任务时点 |
| 待补货、待确认禁补、已处理数量 | 当前批次中当前角色有权任务的最新状态 | 形成采购任务摘要 |
| SPU ID、名称、店铺/平台 | 当前角色有权的采购任务对象投影 | 帮助识别单条采购任务 |
| 补货/禁补结论 | 固化采购动作 | 明确需要采购执行或确认的动作 |
| 仓内库存、在途库存 | 采购任务必要依据 | 核对库存基础 |
| 最近 14 天销量、平均日销量及周期 | 采购任务必要依据 | 核对近期销售基础 |
| 库存可售天数及可计算状态 | 采购任务必要依据 | 核对补货判断所用库存周期 |
| 采购动作状态、采购结果摘要、更新时间 | 当前采购动作与结果 | 区分待办、已处理及冲突后的最新结果 |
| 最新操作者与时间 | 当前采购动作最新合法记录 | 状态变化或并发冲突时帮助用户判断 |
| 库存与销量数据限制 | 当前任务允许公开的数据质量标记 | 明确缺失、异常或无法计算，不误读为 0 |

### 10.2 页面提交什么数据

采购工作台本身不提交补货、禁补、执行状态、结果或备注，只产生以下导航与读取意图：

| 数据或意图 | 触发时机 | 用途 |
| :--- | :--- | :--- |
| 当前批次采购任务分组 | 点击待补货、待确认禁补或已处理摘要 | 打开 `PAGE-F05-02` 对应采购任务投影 |
| 单条采购任务身份 | 点击“查看并处理”或“查看详情” | 在再次校验当前角色和任务关联后打开 `PAGE-F06-03` 采购裁剪详情 |
| 刷新意图 | 点击重新加载或从详情返回 | 获取最新批次、计数和任务状态，不创建业务事件 |

正式状态、备注和采购结果由 `PAGE-F06-03` 在当前角色、当前状态和版本校验通过后提交。

### 10.3 明确排除的数据

- 完整利润、经营准利润率、经营准利润值和其他利润结果。
- 推广费用、广告计划、广告单元、关键词、素材及完整推广信息。
- 品退率、品退件数、退款/退货原因、评价、差评主题及其他售后信息。
- 经营主动作、完整建议问题描述、AI 完整解释、优化提示和规则证据全貌。
- 主管审核备注、运营动作备注、完整经营结果及其他角色的任务状态。
- 不属于当前采购角色的建议身份、SPU 身份、任务类型、任务状态和历史事件。
- 原始 XLSX、完整批次校验明细、消费者个人信息和 LiteLLM 凭据。
- SKU 级身份、库存、利润或动作数据。

| S-01 | 角色门禁 | 非采购计划角色或角色失效后访问本页，不返回批次任务计数、对象身份或任务状态 |
| S-02 | 对象授权 | 采购计划只能查看与当前角色存在有效任务关联的补货/禁补任务；无关联任务返回权限不足且不返回建议身份或状态 |
| S-03 | 敏感字段隔离 | 页面、任务计数、任务预览、跳转、错误和空状态中完整利润、推广、品退及售后字段出现数为 0 |
| S-04 | 操作隔离 | 工作台不提供建议审核、经营动作、经营结果、角色配置、批次导入或其他角色任务入口 |
| S-05 | 直接地址保护 | 篡改批次或任务地址不能获得无权 SPU 身份、任务类型、状态或任何受限经营字段 |
| S-06 | 会话与角色复核 | 会话失效或采购角色被撤销后，后续读取立即停止返回任务数据；重新认证后按最新角色决定去向 |
| S-07 | 聚合防旁路 | 三类摘要数量只基于当前角色有权任务，不通过跨角色总数、差值或错误信息暴露其他任务存在性 |
| S-08 | 历史路径裁剪 | 从已处理任务或旧地址进入详情时仍使用采购裁剪视图，不因历史状态返回完整建议、利润、推广、品退或售后信息 |
| S-09 | 重试与并发保护 | 页面刷新、重复点击、网络重试或多窗口使用均不新建采购动作/结果，不覆盖第一条合法状态变化 |
