## 2. 页面概述
### 2.1 一句话定位
让三类直接用户仅通过公司钉钉身份完成认证，并在有效唯一角色映射后进入业务工作台。
### 2.2 存在理由
1. 没有统一身份无法建立真实 actor 与角色权限。
2. 无有效角色时必须默认拒绝，避免自动赋权。
3. 认证失败需有重新认证或联系 IT 的明确恢复路径。
### 2.3 页面目标（可衡量）
| 维度 | 指标 |
| :--- | :--- |
| 认证单一性 | 未出现账号密码、注册、找回密码或共享账号入口 |
| 默认拒绝 | 无认证或无有效角色时经营数据返回量为 0 |
| 角色一致 | 成功后页面、接口、错误及历史路径统一应用同一角色 |
### 2.4 不做什么（范围边界）
- 不提供账号密码、短信/邮件验证码、注册或找回密码。
- 不让用户在页面选择或申请角色。
- 不建设业务侧角色管理后台——角色由事业部负责人审批、IT 配置。
- 不在认证失败时展示经营数据或默认运营角色。

## 3. 用户与场景
### 3.1 目标用户
| 维度 | 描述 |
| :--- | :--- |
| 角色 | 运营、运营主管、采购计划 |
| 技术熟练度 | 中等，熟悉钉钉扫码/授权 |
| 设备/姿势 | PC 浏览器，近距离坐姿 |
### 3.2 核心使用场景
**场景 A：钉钉认证成功（主场景）**
- 时机：首次进入或登录态失效；前置：拥有公司钉钉身份且 IT 配置唯一有效业务角色；动作：点击发起钉钉认证，完成授权后进入工作台并看见当前角色；情绪：熟悉、快速。

**场景 B：未配置有效角色（兜底场景）**
- 时机：钉钉认证已成功但角色缺失/无效/不唯一；前置：IT 映射未就绪；动作：停留在拒绝状态，可重新认证或按指引联系 IT；情绪：明确知道谁能解决，不误以为系统无数据。
### 3.3 用户核心诉求（优先级排序）
1. 使用公司现有身份快速进入。
2. 失败时知道是认证问题还是角色配置问题。
3. 不需要记忆新的账号密码。

## 4. 信息架构
### 4.1 区域划分
1. 产品品牌与用途；2. 钉钉认证主卡片；3. 安全/角色说明；4. 状态反馈；5. 联系 IT 恢复路径。
### 4.2 区域内容
- 品牌：产品名、玩具事业部内部经营协作说明。
- 主卡片：钉钉矢量标识、单一“使用钉钉认证”按钮。
- 反馈：认证中、认证失败、登录态失效、无有效角色四类状态。

## 6. 交互流程
### 6.1 页面加载与初始化
- 检查安全会话；有效且角色唯一时跳转原来源页或工作台。
- 无会话仅渲染门禁，不预取任何经营接口。
### 6.2 核心操作流程
```text
点击钉钉认证 → 跳转/打开钉钉统一认证 → 服务端校验身份与角色映射
  ├─ 唯一有效角色 → 建立安全会话 → 显示角色 → 进入来源页/工作台
  ├─ 认证失败/会话失效 → 不建立会话 → 可重新认证
  └─ 角色缺失、无效或不唯一 → 拒绝业务访问 → 联系 IT/重新认证
```
### 6.3 辅助操作
- 认证进行中按钮禁用，避免重复发起。
- “联系 IT”展示企业既有支持指引，不采集密码或敏感凭据。

## 7. 状态与边界
### 7.1 页面状态全景
| 状态 | 触发条件 | 页面表现 |
| :--- | :--- | :--- |
| 初始态 | 无有效会话 | 单一钉钉认证按钮 |
| 输入态 | 不适用（无本地凭据表单） | 不出现账号密码字段 |
| 提交态 | 发起认证 | “正在前往钉钉”，按钮禁用 |
| 成功态 | 身份与唯一角色有效 | 建立会话并跳转 |
| 失败态 | 认证拒绝/回调失败 | 明确失败且可重新认证 |
| 异常态 | 网络/服务异常 | 不进入业务页，可重试 |
| 无角色态 | 映射缺失/无效/不唯一 | 联系 IT，不返回经营数据 |
### 7.2 边界与容错
| 边界场景 | 处理策略 |
| :--- | :--- |
| 网络异常 | 停留门禁，提示网络异常并可重试 |
| 会话过期 | 清理业务展示并回门禁，提示重新认证 |
| 连续/重复点击 | 认证进行中禁用，不创建并行产品会话 |
| 回调参数异常 | 统一认证失败，不暴露校验细节 |
| 多标签认证并发 | 仅接受合法当前会话结果，其余刷新现状 |
| 无角色/多角色 | 默认拒绝，不自动选择或赋予角色 |
| 钉钉暂不可用 | 不降级为账号密码或共享账号 |

## 8. 业务规则与校验
### 8.1 字段定义
| 字段 | 说明 |
| :--- | :--- |
| `dingtalk_identity_ref` | 服务端关联的稳定钉钉身份引用 |
| `business_role` | IT 映射的运营/运营主管/采购计划唯一角色 |
| `return_to` | 认证前合法的站内来源路径 |
### 8.2 校验规则
| 校验项 | 时机 | 规则 | 失败反馈 |
| :--- | :--- | :--- | :--- |
| 身份认证 | 服务端回调 | 钉钉结果有效 | “钉钉认证未完成，请重新认证” |
| 角色映射 | 建立会话前 | 必须是三类角色之一且唯一有效 | “未配置有效业务角色，请联系 IT” |
| 来源路径 | 跳转前 | 仅允许合法站内路径 | 非法时进入工作台 |
| 会话状态 | 每次业务请求 | 有效且角色一致 | 失效返回门禁 |
### 8.3 特殊业务规则
- 钉钉是唯一认证入口；产品不保存用户输入的认证凭据。
- 角色映射由 IT 维护，事业部负责人审批；失败时零经营数据返回。

## 9. 页面流转
### 9.1 流转图
`产品入口/登录态失效 → 本页 → 钉钉认证 → 身份+唯一角色校验 → 来源页或角色工作台`。
### 9.2 与其他模块的关系
- 成功会话为 F01—F08 所有页面与接口提供统一 actor/role。
- 失败与无角色状态隔离全部批次、建议和历史数据。
### 9.3 扩展预案
| 方向 | 触发条件 | 改造点 |
| :--- | :--- | :--- |
| 新角色 | PRD 新增 REQ 且审批/维护责任明确 | 增量扩展映射和权限，不让用户自选 |

## 11. 验收标准
### 11.1 功能验收
| 编号 | 验收点 | 通过标准 |

## 12. 生产实现映射

- 前端路由：`apps/web/src/pages/AuthPage.tsx`，保持双栏认证门禁、唯一钉钉 CTA、四类认证反馈与利润—库存双轨决策带。
- 身份客户端：`apps/web/src/api.ts`，仅调用真实 `/api/auth/*`，未认证时返回空身份，不建立默认用户或默认角色。
- 服务端路由：`apps/api/src/routes/auth.ts`；钉钉协议适配器：`apps/api/src/auth/dingtalk.ts`；OAuth state 与安全会话由 PostgreSQL 持久化。
- 状态对应：`status=failed`、`role_missing`、`unavailable` 分别显示认证失败、角色缺失和服务异常；提交态按钮禁用并跳转真实认证地址。
