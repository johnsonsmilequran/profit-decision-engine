## 2. 页面概述
### 2.1 一句话定位
让运营记录其负责的加投、观察、SPU 整体推广止损或清仓的人工执行事实，并与采购动作独立留痕。
### 2.2 存在理由
1. 将规则动作转为有责任人、时间和备注的线下执行事实。
2. 防止经营执行覆盖采购动作进度。
3. 观察动作必须有真实观察记录，避免空完成。
### 2.3 页面目标（可衡量）
| 维度 | 指标 |
| :--- | :--- |
| 责任准确 | 仅运营可提交经营动作，错误角色成功数 0 |
| 证据完整 | 每次成功执行含动作、时间、备注/结果、actor、version |
| 并发安全 | 过期 version 覆盖成功事实次数 0 |
### 2.4 不做什么（范围边界）
- 不修改固定主动作或采购动作。
- 不自动写广告、库存或内容系统——仅记录人工事实。
- 不记录广告计划、关键词、素材、SKU 等无数据支持的明细。
- 不在本页记录后续销售额、利润和库存表现——由经营结果表单承担。

## 3. 用户与场景
### 3.1 目标用户
| 维度 | 描述 |
| :--- | :--- |
| 角色 | 运营 |
| 技术熟练度 | 中等，熟悉商品经营与推广操作 |
| 设备/姿势 | PC，完成线下动作后回填 |
### 3.2 核心使用场景
**场景 A：回填清仓执行（主场景）**
- 时机：建议已通过且运营完成线下清仓安排；前置：经营动作待执行；动作：核对动作、填写执行时间与事实备注并确认；情绪：快速、确定。

**场景 B：观察动作证据不足（兜底场景）**
- 时机：主动作是观察；前置：没有评价/退款原因/广告明细；动作：仅记录非空观察范围、周期或有证据支持的价格/内容/详情页优化，不填写具体归因；情绪：克制、不被迫编造。
### 3.3 用户核心诉求（优先级排序）
1. 核对自己执行的是冻结的正确动作。
2. 少量字段即可形成可信执行记录。
3. 冲突后不丢输入，也不覆盖别人结果。

## 4. 信息架构
### 4.1 区域划分
1. 应用壳与面包屑；2. SPU 与建议摘要；3. 双轨动作带；4. 经营动作执行表单；5. 提交摘要；6. 冲突提示。
### 4.2 区域内容
- 摘要：SPU、主动作、问题、必要关键依据、建议审核状态。
- 双轨带：突出经营轨，采购轨只显示进度，不提供编辑。
- 表单：执行状态、执行时间、执行备注、动作结果摘要。

## 5. 界面内容
### 5.1 元素清单
| 元素 | 内容/文案 | 数据来源 | 显示条件 |
| :--- | :--- | :--- | :--- |
| 主动作卡 | 加投/观察/SPU 推广止损/清仓 | ActionItem 快照 | 始终 |
| 执行状态 | “确认已执行” | 用户选择 | 动作待执行 |
| 执行时间 | 日期时间 | 用户输入，默认当前时刻可修改 | 动作待执行 |
| 执行备注 | “说明实际采取的经营动作” | 用户输入 | 动作待执行 |
| 动作结果 | 线下执行结果简述 | 用户输入 | 动作待执行 |
| 采购轨状态 | 补货/禁补及当前状态 | 只读裁剪数据 | 建议含采购动作 |
### 5.2 辅助信息
- 观察提示：“只记录当前证据支持的观察或优化，不填写评价、退款原因或广告明细归因。”
- 清仓/止损提示：“系统不会自动修改外部广告或库存系统。”

## 6. 交互流程
### 6.1 页面加载与初始化
- 校验运营角色、建议已通过、经营动作待执行；读取 execution_version。
- 恢复本地会话中该 actionId 的未提交文本。
### 6.2 核心操作流程
```text
核对主动作 → 填写时间、备注和结果 → 全量校验 → 摘要确认
  ├─ version 当前 → 仅更新经营动作并追加事件 → 返回建议详情
  └─ version 过期/重复 → 不覆盖 → 显示既有结果或最新状态，保留输入
```
### 6.3 辅助操作
- 取消返回详情；有输入时离开确认。
- 提交期间禁用按钮；采购轨不可点击编辑。

## 7. 状态与边界
### 7.1 页面状态全景
| 状态 | 触发条件 | 页面表现 |
| :--- | :--- | :--- |
| 初始态 | 合法待执行动作 | 展示冻结动作，时间预填 |
| 输入态 | 编辑字段 | 失焦校验，草稿保留于本地会话 |
| 提交态 | 确认执行 | 显示“记录中”，禁止重复提交 |
| 成功态 | 保存成功 | Toast 后回详情，经营轨更新 |
| 失败态 | 字段/服务失败 | 明确字段或服务原因，保留输入 |
| 异常态 | 网络/version 冲突 | 展示恢复路径与最新操作者 |
| 无权限态 | 非运营/无对象权 | 转权限不足，不返回业务字段 |
### 7.2 边界与容错
| 边界场景 | 处理策略 |
| :--- | :--- |
| 网络异常 | 不标成功，保留草稿并可重试 |
| 会话过期 | 返回钉钉门禁，重新认证后再校验现状 |
| 重复提交 | 首次处理中禁用；成功重试返回既有结果 |
| 异常时间 | 无效或明显未来时间阻止提交 |
| 并发操作 | 旧 execution_version 拒绝并返回最新状态 |
| 建议未通过/已驳回 | 拒绝执行并引导返回详情 |
| 观察备注为空白 | 阻止提交，不把动作标为已执行 |

## 8. 业务规则与校验
### 8.1 字段定义
| 字段 | 说明 |
| :--- | :--- |
| `executed_at` | 实际人工执行时间 |
| `execution_note` | 执行事实备注；观察动作必填非空 |
| `action_result` | 本次线下执行结果简述 |
| `execution_version` | 经营动作当前版本 |
### 8.2 校验规则
| 校验项 | 时机 | 规则 | 失败反馈 |
| :--- | :--- | :--- | :--- |
| 执行时间 | 失焦/提交 | 合法日期时间，不晚于当前可接受业务时刻 | “请填写有效执行时间” |
| 观察备注 | 失焦/提交 | 主动作为观察时去空白后非空 | “请记录观察范围或已采取的优化” |
| 证据范围 | 提交 | 不接受无来源的广告/评价/退款明细归因 | “请仅记录当前数据支持的事实” |
| 状态/version | 服务端 | 已通过、待执行且版本一致 | “动作状态已变化，请刷新确认” |
### 8.3 特殊业务规则
- 仅更新经营 action_id；采购 action_id 与状态不得改变。
- 成功状态与事件原子追加；人工记录不得表述为外部系统回执。

## 9. 页面流转
### 9.1 流转图
`建议详情（经营动作待执行） → 本页 → 摘要确认 → 建议详情（经营动作已执行）`。
### 9.2 与其他模块的关系
- 依赖建议级已通过状态；F08 追加经营动作事件。
- 提交后可从建议详情进入经营结果记录，采购动作独立继续。
### 9.3 扩展预案
| 方向 | 触发条件 | 改造点 |
| :--- | :--- | :--- |
| 外部系统回执 | 阶段2形成接口 REQ | 以稳定 action_id 追加回执，不覆盖人工记录 |

## 10. 数据需求
### 10.1 页面需要什么数据
| 数据 | 来源 | 用途 |
| :--- | :--- | :--- |
| SPU/建议/经营动作快照 | DecisionRecord/ActionItem | 核对动作 |
| 建议审核与双轨状态 | 状态投影 | 校验可执行性 |
| execution_version/角色 | 动作与会话 | 并发与授权 |
### 10.2 页面提交什么数据
| 数据 | 触发时机 | 用途 |
| :--- | :--- | :--- |
| action_id、executed_at、note、result、version | 确认提交 | 追加经营执行事实 |
### 10.3 明确排除的数据
- 不提交采购结果、经营后销售利润库存指标或外部系统凭据。

### 10.4 实施同步
生产 API 已实现 `POST /api/action-items/:actionItemId/execute`。运营只能锁定并更新 business 轨动作；建议必须已整体通过，动作必须为待执行且 version 当前。执行时间、事实备注和线下结果分别持久化，采购动作状态/version 在同一请求中不被读取修改；成功状态与 `action_executed` 事件原子提交，重复幂等键不重复写入。

## 11. 验收标准
### 11.1 功能验收
| 编号 | 验收点 | 通过标准 |
| :--- | :--- | :--- |
| F-01 | 四类动作 | 加投、观察、SPU 止损、清仓均可记录人工执行 |
| F-02 | 观察必填 | 空白观察备注不能进入已执行 |
| F-03 | 独立更新 | 经营执行后采购动作状态和 version 不变 |
| F-04 | 成功留痕 | 保存 action、时间、备注/结果、actor 和事件 |
| F-05 | 并发保护 | 旧 version 不覆盖既有结果，不产生重复事件 |
### 11.2 体验验收
| 编号 | 验收点 | 通过标准 |
| :--- | :--- | :--- |
| U-01 | 动作核对 | 首屏清晰显示冻结主动作和 SPU |
| U-02 | 双轨理解 | 可见采购轨进度但无编辑入口 |
| U-03 | 证据提示 | 观察动作显示证据边界提示 |
| U-04 | 输入保留 | 网络失败或冲突后文本与时间不丢失 |
| U-05 | 完成反馈 | 成功后返回详情并仅更新经营轨 |
### 11.3 安全验收（产品层）
| 编号 | 验收点 | 通过标准 |
| :--- | :--- | :--- |
| S-01 | 运营专属 | 非运营提交被服务端拒绝 |

| S-03 | 字段最小化 | 响应不含凭据或无关审计详情 |

| S-05 | 审计身份 | 成功事件使用钉钉关联 actor_ref |
