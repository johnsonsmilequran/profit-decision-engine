# 页面名称：经营结果记录表单

| 字段 | 内容 |
| :--- | :--- |

| Source IDs | `REQ-F06-03, AC-F06-05, AC-F06-06` |
| 所属产品 | 趣然 AI 商品经营与利润决策助手 |

## 2. 页面概述
### 2.1 一句话定位
让运营在经营动作执行后，按明确周期记录销售额、利润、库存结果，缺数时也能如实标记未提供。
### 2.2 存在理由
1. 执行动作不等于产生经营结果，必须分层记录。
2. 结果需关联原建议、周期、记录人与时间以便复盘。
3. 不能用默认零值伪造尚未提供的指标。
### 2.3 页面目标（可衡量）
| 维度 | 指标 |
| :--- | :--- |
| 关联完整 | 结果关联原 decision/action、周期、actor、记录时间率 100% |
| 缺数真实 | 未提供值被默认写为 0 的次数为 0 |
| 并发安全 | 旧 version 覆盖已成功结果次数为 0 |
### 2.4 不做什么（范围边界）
- 不修改原动作、规则或审核状态。
- 不替采购计划记录补货/禁补结果。
- 不自动从外部系统拉取或回写结果。
- 不计算动作因果或承诺利润改善。

## 3. 用户与场景
### 3.1 目标用户
| 维度 | 描述 |
| :--- | :--- |
| 角色 | 运营 |
| 技术熟练度 | 中等，能理解销售、利润、库存口径 |
| 设备/姿势 | PC，周期结束后集中回填 |
### 3.2 核心使用场景
**场景 A：记录完整经营结果（主场景）**
- 时机：经营动作已执行且观察周期结束；前置：有权访问原建议；动作：声明结果周期，录入销售额、利润与库存结果、备注后确认；情绪：客观、希望可复盘。

**场景 B：部分结果尚未提供（兜底场景）**
- 时机：周期结束但部分指标未取得；前置：至少能声明周期；动作：将相应指标明确设为“未提供”，填写说明后提交；情绪：诚实、不被迫填零。
### 3.3 用户核心诉求（优先级排序）
1. 明确结果对应哪个动作和周期。
2. 可记录部分可用结果并如实说明缺数。
3. 冲突后保留已填数据。

## 4. 信息架构
### 4.1 区域划分
1. 应用壳与面包屑；2. 原建议/动作摘要；3. 结果周期；4. 销售、利润、库存结果；5. 备注与确认；6. 冲突提示。
### 4.2 区域内容
- 摘要：SPU、冻结主动作、执行时间、执行人、原关键依据。
- 周期：起止日期与口径提示。
- 三类结果：各自“已提供/未提供”状态及对应值；库存可记录数量或事实描述。

## 5. 界面内容
### 5.1 元素清单
| 元素 | 内容/文案 | 数据来源 | 显示条件 |
| :--- | :--- | :--- | :--- |
| 动作摘要 | SPU、主动作、执行时间 | 冻结快照/执行事件 | 始终 |
| 结果周期 | 起止日期 | 用户输入 | 始终 |
| 销售额结果 | 提供状态、金额 | 用户输入 | 始终 |
| 利润结果 | 提供状态、金额/利润率说明 | 用户输入 | 始终 |
| 库存结果 | 提供状态、数量/描述 | 用户输入 | 始终 |
| 结果备注 | “说明数据来源、口径或未提供原因” | 用户输入 | 始终 |
### 5.2 辅助信息
- 明示“未提供不等于 0”；金额按人民币显示，存储使用未格式化数值。
- 记录结果不改变原规则结论。

## 6. 交互流程
### 6.1 页面加载与初始化
- 校验运营角色、经营动作已执行、当前 outcome_version；加载原动作摘要。
- 每类指标默认未选择提供状态，不预填 0；恢复同 actionId 本地草稿。
### 6.2 核心操作流程
```text
填写周期 → 为三类结果选择“已提供/未提供” → 已提供则填值 → 填备注 → 确认
  ├─ version 当前 → 追加 OutcomeRecord/事件 → 返回详情
  └─ version 过期/网络失败 → 不覆盖 → 保留所有输入并显示恢复路径
```
### 6.3 辅助操作
- 取消返回详情；有输入时离开确认。
- 提交摘要按“周期—销售—利润—库存”顺序复核。

## 7. 状态与边界
### 7.1 页面状态全景
| 状态 | 触发条件 | 页面表现 |
| :--- | :--- | :--- |
| 初始态 | 合法进入 | 展示动作摘要，结果均未选择 |
| 输入态 | 编辑周期/指标 | 条件字段展开，失焦校验 |
| 提交态 | 确认记录 | 按钮“记录中”，禁止重复提交 |
| 成功态 | 保存成功 | Toast 后返回详情，经营轨显示已记录结果 |
| 失败态 | 字段/服务失败 | 定位问题并保留输入 |
| 异常态 | 网络/version 冲突 | 展示最新状态、操作者、刷新入口 |
| 无权限态 | 非运营/无对象权限 | 权限不足且无业务数据 |
### 7.2 边界与容错
| 边界场景 | 处理策略 |
| :--- | :--- |
| 网络异常 | 不显示成功，保留草稿可重试 |
| 会话过期 | 返回钉钉门禁，重认证后重新校验动作状态 |
| 重复提交 | 请求中禁用；重复到达返回既有结果 |
| 周期倒置/缺失 | 阻止提交并定位日期字段 |
| 提供状态与值矛盾 | 已提供无值则阻止；未提供不提交数值 |
| 并发提交 | 旧 version 拒绝且不新增结果事件 |
| 经营动作未执行 | 不允许提前记录结果 |

## 8. 业务规则与校验
### 8.1 字段定义
| 字段 | 说明 |
| :--- | :--- |
| `period_start/end` | 经营结果观察周期 |
| `sales_status/value` | 销售额是否提供及值 |
| `profit_status/value` | 利润是否提供及值 |
| `inventory_status/value` | 库存是否提供及值/描述 |
| `outcome_note` | 来源、口径或缺失原因 |
| `outcome_version` | 结果记录版本 |
### 8.2 校验规则
| 校验项 | 时机 | 规则 | 失败反馈 |
| :--- | :--- | :--- | :--- |
| 结果周期 | 失焦/提交 | 起止齐全且结束不早于开始 | “请填写合法结果周期” |
| 提供状态 | 提交 | 三类结果均明确已提供或未提供 | “请明确每类结果是否已提供” |
| 结果值 | 失焦/提交 | 已提供时可解析；未提供时不提交默认值 | “请填写有效结果或选择未提供” |
| version | 服务端 | 与当前状态一致 | “结果状态已变化，请刷新确认” |
### 8.3 特殊业务规则
- 可部分提供结果，但所有缺数必须显式标为未提供；成功记录追加，不覆盖历史。
- 采购角色不能获得完整经营结果字段。

## 9. 页面流转
### 9.1 流转图
`建议详情（经营动作已执行） → 本页 → 摘要确认 → 建议详情（已记录经营结果）`。
### 9.2 与其他模块的关系
- 依赖 F06 经营执行事件；结果通过 F08 时间线追溯。
- 建议详情继续展示原 F03/F08 快照，不被结果值改写。
### 9.3 扩展预案
| 方向 | 触发条件 | 改造点 |
| :--- | :--- | :--- |
| 自动取数 | 外部系统、口径及责任形成新 REQ | 以 action/outcome ID 追加来源，不覆盖人工值 |

## 10. 数据需求
### 10.1 页面需要什么数据
| 数据 | 来源 | 用途 |
| :--- | :--- | :--- |
| 原建议与经营动作摘要 | 冻结快照/执行事件 | 明确结果对象 |
| 当前状态、version、角色 | 服务端 | 授权与并发校验 |
### 10.2 页面提交什么数据
| 数据 | 触发时机 | 用途 |
| :--- | :--- | :--- |
| action_id、周期、三类提供状态/值、备注、version | 确认提交 | 追加经营结果 |
### 10.3 明确排除的数据
- 不提交采购结果、规则更新、外部系统凭据或消费者 PII。

### 10.4 实施同步
生产 API 已实现 `POST /api/action-items/:actionItemId/outcome`，仅允许运营对已执行 business 动作提交。服务端校验合法周期、三类结果逐项 `provided/not_provided` 和当前 version；未提供项不接收默认值。结果值、周期、备注、记录人/时间、动作新状态与 `business_outcome_recorded` 事件同事务追加；采购调用在读取业务对象前直接拒绝。React 路由 `/decisions/:decisionId/operations-outcome` 已实现周期双日期、销售/利润/库存逐项提供状态与条件值、口径说明及 version 冲突保留；没有预填零值，只有已执行经营动作显示入口。

| U-03 | 条件字段 | 选择已提供后才要求对应值 |
