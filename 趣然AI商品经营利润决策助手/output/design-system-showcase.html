核心隐喻 · 晨间经营指挥室

每周一早晨，运营、主管与采购走进同一间安静的经营指挥室。浅灰桌面吸收数据杂音，白色工作纸承载可核对事实；深海军蓝提供确定感，铉蓝只在真正可操作的地方出现。这里不是豪华驾驶舱，而是一间让数字保持锋利、让判断保持克制、让跨部门协作保持同一节拍的业务作战室。

Section 02

设计理念

让风险可见，但不制造恐慌

用户情绪

冷静掌控：迅速知道现在最该处理什么。

可信：沿指标、阈值和规则版本复核结论。

协同压力：风险清楚存在，但不以满屏红色放大。

闭环感：经营与采购动作并排，断点不被总状态遮住。

浅色与风格理由

白天长时间使用的 PC 企业工具，需要持续读取中文名称、金额、百分比、日期、阈值和长表格。浅色保证细小数据的边缘清晰，也接近原始经营表的阅读习惯。MVP 只做浅色，降低未经验证的维护面。

最终坐标是 Professional & Corporate：稳健、精确、可追溯，AI 只作为次级解释层，固定规则始终拥有主视觉权威。

微反馈与 Reduced Motion

按钮按下加深铉蓝；输入聚焦显示统一焦点环；卡片悬停只响应底色和边框。系统检测 prefers-reduced-motion: reduce 后移除进场、模糊与过渡时长，但保留颜色和焦点反馈，不使用全局星号覆盖。

Agent Prompt Guide

  1. 先呈现固定规则结论，再呈现 AI 增强解释。
  2. 每个建议保留优先级色轨、依据筹码和双动作轨。
  3. 只使用 tokens.css 中的变量，不硬编码颜色、阴影、动效或字体。
  4. 所有交互实现 hover、active、focus-visible 和明确 disabled 原因。
  5. 分别设计数据空、筛选空、加载、失败、无权限和版本冲突。

Section 11

设计禁忌

边界让系统保持可信

✓ 浅色经营工作纸

服务白天长时间阅读。

✕ 暗色霓虹 HUD

会把内部工作台误塑造成值守大屏。

✓ 固定规则结论在前

AI 只增强解释。

✕ AI 文案抢占首层

AI 不拥有动作裁决权。

✓ 风险红只表达业务后果

用于清仓、止损与阻断错误。

✕ 用红色装饰导航

装饰会稀释风险含义。

✓ 色彩响应

悬停改变背景、边框或文字色。

✕ 混用阴影提升和位移

会破坏统一交互物理。

✓ 普通卡片最大 12px 圆角

保持密集经营数据精确感。

✕ 过度柔软的大圆角

削弱企业数据工具的克制。

✓ 状态有颜色也有文字

照顾色觉差异用户。

✕ 只放彩色圆点

状态语义无法可靠读取。

✓ 次级证据满足 AA

周期、来源和口径仍清楚可读。

✕ 极浅灰脚注

会让决策证据消失。

✓ 依赖本地系统字体

确保企业内网与中国大陆稳定可达。

✕ 从境外 CDN 加载字体

网络条件不应决定基础排版。

✓ 稳定分页与上下文恢复

行动清单和追溯记录可返回原位置。

✕ 无限滚动

用户无法稳定引用和恢复上下文。

✓ 密集表格保留至少 12px

不足宽度时横向滚动。

✕ 压缩到 11px 以下

金额、阈值与状态不能被牺牲。

✓ 状态变更有持久证据

驳回、执行和结果留在时间线。

✕ 只显示短暂 Toast

无法承担可追溯闭环。

✓ 服务端移除采购受限字段

最小必要数据不进入响应。

✕ 前端模糊或遮挡

隐藏不等于数据权限。
