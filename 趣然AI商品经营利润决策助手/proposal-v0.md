# F09 Admin 管理后台方案 V0

> 状态：Lead PM 初稿，等待工程、设计、商业、战略四方独立评审。本文不代表用户已确认方案。

## 1. 目标与边界

让“钉钉身份已确认但没有唯一有效业务角色”的员工，经外部业务审批和唯一 Admin 配置后进入正确工作台；错误授权为 0，高权限操作审计覆盖率 100%。

不变边界：

- 只保留一名 Admin，不支持第二名 Admin、委派或管理员角色树。
- Admin 使用独立本地用户名、密码、TOTP 和独立管理会话，不依赖钉钉登录。
- Admin 权限与运营/运营主管业务角色正交，默认不能读取经营数据。
- 业务角色固定为运营、运营主管，同一身份只能有一个有效角色。
- 事业部负责人审批，Admin 只执行已审批结果并记录依据。
- 首版不接 OA 审批 API，不建设通用 IAM、IGA、权限编辑器或审批工作流引擎。

## 2. 产品闭环

```text
钉钉认证 → 无唯一角色 → 幂等生成待审批身份 → 用户看到状态与处理指引
        → 事业部负责人在外部审批 → Admin 核验并记录审批依据
        → 配置唯一业务角色 → 撤销冲突/旧业务会话 → 用户进入正确工作台
```

首次部署先执行：

```text
运维配置一次性初始化口令 → /admin/setup 创建唯一 Admin
→ 绑定 TOTP、生成保存型恢复码 → 初始化入口与口令立即失效
```

日常 TOTP 丢失优先使用保存型一次性恢复码；全部正常凭据不可用时，运维按内部审批生成短时部署恢复口令，经 `/admin/recovery` 重设密码与 TOTP，撤销全部旧 Admin 会话并记录不可变审计。此补偿流程不得宣称符合 NIST AAL2。

## 3. 交付物

| 交付物 | 完成标准 |
|---|---|
| 唯一 Admin 初始化 | 正确口令只成功一次；成功后入口关闭；并发不能产生第二名 Admin |
| Admin 独立认证 | 密码 + TOTP 登录、退出和超时；管理会话不能充当业务会话 |
| 两级凭据恢复 | 保存型恢复码与部署恢复口令均单次消费；部署恢复后旧会话为 0 |
| 待审批身份入口 | 同一 `actor_ref` 重复登录不重复建单；待审批用户不可读取业务数据 |
| 角色生命周期管理 | 新增、变更、停用、恢复均要求审批信息；任何时刻最多一个有效角色 |
| 独立管理审计 | 初始化、安全事件、恢复和授权均可查且 Admin 不可修改或删除 |
| 首用计时台账 | 区分外部审批等待与产品内处理；有效审批已具备时全闭环不超过 10 分钟 |
| 运维操作手册 | 可完成首次部署、恢复演练、秘密轮换和备份恢复后的安全处置 |

## 4. 功能优先级

### P0 / 必做

- 一次性创建唯一 Admin，强制绑定 TOTP，并仅当次展示保存型恢复码。
- 独立 Admin 密码 + TOTP 登录、退出、会话超时、失败限制与安全审计。
- 保存型一次性恢复码；运维短时一次性部署恢复口令；部署恢复后全量撤销旧 Admin 会话。
- 钉钉无角色身份按稳定标识幂等登记；用户状态页展示申请状态、更新时间、处理责任和联系指引。
- Admin 待处理列表与检索；身份详情显示可用于和审批材料交叉核验的身份信息。
- 审批人、审批时间、审批依据、目标角色结构化必填；新增、变更、停用、恢复唯一角色。
- 保存前突出显示目标身份和变更前后角色；冲突或双有效角色时拒绝提交。
- Admin 与业务会话、Cookie、路由和数据权限隔离；Admin 未另获业务角色时不能进入业务区。
- 独立不可变管理审计；覆盖初始化、登录失败、恢复尝试、校验拒绝和所有角色变更。
- 首次授权闭环分段计时，支持验证 10 分钟目标和错误授权为 0。

### P1 / 应做

- 授权结果与生效状态反馈，待审批用户可看到“已配置，需重新登录”。
- 部署恢复成功后通知预配置的运维负责人和系统责任人。
- 审计变更前后值对比视图。
- 待审批积压筛选或醒目标识。

### P2 / 后续评估

- 审计导出。
- 周期性角色复核提醒，不自动撤权。
- OA 审批结果自动同步；只有接口、责任与收益明确后才评估。

## 5. 角色与操作面

| 角色 | 可操作 | 不可操作 |
|---|---|---|
| 唯一 Admin | 查看待审批身份；按审批配置、变更、停用和恢复业务角色；查询管理审计；管理自身安全凭据 | 代替业务审批；创建第二名 Admin；停用或删除自己；仅凭 Admin 身份读取经营数据 |
| 事业部负责人 | 在产品外决定员工应获运营或运营主管角色并提供可核验依据 | 使用 Admin 凭据或直接在后台改角色 |
| 待授权用户 | 钉钉登录后查看自己的申请状态和处理指引 | 自选角色、查看他人申请或经营数据 |
| 已授权业务用户 | 按既有运营或运营主管角色进入对应工作台 | 使用业务会话进入 Admin 后台 |
| 运维 | 配置、轮换初始化/恢复秘密；保障时钟与环境安全；执行恢复流程 | 决定业务角色或借恢复能力取得经营数据 |
| 系统 | 幂等登记、唯一性校验、会话撤销、审计和计时 | 自动授予角色或自动将首个用户提升为 Admin |

主要页面：`/admin/setup`、`/admin/login`、`/admin/recovery`、待审批身份、已授权身份、管理审计、Admin 安全设置；业务侧提供待审批、已配置待重新登录、已授权、已停用和配置冲突五种明确状态。

## 6. 前置能力与外部责任

| 能力/配置 | 责任与约束 |
|---|---|
| 钉钉稳定身份标识 | 系统需稳定取得 `actor_ref`；姓名不可用时允许掩码降级，但授权必须与审批材料交叉核验 |
| 业务角色与会话 | 保持运营/运营主管唯一有效角色；角色变更、停用、恢复后旧业务会话失效 |
| 独立 Admin 身份域 | 新增独立账号、会话、Cookie、中间件和审计，不进入业务角色枚举 |
| 初始化口令 | 运维高熵随机生成，仅进入目标环境；成功后消费并移除；备份恢复后必须换新 |
| 部署恢复口令 | 运维经内部恢复审批生成，高熵、短时、单次；成功后消费、移除并轮换 |
| TOTP 保护密钥 | 目标环境独占，开发/线上分离；原始值不得进入日志、审计或前端包 |
| 可靠时钟与 HTTPS | 运维保障 TOTP 时钟同步；线上管理入口使用 HTTPS、同源、受保护 Cookie 与写操作防护 |
| 业务审批材料 | 事业部负责人提供，Admin 录入引用信息；新变更形成新记录，不覆盖历史 |
| 恢复通知接收人 | 企业预配置运维负责人和系统责任人；人员变化时同步维护 |
| 审计留存 | V1 前明确产品内留存期限以及导出/归档责任 |

## 7. 成功指标

| 指标 | 第一版目标 | 口径 |
|---|---:|---|
| 首次授权闭环时间 | ≤10 分钟 | 有效审批依据已具备；从打开初始化页到目标用户进入正确工作台 |
| 错误业务授权 | 0 | 身份错误、角色错误、双有效角色均计入 |
| 高权限操作审计覆盖率 | 100% | 初始化、恢复、角色新增/变更/停用/恢复逐类核对 |
| 重复待审批记录 | 0 | 同一稳定钉钉身份重复认证仍只有一条当前申请 |
| 恢复后旧 Admin 会话 | 0 | 部署恢复完成后核对所有旧会话 |
| 年度价值验证 | 每年重算 | 12 次/年为待验证假设，三年约 216 万元仅为可支撑价值 |

## 8. 待评审关键决策

1. **管理审计留存**：Lead PM 建议产品内保留 3 年，与价值验证窗口一致；备选为 1 年并依赖外部归档。
2. **恢复安全通知**：Lead PM 建议通知预配置的运维负责人和系统责任人；若首版无通知通道，则必须形成上线前线下通知补偿控制。
3. **审批依据格式**：Lead PM 建议结构化必填审批人、审批时间、目标角色、OA 单号/链接或可核验文字，不上传附件、不只填自由备注。

## 9. 风险与缓解

- **单 Admin 锁死**：保存型恢复码 + 部署恢复口令两级恢复，并要求恢复演练。
- **恢复绕过 MFA**：高熵、短时、单次、运维审批、恢复通知、旧会话全撤销和不可变审计。
- **错人或错角色**：身份与审批材料交叉核验、结构化依据、提交前二次展示、数据库唯一约束和错误授权台账。
- **待审批成为新死路**：状态、更新时间、责任人、联系指引与积压筛选均可见。
- **管理权限穿透业务数据**：身份、会话、路由和权限判断独立，隔离行为纳入不可回归验收。
- **审计只记成功**：失败登录、恢复尝试和被拒绝的授权校验也留安全事件，但不记录任何秘密值。

## 10. Lead PM 结论

首版只完成一条最小但闭合的授权链：**钉钉认证 → 幂等待审批 → 外部业务审批 → 唯一 Admin 配置 → 唯一角色生效 → 正确工作台 → 全过程可审计**。不扩张为通用权限平台，不改变已确认的单 Admin、两种业务角色和审批/执行分离边界。
